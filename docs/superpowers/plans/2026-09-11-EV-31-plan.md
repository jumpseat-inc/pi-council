# EV-31 Implementation Plan — durable usage store with session provenance

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A completed council invocation writes one durable usage record into
`getAgentDir()/council/usage/` (outside the pruned run directory), wrapping
EV-30's `SpendRecord` byte-verbatim plus a provenance pointer (session JSONL
path + entry range) whose never-throwing read-back resolves to one of five
stated outcomes.

**Architecture:** New module `extensions/usage-store.ts` — the I/O sibling of
the pure `spend.ts`, on the `mcp/auth-store.ts` pattern (parameter-with-default
root derived from `getAgentDir()`, atomic tmp+rename, explicit `chmod`). One
gated write path (`marker on-chain && forestFullySettled && no file for the
key`) lives in the module and is driven from three triggers wired in
`extensions/index.ts`: hub `onChange`, `agent_settled`, and the
`session_shutdown` sweep. The store key is the invocation marker's `at`
(choose-once is structural and survives restarts).

**Tech Stack:** TypeScript (strict), `bun:test`, pi's `parseSessionEntries`,
pi's `getAgentDir()` (reads `PI_CODING_AGENT_DIR` at call time).

**Spec:** `docs/superpowers/specs/2026-09-11-EV-31-design.md` — the plan argues
from the spec; the binding step-6 `product-owner` ruling is appended verbatim
to `council/cards/EV-31.md`. Where spec and ruling disagree, the ruling wins.

## Global Constraints

- Store root: `getAgentDir()/council/usage/` (R-3). Never `~/.pi-council`,
  never under the repo.
- Filename byte-exact (R-3): `<ISO-basic>_<runId>_<command>.json`; ISO-basic
  `YYYYMMDDThhmmssSSS` rendered from the **marker's `at`**, never wall-clock.
- Modes (R-3): directory `0700`, record files `0600`, `README.md` `0600` —
  explicit `chmodSync` so modes hold regardless of umask.
- `SpendRecord` is frozen: no field gained, lost, or renamed; the stored
  record *wraps* it.
- Read-back `resolveProvenance` never throws; five-value `ResolveOutcome`
  (`resolved | pruned-expected | missing-unexpected | no-session-file |
  range-missing`) per the ruling's mapping table. `pointerSurvivable` is the
  **operative** semantics: `true` iff `sessionPath !== null` and the path was
  *outside* `runsDir(repoRoot)` at write time (the card's drafting note
  documents the ruling's literal formula as arithmetically inverted; gloss and
  mapping win).
- Choose-once: refuse an existing key (byte-identical no-op); never overwrite,
  never recompute, never fabricate a marker time.
- Notify wording is **EV-32's** — assert presence only (one notify on success;
  ≥1 on failure containing the absolute target path).
- No test writes to `~/.pi/agent/`: store root is injectable
  (parameter-with-default) **and** the acceptance leg isolates via
  `PI_CODING_AGENT_DIR` set to an `fs.mkdtempSync` dir (oauth.test.ts
  precedent; read at call time).
- Tests use `bun:test`, live in `test/`, fresh `fs.mkdtempSync` roots; TDD,
  failing test first; Conventional Commits; no hardcoded `.pi` /
  clone paths.
- Gates, in order, on the worktree tree: `bash council/preflight.sh`,
  `bunx tsc --noEmit`, `bun test`, `python3 council/validate.py`. The
  network integration test stays gated behind `COUNCIL_INTEGRATION=1`.
- Work only in `/home/tista/codes/pi-council/.worktrees/ev-31-usage-store`
  (branch `feat/ev-31-usage-store`); never checkout/switch/reset the main
  checkout.

### Task 5: `flushPendingInvocations` — the one gated write path

**Files:** modify `extensions/usage-store.ts`, `test/usage-store.test.ts`

**Interfaces (produced):**
- `interface PendingInvocation { command: string; markerId: string; runId: string; markerAt: number | null; sessionFile: string | null }`
- `flushPendingInvocations(input: { repoRoot; entries; leafId; sessionId; pending; trigger; notify?; storeRoot?; now? }): { outcomes: Array<{ markerId; status: "written"|"existing"|"gate-closed"|"failed"|"unkeyable"; file?; error? }>; remaining: PendingInvocation[] }`

Gate, per pending entry, in order: keyable (`markerAt !== null`, else
`unkeyable` + warning notify + drop) → marker on-chain (parent-walk from
leafId) → `forestFullySettled` (every manifest with `startedAt >= markerAt`
has `exitCode !== null`; else keep pending) → no file exists for the key
(else `existing`, drop — durable no-op) → compute `spendRecord` at this
moment and persist. Per-record catch: never crashes the caller; on failure
notify ≥1 line containing the absolute target path and drop the entry (no
retry-spam against a failing store); on success exactly one notify naming
command, runId, and the record file.

  exactly one success notify containing file/command/runId; EACCES via a

  throw).
- [ ] **Step 2: Fail. Step 3: implement. Step 4: Pass.**

## Self-review notes

- Spec coverage: §2.1–2.8 → Tasks 1–5; §3 wiring → Task 6; §4 T-U1…T-U16 all
  appear (T-U5 T1, T-U3/T-U4 T2, T-U6/7/8/9/15 T3, T-U1/2/10/11/12 T4,
  T-U13/14 T5). §5 out-of-scope items are not implemented.
- The EACCES test uses a read-only **parent** dir (not `chmod 0500` on the
  store root itself): `ensureUsageDir` re-asserts 0700 as owner, which would
  silently undo a root-only chmod and the write would succeed — the parent-dir
  construction is the honest way to make mkdir fail.
- Notify literals in this implementation are placeholders owned by EV-32;
  tests assert presence/substring only.
