# EV-40 Implementation Plan — automatic continuation of a parent turn that ends in a provider error

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A parent turn that ends with `stopReason: "error"` is continued automatically after the configured backoff, and once the budget is exhausted the session stops with a named terminal message rather than a bare Continue.

**Architecture:** Council owns the loop: detect the retryable errored assistant turn at `message_end`/`agent_end`, re-issue only at `agent_settled` (the one event pi documents as "no automatic retry … will run"), drop the errored assistant messages from the continuation's request via a structural one-pass `context` filter, back off with a pure policy function, and surface a `RetryEditor` (TUI) / stdout countdown + exit 75 (headless). The offline faux-provider harness (`test/ev40-harness/`) generalizes `ev43/` and settles P1 and D1 before the engine implementation lands.

**Tech Stack:** TypeScript (strict, `bunx tsc --noEmit`), `bun:test`, the real installed pi CLI driven headless offline (`--offline` + faux provider, scratch HOME, explicit env), pi-tui `CustomEditor` composition.

**Spec:** `docs/superpowers/specs/2026-09-16-EV-40-design.md` (authoritative; the step-6 `product-owner` ruling wins on any conflict).

## Fix cycle 1 — the two Skeptic `closed-red` defects (head SHA `e885d10`)

Both defects were root-caused with a live probe before any fix (systematic
debugging: no symptom patches), then fixed at the source and re-proven live.

### Defect 1 — O-ROUTE: the headless copy must be the final **stdout** line

**Probe** (a minimal `-e` extension writing four distinctive lines, run through
the real installed CLI in print mode):

```
$ node <pkg>/dist/cli.js -p "start" -e harness -e probe --offline --provider ev40 …
EXIT=0
=== STDOUT ===
[PROBE-FSYNC]
EV40-SECOND-RESPONSE call=1
=== STDERR ===
[PROBE-CONSOLE]
[PROBE-STDOUT]
[PROBE-STDERR]
```

**Root cause:** pi's `main` calls `takeOverStdout()` for every non-interactive
mode (`dist/main.js:504` → `dist/core/output-guard.js`), which reassigns
`process.stdout.write` to `stderr.write`. `console.log` and
`process.stdout.write` therefore land on STDERR; `fs.writeSync(1, …)` (a raw
fd-1 write, untouched by the takeover) is the only path to the real stdout.

**Fix:** the headless `print` host in `extensions/index.ts` is now
`fs.writeSync(1, \`${line}\n\`)`, so the R5 countdown lines and the terminal
copy reach real stdout. The live P4 gate asserts the terminal copy is the final
stdout line and each countdown line is on stdout.

### Defect 2 — O-Q5-exit: the live headless exhaustion must exit `75`

**Probe** (an exit-setting extension on a failing faux turn):

```
VARIANT A (process.exitCode = 75 in agent_settled)      EXIT=1
VARIANT B (same 75 re-set from a process.once("exit"))  EXIT=75
VARIANT C (fs.writeSync(1,…); process.exit(75))         EXIT=75
```

**Root cause:** `runPrintMode` returns `1` for an errored final assistant turn
and `main` then assigns `process.exitCode = exitCode` (`dist/main.js:796–798`)
*after* the settle handler has run, clobbering the engine's `75`.

**Fix:** `setHeadlessExitCode` re-sets the code from a one-shot
`process.once("exit")` listener (variant B — the least-destructive means that
works: pi's whole teardown still completes). The live P4 gate asserts
`run.exitCode === 75`.
