# EV-36 One-Row Floor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At every inline progress viewport from one row to a full panel the transcript's rendered line count never exceeds the granted viewport and is never empty, and the one-row case shows the active block's composed head rather than a mid-body continuation.

**Architecture:** Three changes, all inside `extensions/navigator.ts`, plus a new test suite. (1) `TranscriptView.render` gains a `viewportRows === 1` branch that returns exactly one line — element 0 of `unitLines` for the **effective-indexed** unit, read-only: `follow ? vis[vis.length-1] : fv` (ruling Q1, R3); `focused` is never written by the projection. (2) The grant becomes a per-render parameter: `TranscriptView.setViewportRows(n)` and `CouncilTreeWidget.renderProgress` re-grants the cached view every render (fixes the frozen-grant defect at the termRows-9 vector). (3) One width clamp at the `unitLines` single-head site (ruling Q4), idempotent with the toolCall head's existing clamp.

**Tech Stack:** TypeScript (strict), bun:test, `@earendil-works/pi-tui` helpers (`visibleWidth`, `truncateToWidth`).

**Spec:** `docs/superpowers/specs/2026-09-15-EV-36-design.md` (commit `4a62771`) — the plan argues from the spec; executors read both. The step-6 product-owner ruling (Q1–Q4) is binding; where this plan and the spec disagree, the spec wins.

```ts
		const focusLine = starts[fv] ?? 0;
		const maxTop = Math.max(0, all.length - this.viewportRows);
		if (this.viewportRows === 1) {
			// EV-36 (R3): one-row floor — the effective-indexed unit's composed head,
			// read-only. follow ? live tail : cursor. No write to `focused` (Q2); the
			// marker stays the existing `vi === fv` gate, so a fresh follow-on view
			// at vis.length > 1 carries no ▌ (ruling Q3 — the shipped comprehension
			// rule; the marker returns on the next nav key, which sets follow=false).
			const line = vis.length === 0 ? all[1]! : all[starts[this.follow ? vis.length - 1 : fv]!]!;
			return [line];
		}
		if (this.follow) this.topLine = maxTop;
		else this.topLine = Math.min(Math.max(0, focusLine - 2), maxTop);
		return all.slice(this.topLine, this.topLine + this.viewportRows);
```

`all[1]` is the existing empty-vis placeholder (`render` pushes exactly one placeholder line after the header when `vis` is empty). The branch returns early — it never touches `this.topLine`, so no staleness carries when the grant later grows (the slice branch recomputes `topLine` every render).
