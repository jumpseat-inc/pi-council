## Grounding (verified against the code, not recalled)

- `extensions/dispatch.ts:55` — `spawnSeatJob` reads `process.env.COUNCIL_EVAL_MODEL` (ambient) and resolves via `resolveEffectiveModel(seat, envModel, {model, thinking})`.
- `extensions/seats.ts:415-445` — precedence per dimension: explicit per-dispatch param > `COUNCIL_EVAL_MODEL` env > `.council.json` > frontmatter. Layer 2 (`:427`): an env value carrying a `:thinking` suffix sets `thinkingLevel` **even when the param supplies the model** (the param supplies no thinking). This changes `thinkOverridden` (`dispatch.ts:59`) and therefore the string written to `spawnEnv.COUNCIL_EVAL_MODEL` (`dispatch.ts:97-99`) — the ambient can change line 210's expectation, not only line 213's.
- `extensions/dispatch.ts:92-99` — the spawn env is a spread copy of `process.env`; the eval carrier rides the spawn env, never the parent's `process.env`. **This is the invariant line 213 was reaching for**: "the dispatch primitive does not mutate the ambient" — but as written it only tested "the ambient happened to be unset".
- `extensions/seats.ts:17,377-392` — `THINKING_LEVELS` includes `"high"`; `parseQualifiedModel("openrouter/ambient/model:high")` → model `openrouter/ambient/model`, thinking `high`.
- `test/override.test.ts` sets/deletes its own `COUNCIL_EVAL_MODEL` — controlled; only `test/eval-runner.test.ts:210,213` read the ambient uncontrolled.
- `bun test` runs the file in-process, so the ambient is whatever the runner's shell exports (a council seat shell legitimately carries it — it is the canonical eval carrier).
