# FLLWUP-44 — Name the provider failure before the backoff countdown — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** During a retried parent turn's backoff, the surface names the provider failure once per episode — a second `RetryEditor` line above the R5 countdown (TUI) and one `host.print` before each episode's first countdown (headless) — with the R3-ruled string `The provider returned an error.`

**Architecture:** Zero new controller state. `RetryController.failureLineText()` returns the static ruled string iff `surfaceState === "backoff"` (the sole gate, exactly mirroring `lineText()`); `RetryEditor.render(width)` pushes the failure line above the countdown with the same `borderColor` token and the same `truncateToWidth` clamp; the headless schedule branch in `onSettled` prints the same string once per episode immediately before `runHeadlessCountdown`. The failure being named is a single constant (`classifyParentTurnRetry` retries only the byte-exact literal `Provider finish_reason: error`), so a pure static formatter is correct by construction.

**Tech Stack:** TypeScript (strict), `bun:test`, pi's `pi-tui` (`truncateToWidth`, `EditorTheme`).

**Spec:** `docs/superpowers/specs/2026-09-17-FLLWUP-44-design.md` (committed at `a64ac7b`) — the plan argues from the spec; executors read both. Card: `council/cards/FLLWUP-44.md` (steps 1–6b verbatim; R3 ruling is binding).

## Global Constraints (verbatim from the R3 ruling + spec §2)

- Ruled string, byte-exact: `The provider returned an error.` — period, no glyph, no vendor token, no `finish_reason` substring, not byte-equal to `Provider finish_reason: error`, does not start with `Retrying in`.
- Re-show semantic: **per backoff episode** — shows at every `beginBackoff` (attempts 2 and 3), survives that episode's countdown ticks, disappears with `clearToIdle()` / `moveToExhausted()` / `escAbort()`. **Zero new controller state**; `surfaceState === "backoff"` is the whole gate.
- Emitted iff `classifyParentTurnRetry(pendingError) === "retry"` — never assembled from `pendingError.errorMessage`; pure static `formatRetryFailure()` output.
- R5 binding strings are immutable: countdown `Retrying in 2s (attempt 2 of 3) — Esc to abort` (dash U+2014); exhaustion `Retries exhausted after 3 attempts. The provider kept failing. Press Enter to try again.` Exit 75 headless unchanged.
- Existing R5-guard tests pass **unmodified**. The ONLY permitted edit to an existing test is the one literally titled "appends exactly one extra line while the surface is non-idle; none while idle" (title lies about its `>= 1` assertion) — retitle/repair it to pin the new composition without changing its R5 string content.
- No `ui.notify` / chat carrier; no `RetryController` latch; no raw `fs.writeSync` in `onSettled` (the injected `ParentRetryHost.print` is the only observable path).
- TDD: failing test first for every pin; keep the suite green per task.
- Gates (this repo's set, in order): `bunx tsc --noEmit`; `bun test`; `python3 council/validate.py`. No database/import/server gate; `COUNCIL_INTEGRATION=1` stays gated off.

/** FLLWUP-44 (R3 ruling): the backoff episode's failure line. The parent
 * classifier (classifyParentTurnRetry) retries exactly one literal, so this
 * line is a pure static output — never assembled from pendingError. If the
 * classifier ever widens past that single literal, this static line must be
 * revisited. */
export function formatRetryFailure(): string {
	return "The provider returned an error.";
}

On `RetryController`, next to `lineText()`:

```ts
	/** FLLWUP-44: the failure line for the current surface — the ruled string
	 * exactly while the backoff surface is up (per episode; zero extra state),
	 * "" otherwise. Mirrors lineText(). */
	failureLineText(): string {
		return this.surfaceState === "backoff" ? formatRetryFailure() : "";
	}
```

In `RetryEditor.render(width)`, push the failure line above the countdown:

```ts
	render(width: number): string[] {
		const lines = super.render(width);
		const failure = this.controller.failureLineText();
		if (failure) {
			const styledFailure = this.borderColor ? this.borderColor(failure) : failure;
			lines.push(truncateToWidth(styledFailure, width));
		}
		const lineText = this.controller.lineText();
		if (!lineText) return lines;
		const styled = this.borderColor ? this.borderColor(lineText) : lineText;
		lines.push(truncateToWidth(styled, width));
		return lines;
	}
```
