# EV-19 — Scoring rubric and run verifier: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the pure scoring module `extensions/eval-rubric.ts` (gradeCell + replayJudgeVerdicts + projectVerdictRecord, plus the VerdictRecord/ResultRecord/GradingUsage/JudgeVerdicts/GradedCriterion/GradeIO types), narrow the `settled` rubric validation to role-only, and add `test/rubric.test.ts` covering all ten settled testable claims.

**Architecture:** A pure, dependency-injected module. `gradeCell` is a pure function over `{rubric, judgeVerdicts, io}` where `io` is the injected `GradeIO` seam (the only outside contact). Judge criteria replay from a caller-supplied `judgeVerdicts` map; gates/artifacts/settled probe through `io`. No `node:fs`, no `node:child_process`, no store, no dispatch path — those are EV-20's boundary.

**Tech Stack:** TypeScript (strict), bun:test, bun run isolate.

**Spec:** `docs/superpowers/specs/2026-09-03-EV-19-design.md` (settled/binding; derives from EV-16 §5/§6.3/§6.4, EV-18 §3/§5 and the EV-19 O1 ruling — none reopened).

## Global Constraints

- `extensions/eval-rubric.ts` must be **pure**: never touches `node:fs` or `node:child_process` (spec §2, A4, test 10.9).
- Import `validateRubric`, `Rubric`, `RubricCriterion` from `./eval-fixtures.ts` — single authority, no second validator (spec §2, C3, test 10.10).
- Score = `passes / criteria.length`, judge always in the total denominator (spec §2 scoring).
- Missing judge verdict → `gradeCell` throws (never 0, never renormalize) (spec §2, test 10.5).
- `score` range 0..1.
- `settled` narrowing: `validateCheck` `settled` requires `role`, forbids `path`; both path-only and role+path throw at load (spec §6, O2, test 10.6). Defense-in-depth: `gradeCell` throws on any role-less/path-bearing `settled` it receives.
- `projectVerdictRecord` merge (O4): `gradingUsage = {input,output,cost}` from `report.usage` + `elapsedMs`/`stopReason` from report top-level; `report.usage.turns` excluded (spec §7, test 10.7).
- Exact type exports per spec §2 (names + fields verbatim from the spec).
- Gates (authoritative = `.github/workflows/gates.yml`), run in order and full: `bun install --frozen-lockfile`; `bunx tsc --noEmit`; `bun test` (integration stays gated off unless `COUNCIL_INTEGRATION=1`); `python3 council/validate.py` prints `All council artifacts valid`.
- Commits Conventional Commits format; pushed against `main`; PR opened against `main`, not merged.

- [ ] **Step 3: Narrow the validator**

Replace the `settled` branch in `validateCheck` (`extensions/eval-fixtures.ts`):
```ts
case "settled": {
  const role = typeof raw.role === "string" && raw.role !== "" ? raw.role : undefined;
  const p = typeof raw.path === "string" && raw.path !== "" ? raw.path : undefined;
  if (role === undefined) {
    throw new Error(`${file}: settled check must carry "role" (a settled check is role-only)`);
  }
  if (p !== undefined) {
    throw new Error(`${file}: settled check must not carry "path" — use artifact-present for a file probe`);
  }
  return { kind, role };
}
```
