# EV-42 — Per-attempt identity for a retried dispatch: settled design

Status: **settled** — written at step 7 from the Council record
(`council/cards/EV-42.md` steps 1–6), not re-derived. Where this spec and the
step-6 `product-owner` ruling disagree, the ruling wins.

Card: `EV-42` — *Per-attempt identity for a retried dispatch in the run
substrate* (EPIC-9). Goal (unchanged):

> Every attempt of a retried dispatch is recoverable from that dispatch's
> manifest alone — its session transcript and its spend — and the dispatch's
> provider-reported figure sums every attempt.

## 0. Authority and binding inputs

- **Card re-scope (EV-39 step-6 `steward` ruling, applied):** one job id, one
  manifest, one job-tree row per dispatch; `attempt` is fixed by the EV-40
  §2.8 agreement and may not be renamed; `attemptGroupId` is dropped.
- **Phase 1 rulings R1–R5 (binding):** the retry classifier (`retry.ts`), the
  retry policy (`seats.ts` `loadRetryConfig` + scaffold defaults), and the
  one-row-per-dispatch cardinality are consumed as settled inputs; this card
  changes none of them.
- **`product-owner` step-6 ruling (job-24, binding; J1/J3).** Full document
  `vault/raw/2026-09-17-po-ev42-step6-ruling.md`, appended verbatim to the
  card. J1 fixes the `partial` producer predicate; J3 fixes the new legend
  copy and its forward-safety discipline. J2/J4/O10 ride as gates/evidence
  items, not as rulings.
- **`owner` dissent (recorded, not adopted):** the all-unaccounted retried
  record must carry a non-undefined `partial`. J1 rejects it; the spec
  implements the figure-scoped branch.

## 1. What is already true at the cut

Read first-hand at `1b99ed9` (HEAD at spec time):

- `Hub.respawn` reuses the job id, carries `usage` cumulatively (it spreads
  `...prev` and does **not** override `usage`), keeps `startedAt`, and
  re-bases `attemptStartedAt` (`extensions/hub.ts:186-221`). `writeJobManifest`
  emits **one** `sessionId` — the current attempt's — plus `attempt` only when
  `> 1` (`extensions/hub.ts:111-128`; `extensions/runs.ts:44-62`).
- `council_dispatch` mints per-attempt session ids `${jobId}-attempt${n}`
  (`extensions/hub-tools.ts:269-276`), and each attempt writes its own JSONL
  into the same run dir. `RunManifest` indexes none of them — **this is the
  gap the card closes.**
- The flush maps **one job per manifest** off `m.sessionId`
  (`extensions/usage-store.ts:421-427`), so it fetches only the final
  attempt's generations, then stamps `partial:"final-attempt-only"`
  unconditionally on the report copy whenever any eligible manifest has
  `attempt > 1` (`extensions/usage-store.ts:443-448`). **This is the line
  EV-42 replaces.**
- `fetchProviderReport` builds the report: `status = failures.length > 0 ?
  "unavailable" : "reported"`; per-entry `sessionPath === null` pushes
  `session-missing`, zero generation ids pushes `no-generation-id`, a
  transport rejection pushes `fetch-failed:`/`timeout`; reason is the C3
  worst (`extensions/provider-cost.ts:200-211, 275-335`).
- `formatUsageBlock` pushes the partial legend iff `provider.partial !==
  undefined`, after the reported row and before the `n/a` legend
  (`extensions/usage-block.ts:32, 113-121`); the legend key and predicate are
  presence-based.
- `manifest.usage` is cumulative and feeds `sumSubtreeUsage` / `spend.ts:250`.
- `pruneRuns` deletes the whole run dir, manifest included
  (`extensions/runs.ts:171-178`), so manifest-level attempt data and the
  JSONLs die together; the durable store record is the only long-lived
  artifact. "Recoverable from the manifest alone" is an **index** claim while
  the run lives (the manifest names each attempt's transcript; spend is
  recovered from it), plus a durable decomposition on the record
  (`ProviderGeneration.attempt`).

## 2. Settled design

### 2.1 The manifest field (substrate)

`extensions/runs.ts` — `RunManifest` gains:

```ts
/** EV-42 — per-attempt provenance. Present iff attempt > 1 (same gate as
 * `attempt`); ordered and unique across attempts 1..N at every settled
 * write; a mid-flight (retrying) manifest carries the settled prefix.
 * Pointer-only: each attempt's spend is recovered from the session JSONL
 * this names. */
attempts?: { attempt: number; sessionId: string }[];
```

- **Pointer-only.** No per-attempt timing, exit state, or `usage` tuple. The
  round-2 delta-tuple design (`{attempt, sessionId, usage}` +
  `usageBaseline`) was proposed and withdrawn by its own author; the Intent's
  mechanism sentence ("persisting the per-attempt session **pointers** on the
  manifest and walking that list") and the `pruneRuns` bound settle it. A
  persisted tuple adds no post-pruning recoverability and needs snapshot /
  subtract machinery because `respawn`'s `...prev` spreads the live `usage`
  accumulator by reference (`extensions/hub.ts:196-201`, mutated in place by
  `processLine`).
- **Non-retried manifest byte-identical:** neither `attempt` nor `attempts`
  is emitted when the ordinal is `<= 1`.

### 2.2 Hub bookkeeping (additive only — AGENTS.md §7)

`extensions/hub.ts` deltas, each failing-test-first, touching no
kill/stall/timeout semantics:

1. `Job` gains `attempts?: {attempt: number; sessionId: string}[]`.
2. `spawnJob` seeds the attempt-1 record (`{attempt: 1, sessionId:
   opts.sessionId ?? id}`).
3. `settle()` appends the **just-completed** attempt
   `{attempt: job.attempt ?? 1, sessionId: job.sessionId ?? job.id}` **before**
   calling `job.retry?.onSettle(...)`. This is the only point where the
   completed ordinal and the completed session id are unambiguously paired:
   `onSettle` advances `job.attempt` to the *pending* ordinal before the hub's
   retrying write (`extensions/job-retry.ts:65-80`, then
   `extensions/hub.ts:335-352`). Append is idempotent per ordinal (guard
   against re-entry).
4. `writeJobManifest` emits `attempts` under the same
   `attempt !== undefined && attempt > 1` gate as `attempt`. It must **never**
   synthesize an entry from `job.attempt` — doing so inside the retrying write
   would record `{attempt: 2, sessionId: <attempt 1's id>}`, a lie.

Resulting shapes (pinned by tests):

| point in the chain | manifest `attempt` | manifest `attempts` | manifest `sessionId` |
|---|---|---|---|
| attempt 1 running | absent | absent | `id` |
| attempt 1 settles retryable (retrying) | `2` (pending) | `[{1, id}]` | `id` (completed) |
| attempt 2 running (respawn) | `2` | `[{1, id}]` | `id-attempt2` |
| attempt 2 settles (final, done) | `2` | `[{1,id},{2,id-attempt2}]` | `id-attempt2` |
| cancel mid-backoff | `2` | `[{1, id}]` | `id` |

Invariant: `attempts[last].sessionId === manifest.sessionId` at every
**settled** write. It does not hold mid-flight (respawn write), which is fine:
the flush is gated closed while any window manifest has `exitCode === null`
(`forestFullySettled`) and reads manifests only after the final settle.

### 2.3 The substrate accessor

`extensions/runs.ts` gains a pure accessor so the legacy fallback lives in one
place:

```ts
export function attemptEntries(m: RunManifest): {attempt: number; sessionId: string}[] {
  return m.attempts ?? [{ attempt: m.attempt ?? 1, sessionId: m.sessionId }];
}
```

The fail-closed legacy fallback synthesizes exactly one entry and **never**
relabels `m.usage` as a per-attempt delta (the pointer shape carries no
usage). Shape discrimination (new shape vs legacy window shape) is the
manifest's own property: `m.attempts !== undefined`.

### 2.4 The harvest walk (usage-store)

`extensions/usage-store.ts:421-427` — replace the one-entry-per-manifest map
with a per-attempt flatten:

```ts
const jobs = manifests
  .filter((m) => m.model.startsWith("openrouter/") && m.startedAt >= p.markerAt!)
  .flatMap((m) =>
    attemptEntries(m).map((a) => ({
      jobId: m.id,
      model: m.model,
      attempt: a.attempt,          // present on the new shape + window shape
      sessionPath: findSessionFile(input.repoRoot, p.runId, a.sessionId) ?? null,
    })),
  );
```

`attemptEntries` distinguishes the shapes: the new shape yields one entry per
recorded attempt (`attempt` ordinals); the legacy fallback yields one entry
derived from `m.attempt`/`m.sessionId`. To keep the carve-out explicit, the
store computes:

```ts
const openrouterInWindow = manifests.filter(
  (m) => m.model.startsWith("openrouter/") && m.startedAt >= p.markerAt!,
);
const hasNewShape = openrouterInWindow.some((m) => m.attempts !== undefined);
const hasLegacyWindowShape = openrouterInWindow.some((m) => (m.attempt ?? 1) > 1 && m.attempts === undefined);
```

**Delete the unconditional `retried` stamp at `usage-store.ts:443-448`.**
Replace with:

- If `hasNewShape`: no store-side stamp. The report already carries the
  figure-scoped `partial` + `unaccountedAttempts` computed by
  `fetchProviderReport` (§2.5).
- Else if `hasLegacyWindowShape`: keep today's stamp **byte-identical** —
  `{ ...provider, partial: "final-attempt-only" as const }` whenever
  `provider !== null` (status-independent, exactly as today).
- Else: unchanged passthrough.

(Precedence note: a window containing both shapes is possible after a package
upgrade; the new-shape producer owns the disclosure and the legacy stamp does
not fire. Pinned by test.)

### 2.5 Provider module semantics (figure-scoped `partial`)

`extensions/provider-cost.ts`:

- `ProviderPartialReason` becomes `"final-attempt-only" |
  "attempts-unaccounted"`.
- `ProviderCostReport` gains record-only
  `unaccountedAttempts?: number[]` (present iff a figure exists and the walk
  left ≥1 attempt unaccounted).
- `FetchProviderReportInput.jobs` entries gain `attempt?: number`.
- `ProviderGeneration` gains additive `attempt?: number` (absent for
  single-attempt / legacy entries ⇒ old records byte-identical);
  `toGeneration` stamps it from the job entry. `jobId` stays the tree-row id —
  no `${jobId}-attemptN` job key is minted.

**Per-entry rule** (discriminator: does the entry carry `attempt`?):

| entry state | new shape (entry carries `attempt`) | legacy entry (no `attempt`) |
|---|---|---|
| `sessionPath === null` | unaccounted (`session-missing`) | failure `session-missing` (today) |
| readable, zero ids, or read throws | unaccounted (`no-generation-id`) | failure `no-generation-id` (today) |
| ids present, fetch succeeds | reported generation | reported generation (today) |
| ids present, fetch rejects | failure `fetch-failed:`/`timeout` | failure (today) |

A read failure (truncated/corrupt file) must land in the **unaccounted**
bucket, never in a contribute-zero bucket — otherwise a corrupt attempt
collapses to `ids = []` and the figure reads whole (the EV-39 falsification
class). Today's code collapses unreadable → `ids = []` →
`no-generation-id` (`extensions/provider-cost.ts:288-297`); under the new
shape that class becomes unaccounted, which is exactly why this rule is
load-bearing.

**Report assembly:**

- `no-api-key` → early `unavailable`, `totalCost: null`, unchanged.
- `generations` = every successfully fetched generation across all entries,
  in walk order; `totalCost` = Σ over reported generations (`null` iff none
  reported), unchanged reduce.
- `unaccountedAttempts` = sorted ordinals of new-shape entries that yielded no
  generation ids.
- `status = (failures.length > 0 || generations.length === 0) ? "unavailable"
  : "reported"`. The `generations.length === 0` clause is what makes the
  all-unaccounted new shape `unavailable`; it does not change any legacy path
  (legacy zero-generation entries already push a failure).
- On `unavailable`, `reason` = C3 worst over the observed classes, including
  the unaccounted entries' classes (`session-missing` ranks above
  `no-generation-id`, `extensions/provider-cost.ts:200-211`).
- **The predicate (J1, binding):** on the new shape,
  `partial := totalCost !== null && unaccountedAttempts.length > 0`, literal
  `"attempts-unaccounted"`; otherwise `partial` is absent. Set it in the
  producer, not post-hoc in the caller — the disclosure is the module's claim.

### 2.6 The renderer (legend copy, J3)

`extensions/usage-block.ts`:

- The predicate stays `input.provider?.partial !== undefined`.
- Replace the single `PARTIAL_LEGEND` constant with a **total legend map** plus
  a fallback, so a durable record carrying a literal this build does not know
  never fails open into a silent drop of the qualifier (choose-once records at
  `extensions/usage-store.ts:388-392` are never rewritten):

```ts
const PARTIAL_LEGENDS: Record<ProviderPartialReason, string> = {
  "final-attempt-only": "usage  partial = reported figure is final-attempt-only",
  "attempts-unaccounted": "usage  partial = reported figure excludes unaccounted attempts",
};
const PARTIAL_LEGEND_FALLBACK = "usage  partial = figure is not whole";
```

Stack order unchanged: reported row → partial legend → `n/a` legend.

**Legacy literal rendering is verbatim, not migrate-on-read.** Both J3 paths
were ruled honest; the spec picks verbatim because an existing green pin fixes
it: `test/usage-block.test.ts:612` asserts a record whose `partial` is
`"final-attempt-only"` renders `usage  partial = reported figure
is final-attempt-only`, and the EV-39 G4 pin
(`test/usage-store.test.ts:845-885`) asserts the same legend for the window
shape's persisted record. Migrate-on-read would change that rendered output
and break the pin; it is not worth a red suite for a surface-smoothing
preference. Both literals name the figure's property; both are honest.

### 2.7 Byte-identity and blast radius (mandatory)

- **Non-retried dispatch:** manifest has neither `attempt` nor `attempts`;
  persisted record byte-identical to pre-EV-42 (no `attempt` on generations,
  no `partial`, no `unaccountedAttempts`, no legend).
- **Legacy window shape:** `partial:"final-attempt-only"` persists
  byte-identical (EV-39 G4 pin stays green, including its rendered legend).
- **Single-attempt readable-empty:** `no-generation-id` → `unavailable`, no
  `partial` (`test/provider-cost.test.ts:361-389` stays byte-green).
- **`manifest.usage` stays cumulative**; `sumSubtreeUsage` / `spend.ts:250`
  unchanged (O6 `closed-green`).
- **`USAGE_RECORD_SCHEMA_VERSION` stays 2** — only optional fields are added.
- **`hub.ts` is touch-additively** (§2.2); no retry/kill/stall semantics move.

## 3. The disclosure contract (tests the owner must write)

The ruling's five cases, each runnable off injected transports / a temp
repoRoot (no network):

1. **Whole retried dispatch.** Two attempt JSONLs each with one generation,
   costs c1 + c2 → persisted `provider.status === "reported"`,
   `totalCost === c1 + c2`, `partial === undefined`, generations carry
   `attempt: 1|2` with the same `jobId`, and the block renders **no** `partial`
   legend. *Fails today: the flush resolves only the final attempt's file and
   stamps `partial` (`test/usage-store.test.ts:877`).*
2. **Partial-with-figure (new shape).** Attempt 1 unaccounted, attempt 2
   reports c2 → `status:"reported"`, `partial:"attempts-unaccounted"`,
   `unaccountedAttempts:[1]`, `totalCost === c2`; the block renders the
   reported row and exactly
   `usage  partial = reported figure excludes unaccounted attempts`, with **no**
   `n/a` legend.
3. **All-unaccounted (new shape) — load-bearing.** Both attempts unaccounted →
   `status:"unavailable"`, `reason` = C3 worst (`session-missing` if a pointer
   was null, else `no-generation-id`), `totalCost:null`,
   `partial === undefined` (assert `!("partial" in provider)`),
   `unaccountedAttempts` may be present as audit but the block renders the
   subtree `cost=n/a`, last line exactly
   `usage  n/a = provider figure unavailable`, and **no `partial` legend**.
   This is the case `owner` dissented on; the assertion follows J1.
4. **Legacy window carve-out.** Manifest `{attempt: 2, attempts: undefined}`
   → persisted `partial:"final-attempt-only"` byte-identical (extends the
   EV-39 G4 pin). Also pin the mixed-window precedence (§2.4).
5. **Non-retried byte-identity.** Single-attempt manifest has no `attempts`;
   persisted record byte-identical to pre-EV-42.

Additional pins the deliberation requires:

- **Ordinal-at-settle:** after an attempt-1 retryable settle the on-disk
  manifest reads `{attempt: 2, nextAttemptAt: <set>, attempts: [{attempt: 1,
  sessionId: <id>}]}`, `sessionId === <id>` — never `{attempt: 2}` paired with
  attempt 1's session id, never an entry synthesized from `job.attempt`.
- **Complete + ordered list:** after budget exhaustion, `attempts` is 1..N in
  order, unique, and `attempts[last].sessionId === manifest.sessionId`.
- **Single-entry compatibility:** a single-entry present-but-empty legacy
  session stays `unavailable` / `no-generation-id` with no `partial`
  (`test/provider-cost.test.ts:361-389`).
- **Legend fail-closed:** a report whose `partial` is an unknown literal still
  renders a `usage  partial` line from the fallback (never fails open).
- **Unaccounted is not zero:** a corrupt/truncated attempt file plus a
  reporting sibling never yields `reported && partial === undefined`.
- **No double count:** `sumSubtreeUsage(manifests, id).subtree.cost ===
  manifest.usage.cost` for a retried manifest.

## 4. O10 — implementation-time evidence item (not a blocker)

O10 (`open-untested` at step 4): does a failed attempt commonly leave an
**absent** JSONL or a **header-only** one? It cannot be measured in
deliberation; it belongs to implementation. Under the converged P2 grouping
both states are `unaccounted`, so the semantics do not depend on the answer —
but the owner should, if it observes a real failed attempt's run dir during
implementation, record which file state it produced, since the distribution is
the input to whether `owner`'s grouped-vs-split weighting should be revisited.
Absent evidence is acceptable; a fabricated fixture is not.
