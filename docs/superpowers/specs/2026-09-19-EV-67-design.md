# EV-67 — Gate verdict rendered as information at the draft-then-confirm approval gate

Design spec, settled by the EV-67 council (full council, surface-touching;
three seats × 2 rounds, skeptic attack, consolidator synthesis, product-owner
ruling J1–J4). This file is the owner's complete handoff: an owner reading
only this, plus the code it names, must reach exactly one design.

## Contract (the judge's verbatim text)

> At the /features-new draft-then-confirm approval gate — the step that
> presents each drafted card for approve, edit, or drop — every card of a
> gate-enabled run renders exactly one additional line naming the resolved
> mode and the recorded one-line basis, no card lacks that line, and a test
> over the render function proves the approve, edit, and drop options and the
> printed card body are byte-identical to the pre-gate rendering.

Locators, pinned: the **approval gate** is `council/procedures/features-new.md`'s
`## 4. Draft-then-confirm` step; the **gate call** step is `## 3. Record the
advisory gate call` and only *records* the verdict. The line is presented at
step 4, never at step 3.

## What exists today (verified at base, read from source)

- `extensions/gate-ledger.ts` — the record schema (`GateLedgerRecord`), the
  append-only JSONL writer, and the tolerant reader `readGateLedger(repoRoot)`
  (zero-write: `existsSync`/`readFileSync` only). The record's `basis` field
  is optional (`basis?: string`) and its doc comment already stakes the claim
  `"Mode: " + resolvedMode + " — " + basis` byte-equals EV-67's pinned render
  (the separator is the em dash, U+2014). On a failed call the writer
  (`gate-run.ts`'s `failRun`) records `resolvedMode: "Deliberate"` and
  `basis: "gate call failed: " + <verbatim transport reason>` into the same
  two fields — **there is no failure branch in the record**.
- `extensions/gate-tool.ts` — the parent tool `council_gate` returns exactly
  `{ policyMode, cards: [{ id, callId, status, message? }] }`. A non-null
  `callId` implies a ledger line was written at call time (the writer returns
  `rec.callId` only after a successful append). `callId: null` + `status:
  "failed"` means the call threw **before** recording — the transport reason
  is scrubbed at this tool boundary (only a generic message survives), so no
  render can ever show it. Under the packaged default (`mode: "off"`) the
  result is `{ mode: "off", recorded: 0 }` with **no `cards` key at all**.
- `council/procedures/features-new.md` — step 3 currently says "do not print
  the recorded verdict — the human sees the card text at the step-4 gate, not
  the gate's verdict" (the clause this card inverts), and step 4 is the
  draft-then-confirm presentation.
- `test/ev66-advisory-intake.test.ts` — the ledger-source canary: (arm 1) no
  `extensions/` module outside `gate-ledger.ts` references `readGateLedger` or
  `gate-ledger.jsonl`; (arm 2) `gate-ledger.ts`'s only runtime importer is
  `gate-run.ts`. `extensions/gate-render.ts` trips **both** arms by
  construction, so the canary is amended (below) — this is sanctioned; the
  read-only posture the canary protects is preserved by assertion, not
  deleted.
- EV-66's opacity contract: no verdict token, no `Mode: `, no basis ever
  crosses the `council_gate` tool result. **It is untouched by this card** —
  the existing EV-66 opacity assertions must pass unmodified.

## The settled design

### 1. The format string lives at the record layer — `decisionLine` in `gate-ledger.ts`

Export from `extensions/gate-ledger.ts`:

```ts
export function decisionLine(record: { resolvedMode: string; basis?: string }): string
```

producing exactly `"Mode: " + resolvedMode + " — " + basis` (U+2014), and —
the ruling's A′ addendum — when `basis` is absent (a v1 ledger line), the
mode token alone: `"Mode: " + resolvedMode`. Implementation must make the
absent-basis path nullish-coalescing or equivalent so no `undefined`, `null`,
or `NaN` byte can ever appear. `gate-ledger.ts` is the **only** module in the
repo owning a `Mode: `-prefixed format expression; the doc comment's
byte-equality claim becomes executable.

Cell table (all cells route through `decisionLine` — there is no
failure-format branch; fallbacks are basis-slot text, per ruling J2, and
carry no `Mode: ` prefix of their own):

| Cell | Condition | Rendered line |
|---|---|---|
| A | record found (success **or** recorded failure) | `Mode: <resolvedMode> — <basis>` (a recorded failure's basis already reads `gate call failed: <reason verbatim>` — the verbatim reason renders exactly once, from the record) |
| A′ | record found, `basis` absent (v1 line) | `Mode: <resolvedMode>` — no separator, no `undefined` |
| B | `callId: null` (failed before recording) | `Mode: Deliberate — gate call failed before recording a verdict` |
| C | recorded `callId`, no matching ledger line | `Mode: Deliberate — recorded gate call not found in ledger` |

Cells B and C are implemented by feeding a **fallback-literal basis
constant** into `decisionLine` with `resolvedMode: "Deliberate"` — e.g.
`decisionLine({ resolvedMode: "Deliberate", basis: "gate call failed before
recording a verdict" })`. Neither fallback literal may gesture at the
scrubbed transport reason or carry an imperative verb (an imperative there
would turn a failure fact into an instruction). B ("before recording a
verdict") and C ("recorded … not found") are distinct, honestly different
states — never conflated.

### 2. The presentation module — `extensions/gate-render.ts`, a pure leaf

New parent-session tool `council_gate_render` (registered in `index.ts`'s
parent-mode block, **never** in `registerHubTools`):

- **Input**: the mechanical step-3 result's per-card array
  `[{ id, callId, status }]`. The tool takes **no card text** — no `title`,
  `goal`, or `acceptance` field in its schema (that is the construction that
  makes the byte-identity test cheap and load-bearing: the render function
  cannot alter the card body because it never sees it).
- **Join**: one `readGateLedger(repoRoot)` pass, joined by `callId`. Never
  `stateHash` — identical draft text in two runs collides in a committed,
  append-only file, and the hash moves if `wiki/`/`rulings/` change between
  call and presentation. `callId` is the only sound per-card correlate.
- **Output**: `{ cards: [{ id, modeLine }] }`, in input order — strings
  only. Per-card attachment rides the input order; the procedure places each
  line under its own card.
- **Posture**: zero writes, zero policy loads (`loadGatePolicy` is never
  referenced), no widget calls, no card-body text, no prompt vocabulary.
  Off-mode: the tool is never invoked per procedure copy (the step-3 result
  has no `cards` key); defensively, an invocation with an empty array
  returns `{ cards: [] }` — zero lines.

### 3. Procedure edit — `council/procedures/features-new.md`

- **Step 3**: replace the "do not print the recorded verdict — the human sees
  the card text at the step-4 gate, not the gate's verdict." clause with the
  one-line mandate (the verdict is rendered at the step-4 approval gate, per
  the card's `goal`). Byte-preserve: the `recorded, never acted on` sentence
  and the "name it at the step-4 gate as mechanical bookkeeping" instruction;
  the `## 3.` heading and its position before `## 4.` must not move.
- **Step 4**: an additive block — after presenting each card's draft, invoke
  `council_gate_render` ONCE with the per-card `{id, callId, status}` array
  from step 3's `council_gate` result, then print each returned `modeLine`
  verbatim, exactly once, immediately below that card's body and above its
  approve/edit/drop prompt. Add no words around it, reformat nothing, write
  nothing (the mode line is presented, never written — third member of the
  presented-never-written pattern). Under the packaged default (mode `off`)
  the render tool is never invoked and no line renders.

### 4. Canary amendment — `test/ev66-advisory-intake.test.ts`

Replace both arms with the role-enumerated accessor allowlist
`{ gate-run.ts: writer, gate-ledger.ts: owner, gate-render.ts: presentation }`
plus two preserved-in-strength assertions:

1. **Read-only posture**: no module outside `gate-run.ts` references
   `appendGateCall`/`appendGateOutcome` (and `gate-render.ts` references
   neither).
2. **Import directionality**: no execution-path module imports
   `gate-render.ts` — the recorded line makes no policy change effective.

EV-66's opacity assertions (tool result byte-shape) pass **unmodified**.

### 5. Mechanism-fix fold-ins (converged corrections)

- **O1**: the imperative-verb scan is scoped to the TS-authored
  **fallback-literal constants only** — never to `decisionLine` output
  (every legitimate composite basis contains the word `verify`, e.g.
  `composite 2.75 ≥ verify threshold 2.60`, so an output-wide scan cannot
  pass).
- **O2**: the A′ nullish-coalescing cell plus a no-`undefined`/`null`/`NaN`
  falsifier test.
- Downstream note (no code this card): EV-70 reads the **mode token**, not
  the composite.

## Tests (all red at base where they touch new symbols, green at head)

1. `decisionLine` battery: composite byte-equality (`"Mode: " + resolvedMode
   + " — " + basis`, em dash U+2014) for every fixture, including a record
   whose basis is the pinned EV-65 failure string; A′ absent-basis input
   renders the mode token alone with no `undefined`.
2. Render-function golden: the approve/edit/drop options and the printed card
   body are byte-identical to the pre-gate rendering. Delta-only construction:
   body/prompt bytes enter the test as pre-gate golden constants and the
   render function's only contribution is the one mode line — byte-identity
   of the composition holds by construction over the constants.
3. B vs C distinct literals; B fires on `callId: null` + `status: "failed"`,
   C on a recorded `callId` matching no line (join-miss fixture, e.g.
   `callId: "zzz"`).
4. Verbatim-reason rendering for a recorded failure: basis
   `"gate call failed: <reason>"` renders as-is, no paraphrase.
5. No-`undefined` falsifier over every cell.
6. Imperative-verb scan over the fallback-literal constants only (fails if a
   fallback gains an imperative verb or gestures at the transport reason).
7. `council_gate_render` schema takes no card text; zero-write/no-policy-load
   behavioral test on a mkdtemp repo (tree hash unchanged after a render
   call) plus a source canary (no `appendGateCall`, no `loadGatePolicy`).
8. EV-66 opacity assertions unmodified and green; off-mode render returns
   zero lines.
9. Prose pins: step 3's `recorded, never acted on` byte-preserved; heading
   ordering `## 3.` < `## 4.` intact; step 4's pre-existing presentation
   sentence byte-unchanged; the new instruction block pins
   verbatim-once/placement/add-no-words/presented-never-written/off-skip.
10. Ordering fence: `features-new.md` contains no `council_dispatch` /
    `council_wait` occurrence after the `## 3.` heading (the property that
    makes presentation-time delivery safe).
