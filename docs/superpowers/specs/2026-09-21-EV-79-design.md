Settled by the deliberation (owner/principal rounds 1–2), the skeptic's step-4
attack, and the consolidator's synthesis — see the card's deliberation record.
Binding rulings applied: intake R4 (precedence), R2 (vocabulary), the EV-78

## What ships

`decideFollowup(answers, policy)` — a pure function in one module, returning
exactly `{ disposition: FollowupDisposition; basis: string }` where
`disposition ∈ {File, Merge, Drop}` (R2). No fs, no network, no model call.
Purity is behavioral, proven by two identical calls yielding byte-identical
results (`gate.ts` imports `node:fs`, so a static fs-free proof is not
available — the shipped `decide()` precedent is the same posture).

```ts
export interface FollowupDecision {
	disposition: FollowupDisposition;
	basis: string; // single line, byte-stable
}
export function decideFollowup(
	answers: Record<string, GateAnswer | null>,
	policy: FollowupDecisionPolicy,
): FollowupDecision;
```

## Module placement

call site passes `policy` — still assignable. **Behavior at every existing gate
call site must be byte-identical**: `test/gate-decide.test.ts` must stay green
unchanged (owner test obligation 14).

## Signature and answer handling

- `answers` values reuse `GateAnswer` from `gate-ledger.ts` (the transport- and
  ledger-verbatim shape `decide()` already takes). Runtime fail-loud validation
  names the question id; the loose shape preserves the `DecideFn` re-derivation
  seam and EV-81's answer transport without a parallel type.
- A `score`-type answer **throws naming the id**: the followup policy has no
  `score` floor, so a score answer is unfloorable and R4 forbids proceeding on
  unfloored input. Unknown types throw the same way. Missing/non-numeric
  `confidence` on choice, and missing/out-of-shape `probability` on noul: throw
  naming the id. Error grammar mirrors `decide()`'s with a distinct
  `followup:`-prefixed form so the two domains' errors never confound.

## Precedence (R4, pinned): floors → overrides → composite

Numbers render through the existing private `fmt` (`toFixed(2)`) — the
byte-stability guarantee. Single-line-ness is inherited: the three interpolated
override strings are loader-validated single-line (`basisSafeString`), and `fmt`
never emits a newline.

**Phase 1a — unanswered weighted questions (iterate `Object.keys(policy.weights)`,
NOT `Object.keys(answers)`).** For each weight id in declaration order:
absent / `undefined` / `null` are ONE state →
`{ "File", "<id>: unanswered" }` returned immediately, before any override is
evaluated. (Shipped `decide()` iterates answers and is structurally blind to
absence — gate.ts:937/939, skeptic closed-green; gate-run.ts:254–256 records
that unanswered questions are absent from the answers map. A faithful mirror
would produce a dead fail-safe — this loop axis is the card's central inversion.)
Then, for present weighted answers: choice confidence `< policy.floors.choice` →
`{ "File", "<id>: confidence X.XX < choice floor X.XX" }`; noul certainty
`Math.max(p, 1-p) < policy.noulThreshold` → `{ "File", "<id>: certainty X.XX < noul threshold X.XX" }`
(first failure wins, weights declaration order).

**Phase 1b — floors over present unweighted answers ("floor-everything").**
Every present answer the policy does not count is still floor-checked and
shape-validated (throwing names the id) — the card's acceptance binds "a
below-floor answer returns File" unqualified, and floor-checking can only move
toward `File`, never violating the fail-safe contract. **Iterate unweighted ids
in canonical sorted key order** (`Object.keys(answers).sort()`, weighted ids
skipped, nulls skipped): shipped `decide()` is insertion-order-dependent in its
floors basis (skeptic probe v closed-green), and the determinism test
(obligation 11) fails unless 1b canonicalizes its order. Determinism across
insertion orders then holds for ALL phases.

**Phase 2 — overrides, declared order.** Fire test mirrors `overrideFires`
minus score: choice `answer.value === option`; noul `sideProbability(id, option) > 0.5`
— fired on the answer itself. An override whose answer is below its floor
never reaches phase 2 (the R4 carve-out: a gated rule, not a dead one — the
same rule must be shown firing on confident input elsewhere in the fixture set).
On fire: `{ rule.disposition, "<id>? <option> (<rule.basis>)" }` — byte-shape
equal to `decide()`'s override basis, **no `→ <Disposition>` tail** (EV-82's
`decisionLine` renders `Mode: <disposition> — <basis>`; a tail would render the
disposition field a second time from a second place).

**Phase 3 — weighted composite.** `composite = Σ weights[id] ×
sideProbability(answers[id], countedOption[id])` over `Object.keys(policy.weights)`
— raw sum, no normalization; every weighted id is known answered and on-floor by
phase 1a. Walk (drop-arm first, because strict `merge < drop` is loader-pinned):
`composite >= thresholds.drop` → `{ "Drop", "composite X.XX ≥ drop threshold X.XX" }`;
`>= thresholds.merge` → `{ "Merge", "composite X.XX ≥ merge threshold X.XX" }`;
else → `{ "File", "composite X.XX < merge threshold X.XX" }`.

## Tolerated gaps (EV-78 validates each file independently)

- A weight id with no question → always absent from `answers` → always `File`
  (fail-safe by construction; documented, tested behavior — the residual is
  liveness, never safety).
- An answer id not in `weights` → floor-checked and shape-validated (1b) but
  never composited.
- An override `option` absent from the question's criteria → cannot fire
  (gated-but-inert, not a crash).

## Named notes and residuals

1. **Composite Drop band is empty on the packaged policy for well-formed
   answers**: on-floor non-firing noul max p = 0.4 per yes-counted question,
   `actionable` contributes 1.0 → 0.4 + 0.4 + 1.0 = **1.8 < 2.0**. Every
   packaged-data Drop comes from an override. `thresholds.drop: 2.0` stays as
   declared tuning data (no retune in this card, no test asserting emptiness —
   it would fire on a legitimate retune); the band walk is tested on a tmpdir
   fixture with tuned thresholds. Caveat: the bound assumes well-formed answers
   (malformed `probs{no:1.5}` composites 2.3 ≥ 2.0).
2. **questions↔weights cross-file validation has no owner in EV-79..83** —
   documented-safe in EV-79 ("a misconfigured weight always Files"); a follow-up
   card for the fail-loud equality check at the loader-composition site is filed
   at step 13 once EV-81's wiring exists.
3. **EV-81 transport-validation residual**: `sideProbability`'s choice branch
   range-checks only `Number.isFinite` (noul branch does `[0,1]`) — a malformed
   model probability flips Verify→Direct in the shipped gate today (skeptic
   probe iii, live). The `[0,1]` check for followup choice answers belongs in
   EV-81's parsing; not an EV-79 fix.
