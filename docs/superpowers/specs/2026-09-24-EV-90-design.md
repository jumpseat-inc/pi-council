# EV-90 — Design: pass `renderProcedure`-substituted `council.md` and `features-deliver.md` into the `council-runner` dispatch

Card: `council/cards/EV-90.md` (EPIC-23, surface-touching, mode `Deliberate`).
Settled by the card's deliberation record (owner job-9.1/9.2, principal
job-8.2/9.3, designer job-8.5/9.4, skeptic job-9.5, consolidator job-9.6) and
the product-owner ruling on D1-epic-null (2026-09-24, recorded verbatim on the
card). This spec does not reopen anything that record closed.

## 1. The one new seam: a pure composer

Add one exported pure function in `extensions/seats.ts`:

```ts
export function composeRunnerInput(repoRoot: string, cardId: string, taskInput: string): string
```

- **Resolution — per-file, override-first.** For each of the two procedure
  names (`council.md`, `features-deliver.md`), walk `[repoOverride, packaged]`
  by filename — `<repoRoot>/$CONFIG_DIR_NAME/council/procedures/<name>` first,
  then the packaged copy under `PKG_ROOT` — taking the first file that exists,
  never mixing halves. Apply the same frontmatter strip as the parent command
  scan (`raw.replace(/^---\n[\s\S]*?\n---\n/, "")`, `extensions/index.ts:844`).
  **Never** `path.join(proceduresDir(repoRoot), name)`: `proceduresDir`
  (`seats.ts:557–560`) is directory-level first-hit, and a join reads the
  wrong (unstripped, ENOENT) files in any repo with a partial override —
  confirmed by the skeptic's `ev90-probe-override.ts`.
- **Rendering.** Each body renders through `renderProcedure(body, procDir,
  args)` where `procDir = proceduresDir(repoRoot)` — byte-for-byte what the
  parent slash-command path uses. **Two-args binding** (settled, D1's frame):
  `council.md` renders with **`cardId`**; `features-deliver.md` renders with
  the **epic key derived from the card face's `epic:` field** — read
  `<repoRoot>/council/cards/<cardId>.md`, parse the frontmatter `epic:` value.
  A mismatched (card, epic) pair is therefore impossible by construction; no
  substitution token is added (AC4, FLLWUP-112 consumes, never widens).
- **Epic-null is a fail-loud refusal (the D1 ruling).** When the card face's
  `epic:` field is null or absent, the dispatch is **refused with an error
  naming the card** — the house refusal pattern (the `allowedSeats` refusal,
  `hub-tools.ts:156–161`; the `Unknown seat` hard error). No-throw variants
  (un-substituted overlay, omitted overlay) are rejected by ruling; owner
  test-claims 3 and 4 stand unamended.
- **Framing and order** (designer's named affordances, adopted):
  `<council-procedure>` (the playbook — `council.md` rendered with the card
  id), then `<features-deliver-overlay>` (standing substitutions —
  `features-deliver.md` rendered with the epic key; it addresses the
  orchestrator), then `<task>` (specific work). Top-down reading order =
  working order.
- **Verbatim task tail.** `taskInput` is appended **verbatim** as the `<task>`
  tail — concatenated, never passed through `.replace` (its `$&`/`$n`
  replacement metacharacters would corrupt arbitrary task text).

## 2. `renderProcedure` relocation (the import graph is binding)

`hub-tools.ts` already imports `seats.ts` (`hub-tools.ts:8`); `index.ts`
imports both (`index.ts:6` hub-tools, `:13` seats). Both naive composer homes
cycle (skeptic's `ev90-probe-cycle.ts`): composer-in-`seats.ts` importing
`renderProcedure` from `index.ts` closes `seats ↔ index`;
composer-in-`index.ts` called from `hub-tools.ts` closes `hub-tools ↔ index`.
So: move the 6-line pure `renderProcedure` function from `index.ts` into
`seats.ts`, beside the composer, and **re-export it from `index.ts`** — the
parent scan path and every existing importer (including
`test/render.test.ts`, which imports from `../extensions/index.ts`) stay
green. The substitution set and behavior are byte-identical; only the module
home moves (AC4 untouched). Cycle-free invariant (principal claim 5):
`seats.ts` must not import `./index.ts`, and `hub-tools.ts` must not either —
pinned by a file-content assertion in the new test file.

## 3. The one call site

In `extensions/hub-tools.ts` only: guard on
`seat.name === "council-runner"`, compute the composed string **once**, and
reuse it at **both** `buildChildArgv` sites — the initial spawn
(`hub-tools.ts:254`) and the retry supervisor's `attemptSpec` (`:278`) — so
every attempt carries identical bytes. Touch neither `buildSystemPrompt`,
`buildChildArgv` itself, nor `dispatch.ts`: the eval path
(`eval-runner.ts` → `spawnSeatJob` → fixture `/features-deliver EPIC-1`) forms
its own argv and must carry no bodies (eval-store comparability preserved by
reviewed-diff isolation). Non-runner `council_dispatch` calls are
byte-identical to today (AC5 governs the enumerated fields — same seat,
model, tools, timeouts).

## 4. `card_id` on `council_dispatch`

Add one optional `card_id` param to the `council_dispatch` tool schema
(`extensions/hub-tools.ts`). The orchestrator learns it from the
tool-parameter description the way it learned `mode`/`cellId`/
`timeout_minutes`. A `council-runner` dispatch **without** `card_id` is
refused with a message naming the parameter and the seat (the same refusal
pattern); any other seat dispatches exactly as today, `card_id` or not.
Runner dispatches carry no bodies unless the composer succeeds end to end:
the refusal for a missing `card_id` and the throw for a null/absent `epic:`
both happen before any child spawns.

## 5. AC3 — the seat-block rewrite (`council/agents/council-runner.md`)

The `<procedure>` block (≈lines 48–64) drops the read-in-full instruction for
these two files. The rewrite is **affirmation, not prohibition**, per the
card's Intent: it says what the input carries rather than what must not be
read. Affirmation + designer's interpretation instruction — the overlay block
"addresses the orchestrator — read it as the run's standing substitutions, not
your role" — with the named affordances `<council-procedure>`,
`<features-deliver-overlay>`, `<task>` and an "Execute the in-input text"
close. The "Skip step 0", the two environment facts (database reachability,
seat resolution), and the "everything else in council.md applies" prose stay
byte-anchored. The escalation step-1 class-list read
(`council/procedures/features-deliver.md` Phase 1) stays — it is a rare-path
pointer to a file still legitimately readable, and AC3 scopes only the
`<procedure>` block. `buildSystemPrompt` keeps the `<council_runtime>`
procedures-directory pointer (`seats.ts:598–604`) unchanged — no new block,
no new token.

## 6. Tests (new pure test file adjacent to `test/render.test.ts`)

TDD per AGENTS.md; pure, ms-scale, no network. Load-bearing assertions,
never tautological byte-identity alone (skeptic job-9.5 item 6):

1. **Per-file override falsifier:** tmp repo with
   `$CONFIG_DIR_NAME/council/procedures/` containing only `council.md`
   (sentinel) → composed contains the **override** `council.md` rendering and
   the **packaged** `features-deliver.md` rendering, and does **not** contain
   the packaged `council.md` sentinel. A `proceduresDir`-join implementation
   reds.
2. **Two-args non-tautology** (card `EV-90`, face `epic: EPIC-23`): contains
   `council/cards/EV-90.md`; does **not** contain `council/cards/EPIC-23.md`;
   contains "delivering EPIC-23 autonomously"; does **not** contain
   "delivering EV-90 autonomously". Byte-identity against
   `renderProcedure(...)` per body with its own args asserted **in addition**.
3. **Verbatim tail + strip:** a `$&`-bearing task text appears exactly once,
   unmodified, after both bodies; no `argument-hint:`/`description:`
   frontmatter lines anywhere; no unresolved `$ARGUMENTS` inside either body
   block (task text excluded).
4. **Epic derivation:** face with `epic: EPIC-9` → composed contains
   `EPIC-9`; face with `epic: null` or absent → **throws, message names the
   card** (the D1 ruling).
5. **Placement:** `renderProcedure` defined in exactly one module
   (`seats.ts`), re-exported from `index.ts`; `bunx tsc --noEmit` green;
   existing `test/render.test.ts` pins untouched and passing; the no-cycle
   file-content assertion of §2.
6. **AC3 prose pins** (EV-89 precedent, `test/prose.test.ts`): packaged
   `council-runner.md` no longer contains "read `council.md` and
   `features-deliver.md` from the procedures directory"; contains the marker
   names (`<council-procedure>`, `<features-deliver-overlay>`, `<task>`);
   FLLWUP-107's pin in `test/render.test.ts` still green untouched (AC4).
7. **`card_id` contract:** runner dispatch without `card_id` → refusal naming
   the parameter; non-runner dispatch without `card_id` → succeeds with the
   un-composed input, byte-identical to today.
8. **Retry byte-identity:** the composed string is computed once and reused by
   `attemptSpec` (implementation invariant); existing retry tests guard argv
   shape.
