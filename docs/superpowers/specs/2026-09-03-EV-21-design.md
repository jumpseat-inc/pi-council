## 1. Surface — `/council-leaderboard` (read-only)

A new slash command registered in `extensions/index.ts` alongside
`/council-jobs` and `/council-eval` — a **pure read** of
`council/eval-results/`, rendered via `ctx.ui.notify` (TUI) /
`console.log` (headless), plain text per convention 9.6. No widget, no
report file, no second progress surface (leaderboard = snapshot, not a
stream). No-arg form is the default render; no `[task]` drill-down in v1;
errors non-fatal.

**Reconciliation note**: the ruling packet's CONFIRM-1 spec-text item 1
says "new procedure file `council/procedures/council-leaderboard.md`" —
that is a clerical slip. The deliberation converged on a **code-registered
command** (the `/council-eval` pattern; a markdown procedure cannot host a
pure TS renderer over the store). The binding content of CONFIRM-1 is the
NAME `/council-leaderboard` and its copy obligations; the surface shape is
the deliberation's converged one, recorded here.

Rationale (settled): separating read from write prevents the footgun where
someone typing a rank query accidentally triggers a multi-hour matrix;
`--summary` on `/council-eval` collides with its no-arg "list tasks"
behavior.

## 2. Engine — pure leaderboard module

New `extensions/eval-leaderboard.ts` (joins the `eval*` glob):

- **Input**: `readAllResults(store)` records + fixture metadata.
- **Group-by** (the leaderboard's own key, finer than `summarizeStore`'s
  cell unit): `(taskId, kind, model, thinking, fixtureVersion,
  rubricVersion, scoredUnder)`; each group delegates mean/σ/n/histogram/
  indeterminate to the shared `aggregateCell` (same-function-both-sides —
  the drift-window contract with `/council-eval`'s summary).
- **Kind**: read-time `loadFixture(repoRoot, taskId)` join on
  `fixture.kind`; failure → `"unknown"` bucket (a deleted fixture must
  never crash a history read). **Accepted limitation (J-3)**: kind is
  *current-fixture-kind*; fixture version history is not persisted.
  Disclosure copy binds (below). No store schema amendment — amending
  `StoredResultRecord` was rejected (divergent-payload throw on re-runs,
  no backfill).
- **Rank axis**: the tested `model[:thinking]`. `scoredUnder` is a row
  facet, never a ranked axis: the grader id never appears as a ranked row;
  gate-only (`self`) rows render separated from graded rows.
- **Ordering vs E1**: deterministic sort by mean desc; then adjacent-pair
  `compareCellTriage` over `gradedScores` — overlapping CIs render
  `tied (±CI)` and never an asserted ordinal strength. "Ordered by score"
  = presentation order; the TRIAGE column is the confidence verdict.
  Indeterminate rows (length-majority, no graded repeats) render
  indeterminate, never a low number, excluded from numeric bands.

## 3. CONFIRM-2 — landed-bug fix rides EV-21 (failing-test-first)

**The defect (skeptic-confirmed empirically)**: `summarizeStore`
(`extensions/eval-runner.ts:634`) groups on
`${cellId}\u0000${scoredUnder}` — it drops the `(fixtureVersion,
rubricVersion)` pair the store filename key carries
(`resultStoreName:131`). The store is append-only and never pruned, so
after a fixture bump + re-run the LIVE `/council-eval` summary pools both
version-keyed sets and averages repeats across incomparable rubric
versions (skeptic throwaway: `n_attempted=4, mean=0.625` blended). No
existing test pins the merged behavior (`test/eval-runner.test.ts:320-333`
never calls `summarizeStore`; `:504` is single-version and unaffected).

**The fix (in place, additive)**:
1. **Failing test first**: two-version store (same `cellId`+`scoredUnder`,
   version pairs (1.0.0,1.0.0)/(2.0.0,2.0.0)) → `summarizeStore` must
   return TWO summaries, each with its own mean (0.45 / 0.9). Red on
   today's code; green after the key change. Repeat for the leaderboard
   reader path.
2. `summarizeStore` group key →
   `${cellId}\u0000${scoredUnder}\u0000${fixtureVersion}\u0000${rubricVersion}`
   (full pair, matching the filename key — a rubric-only bump also
   unlocks a new filename set).
3. `CellSummary` gains additive `fixtureVersion`, `rubricVersion`
   (populated from `records[0]`; groups are version-homogeneous by
   construction) and `gradedScores: number[]` (the raw graded repeats —
   required by adjacent-pair `compareCellTriage`; today `aggregateCell`
   discards them).
4. `summaryLines` (live `/council-eval` summary) disambiguates cohorts:
   append `fixture=vX.Y.Z rubric=vA.B.C` when versions are present
   (companion one-liner, not a copy rewrite).
5. **Single-version byte-identity preserved**: for single-version stores
   every existing summary byte stays identical (only the appended version
   stamp is new). The existing smoke Phase-3 re-derivation assertion is
   unaffected (smoke store is single-version — verified by skeptic).

A version-aware *wrapper* was rejected: two functions on opposite sides of
the byte-identity seam is the anti-pattern; the pair must live in the one
shared group key.

## 4. Copy (J-1 — bound)

Column headers: `TASK  MODEL  GRADER  n  MEAN  σ  TRIAGE` (that order).

- `MODEL` — `provider/id[:thinking]` (the rank identity).
- `GRADER` — `self` for gate-only rows, the grader model id otherwise.
  Always present.
- `n` — `n_graded/n_attempted` (e.g. `2/3`); gate-only rows render
  `gate-only (self)`.
- `MEAN` — three decimals; `—` when no graded repeats.
- `σ` — Bessel-corrected sample standard deviation, three decimals; `—`
  when `n_graded < 2`. (The acceptance's word "variance" is the intent;
  `σ` is the honest name of what the mechanism computes — binding.)
- `TRIAGE` — tier phrases (no glyph-only states):
  - `leader` / `runner-up` — CI-on-mean-difference strictly separated
    (`compareCellTriage` `tied: false` + mean ordering).
  - `tied (±CI)` — overlapping CIs with an adjacent row; never a
    fabricated 1st/2nd.
  - `gate-only (self)` — `scoredUnder === "self"`.
  - `indeterminate (length majority)` — `lengthMajority === true`.
  - `indeterminate (no graded repeats)` — `n_graded === 0`,
    `n_attempted > 0`.
  - `n<2 (need 2 to triage)` — `n_graded === 1`.

Sections: **By command (procedure fixtures)** and **By seat (seat
fixtures)** — both slices by default, each labeled by its grouping axis.
Version pairs render as sibling rows with `FIXTURE`/`RUBRIC` in the
per-task header (Q1-D1's "sibling row or version badge", settled as
sibling rows); cohort order: latest fixture+rubric first, mean desc
within.

Disclosure copy (J-3): `kind reflects the current fixture (version
vX.Y.Z); historical rows use the same kind`.

## 5. Empty state (truthful spectrum, bound)

- **A — directory missing**: `council/eval-results/ does not exist — run
  /council-eval <task> <model…> to start` (R-6 name).
- **B — gate-only only** (records exist, all `scoredUnder === "self"`):
  `results exist, all gate-only (self) — not rankable against graded
  cells; run a judge-bearing fixture to compare`. Day-one reality: the
  store today holds exactly one gate-only council-runner cell.
- **C — n_graded = 1**: `n<2 — need 2 repeats to triage`.
- **D — length-majority**: `indeterminate (length majority) — do not pin
  from this cell`.

## 6. Phase-4 smoke (J-2 — mandatory, Q3 precedent)

Append a **separate Phase 4** to `smoke/driver.sh` (never rewrite Phase
3): drive `/council-leaderboard` headlessly against the Phase-3 records
(gate-only eval-smoke fixture, one model, one version pair) and assert
with `|| fatal`:
(a) State B line renders for the gate-only store; (b) both slices render;
(c) `summarizeStore` and the leaderboard reader agree byte-for-byte on
`n`, `mean`, `σ` (same-function-both-sides); (d) `validate.py` green
after the run. **No merge without Phase 4 green.**

The optional fixture-bump+rerun inside Phase 4 is **out of default
scope** (unit tests carry version-cohort correctness; doubling Phase-3
wall-clock is the wrong instrument). A future Phase 5 can add it without
a fresh ruling.

Ranked rows, ties, and version-cohort separation are carried by pure unit
tests at the module layer (no network) — the Phase-3 store cannot
exercise them (one model, one version, gate-only).

## 7. Testable claims

1. **Empty state (A)**: `renderLeaderboard([])` on a missing dir →
   exactly the State A copy, zero rank rows, names `/council-eval`.
2. **State B**: store with only `scoredUnder: "self"` records → State B
   copy, no numeric ranking rendered.
3. **Version cohorts (CONFIRM-2, red today)**: two version pairs in one
   `(cellId, scoredUnder)` → two summaries with correct per-version
   means; `summaryLines` renders the version stamp on both.
4. **Single-version byte-identity**: the key change leaves every existing
   summary byte identical for single-version stores (existing tests stay
   green).
5. **Kind join**: records for `owner` (seat) + `council` (procedure) →
   two slices, bucketed by `loadFixture(...).fixture.kind`, not by name
   sets; missing fixture → `unknown` bucket, no crash.
6. **Rank axis**: a judged cell's row label is the tested model; the
   grader id never appears as a ranked row; gate-only and graded rows
   render in separate blocks.
7. **E1 ties**: two n=3 rows with overlapping CIs → both `tied (±CI)`,
   never leader/runner-up; separated CIs → distinct tiers.
8. **E2/E3**: 2/3 length-flagged cell → `indeterminate (length
   majority)`, excluded from numeric bands, never `mean=0.33`.
9. **Surface gate**: `extensions/index.ts` registers
   `/council-leaderboard` wired to the pure module; it never calls
   `runMatrix` (no side effects); theme-compliance audit (9.6) passes.
10. **Phase-4 smoke green from a fresh container** (extends the EV-20
    gate; no merge without it).
11. Gates: `bunx tsc --noEmit`, `bun test`, `python3 council/validate.py`
    stay green throughout (failing-test-first for CONFIRM-2).
