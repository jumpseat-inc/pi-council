# EV-65 — One-call decisions transport with fail-closed posture

Design spec. Source: the card's deliberation record (`council/cards/EV-65.md`,
rounds 1–3, skeptic attack, consolidator synthesis) and the binding
product-owner ruling of 2026-09-20 (step 6, Q1 ledger home + Q2 verify guard).
Nothing here reopens anything the Council settled; where the ruling
overrides a synthesis detail, the ruling wins and this spec states the ruled
form.

## Modules and import edges

Two new files under `extensions/`:

- **`gate-run.ts`** — orchestration: `runGate`, the decide adapter, wire
  shaping, ledger append, pre-POST guards. May import `gate.ts`,
  `gate-ledger.ts`, `gate-state.ts` (type-only) and `provider-cost.ts`.
- **`gate-transport.ts`** — the `GateTransport` type, the real OpenRouter
  decisions transport (the only `fetch(` in the new code), and the pure wire
  shaper / response parser. Imports types only.

Frozen one-way edges: `gate.ts` and `gate-ledger.ts` never import the new
modules; `gate-state.ts` keeps its type-only edge. `gate.ts` stays
loader-only — **this PR edits no `gate.ts` code** (Q2 ruling blocks it).

## Ledger v2 (Q1 ruling — binding)

`GATE_LEDGER_SCHEMA_VERSION` goes **1 → 2**. `appendGateCall` gains optional
call-time fields and writes the whole union **atomically in one append**.
**EV-65 writes exactly ONE ledger line per call — no `kind: "outcome"` line.**
No card in this epic may put a call-time fact at `record.outcome.*`;
EV-66/EV-67/EV-71 read call-line fields.

Binding v2 call-line key set — the v1 set union, all additive, all
optional-tolerant on read:

```
schemaVersion: 2, kind: "call", callId, stateHash, questionSetVersion,
answers, resolvedMode, policyVersion, recordedAt      (v1, unchanged)
⊎ basis · model (versioned reported model) · provider ·
  usage {input_tokens, output_tokens, cost} · generationId ·
  failure {class} (present only on a failed call) · drops · advisory ·
  unknownAnswerIds
```

Clauses, binding:

1. **`basis`** is the converged composite: `"gate call failed: " +
   verbatimTransportReason` on failures, the `decide()`-derived composite on
   successes. The verbatim reason occurs **exactly once** in the record —
   there is **no `failure.reason` field** on the line (only
   `failure {class}`). `"Mode: " + resolvedMode + " — " + basis` byte-equals
   EV-67's pinned render.
2. **`drops` rides the call line** (discharges the EV-64 deferral). The
   estimator's `measuredTokens` and the provider's `usage.input_tokens`
   end up on the same record.
3. **Additive bump, tolerant reader.** `readGateLedger` performs no
   `schemaVersion` validation, no rewrite or re-serialization of existing
   lines. Mixed v1/v2 files must read with identical `rederiveResolvedMode`
   — this stays a **test** in the suite, not an assumption. No line is ever
   rewritten.
4. **No outcome line.** The outcome surface stays EV-61's post-run record;
   the single-writer property becomes structural (who writes what), not a
   convention.

The last-wins join behavior of the reader is unchanged and remains covered
by the existing tests.

## `runGate` interface

```ts
runGate(state: GateState, questions: GateQuestionSet, opts: RunGateOpts)
  => Promise<GateRunResult>
```

- Takes the `GateState` object (not raw bytes); consumes the producer's
  `stateHash` verbatim (EV-64 ruled producer-side hashing only).
- `RunGateOpts` (all injectable): required `repoRoot` (ledger path — required
  so a test that forgets it cannot append to the real committed ledger),
  caller-loaded `policy` and `decisionPolicy`, optional `transport`,
  `apiKey` (an explicit `apiKey` bypasses resolution; otherwise
  `resolveOpenRouterApiKey()` — env → stored credential → null), `now`,
  `timeoutMs` (provisional default 120_000), `callId`, `ledgerPath`.
- `GateRunResult`: `{status: "ok" | "failed", decision: GateDecision,
  callId, failure?: {kind, reason}, reportedModel?, modelDrift?:
  {pinned, reported}?}`.
- `runGate` loads nothing itself: the future caller command composes
  loaders/`buildGateState` → `runGate`.

### Transport

`GateTransport = (req: {url; headers; body; timeoutMs}) =>
Promise<GateTransportResult>` with
`{ok:true; status; body} | {ok:false; kind:"timeout"|"network"; message} |
{ok:false; kind:"http-error"; status; body}`. The transport **never throws**
— every failure is a value, making fail-closed total. The real transport
(`openRouterDecisionsTransport(apiKey)`) owns an `AbortController` +
`setTimeout` (cleared in `finally`), converts an abort to `kind:"timeout"`
with message `timeout after <timeoutMs>ms`, and reads every body via
`res.text()` so non-2xx bodies are captured verbatim. Failure classification
of a thrown error is a small exported pure helper
(`classifyTransportFailure`), unit-testable without timers. `runGate` and
the test doubles are timer-free.

### Fail-loud pre-POST guards (zero POSTs, zero ledger lines)

- `policy.mode` off — R3: a call under `off` is a programming error, never
  silent.
- `policy.model !== GATE_PINNED_MODEL` (`typesafe/jev-1.13`).
- `policy.endpoint` containing `/chat/completions` — the never-path enforced
  in code.
- The **noul join check** (settled in deliberation, in the same guard
  block): for every noul question, `policy.noulProbabilityOf ∈
  Object.keys(question.criteria)`; on violation fail-loud naming question
  id, token, and keys.
- Credential null → fail-closed `no-api-key`, pre-transport, zero POSTs.

**No verify-threshold guard** — Q2 ruling: the `verify ≤ 0` acceptance gap is
a loader defect, not EV-65's; it ships as a follow-up card filed together
with the EV-63 residual at run close. EV-65 implements no verify guard and
edits no `gate.ts`.

### Orchestration

1. Guards + credential resolution.
2. Shape the wire request `{model: policy.model, state, questions:
   toWireQuestions(questions)}` — state embedded as the JSON value decoded
   from `stateBytes` (live arm confirms the encoding).
3. Exactly one transport call. No retry, no fallback.
4. **Success:** light parse (model string, answers record; each answer
   verbatim) → filter to known ids (unknown dropped, recorded as
   `unknownAnswerIds`) → `decide()` → **one** v2 call-line append. Unanswered
   questions exist only as null in the record, absent from `decide()` input —
   never a negative.
5. **Failure:** no `decide()` call — hard `resolvedMode: "Deliberate"`, full
   panel (`MODE_PANELS.Deliberate`), the one v2 call-line append with all
   asked ids null, `failure {class}`, and `basis = "gate call failed: " +
   <verbatim reason>`.

### Failure taxonomy and verbatim reasons

`failure.class` values (machine tag): `no-api-key | timeout | network |
http-<status> | invalid-response | internal-error`; a 400 whose body contains
the pinned refusal marker is labeled `http-400-refusal` — classification
sugar only, all failures take the identical mechanical path. Verbatim reason
(unmodified, untruncated, single home in `basis`; `GateRunResult.failure`
keeps `{kind, reason}` in-process):

- http-error ⇒ `HTTP <status>: <body>` (whole body)
- timeout ⇒ `timeout after <n>ms`
- network ⇒ `error.message`

A multi-kilobyte error body lands whole in `basis` — accepted cost of
"verbatim" being the acceptance term.

### Wire shaping (noul bijection)

Packaged data stays keyed yes/no. `toWireQuestions` is exported, pure, and
total: for noul, requires criteria keys exactly `{"yes","no"}` and maps
`yes → "true"`, `no → "false"`; any other noul key fails pre-POST (zero
POSTs, zero lines). `loadGateQuestions` accepts a mis-keyed noul (O7 — the
discovery point is the wire seam, by design). Choice option labels and score
arrays pass through untouched. `decide()` is untouched — it never reads
criteria keys (skeptic O6).

### Versioned model logging

`reportedModel` extracted into `GateRunResult` and the ledger line; on
mismatch from `GATE_PINNED_MODEL`, `modelDrift {pinned, reported}`. The
versioned id is durably recorded per call and structurally returned. No UI
in the module — the display contract belongs to the consuming command card.

## Recomputability — stated precondition (Q2 interim wording, binding)

The failed call's re-derivation property (a call-only record re-derives
`Deliberate` from the line alone) holds **for the packaged policy and any
policy with `thresholds.verify > 0`** — asserted against the packaged
`decision.json` (O15: `composite 0.00 < verify threshold 2.60`). Module docs
state the precondition; they do **not** advertise unconditional
recomputability. Tests must **NOT** construct a `verify: 0` policy and call
the disagreement a property. The gap is named in this spec and closed by the
follow-up card (`loadGateDecision`: require `thresholds.verify > 0`; the
existing `verify ≤ direct` rule then makes `direct > 0` follow).

## Tests

`test/gate-run.test.ts` + `test/gate-transport.test.ts`; `mkdtemp` repoRoot,
injected doubles + explicit `apiKey`, no timers, no network. Sharpest
claims:

- **Counting double** asserts exactly one POST on success AND every failure
  path (refusal 400, timeout, 503, no-api-key, off-mode, bad-model,
  bad-endpoint, invalid-response): no retry. URL = `policy.endpoint`; body
  model = pinned; body keys exactly `{model, state, questions}`.
- **Three failure doubles** (refusal 400 + live-capture body, timeout, 503)
  each assert resolvedMode `Deliberate` + full panel + `basis === "gate call
  failed: " + failure.reason` + the verbatim reason occurs **exactly once**
  in the line + **exactly one ledger line** (no outcome line) + the render
  join `"Mode: Deliberate — " + basis` byte-equals EV-67's pinned string.
- **One-line-per-call:** success and failure each produce exactly one line
  carrying `schemaVersion: 2` and the full v2 union (usage, generationId,
  provider, reported model, drops, unknownAnswerIds, advisory, basis).
  Success `basis` === the `decide()` composite.
- **v1/v2 coexistence** (O17, kept a test): a hand-written v1 line next to a
  v2 line both read back with identical `rederiveResolvedMode`; reader
  tolerant.
- **Failed-call re-derivation** (packaged policy): a call-only record
  re-derives `Deliberate`. **No `verify: 0` policy appears anywhere in the
  tests.**
- **Wire shaping:** yes/no → true/false; mis-keyed noul fails pre-POST with
  zero POSTs/lines while `loadGateQuestions` accepts it; join check fires
  (token absent from criteria keys) naming question id/token/keys;
  `decidablyTestable`'s choice labels pass through.
- Guards: off/alias/chat-completions/model-mismatch fail pre-POST with zero
  POSTs and zero ledger lines; env unset + injected resolver null → zero
  POSTs, `failure.class === "no-api-key"`.
- Unanswered → null, absent from `decide()` input; unknown ids dropped +
  recorded; 2xx garbage → `invalid-response` → Deliberate (catch-all).
- **Source canary:** no gate module source contains `chat/completions`
  outside the pinned refusal marker; `fetch(` appears only inside the
  production transport.
- **Live arm** (`COUNCIL_INTEGRATION=1`, mirroring `test/integration.test.ts`):
  tmp repoRoot + advisory policy; one real call asserts versioned
  `reportedModel` matching `^typesafe/jev-1\.13-`, usage present, one v2
  line; a `timeoutMs: 1` probe asserts `kind: "timeout"`; the pole-semantics
  probe (P(true) ≡ P(yes)). The new live file joins the
  `vault/wiki/test-suite-budget.md` live-arm census.

## Tradeoffs accepted

- Verbatim multi-line bodies in `basis` (acceptance term wins).
- Light response validation + `invalid-response` catch-all rather than deep
  schema validation; one coarser failure class; fail-closed wins.
- Noul key strictness enforced at the wire seam, not `loadGateQuestions` — a
  mis-keyed repo-local file is discovered at call time, tested.
- `timeoutMs` stays opts-only (`POLICY_KEYS` frozen).
- Packaged gate ships `mode: "off"` (R3); nothing calls `runGate` in this
  card — the consuming command card is downstream.
