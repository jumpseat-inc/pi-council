## 4. The write leg — named actuator, test does not own the convention

In production the actuator is the facilitator executing step-13 prose (there is no
card-writing tool; EV-83's confirmation-authority ruling — every candidate ends step 13
as `ESCALATION` before any write, writes happen on a resumed confirming dispatch). In
the falsifier the actuator is an in-file **step-13 transcription helper**: it parses
`Mode: <disposition>` from the engine-derived rendered bytes (never the ledger — the
tool result's opacity contract) and applies the pinned table's targets. The
`## Merged from:` heading bytes are pinned to the shipped procedure's own step-13
literal (`test/prose.test.ts:563` pins `## Merged from:\n\n- <source-title>\n-
<source-title>`); if the prose changes, the pin fails and the helper follows — never
vice versa. **T3** (probe below) proves the engine leaves the tree byte-identical.

  from the pinned table in §2; the test goes red if the prose convention and the table
  disagree.
