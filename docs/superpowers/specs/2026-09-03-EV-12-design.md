## The edits

### Edit 1 — the `/features-new` Commands row (Commands table)

The What-it-does cell of the `/features-new` row is sharpened so it names
the seat set and the gate. The feature is **deliberated by** the four
seats in a bounded three-wave session, and nothing reaches the board until
the human approves the draft set. Use the verb "deliberated by" — never
"decomposed by". No "up to three", no "matching /council's cap" anywhere.

Before:
`| \`/features-new <feature>\`          | Decompose a feature into an epic + child cards                            |`

After:
`| \`/features-new <feature>\`          | The feature is deliberated by product-owner, designer, principal, and skeptic in a bounded three-wave session; nothing reaches the board until you approve the draft set |`

### Edit 2 — one paragraph under the seat table ("What you get")

A new paragraph lands in the gap between the seat table's last row
(`council-runner`) and the `**The wiki**` line. It is a **new paragraph,
NOT a new subsection** — no heading. It teaches exactly the two
load-bearing properties in roughly ≤60 words.

Final copy (verbatim for implementation):

> `/features-new` decomposition is deliberated by four seats —
> product-owner, designer, principal, skeptic — in three waves (product-owner
> rules last; no early stop). After the full three-wave session, you always
> get a draft to approve: every card, every run, nothing is written until
> you approve the exact draft set, epic included, each exactly as it would
> be written, in one pass at the single gate. See
> `council/procedures/features-new.md`.

Properties the paragraph carries:

- **(a) the three-wave bounded session** — decomposition is deliberated by
  the four seats in **THREE WAVES** (= three rounds, product-owner ruling
  last), with **no early stop**. Say "three waves" — **NEVER** "up to
  three"; **NEVER** "matching /council's cap" (features-new.md disavows
  stop-early, so "matching /council's cap" invites the wrong /council
  mental model). Name the four seats: product-owner, designer, principal,
  skeptic.
- **(b) the unconditional draft-then-confirm gate** — "every card, every
  run, nothing is written until you approve the exact draft set, epic
  included", presented in one pass at the single step-3 gate. The
  non-converged guarantee is folded INTO this as a clause, not a distinct
  claim, phrased with the O1 qualifier: **"after the full three-wave
  session, you always get a draft to approve"** (the O1 qualifier is
  REQUIRED — it acknowledges the double-fail dispatch stop terminates with
  no draft, so never phrase an unqualified "you always get a draft").
- **attribution-free fold-in, as a clause** — cards carry no deliberation
  narrative; "exactly as each would be written" — one clause ("each exactly
  as it would be written"), not a distinct claim.
- ends with a **one-line normative pointer**: "See
  `council/procedures/features-new.md`."

Forbidden phrasing in the paragraph and the Commands row:
"up to three", "matching /council's cap", an unqualified "you always get a
draft", "decomposed by", a seat name inside any card's narrative, and "as
it deliberates it'll prompt you".
