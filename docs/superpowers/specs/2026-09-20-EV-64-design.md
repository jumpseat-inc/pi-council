# EV-64 — Budget-bounded gate state packing (design spec)

Card: EV-64, EPIC-13 (metered-deliberation routing). Full-council card: the
design below is the settled output of its deliberation (two rounds, Skeptic
attack, consolidator synthesis, recorded on `council/cards/EV-64.md`) plus the
product-owner ruling of 2026-09-20 (`vault/raw/2026-09-20-po-ev64-budget-default-and-estimator-ruling.md`,
appended verbatim to the card record). This spec writes up what was settled;
it reopens nothing.

## 1. Purpose and module placement

The gate's state (what the gate model is given) is packed deliberately: thin
state produces confident wrong answers rather than visible uncertainty. A new
**pure module `extensions/gate-state.ts`** implements the packer.

- It contains the packer, the token estimator, the wiki matcher, and the
  doc-to-page map derivation, in one module.
- It imports **only types** from `./gate.ts` (e.g. `GatePolicy`). Neither
  `gate.ts` nor `gate-ledger.ts` ever imports it — the dependency edge is
  one-way.
- `buildGateState` writes nothing to disk and performs no network or model
  call. Persistence (ledger lines) is EV-65's decision and seam.
- Packing is mode-independent: the same function serves any resolved gate
  mode; R3 is respected by tests that set modes explicitly.

## 2. Inputs and return shape

```ts
interface ParsedCard {
  id: string;
  title: string;
  goal: string;
  acceptance: string;
  touchedFiles: { path: string; linesChanged: number }[];
}
function buildGateState(card: ParsedCard, repoRoot: string):
  { stateBytes: Uint8Array; stateHash: string; drops: DropRecord[] }
```

- The touched-file manifest is an **explicit input, never an ambient git
  diff** — ambient uncommitted state would make the packed bytes a function
  of whatever happens to be dirty. Validation: each entry's `path` a
  non-empty string, `linesChanged` a positive integer; violation is a loud
  named error, never a silent skip.
- **Producer of the manifest (O5, closed-red in deliberation):** EV-64
  defines the shape and validates it; *who* builds it is EV-65's seam — the
  transport assembles `ParsedCard` from the dispatch input. EV-64 ships no
  producer of its own.
- `stateHash` = sha256 of `stateBytes`, computed **at the producer**
  (`gate-state.ts` is the only hasher) and returned, so the ledger's
  `stateHash` (`GateCallInput.stateHash`, currently caller-supplied opaque)
  and the transported bytes can never silently diverge. EV-65 passes the
  returned hash through.
- **Drop record** returned as ordered `[{ section, truncated, kept,
  measuredTokens }]`. Whether the ledger line carries it is EV-65's decision
  (its `GateLedgerRecord` v1 has no `drops` field and call lines are
  byte-frozen; `kind:"outcome"` lines are the only extension mechanism) —
  but this shape is pinned across the seam by this card.

## 3. State shape, fixed section order, per-section caps

JSON state with sections in a fixed declared order (a `const` tuple in the
module):

| order | section | shape | cap (tokens) |
|---|---|---|---|
| 1 | `card` | `{ id, title, goal, acceptance }` (single object) | 4000 |
| 2 | `touchedFiles` | sorted lexicographically by path, `{ path, linesChanged }` entries | 2000 |
| 3 | `wiki` | top pages `{ slug, title, summary, aliases }` | 4000 |
| 4 | `rulings` | `{ slug, date, title, summary }`, ranked (§5) | 8000 |
| 5 | `tests` | covering test names, by stem/path affinity | 1000 |

Caps sum to 19,000 ≤ the 32,000 packaged budget, so a well-formed pack fits
without dropping in the normal case. Caps are pinned in-module constants
(fixed contract, like `MODE_PANELS`) — **not** policy keys.

**O7 coupling, load-bearing for tests:** at the packaged default budget the
budget can never bind and the production drop path is unreachable. The
card's demanded oversized-tail test therefore sets
`gateStateBudgetTokens` **below 19,000** in the fixture policy. The drop
record must make cap-trims and budget-drops distinguishable (§6).

## 4. Token estimator

One pinned pure named function: `ceil(utf8 byteLength / 3.5)`. "Measured
token count" everywhere means this estimator's count.

**Wording is ruled (PO Q2) and grep-falsifiable:** the doc comment says the
estimator is **"an estimate, not uniformly conservative"**, and documents
direction and provenance: over-counts ASCII prose (reference probe: +45.8%),
under-counts dense code (−35.9%), rare CJK (e.g. 龘, −13.3%), and emoji
(−17.2%); ratios measured against the **`o200k_base` reference tokenizer**.
- The word "conservative" must **not** survive anywhere as a claim about the
  estimator (a grep over the shipped source must not find it as such a
  claim).
- Nothing may claim the packed state fits the transport's real context
  window.
- The production gate model's own tokenizer is unprobed — this residual was
  ruled (PO Q2) **self-settling**, not blocking: if any ledger line's
  provider-reported `input_tokens` ever exceeds the estimator's count for
  those bytes, the coefficient is a defect and gets its own card. The bespoke
  tokenizer probe is out of this card's scope.

## 5. Deterministic wiki matcher (no model, no network)

Fixed a repo tree, selection is deterministic. It never calls a model or the
network.

**Candidate set:** every `vault/wiki/**/*.md` page, with two tested
exclusions:
- `vault/wiki/index.md` excluded (cheap insurance; measured score-0 on this
  tree — not load-bearing, but the rule is tested).
- `vault/wiki/sources/**` pages excluded (O4 adjacent gap: with sources in
  the candidate set they took 2 of the top 6 slots and rulings pages would
  double-dip into the wiki section). Tested rule, not a remembered one.

**Parsing:** a minimal flat frontmatter parser (no YAML dependency) reading
`tags`, `aliases`, `summary`, `title`.

**Doc-to-page map:** derived per call, never hand-maintained (FLLWUP-59
lesson): for each page, path-like tokens in its frontmatter and body that
exist in the live tree form an inverted path→slug index. The wiki is ~80
pages; per-call derivation is cheap.

**Scoring:** stopword-extracted lowercase terms from the card's
title+goal+acceptance; weighted field scoring as pinned in-module constants —
aliases ×3, title ×2, tags ×2, summary ×1, paths ×2. Wiki selection is
**fill-to-cap in score order** (k is emergent from the cap, not a second
knob), tie-break lexicographic by page filename.

**Recorded limitation (O3, quantified — route nowhere, no side contests the
probe):** on EV-64's own goal+acceptance the matcher picks
test-suite-budget (47), retired-path-tokens (17), smoke-test (16) over
gate-parity (17), deterministic-merge-check (15), metered-deliberation-routing
(23). Determinism held (byte-identical runs). This is a known term-overlap
limitation, documented as such — **not** evidence of selection competence.
Precision rides the model, not the packer.

## 6. Rulings section

- **Candidate set:** pages under `vault/wiki/sources/` whose tags include
  `pi-council/ruling` (existence verified on the real tree: 19 such pages,
  13 of them epic-9).
- **Relevance:** shares a non-namespace tag with a selected wiki page, or
  aliases/summary match card terms.
- **Ordering (settled by Skeptic measurement, O2):** rank by the same
  card-term scorer, **tie-break date descending**. Direct measurement on the
  real corpus: scorer-then-date mean top-6 relevance 3.17 vs filename-date
  descending 1.00; date ordering is tie-dominated (13/19 share one
  `updated` value; 3 distinct values total); top-5 overlap of the two
  orderings 0/5. The section shape is `{ slug, date, title, summary }`.

## 7. Packing and the drop rule

Greedy forward fill in the fixed declared order. Entry granularity is
**pinned per-section** (O6):

- Array sections (`touchedFiles`, `wiki`, `rulings`, `tests`): an entry is
  one array element.
- The single-object `card` section: **entry = per-field** (the only reading
  that preserves the degenerate-case defense — an over-budget `card`
  section truncates to its field prefix and stays non-empty, rather than
  collapsing to an empty state).

Rule: sections fill in order; the first section whose next entry does not
fit the remaining budget is truncated to its largest whole-entry prefix
(which may be fewer entries than its own cap allows); every later section is
dropped entirely. If even one entry of a section cannot fit its own section
cap, that section contributes nothing.

**Drop record semantics (O7):** when a section is trimmed by its own cap
while the budget still has room, versus cut by the remaining budget, the
drops record must let a reader distinguish the two mechanisms — the shape
carries `truncated`, `kept`, and `measuredTokens` such that a cap-trim and a
budget-drop are not conflated into one indistinguishable line. The record is
ordered, matching the declared section order.

Degenerate fixtures required: over-budget section 1 (non-empty state via
field granularity); pathological all-over-cap fixture (everything dropped,
state still ≤ budget, first section named in the drops record).

## 8. Policy: `gateStateBudgetTokens` (PO ruling Q1 — all three clauses binding)

1. **Present ⇒ validated unconditionally, in every mode.** A `0`, `-1`,
   `1.5`, or `"32k"` in a `mode: "off"` file still FAILs. An invalid value
   must never lie dormant waiting to become live when the consumer flips the
   mode on. This is EV-62's existing fail-loud posture, unchanged.
2. **Absent ⇒ legal only on the off path.** A policy that resolves to
   `advisory` or `active` without the key FAILs, on the same single-line
   `FAIL: <file> has an invalid <key> — <what was found> — …` surface, with
   copy that **drops the template's "remove the key to use the packaged
   default" advice** — wrong for an absent key under whole-file shadowing
   (removing the key from a repo-local file cannot summon the packaged
   value; first-hit whole-file means no merge).
3. **The packaged `council/gate/policy.json` carries `mode: "off"` and
   `gateStateBudgetTokens: 32000`** — the field is not unreachable
   decoration.

Implementation shape in `extensions/gate.ts`:

- `GatePolicy` gains `gateStateBudgetTokens` (present, validated positive
  integer, or absent-when-off); `POLICY_KEYS`/`ALLOWED_POLICY_KEYS` gains the
  key.
- Validation order: the key is validated whenever present (before mode
  resolution can short-circuit anything); when absent, the resolved mode
  must be `off`, else the clause-2 FAIL fires.
- **No code-side 32000 fallback constant** (PO Q2 rejected option (c):
  contradicts EV-62's data-not-code and silently-defaulted-is-untested; two
  independent 32000 constants can drift). The packaged data file is the
  only 32000. Consequently `buildGateState` invoked against a resolved
  policy whose file omits the key (reachable only on the off path, where no
  packing should occur) fails loud with the same single-line surface naming
  the policy file and the absent key — it never silently assumes 32000.
- Whole-file override semantics untouched (repo-local policy shadows
  packaged whole-file, first-hit). `policyVersion`/`model`/`endpoint`
  required exactly as today. R3 untouched: packaged default `mode: "off"`;
  tests set modes explicitly.

## 9. Tests (the gate set this card ships)

All on fresh `fs.mkdtempSync` synthetic trees (vault + gate policy + card);
never the real repo. Key fixtures:

1. **Oversized recent-rulings tail-drop** (the card `goal:`'s demanded test):
   fixture policy with `gateStateBudgetTokens` below 19,000; oversized
   rulings section; every earlier section **byte-identical** to the
   untruncated pack; drop recorded naming the section.
2. **Byte/hash identity** across repeated calls on a fixed tree.
3. **Hash single-source**: independent recompute of sha256(stateBytes)
   equals the returned `stateHash`.
4. **Drop-shape sufficiency**: present bytes reconstructible from the drop
   record + declared section tuple.
5. **Budget-only change moves the cut, never the prefix**: lowering the
   budget changes where the tail is cut; earlier sections stay byte-equal.
6. **Estimator pinned by recompute**; CJK divergence fixture demonstrating
   the byte-based measure (direction/provenance, per §4 wording).
7. **Matcher determinism**: two calls, byte-identical selection.
8. **Exclusions as tested rules**: `index.md` and `sources/**` excluded
   (fixture page in each exclusion class).
9. **Ruling ordering red/green**: a term-matched older ruling outranks a
   tag-only newer one (epic-skew counter-fixture).
10. **Policy FAIL matrix**: present-invalid in `mode:"off"` FAILs (0, -1,
    1.5, "32k"); absent in advisory/active FAILs with clause-2 copy (no
    "remove the key" advice); absent in off resolves cleanly; packaged
    default (off + 32000) loads clean.
11. **Touched-file canary**: a file-contents sentinel string never appears
    in the state bytes; entries carry only path + linesChanged.
12. **Degenerate cases**: over-budget section 1 keeps a non-empty state
    (field granularity); pathological all-over-cap fixture still ≤ budget
    with the first section named.
13. **Cap-trim vs budget-drop distinguishable** in the drops record.

The suite stays inside the [[test-suite-budget]] envelope; no network, no
model call, no COUNCIL_INTEGRATION arm.
