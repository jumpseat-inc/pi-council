# EV-19 — Scoring rubric and run verifier (design)

Settled design for card EV-19 (epic EPIC-4). This document is the write-up
of the Council's deliberation (rounds 1–3, Skeptic verification) plus the
resumption ruling that closed the one open-judgment dispute (O1 —
ResultRecord store key). It derives nothing new; it records what the
deliberation settled and what the ruling bound. It also closes, in spec
text, the two writer-closeable open objections (O2 — `settled` both-role+
path; O4 — gradingUsage merge). An owner reading only this file, with no
memory of the deliberation, must not be able to reach two different designs.

## Goal (from the card)

> A scorer grades a captured eval run against its fixture's rubric and emits
> a comparable numeric score plus a pass or fail per criterion, with every
> criterion checkable by a deterministic gate or a recorded verdict

## Binding resumption ruling — O1, ResultRecord store key

The ruling is recorded in full on the card record
(`council/cards/EV-19.md`, step 6.5) and in
`vault/raw/2026-09-03-po-ev19-resultrecord-key.md`. Binding summary:

1. **ResultRecord carries `scoredUnder: string`** — the grader's model id at
   the time of the score, the symmetric analogue of VerdictRecord's
   `gradedBy`, stamped at write time.
2. **On-disk store key is `(cellId, repeat, scoredUnder)`.** Two graders
   re-grading the same `(cellId, repeat)` produce two ResultRecords, both
   readable. **There is no first-write-wins at the ResultRecord layer.**
3. **EV-20's writer keys filenames from the triple `(cellId, repeat,
   scoredUnder)`** — same atomic-write pattern as the VerdictRecord writer;
   absent triple → new file; existing triple with a divergent payload →
   throws (a defect, not a re-write); same payload → no-op.
4. **EV-21 reads `council/eval-results/` and aggregates on the explicit
   `scoredUnder` dimension** — one row per grader when a cell has been
   re-graded, one row when only one grader has run; no `scoredUnder` is
   invisible.
5. **`scoredUnder = gradedBy` invariant** — the ResultRecord's `scoredUnder`
   equals the VerdictRecord's `gradedBy` projected into the merged score; a
   divergent value is a writer defect.
6. **C1 reproducibility** still holds under the same `scoredUnder`: same-key
   re-grade re-reads the same VerdictRecord, replays the same judge
   verdicts, re-runs gates deterministically — byte-identical score.

## 1. Two record types (settled)

The card's two outputs are **two distinct record types**; they must not
collapse into one. A gate-dominant rubric (council, council-runner,
features-deliver, judge, owner, skeptic, wiki-lint — 7 of the 16 shipped)
never dispatches a grader and therefore has **no VerdictRecord**, yet still
produces a full score; so the score-carrying record exists independently of
any verdict record.

- **VerdictRecord** (EV-16 §6.3) — the *grader's contribution*: judge
  criteria only (per-criterion pass/fail + evidence), `gradingUsage`, the
  grader's linkage. **No score.** EV-20's persistence unit (this card is
  not the writer). Append-only keyed `(cellId, gradedBy)` with
  first-write-wins per `(cellId, gradedBy, fixtureVersion, rubricVersion)`.
- **ResultRecord** — the *merged, score-carrying* record: per-criterion
  pass/fail for **all** criteria in rubric order, numeric `score`, and a
  `scoredUnder` stamp. EV-20/EV-21 domain. Store key `(cellId, repeat,
  scoredUnder)` per the binding ruling.

## 2. `extensions/eval-rubric.ts` — module shape (settled)

One pure file. It imports `validateRubric`, `Rubric`, `RubricCriterion`
from `./eval-fixtures.ts` (C3 = EV-18's: rubric validation is not re-derived
here). It never touches `node:fs` or `node:child_process` and holds **no
store and no dispatch path** — that is the EV-20 boundary (R-1, EV-16
§6.2 "the harness writes").

### Types (type exports)

```ts
export interface GradeIO {
  readFile(path: string): string | undefined;  // undefined = absent
  jobState(role: string): string | undefined;  // "done" | "stalled" | "timeout" | undefined
  run(argv: string[], opts?: unknown): { exitCode: number; stdout: string };  // may be async
}

export type Verdict = "pass" | "fail";
export type JudgeVerdicts = Record<string, Verdict>;  // criterionId → verdict

export interface GradedCriterion {
  criterionId: string;
  verdict: Verdict;
  evidence: string;  // gate: exitCode/stdout or path/fragment; judge: the recorded verdict text
}

export interface GradingUsage {
  input: number; output: number; cost: number; elapsedMs: number; stopReason?: string;
}

export interface VerdictRecord {        // EV-16 §6.3 — grader-only, EV-20's persistence unit
  cellId: string; gradedBy: string;
  fixtureVersion: string; rubricVersion: string;
  perCriterion: GradedCriterion[];      // judge criteria ONLY
  gradedAt: number;
  gradingUsage: GradingUsage;
}

export interface ResultRecord {         // EV-20/EV-21 domain — gradeCell's output
  cellId: string; taskId: string; model: string; thinking?: string; repeat: number;
  fixtureVersion: string; rubricVersion: string;
  scoredUnder: string;                  // = the grader's model id (marked, per the ruling)
  perCriterion: GradedCriterion[];      // ALL criteria, rubric order
  score: number;                        // passes / criteria.length, 0..1
  gradedAt: number;
}
```

### `gradeCell`

```ts
gradeCell(input: {
  rubric: Rubric;
  io: GradeIO;
  judgeVerdicts: JudgeVerdicts;       // must be COMPLETE for every judge criterion
  meta: { cellId; taskId; model; thinking?; repeat;
          scoredUnder; fixtureVersion; rubricVersion; gradedAt };
}): Promise<ResultRecord>  // or synchronously — the seam never hard-I/Os either way
```

A **pure** function of `{ rubric, judgeVerdicts, io }`: the only outside
contact is the injected `GradeIO`. Per criterion, in rubric order:

| Check kind | Behavior | Pass iff |
|---|---|---|
| `gates` | `io.run(argv)` | `exitCode === expect.exitCode` and (`stdoutContains` absent or `stdout.includes(stdoutContains)`). A run that throws or never resolves → **fail**, no hang. |
| `artifact-present` | `io.readFile(path)` | `readFile(path) !== undefined` |
| `artifact-contains` | `io.readFile(path)` | `(readFile(path) ?? "").includes(contains)` |
| `settled` | `io.jobState(role)` | `jobState(role) === "done"`; `stalled`/`timeout`/`undefined` → **fail** (a gradeable fail, not a throw). `settled` is role-only (§6); a role-less or path-bearing `settled` → **defense-throw**. |
| `judge` | `judgeVerdicts[criterionId]` | `judgeVerdicts[criterionId] === "pass"`. A missing criterionId → **throws** (never 0, never renormalize). |

**Scoring:** `score = passes / criteria.length` — the judge criteria count
toward the **total** denominator, always. Because `gradeCell` requires a
complete `judgeVerdicts` map and throws on a missing judge criterion, every
criterion is graded: `n_total == n_graded == criteria.length` at this
level. The `ungraded`/`n_attempted`-vs-`n_graded`/terminal-state machinery
exists only at the **repeat level** and is EV-20/EV-21's (§9).

### `replayJudgeVerdicts` and `projectVerdictRecord`

```ts
replayJudgeVerdicts(record: VerdictRecord): JudgeVerdicts   // pure; lossless extractor
projectVerdictRecord(result: ResultRecord, report: { usage: {input; output; cost; turns}; elapsedMs; stopReason }): VerdictRecord
```

- `replayJudgeVerdicts` extracts the judge-criteria verdicts from a
  `VerdictRecord`, feeding C1's re-grade replay (no dispatch).
- `projectVerdictRecord` builds a `VerdictRecord` from a `ResultRecord` +
  a `JobReport`-shaped object. It projects **judge criteria only**, sets
  `gradedBy = result.scoredUnder`, stamps `gradedAt`, and constructs
  `gradingUsage` per the O4 merge (§10).

## 3. Re-grade and replay semantics (C1)

C1 (reproducibility): re-grading under the **same** `scoredUnder` re-reads
the same `VerdictRecord` (EV-20's read path — the judge verdicts), replays
them through `replayJudgeVerdicts` → `gradeCell`, with deterministic gates
re-run against the same bytes. The result is byte-identical. `gradeCell`'s
gates re-run through `io.run` on re-grade; judge criteria make **zero** `io`
calls (they replay from the supplied `judgeVerdicts`). This is the testable
half of C1 inside EV-19: the cross-run form (a byte-identical materialized
seed tree) is EV-20's boundary clause, pinned by `sha256Tree`.

C2 (replay append-only): because `gradeCell` is pure, re-grading under a
different `scoredUnder` produces a **new** `ResultRecord` with that
`scoredUnder`; the original is byte-identical. The on-disk
first-write-wins / throw semantics live at EV-20's writer (§8), not here.

## 4. ResultRecord store keying — commit to `(cellId, repeat, scoredUnder)`

Per the binding ruling (§"Binding resumption ruling"). This is the EV-19
record's key dimension; EV-20 implements the store against it and EV-21
aggregates on it. No first-write-wins at the ResultRecord layer.

## 5. The `GradeIO` seam vs NormalizedRunState

The `GradeIO` seam is equivalent to `(RulingsState.files + RulingsState.jobs)
+ artifactRoot` — it is the cleaner packaging because the scorer never
consults `RulingsState.reports`/`.board`. `GradeIO` is the settled seam;
`NormalizedRunState` is withdrawn. The freeze-at-grade-time insight survives
as an **EV-20 boundary clause, not a seam shape**: grade before disposal OR
persist the artifact tree; C1's cross-run form asserts `sha256Tree(artifactRoot)`
equality against the cell's seed-plus-delta.

## 6. `extensions/eval-fixtures.ts` narrowing (settled → role-only)

`validateRubric`'s `settled` branch is narrowed so that `settled` **requires
`role`** and **forbids `path`**:

- a **path-only** `settled` throws at load (the ownership/name rule: one
  name per check — `artifact-present` is the file-exists probe; no
  `settled {path}` synonym);
- a **role+path** `settled` (O2) also throws at load — no silent ignore of
  `path`;
- a `settled` with neither throws (unchanged).

This narrows the current `eval-fixtures.ts` `settled` validation (which
accepts role OR path, or both). It invalidates **no shipped rubric**: the
only four `settled` usages (council, features-deliver, judge, skeptic)
carry `role` only (Skeptic O5/O10 closed-green confirmed this). As
defense-in-depth, `gradeCell` hard-throws on any role-less or path-bearing
`settled` it ever receives.

## 7. gradingUsage merge (O4, closed)

`projectVerdictRecord` constructs `gradingUsage` from a `JobReport`-shaped
object by merging:

- `report.usage.{input, output, cost}` → `gradingUsage.{input, output, cost}`;
- `report.elapsedMs` (top-level) → `gradingUsage.elapsedMs`;
- `report.stopReason` (top-level) → `gradingUsage.stopReason`;
- `report.usage.turns` is **excluded by design** (turns are not part of the
  `GradingUsage` shape); nothing else is lost.

This is the settled merge — the EV-16 §6.3 shape is `{input, output, cost,
elapsedMs, stopReason}`, while `JobReport.usage` carries `{input, output,
cost, turns}` with `elapsedMs`/`stopReason` at the top level. EV-19
consumes the in-memory `JobReport`; **no RunManifest extension is required
on this card**.

## 8. Store contract (EV-20's, per the ruling)

EV-19 commits the store **contract** and EV-20 implements it
(`council/eval-results/`, R-1, EV-20's writer):

- **VerdictRecord** — append-only keyed `(cellId, gradedBy)`, first-write-
  wins per `(cellId, gradedBy, fixtureVersion, rubricVersion)`. Owns judge
  verdict reads.
- **ResultRecord** — filenames from the triple `(cellId, repeat,
  scoredUnder)`; atomic write; absent triple → new file; existing triple +
  divergent payload → throw (defect, not re-write); same payload → no-op.
  Within `(fixtureVersion, rubricVersion)` the score is a deterministic
  function of the seed + judge verdicts, so a divergent payload is a
  writer defect. Owns the merged per-criterion + score reads.

## 9. EV-20/EV-21-bound commitments (referenced, not bound by EV-19)

These are settled on later cards and EV-19's spec only **references** them:

- **O3 — judge extraction robustness.** EV-20's verdict extraction is pinned
  to `judge.md`'s `output_format` (`**Verdict** — \`PASS\`/\`REJECT\` +
  **Basis**`); empty/`stopReason=length`/missing ⇒ **indeterminate** ⇒ the
  repeat is `n_attempted`-not-`n_graded`, never a fabricated pass/fail.
  A sloppy-but-reject line degrades to indeterminate, never a silent misparse.
- **E2 — `stopReason=length` length-flag at repeat level**; `facilitator`
  role alias = the harness's command job; the §7 RunManifest extension
  (usage/stopReason persisted at settle) — all EV-20's.
- **Repeat-level accounting** (`n_attempted` vs `n_graded`, terminal-state
  histogram) — EV-20/EV-21's.

## 10. Tests — `test/rubric.test.ts` (new)

Testable claims per the settled deliberation (failing first, TDD). Uses
`bun:test`; pure module means a recording fake `GradeIO` stands in for real
fs/child_process (no `node:fs` in the module under test):

1. **C1 reproducibility** — recording fake `io`; re-grade feeding
   `replayJudgeVerdicts`' output back → deep-equal ResultRecord; assert
   `io.run` called for the gate on re-grade but **zero** times for the judge.
2. **C2 structural half** — `gradeCell` with `scoredUnder=M2` vs existing
   `M1` returns distinct ResultRecords; M1 deep-unchanged. (The fs
   append-only/throw is EV-20's writer test, stated as the boundary.)
3. **Gate truth table (2×N)** across all four kinds — `settled` role
   `done` → pass; `stalled`/`timeout`/absent → **fail** (gradeable fail, not
   throw); `artifact-present`/`artifact-contains`; `gates` exitCode +
   stdoutContains.
4. **Scoring** — 2 pass + 1 fail → 2/3; all pass → 1.0; all fail → 0;
   judge-only single pass → 1.0; 1 gate-fail + 2 judge-pass → 2/3 (judge in
   the total denominator).
5. **[gate-pass, judge] with `{}` judgeVerdicts → `gradeCell` throws**, never
   `{score:1.0}` (B).
6. **`validateRubric` rejects path-only AND role+path `settled`** (the O2
   narrowing) + `gradeCell` defense-throws on any role-less/path-bearing
   `settled` it receives (F).
7. **`projectVerdictRecord` gradingUsage merge (O4)** — merges
   `report.usage.{input,output,cost}` + report-level `elapsedMs`/`stopReason`;
   `turns` excluded; nothing else lost.
8. **Totality** — every check the narrowed validator accepts is graded; the
   sole `GradeIO`-independent throw is a missing judge verdict.
9. **Purity probe (A4-mirror)** — importing `eval-rubric.ts` touches no
   `node:fs`/`child_process`; `gradeCell` with an identical input twice
   yields identical output with no I/O.
10. **C3 is EV-18's** — `validateRubric` is imported, not re-derived; the
    scorer adds no second validator (import-probe).

## 11. Acceptance mapping

- **Card acceptance 1** (every rubric has ≥1 criterion; each graded by a
  deterministic gate or recorded judge verdict): `validateRubric` (EV-18's,
  1–5 criteria enforced) + `gradeCell` truth table (10.3) + judge criteria
  graded via `judgeVerdicts` and replayed (10.1/10.2).
- **Card acceptance 2** (normalized numeric score + per-criterion pass/fail;
  same run re-graded → same score): `score = passes / criteria.length`
  (10.4) + C1 reproducibility (10.1).
- **EV-16 §10**: C1 (10.1), C2 (10.2), C3 (import, 10.10), A4 (purity, 10.9).

## 12. Scope guard

This card ships the pure `eval-rubric.ts`, the `settled` validator
narrowing, and `test/rubric.test.ts`. It implements no store, no harness
dispatch, no judge extraction, no leaderboard aggregation, and no RunManifest
extension. Nothing in this spec asserts a design choice as settled that the
deliberation, the resumption ruling, or the EV-16/EV-18 specs left open.
