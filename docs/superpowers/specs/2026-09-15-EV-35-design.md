# EV-35 design — transcript interaction model: visible focus, honest keymap, visible toggles

- **Card:** `EV-35` (epic `EPIC-8`), `council/cards/EV-35.md`
- **Status:** settled by the step-2–6 deliberation and the step-6
  `product-owner` ruling (`job-12`), appended verbatim to
  `council/cards/EV-35.md`. This document is the write-up, not a
  re-derivation. Nothing settled in steps 2–6 is reopened here, and where
  this document and the ruling disagree, the ruling wins.
- **Binding inputs:** Phase 1 rulings **R-KEYMAP** (on-state header copy),
  **R-MARKER** (`TREE_ROW_MARKER`, U+258C, no new glyph), **R-MODAL**
  (modal out of scope), **R-ORDER** (EV-34 merged; EV-35 next),
  **R-GATES** (owner gate set), **R-MERGE**, **R-FOLLOWUP**,
  **R-ESCALATE**; and the step-6 ruling's Q1–Q5.
- **Scope:** the inline progress transcript hosted by
  `CouncilTreeWidget.renderProgress` → `ensureView` (`extensions/navigator.ts`)
  — its header line, its focus signifier, its key handling, and the
  production key gate that feeds it (`classifyProgressKey`,
  `extensions/focus-nav.ts`). Not the full-screen modal (R-MODAL), not the
  follow-vs-viewport reconciliation / one-row legibility (EV-36), not the
  unreachable legacy `blockLines` renderer (FLLWUP-36), not cursor stability
  across `t` (ruling Q5 — out of scope).

## 1. Problem

The inline progress transcript's header advertises a keymap the surface does
not honor in two independent ways, and its focus cursor is invisible:

1. **The header omits `g`/`G`.** `handleInput` implements jump-to-first (`g`)
   and jump-to-last (`G`) at `navigator.ts:770-774`, but the header string at
   `navigator.ts:788` stops at `· esc back` and never advertises them. The
   card's `goal` requires every advertised key to work; the Phase 1
   **R-KEYMAP** ruling fixes the copy to advertise them rather than removing
   the behavior.
2. **The production key gate drops the four character keys on kitty /
   modifyOtherKeys terminals.** `classifyProgressKey`
   (`focus-nav.ts:62-72`) classifies `e`/`t`/`f`/`g` by raw string equality
   (`data === "e"` …) while every other key in the same function uses
   `matchesKey`. On a terminal that sends the CSI-u form
   (`\x1b[101u` for `e`, `\x1b[116u`/`t`, `\x1b[102u`/`f`, `\x1b[103u`/`g`),
   the gate returns `"other"`, `routeEditorFocus("other")` forwards, and the
   key is typed into the editor draft behind the transcript instead of
   reaching `TranscriptView.handleInput`. The repo's own
   `smoke/search-smoke/driver.py:49-60` models exactly this flag-1 CSI-u
   class. The Skeptic verified this as `closed-red` (O1) — every seat agrees
   it is a real defect, and the step-6 ruling (Q1) folds the fix into this
   card with no goal amendment.
3. **The focus cursor is never drawn.** `focused` (`navigator.ts:618`) exists
   only as an integer; `focusLine = starts[this.focused]` (`navigator.ts:796`)
   is used solely as a scroll anchor. A person cannot see which unit `e` will
   expand. **R-MARKER** fixes the glyph; this spec fixes the derivation.

## 2. Settled design

### 2.1 Header copy — R-KEYMAP on-state, presence/absence off-state

The header line becomes, verbatim:

```
<title> — ↑↓ move · e expand · t thinking · f follow(on) · g/G jump · esc back
```

with follow on, and

```
<title> — ↑↓ move · e expand · t thinking · f follow · g/G jump · esc back
```

with follow off. The state indicator is **presence/absence of the `(on)`
suffix** (ruling Q3): the existing `this.follow ? "(on)" : ""` conditional at
`navigator.ts:788` survives unchanged, and the only textual change is the
insertion of ` · g/G jump` between `follow` and `· esc back`. No `(off)`
token, no `dim`/`accent` styling of the suffix, no new theme token
(AGENTS.md 9.6). The whole line stays one `t.bold(...)` unit.

Minimal diff:

```ts
t.bold(`${this.title} — ↑↓ move · e expand · t thinking · f follow${this.follow ? "(on)" : ""} · g/G jump · esc back`),
```

### 2.2 The production key gate — `classifyProgressKey`

Replace the four raw-equality branches with `matchesKey`, keeping the order
and every other branch exactly as written:

```ts
if (matchesKey(data, "e")) return "e";
if (matchesKey(data, "t")) return "t";
if (matchesKey(data, "f")) return "f";
if (matchesKey(data, "g")) return "g";
if (matchesKey(data, Key.shift("g"))) return "G";
```

Verified by probe against the installed `pi-tui`: `matchesKey(data, "g")` is
`false` for both the legacy uppercase `"G"` and the CSI-u shift form
`"\x1b[71;2u"`, so the `g` branch does not swallow `G` and the existing
ordering stays correct. `matchesKey("\x1b[103u", "g")` is `true`. Every
other branch (`enter`, `escape`, `up`, `down`) is already
`matchesKey`-based and unchanged; the function's signature, its return
union, and `routeEditorFocus` are untouched. This is the surface's key
predicate, not the routing kernel.

### 2.3 Focus signifier — `TREE_ROW_MARKER` on the focused unit's head

- The marker is `theme.fg("accent", TREE_ROW_MARKER)` + `" "` (two visible
  columns, mirroring the tree-row idiom at `navigator.ts:382`), prepended to
  the **head line only** of the unit at `vis[this.focused]`. Body lines never
  carry it.
- The marker is derived from the **same expression `e` reads** —
  `vis[this.focused].i` / the `vis[this.focused]` entry — so marker↔`e`
  cannot drift by construction. Concretely: pass an `isFocused: boolean`
  into `unitLines` (computed in the `render` loop as `vi === fv`, where
  `fv` is the clamped `this.focused`), rather than inferring focus inside
  `unitLines` from `i`.
- The marker must **not** read `controller.surface` or any constructor flag:
  T11 (`test/ev9-progress.test.ts:267`) asserts the inline view and a
  standalone `TranscriptView` render byte-identically. Focus state is the
  only input; parity holds by construction.
- Prepend the marker before any `truncateToWidth` so a narrow width cannot
  truncate it away: `truncateToWidth(marker + head, width)` for the
  toolCall/single heads that are truncated today; for heads that are not
  truncated today, `marker + head` is acceptable (no width behavior change
  beyond the marker itself).
- `focused` remains a **visible-array index**. No rename, no
  `focusedAbsolute`, no `focusedVisible()` getter, no render-time recompute
  (ruling Q5). `expanded` stays keyed by absolute unit index `i` (unchanged).

### 2.4 Empty-`vis` guards and clamp semantics

The render-time clamp today is top-only
(`if (this.focused >= vis.length) this.focused = Math.max(0, vis.length - 1)`,
`navigator.ts:786`) — there is no lower clamp, so `DOWN` on an empty
transcript drives `focused` to `-1` (Skeptic O6a `closed-green`). Required:

- **Lower clamp in `render`:** `this.focused` is clamped into
  `[0, vis.length - 1]` when `vis.length > 0`, and set to `0` when
  `vis.length === 0`.
- **Empty-`vis` consumed no-ops:** when `vis.length === 0`, `up`, `down`,
  `e`, `g`, and `G` are consumed no-ops — no `focused` mutation, no marker,
  no crash. `t`, `f`, and `esc` keep their existing behavior (they do not
  depend on `vis`).

Clamp semantics (Skeptic O6d `closed-green`, binding):

- A boundary clamp is defined as **cursor position unchanged**.
- Strict byte-identical render before/after holds **only with follow already
  off** (press `f` once first). UP-at-top and DOWN-at-bottom are both
  byte-identical in that state.
- With follow on, UP-at-top legitimately changes the render: `up` sets
  `follow = false`, so the header drops `(on)`. Tests must not assert
  byte-identity for a clamp while follow is on.

### 2.5 Defined no-ops

`e` is a **defined consumed no-op** on:
- a `user` or `assistant` unit (their bodies are unconditionally shown —
  `showBody` is true for them at `navigator.ts:717`, so toggling `expanded`
  changes no line — Skeptic O6b `closed-green`); and
- an unpaired `toolCall` unit with no result body to reveal.

Honest keymap means every key's behavior is defined and asserted, including
its no-ops — not that no key is ever a no-op. The assertion for these cases
is a byte-identical before/after render.

### 2.6 State visibility

- **Follow** is visible as the presence/absence of `(on)` in the header
  (2.1), and in the body window moving off the tail when follow is off.
- **Thinking** is visible as a body assertion, not a header assertion
  (R-KEYMAP gives `t` no suffix): the `t`-visibility proof fixture **must
  contain a thinking block**, or the assertion is vacuous (Skeptic O4 /
  principal's blind-spot note). Assert: no rendered line
  contains the thinking head before `t`; a rendered line contains it after
  `t`; it is gone after `t` again.
- **Focus** is visible as the `▌` marker.

### 2.7 Deferred — the overflow header (ruling Q2)

EV-35 does **not** pin the header as row 0 of the viewport. Header and marker
assertions are scoped to fixtures where `maxTop === 0` (the header is already
row 0 by default). The overflow case — with follow on over a transcript
longer than the viewport, the header scrolls off and the marked line is
sliced with the body (Skeptic O2a/O2b/O6e) — is **deferred**. Closure paths,
recorded so it does not evaporate:

1. **EV-36**, if it chooses to consume the overflow case (its Intent owns the
   follow-vs-viewport reconciliation, and a pinned header at `termRows 7`
   would collide with EV-36's Acceptance bullet "At one row, the visible
   line identifies the active block"); or
2. a new `FLLWUP` card confirmed by `steward` (R-FOLLOWUP).

### 2.8 Modal path

Unchanged and out of scope (R-MODAL). The modal `openTranscript` path is in
fact unreachable from the production editor route (`onActivate` is stored at
`focus-nav.ts:278` and never invoked; tree ENTER calls `enterProgress` only —
Skeptic O6c).

## 3. Test contract

### 3.1 Step-9 minimum kit (the Skeptic's named blocking set)

All assertions are handleInput/render driven against a real `TranscriptView`
and a real `CouncilTreeWidget`, on a token-identity theme, over fixture JSONL.

1. **O1 (gate, two assertions):** `classifyProgressKey("\x1b[101u") === "e"`,
   and the routed path consumes it — the editor draft does **not** receive
   the kitty-encoded key (`"e"` → `consumed`, `"other"` → `forward` through
   `routeEditorFocus`). Same shape for `\x1b[116u`/`t`, `\x1b[102u`/`f`,
   `\x1b[103u`/`g`.
2. **O6a (empty-file guards):** on an empty transcript, `DOWN`, `UP`, `e`,
   `g`, `G` are each consumed; render never crashes, never draws a marker,
   and stays `header + (waiting for output · idle)`.
3. **O6d (clamp equalities, follow off):** with follow already off, snapshot
   the full render at `focused = 0`, press `UP`, render → byte-identical;
   mirror at the bottom for `DOWN`.
4. **O2 (`maxTop === 0`-scoped header/marker):** with a fixture sized so the
   header sits at row 0, `render(width)[0]` contains `g/G jump` and, fresh
   (follow defaults true), `f follow(on)`; after `f`, `[0]` contains
   `f follow` and not `follow(on)`. Exactly one rendered line starts with
   `▌` and it is the focused unit's head line. **No deep-scroll header
   assertion.**
5. **O3 (T9 narrowing + positive):** narrow `test/ev9-progress.test.ts:262`
   in place — the no-`▌` assertion scopes to the tree-row slice
   (`lines.slice(0, layout.treeLines)`), preserving T9's named intent
   (the tree-row marker is `surface`-gated); keep `:264` (marker restored on
   tree) untouched. **Ship the paired positive assertion in the same test
   file:** with a session file written and a unit focused, the joined
   progress render contains exactly one `▌`, on the focused unit's head line.
6. **Unchanged T11 parity:** inline view lines equal a freshly constructed
   standalone `TranscriptView` with the same JSONL + width + `viewportRows`,
   byte for byte.
7. **Five suites green** (see 3.2).

### 3.3 Additional assertions the deliberation settled

- `g`/`G` jump proven through the rendered marker position: from the top,
  `G` moves the marker to the last visible unit's head and turns follow off;
  `g` then moves it to the first visible unit's head.
- `e` expands the marked unit: pressing `e` on a focused collapsed `toolCall`
  makes the indented result body appear directly beneath the marked head,
  and the marked line does not move.
- `e` on `user`/`assistant` and on an unpaired `toolCall` is byte-identical
  before/after.
- `t` toggles visibility of a thinking block in the body (fixture contains
  one); the header still reads `t thinking` (no suffix).
- Marker↔`e` share the expression: after `t` moves the visible list, the
  marker and `e` still target the same unit.

## 4. Non-regression / anti-goals

- **No new theme tokens, no literal hex/ANSI**; `theme.fg`/`theme.bold` only
  (AGENTS.md 9.6). `test/theme-compliance.test.ts` is a live gate.
- **No renderer fork.** The marker derives from focus state alone; T11 parity
  is a gate, not a nicety.
- **Do not touch** `routeEditorFocus` or the routing kernel; only
  `classifyProgressKey`'s four branches change in `focus-nav.ts`.
- **Do not touch** the legacy `blockLines` renderer (FLLWUP-36), the modal
  `openTranscript` path (R-MODAL), or `DISPLAY_FLOOR` (EV-36).
- **No header pin** (2.7); no deep-scroll header/marker assertions.
- **No `focusedAbsolute` / recompute** (Q5) and no cursor-stability work.
- **No `(off)` token and no suffix styling** (Q3).
