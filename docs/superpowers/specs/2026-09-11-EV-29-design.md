# EV-29 design — provider-reported actual cost at the provider's own granularity

- **Card:** `EV-29` (epic `EPIC-7`), `council/cards/EV-29.md`
- **Status:** settled by the step-2–6 deliberation and the **step-6 rulings**
  (`steward` on the goal wording, acceptance bullets 1–2, BYOK `(reported)`
  semantics and the authoritative granularity; `product-owner` on items C1–C5
  and D/E), appended verbatim to the card's run record. This document is the
  write-up, **not a re-derivation**. Nothing settled in steps 2–6 is reopened
  here.
- **Binding inputs:**

    `cost≈$0.1234 (catalogue)`), **R-2** (unavailable marker literal `n/a` +
    legend line `n/a = provider figure unavailable`), **R-7** (persist the
    routed upstream provider id alongside the reported figure), **R-GATES**,
    **R-MERGE**.
  - The **step-6 `steward` ruling** — the amended `goal` and acceptance

    per-component **native token counts**; the four `Usage.cost*` slots stay

    surface reports **generation-level dollars only** (no per-component dollar
    field); `responseId` already rides the child session JSONL

- **Scope:** the provider retrieval module, the durable record's `provider`

## 1. Problem

EV-28 gave the hub a catalogue-derived usage tuple; EV-30 computed an
invocation-scoped `SpendRecord`; EV-31 made it durable; EV-32 renders it. Every
dollar figure in that chain is `cost≈$X (catalogue)` — `pi-ai`'s
`calculateCost(model, usage)` multiplies catalogue rates and **overwrites** the
wire cost object (`pi-ai/dist/api/openai-completions.js:1203-1205`,
`models.js:530-549`). The human's intake: the pi figure ran 2–3× (sometimes 5×)
above what was billed while cache hits read optimistic. OpenRouter fronts many
upstream providers and reports what a generation actually cost; EV-29 records
those reported figures beside the estimate and marks them unavailable
explicitly when they cannot be retrieved.

**The verified granularity (Skeptic O-3, closed-green).** The fetchable surface
(`GET https://openrouter.ai/api/v1/generation?id=<gen-id>`) returns
generation-level dollars — `total_cost`, `upstream_inference_cost` (BYOK),
nullable `cache_discount`, `is_byok` — plus per-component **native token**
counts (`native_tokens_prompt/completion/reasoning/cached`) and `provider_name`.
`cost_details` carries a BYOK-only two-way prompt/completions dollar split.
There is **no** per-component cache/output dollar field. Per the steward
ruling, the four `Usage.cost*` slots therefore stay `catalogue-estimate`; the
reported figure is a **separate reported datum**, never a pro-rated
per-component `(reported)` dollar.

**The carrier already exists (O-3).** `output.responseId ||= chunk.id`
(`pi-ai/dist/api/openai-completions.js:374`) is persisted on every assistant
`message_end` (`agent-session.js:398`), and the child's session JSONL lives in
the run dir (`seats.ts:517`). `hub.ts` never reads it and is **not touched**
(AGENTS.md convention 7). The generation id is read parent-side through
`runs.ts` (`findSessionFile`) as convention 12 requires.

## 2. Settled design

### 2.1 Module `extensions/provider-cost.ts`

New injected-transport module. No `ctx`, no hub import; it reads each job's
already-resolved `sessionPath` (the flush resolves it via `findSessionFile`,
`runs.ts`) and parses the session JSONL with pi's `parseSessionEntries` (the
`spend.ts`/`usage-store.ts` precedent). Reading the session file is its only
filesystem access.

```ts
import type { SessionEntry } from "@earendil-works/pi-coding-agent";
import type { RunManifest } from "./runs.ts";

/** C3 literals — record-only, never rendered. */
export type ProviderUnavailableReason =
  | "no-generation-id"
  | "session-missing"
  | `fetch-failed:${string}`
  | "timeout"
  | "no-api-key";

export interface ProviderNativeTokens {
  prompt: number | null;
  completion: number | null;
  reasoning: number | null;
  cached: number | null;
}

export interface ProviderGeneration {
  generationId: string;
  jobId: string;                       // R-7 attribution
  model: string;
  providerName: string | null;         // R-7 routed upstream provider (per generation)
  totalCost: number | null;            // generation-level dollars
  upstreamInferenceCost: number | null;
  upstreamInferencePromptCost: number | null;      // BYOK-only split, when returned
  upstreamInferenceCompletionsCost: number | null; // BYOK-only split, when returned
  cacheDiscount: number | null;
  isByok: boolean | null;              // persisted verbatim (steward B), never rendered
  nativeTokens: ProviderNativeTokens | null;       // per-component native token counts
  status: "reported" | "unavailable";
  reason?: ProviderUnavailableReason;  // present iff unavailable
  fetchedAt: string;
}

export interface ProviderCostReport {
  status: "reported" | "unavailable";  // worst-of: unavailable if ANY generation is unavailable
  reason?: ProviderUnavailableReason;  // deterministic; present iff unavailable
  totalCost: number | null;            // Σ over reported generations; null iff none reported
  generations: ProviderGeneration[];
}

/** The generation endpoint's wire shape; every field optional and defensively read. */
export interface GenerationResponse {
  id?: string;
  total_cost?: number | null;
  upstream_inference_cost?: number | null;
  upstream_inference_prompt_cost?: number | null;
  upstream_inference_completions_cost?: number | null;
  cache_discount?: number | null;
  is_byok?: boolean | null;
  provider_name?: string | null;
  native_tokens_prompt?: number | null;
  native_tokens_completion?: number | null;
  native_tokens_reasoning?: number | null;
  native_tokens_cached?: number | null;
}

/** Injected transport (the test seam — no network in the default suite). */
export type FetchGeneration = (generationId: string, signal: AbortSignal) => Promise<GenerationResponse>;

/** Pure: assistant entries' responseIds, file order, deduped (first occurrence wins). */
export function collectGenerationIds(entries: SessionEntry[]): string[];

/** The record-level unavailable marker (R-2 literal). Every nameable figure
 * returns the identical non-empty literal `n/a` on a failed report (D/E). */
export const UNAVAILABLE_MARKER = "n/a";
export const PROVIDER_COMPONENTS = [
  "totalCost",
  "upstreamInferenceCost",
  "upstreamInferencePromptCost",
  "upstreamInferenceCompletionsCost",
  "cacheDiscount",
  "nativeTokens.prompt",
  "nativeTokens.completion",
  "nativeTokens.reasoning",
  "nativeTokens.cached",
] as const;
export type ProviderComponent = (typeof PROVIDER_COMPONENTS)[number];
export function providerComponentFigure(
  report: ProviderCostReport | undefined,
  component: ProviderComponent,
): number | string; // the figure, or UNAVAILABLE_MARKER on a failed report / absent field

export interface FetchProviderReportInput {
  repoRoot: string;
  runId: string;
  /** Invocation-window manifests: model OpenRouter-modelled and startedAt >= markerAt. */
  jobs: { jobId: string; model: string; sessionPath: string | null }[];
  fetchGeneration: FetchGeneration;   // injected; production passes the real HTTP transport
  apiKey: string | null;
  now?: () => string;                 // default ISO wall clock
  timeoutMs?: number;                 // default 5000 (AbortSignal.timeout)
}
/** null = no eligible job (no OpenRouter-modelled manifest) ⇒ no provider block. */
export function fetchProviderReport(input: FetchProviderReportInput): Promise<ProviderCostReport | null>;
```

**Reason precedence (C3).** A report is `unavailable` whenever any generation
is unavailable. `report.reason` is one deterministic literal, chosen in this
fixed order of the failure classes actually observed:
`no-api-key` → `session-missing` → `no-generation-id` → `timeout` →
`fetch-failed:<trimmed Error.message>`. Per-generation `reason` carries its own
class; the first failure in the loop sets `report.reason` unless a
higher-precedence class appears later.

**Retrieval rules.**

1. `jobs.length === 0` ⇒ return `null` (no OpenRouter-modelled seat in the
   invocation) — the flush writes **no** `provider` field.
2. `apiKey === null` ⇒ one `unavailable` report, `reason: "no-api-key"`,
   `generations: []` — the transport is never called.
3. Per job: `sessionPath === null` ⇒ class `session-missing`. Else
   `collectGenerationIds(parseSessionEntries(readFile(sessionPath)))`; empty ⇒
   class `no-generation-id`.
4. Per generation id: one bounded fetch (`AbortSignal.timeout(timeoutMs)`). An
   `AbortError`/timeout ⇒ generation `status: "unavailable"`,
   `reason: "timeout"`; any other rejection ⇒ `status: "unavailable"`,
   `reason: "fetch-failed:<trimmed message>"`; success ⇒ `status: "reported"`
   with the response's fields mapped above.
5. `totalCost` = Σ over reported generations' `totalCost` (each non-null),
   `null` iff none reported. Native tokens are persisted per generation only
   when the response carried them (`nativeTokens: null` otherwise) — never
   fabricated from catalogue rates (C4).

**Credential resolution (production default only).** `getEnvApiKey("openrouter")`
(`pi-ai/dist/env-api-keys.d.ts:19-20`) falling back to
`readStoredCredential("openrouter")` (re-exported from
`@earendil-works/pi-coding-agent`); neither present ⇒ `apiKey: null`. Tests
inject an explicit `apiKey` so the real resolution is never exercised offline.

The production HTTP transport is the only network-touching code and is **never
reached by the default test suite** (only via an injected
`COUNCIL_INTEGRATION=1` probe, §4 T-P9).

### 2.2 Durable record — `StoredUsageRecord.provider` (ruling D)

`extensions/usage-store.ts`:

```ts
export const USAGE_RECORD_SCHEMA_VERSION = 2;   // was 1; D ruling

export interface StoredUsageRecord {
  schemaVersion: number;
  spend: SpendRecord;
  provenance: UsageProvenance;
  runId: string;
  command: string;
  repoRoot: string;
  writtenAt: string;
  basis: { trigger: UsageTrigger; manifestsObserved: number };
  provider?: ProviderCostReport;   // NEW sibling; absent when no OpenRouter-modelled seat

```

- `spend` stays byte-verbatim (EV-31's freeze covers `spend`, not the wrapper).
  `SpendRecord` gains no field; the four `Usage.cost*` slots stay
  `catalogue-estimate` (steward A).
- `PersistUsageInput` gains `provider?: ProviderCostReport`; `persistInvocationUsage`
  copies it only when defined (so pre-EV-29 records and non-OpenRouter runs stay
  byte-identical to v1 modulo `schemaVersion`).
- `readUsageRecords`' loose predicate (`rec && typeof rec === "object" &&
  rec.spend && rec.provenance`) already tolerates the sibling — **unchanged**
  (O-5, closed-green).
- No separate durable artifact; no extension of `SpendRecord`; no wrapping
  inside `spend.basis` (D's rejected set).

### 2.3 The flush — fetch before persist, inside the one gated write path

`flushPendingInvocations` becomes **async** and calls the provider module
**internally** (only the HTTP transport is injectable). The order per pending
invocation is:

```
1. keyable gate                     (unchanged)
2. marker on-chain                  (unchanged)
3. forestFullySettled               (unchanged)
4. choose-once file-exists check    (unchanged — precedes the fetch; a second flush never re-fetches)
5. spend = spendRecord(...)         (unchanged)
6. jobs = invocation-window OpenRouter manifests (below)
7. provider = await fetchProviderReport({...})   (null ⇒ absent field)
8. persistInvocationUsage({ ..., provider })     (once, with the report)
9. notify(formatUsageBlock({ record: res.record.spend, provider: res.record.provider }))
   — the written transition, from the **persisted** record so "what was shown"
     and "what is on disk" are equal by construction
```

A **fetch failure never fails the record write**: the `unavailable` report is
persisted and the block renders the marker. Only a *write* failure takes the
`{ failed }` path (R-5). An exception inside `fetchProviderReport` is caught by
the same per-record `try` and reported as `failed` — the store is never left
without an attempt.

**Job selection (invocation-window, matching `spendRecord`).** The flush already
reads `manifests = readManifests(repoRoot, p.runId)`. Eligible jobs are
`manifests` with `m.model.startsWith("openrouter/")` and `m.startedAt >=
p.markerAt`, mapped to `{ jobId: m.id, model: m.model, sessionPath:
findSessionFile(repoRoot, p.runId, m.sessionId) ?? null }`. `findSessionFile`
is EV-31's `runs.ts` reader (convention 12); the id set is therefore harvested
from the invocation's own sessions, never a caller-supplied list (O-2/O-4).

**Injection seam.** `flushPendingInvocations` input gains
`providerDeps?: { fetchGeneration?: FetchGeneration; apiKey?: string | null;
now?: () => string; timeoutMs?: number }`. Production callers pass nothing:
`fetchGeneration` defaults to the real transport and `apiKey` to the resolved
credential. Tests pass an explicit transport and key. There is **no**
caller-supplied job or id list — that is what makes acceptance bullet 3's
never-fetch falsifier bite (O-2/O-7).

### 2.4 The block — one new row, byte-identical measurement rows (ruling C1)

`extensions/usage-format.ts` gains:

```ts
/** R-1's reported literal, composed (never forked). */
export function formatReportedMoney(total: number): string {
  return `cost=$${total.toFixed(4)} (reported)`;
}
```

`extensions/usage-block.ts`: `UsageBlockInput`'s record variant gains
`provider?: ProviderCostReport`.

```ts
export type UsageBlockInput =
  | { record: SpendRecord; unavailableCost?: Half[]; provider?: ProviderCostReport }
  | { failed: string };
```

The three whole-block states (EV-32 §2.3, `failed > unresolved > empty`) are
**unchanged** and return before any reported row. In the resolved state:

1. The two measurement rows, the boundary row, and the conditional legend keep
   their exact bytes/grammar (EV-32 §2.1). `unavailableCost` still renders a
   half's money slot as `cost=n/a`.
2. `provider.status === "unavailable"` ⇒ the subtree half is added to the
   unavailable set (per-half `cost=n/a` + legend, C4/E). A total failure (zero
   reported generations) renders **no** reported row; a partial failure renders
   the half `cost=n/a` + the legend **and** the reported row (C2: omitted only
   when unavailable **and** zero reported).
3. When `report.totalCost !== null` (which holds iff ≥1 reported generation
   carried a `total_cost`), append exactly one row **after the boundary row and
   before the legend**:

   ```
   usage  reported  cost=$<Σ.toFixed(4)> (reported) routed=<multiset>
   ```

   `<multiset>` is the reported generations' `providerName` counts, ordered
   **descending count, then ascending name**, formatted
   `<name>x<n>,<name>x<m>` with **no spaces** around commas and the ASCII glyph
   `x` (C2). `providerName === null` is excluded from the multiset; if the
   multiset is empty the `routed=` segment is omitted (unruled edge — no
   invented copy). This row-presence rule is a faithful superset of C2's: zero
   reported generations ⇒ `totalCost === null` ⇒ the row is omitted; ≥1
   reported generation always carries `total_cost` on the OpenRouter surface,
   so the row renders — even a single `routed=Infermaticx1`. The only case in
   which a reported generation yields no row is a defensive one (a response
   missing `total_cost`, contrary to the documented surface) where there is no
   dollar figure to print.
4. **≤160 columns, hard** (C2). If the full routed multiset would push the row
   over 160 on the wide fixture, render `routed=(mixed; +K more)` where `K` is
   the number of distinct provider names minus one; the omitted names remain
   verbatim on the record (`ProviderGeneration.providerName`). Never wrap,
   never truncate silently.
5. `formatRunnerUsageBlock` is **unchanged** and never carries `routed=` or a
   reported row (C2; it has no store record).

`providerComponentFigure` (record-level, §2.1) carries the R-2 marker for the
durable record: on an `unavailable` report it returns the identical non-empty
literal `n/a` for **every** named component; on a `reported` report it returns
the field's figure, or `n/a` for a genuinely absent nullable field (E).

### 2.5 Async plumbing — `extensions/index.ts`

The written record is the completion guarantee, so the awaited drains must
await:

- `flushUsage` closure becomes `async (trigger, ctx): Promise<void>`; it
  **serializes** on a module-closure chain (`chain = chain.then(() =>
  flushPendingInvocations(...))`) so an awaited drain observes a prior
  fire-and-forget forest-settle write and never double-fetches.
- `agent_settled` handler becomes `async` and awaits the flush (pi awaits
  handler promises — O-1 closed-green).
- `session_shutdown` handler awaits its flush.
- the hub `onChange` site calls `void flushUsage("forest-settle", uiCtx).catch(() => {})`
  (fire-and-forget; the awaited drains are the guarantee).
- `CouncilEvalDeps.flushUsage` is typed `(trigger, ctx) => Promise<void>` and
  the eval tail becomes `await deps.flushUsage("agent-settled", ctx)` before
  `emit(summaryLines(...))` (O-6: the type must change or TypeScript stays
  green while the tail silently stops awaiting).
- `pendingInvocations` mutation stays inside the serialized flush.
- **`extensions/hub.ts` is untouched** (convention 7).

## 3. Acceptance (as amended by the step-6 rulings)

The card's own `Acceptance` bullets stand, read through the rulings:

1. **A fixture provider response whose reported generation-level dollar total
   and per-component native token counts differ from the catalogue estimate is
   persisted with the response's values.** The record's
   `provider.generations[0]` carries the response's `totalCost`,
   `providerName`, and `nativeTokens`, all differing from the catalogue
   estimate. Joined to the identity-binding conjunct (below). **Red today** —
   no fetch path exists.
2. **A fetch-failure fixture persists the same non-empty unavailable marker for
   the absent provider figure, identical across every field of the provider
   report.** The persisted `provider.status === "unavailable"`, `reason` is a
   deterministic non-empty C3 literal, and `providerComponentFigure(
   record.provider, c) === "n/a"` for every `c ∈ PROVIDER_COMPONENTS`.
3. **An implementation that never fetches fails the first test; one that always
   returns the estimate fails the second.** The first test asserts the persisted
   report's values **and** that the fetch saw exactly the ids harvested from the
   fixture session JSONL (`fetchCalls.map(c => c.generationId)` equals the
   fixture ids) — a never-fetching production path has no id channel and no
   fields. The second test asserts `string === string` for every component — an
   always-estimate implementation returns catalogue numbers and fails.
4. `bun test`, `bunx tsc --noEmit`, `python3 council/validate.py` stay green.

**The late-fetch vs fetch-failure distinction (O-7).** The design makes them
non-identical: a fetch failure persists `provider.status === "unavailable"` +
`reason`; a persist that happens before the fetch lands persists **no**
`provider` field at all. T-S3 (below) asserts both.

## 4. Test plan (failing test first)

New `test/provider-cost.test.ts`; additions to `test/usage-block.test.ts` and
`test/usage-store.test.ts`. Every test roots its store under a fresh
`fs.mkdtempSync` dir (explicit `storeRoot`); no test writes to `~/.pi/agent/`
and none touches the network.

**Provider module (`test/provider-cost.test.ts`)**

- **T-P1 (acceptance 1, identity binding).** Tmp repo with a run dir holding a
  manifest (`model: "openrouter/anthropic/claude-x"`, `sessionId: "job-1"`) and
  a session JSONL whose assistant entry carries `responseId: "gen-f1"`.
  Injected transport returns a fixture response with `total_cost: 0.0042`,
  `provider_name: "Infermatic"`, `native_tokens_prompt: 12`,
  `native_tokens_cached: 880`, `is_byok: true`, all differing from the catalogue
  estimate. Assert the recorded calls' `generationId`s equal `["gen-f1"]`
  (sourced via `findSessionFile`) **and** the returned report's
  `generations[0]` carries the response's values (`totalCost === 0.0042`,
  `providerName === "Infermatic"`, `nativeTokens.cached === 880`,
  `isByok === true`). A production caller passing `[]` cannot satisfy the
  first conjunct (O-2).
- **T-P2 (acceptance 2, marker).** Transport rejects with
  `new Error("ECONNREFUSED")` → `status === "unavailable"`,
  `reason === "fetch-failed:ECONNREFUSED"`, and
  `providerComponentFigure(report, c) === "n/a"` for every component. An
  always-estimate accessor returns numbers and fails.
- **T-P3 (granularity honesty).** No persisted provider generation carries a
  per-component dollar field; `PROVIDER_COMPONENTS` contains no
  `costInput|costOutput|costCacheRead|costCacheWrite`; the four `spend.subtree`
  slots stay `costBasis: "catalogue-estimate"`.
- **T-P4 (partial failure, C4).** Two generations, one fetch succeeds, one
  rejects → `status: "unavailable"`, the successful generation retained
  verbatim, `totalCost` = the reported sum, `report.reason` a C3 literal.
- **T-P5 (total failure).** All fetches reject → zero reported generations,
  `totalCost === null`, `reason` present.
- **T-P6 (no eligibility).** No OpenRouter-modelled manifest →
  `fetchProviderReport` returns `null`; the transport is never called.
- **T-P7 (no key).** `apiKey: null` → `unavailable`/`no-api-key`,
  transport never called.
- **T-P8 (session-missing / no-generation-id).** A job whose session file is
  absent → `session-missing`; a session with no `responseId` →
  `no-generation-id`.
- **T-P9 (opt-in live, `COUNCIL_INTEGRATION=1`).** One real generation id →
  the endpoint returns `total_cost` + `provider_name` + `is_byok` and no
  per-component dollar field. Never in the default suite.

**Block (`test/usage-block.test.ts` additions)**

- **T-B1 (C1 bytes).** `provider.status === "reported"` → the two measurement
  rows render byte-identical to EV-32's `(catalogue)` bytes, the boundary row
  is verbatim, and a new line follows it:
  `usage  reported  cost=$0.0042 (reported) routed=Infermaticx1`; the legend is
  last.
- **T-B2 (routed multiset).** Two generations, `providerName`s `["b","a","a"]`
  → `routed=ax2,bx1` (descending count, then ascending name; no spaces; ASCII
  `x`).
- **T-B3 (omission rule, C2).** A report with zero reported generations →
  no `reported` row; the subtree slot renders `cost=n/a` and the legend is
  present. Absent `provider` → no reported row and no legend.
- **T-B4 (partial).** `status: "unavailable"` with ≥1 reported → subtree
  `cost=n/a` **and** the legend **and** the reported row.
- **T-B5 (≤160, C2).** A wide multi-provider fixture → every line ≤160
  columns; the multiset beyond budget renders `routed=(mixed; +K more)`.
- **T-B6 (EV-32 regression).** The existing T1/T2/T3/T4/T5/T8/T9/T10/T16
  expectations remain green byte-for-byte when no `provider` is passed.

**Store + flush (`test/usage-store.test.ts` additions)**

- **T-S1 (acceptance 1 end to end).** Real pending invocation + fixture
  manifest/session in a tmp repo; injected transport/key; `await
  flushPendingInvocations(...)`; read the store file → `provider` present with
  the response's values; `schemaVersion === 2`; `spend` unchanged and
  `!("schemaVersion" in record.spend)` (EV-30 purity).
- **T-S2 (acceptance 2 end to end).** Rejecting transport → persisted
  `provider` unavailable; `providerComponentFigure` returns `"n/a"` for every
  component from the read-back record.
- **T-S3 (ordering, O-1/O-7).** With a transport that resolves on the next
  tick, the awaited flush's persisted record carries the fetched values; a
  deliberately early-persisting variant (`persist` before the `await`) yields a
  record with **no** `provider` field — the late-fetch and fetch-failure
  records are provably distinct.
- **T-S4 (choose-once × provider).** A second flush of the same marker →
  `existing`, byte-identical file, transport call count unchanged.
- **T-S5 (async drain, O-6).** The eval harness (`registerCouncilEvalCommand`)
  awaits `flushUsage`; a slow transport lands before the tail's summary and no
  second fetch occurs.

**Gates.** `bash council/preflight.sh`, `bunx tsc --noEmit`, `bun test`,
