# EV-24 Design — Non-destructive .council.json merge-write for seat overrides

Date: 2026-09-04. Card: `EV-24`. Epic: `EPIC-5`. This is the settled design
written up from the Council deliberation (rounds 1–3, Skeptic, consolidator).
The deliberation already played `brainstorming`; this file records its result.
Do not reopen anything settled below.

## 1. Purpose

EV-24 owns the first `.council.json` write path in the codebase. Given a
seat name, a model, an optional thinking level, and the flat catalogue array,
it validates then atomically merges `council.<seat>` — as the object form
`{ "model": "provider/id", "thinking": "<level>" }` the loader already speaks
— into `.council.json`, preserving the `theme` section, every other seat, and
unknown top-level keys byte-for-byte. Validation failures return an error
message and write nothing; filesystem-level failures throw.

The same flat catalogue array that feeds EV-22's resolver feeds this writer's
validation (settled data flow: `await refresh()` then `getAvailable()` happen
once in the EV-25 handler; both EV-22 and EV-24 read that single array — no
registry refresh inside the writer).

## 2. Rulings that bind this design (applied; do not re-argue)

The deliberation converged fully (owner, principal, designer) across three
rounds; there was no open-judgment item that required a ruling seat. The one
binding real-world fact driving the mechanism: `council/scaffold/.council.json`
**and** the real repo `.council.json` are **tab-indented** (verified `cat -A`
— `^I` units), key order `council` before `theme`, `model` before `thinking`.
A whole-object `JSON.stringify(x, null, 2)` re-serialize would reformat the
tab-indented committed file on the first write, violating the card's
"never disturbs the theme sibling" contract.

## 3. File

New module: `extensions/council-config-writer.ts`. It imports from:
- `./seats.ts` — `THINKING_LEVELS` (currently private at line 17; **must be
  `export`ed** — one-line, behavior-neutral; Skeptic-verified zero external
  consumers today), `AgentOverride` type for the shape, and
  `parseQualifiedModel`/`qualifiedOrThrow`-equivalent grammar awareness if
  needed for error copy. No unused imports.
- `node:fs`, `node:path`, `node:crypto` (for the SHA test contract — if SHA
  is only asserted in the test, the writer itself needs no crypto import).

The module performs **no network I/O** and **no registry access** — the given
`catalogue` array is the sole source for model-presence validation.

## 4. Export + types

```ts
/** Result of a write attempt. `ok: true` means the write landed atomically.
 *  `ok: false` means validation (or malformed existing JSON) refused the
 *  write and NO file byte was changed; `error` is a human message. */
export interface WriteSeatOverrideResult { ok: true } | { ok: false; error: string }

export function writeSeatOverride(args: {
  repoRoot: string;
  seat: string;
  model: string;        // qualified "provider/id" — MUST match a catalogue qualifiedId
  thinking?: string;    // optional; when absent, existing thinking is PRESERVED
  catalogue: CatalogueModel[] | { qualifiedId: string }[] | ...; // see 5
}): WriteSeatOverrideResult
```

The catalogue argument's precise carried shape is up to the owner so long as it
carries the set of selectable `qualifiedId = "${provider}/${id}"` strings —
the natural fit is the same `CatalogueModel[]` (or a derived `qualifiedId[]`)
the EV-25 handler already holds; validation only needs membership of
`model` against the qualifiedId set. Do not accept raw provider HTTP or a
registry object.

## 5. Behaviour, in order

1. **Validate** (pure, I/O-free, before any filesystem action). Reject with
   `{ ok: false, error }` and **write nothing** when:
   - `model` is not a qualified `provider/id` (grammar — loader contract), or
   - `model` is not present in the catalogue's `qualifiedId` set
     (model-presence — dispatch contract), or
   - `thinking` is present and not a member of `THINKING_LEVELS`
     (grammar — loader contract).
   These are the **only** reject conditions. There is **no per-model capability
   check**: `getSupportedThinkingLevels` / `supportedThinkingLevels` are
   picker-only (`extensions/catalogue.ts` is the only consumer), pi's
   `clampThinkingLevel` clamps at spawn and never rejects, and `model-floors`
   proves catalogue capability metadata is unreliable. A capability-invalid
   value must be **accepted** by the writer (it loads, dispatches, round-trips;
   pi clamps at spawn).
2. **Read + parse** the existing `.council.json` (path = `path.join(repoRoot,
   COUNCIL_CONFIG_FILE)`). If absent → greenfield regime (step 4c). If present
   but **unparseable** (malformed JSON) → return `{ ok: false, error }`
   naming the file and the parse message; **never throw, never write** (this
   is not a filesystem failure — the read succeeded; a mid-edit file must not
   be clobbered).
3. **Locate the `council.<seat>` value byte span** with a string-aware scan
   (must not mislocate on string content elsewhere containing the literal seat
   name with escaped quotes). Three regimes:
   - **(a) replace**: seat value span exists → re-emit it as the object form in
     the file's existing indent unit, `model`-before-`thinking`, omitting
     `thinking` when absent. Convert a pre-existing string-shorthand span
     (`"seat": "provider/id:level"`) to object form as part of the replace
     (model preserved, thinking carried if the shorthand had a suffix).
   - **(b) insert**: `council` exists but the seat key is absent → insert the
     seat object into the `council` object in detected indent style, with the
     object form. `council` itself absent and file present → insert a
     `council` section (scaffold order: `council` before `theme`).
   - **(c) greenfield**: file absent → create with a single `council.<seat>`
     object (canonical 2-space + trailing newline), `model`-before-`thinking`.
4. **Merge, not replace-wholesale** for the seat block: **absent `thinking`
   PRESERVES** the pre-existing `thinking` (field-level merge). E.g. existing
   `{"model":"Y","thinking":"high"}` + write `{model:"X"}` →
   `{"model":"X","thinking":"high"}` (model-before-thinking, thinking value
   byte-preserved). Greenfield + write `{model:"X"}` → exactly `{"model":"X"}`
   with no `thinking` key. There is **no way to delete `thinking`** in v1 (a
   clear affordance is a separate follow-up; mirroring the loader, which has no
   reset affordance).
5. **Indent rule** (mixed-indent files): deterministic, throw-free — (1)
   strict-majority indent unit across indented lines; (2) else the target seat
   block's own unit; (3) else tabs (matching the tab-indented seed). Never
   throw over whitespace.
6. **Atomic write**, auth-store pattern, byte-preserving of all untouched
   regions:
   - `fs.mkdirSync(dirname, { recursive: true })`
   - tmp = `${file}.tmp-${process.pid}-${Date.now()}`
   - **mode**: fresh (greenfield) write → default umask (`0o666 & ~umask`),
     **never** explicit `0o600` (`.council.json` is a committed shared file,
     not a secrets store). Rewrite of existing file → preserve the existing
     target's mode: `stat` the target, `chmod` the tmp to that mode **before**
     `rename` (a bare tmp+rename resets e.g. `0600 → 0o664`).
   - `fs.renameSync(tmp, file)`.
   - A rename failure (EROFS/ENOSPC, target is a directory) **throws** — this
     is a filesystem failure.

## 6. Acceptance-test contract — `test/council-config-writer.test.ts`

Round-trip tests against `fs.mkdtempSync` repos (the writer is I/O, so these
are temp-dir integration tests, unlike EV-22's pure unit test). The
`theme` block is SHA-256 asserted byte-identical before/after, key-order
inclusive. Assertions:

- **Discriminating splice test (the crux)**: copy the real tab-indented
  `council/scaffold/.council.json` into the temp repo; write one seat; assert
  every byte outside the `council.<seat>` value span is byte-identical and the
  `theme` block's SHA-256 is unchanged. (This FAILS under a whole-object
  `JSON.stringify(x,null,2)` re-serialize.)
- **Acceptance round-trip**: fixture with a `theme` section, other seats, and
  an unknown top-level key; byte-assert every untouched region, SHA-assert the
  `theme` block.
- **Hostile span-finder**: fixture with a string value elsewhere containing the
  literal seat name with escaped quotes (e.g. `"someKey": "contains \"skeptic\"
  inside"`); after a replace, every byte outside the `council.<seat>` span is
  byte-identical (proves the span-finder doesn't mislocate).
- **Emitted shape**: byte-assert the emitted `council.<seat>` block equals the
  indentation-matched object form `{ "model": "<provider>/<id>", "thinking":
  "<level>" }`, model-before-thinking.
- **Validation writes nothing**: model ∉ catalogue → `{ok:false}`, file
  bytes unchanged (mtime unchanged); model ∈ catalogue → `{ok:true}`, file
  written. `thinking: "super"` (∉ THINKING_LEVELS) → `{ok:false}`, no write.
- **Capability accepted (parity)**: a model whose `supportedThinkingLevels` (in
  the fixture) lacks `xhigh` + write `thinking:"xhigh"` → `{ok:true}` +
  post-write `loadCouncilConfig` round-trips the value (the file loader +
  dispatch accept IS writable).
- **Malformed existing JSON**: pre-existing `"{ not json"` → `{ok:false}`, no
  throw, file byte-identical.
- **Mode**: existing `0o640`/`0o600` file → still that mode after write;
  greenfield → mode is `0o666 & ~umask`, never `0o600`.
- **Absent-thinking merge**: existing `{"model":"Y","thinking":"high"}` +
  write `{model:"X"}` → `{"model":"X","thinking":"high"}` (thinking preserved).
- **Loader round-trip**: after a successful write,
  `loadCouncilConfig(root)[seat]` deep-equals the written `{model, thinking}`
  and `loadThemeConfig(root)` deep-equals the pre-write section — the
  theme-watcher cannot misclassify a model-only edit as a theme change.
- **Idempotency**: two writes of the same `(model, thinking)` → the second
  leaves the file byte-identical.

## 7. Gates (all must clear in full)

The owner's gates are the repo gates (same set as the `gates` CI workflow):
`bunx tsc --noEmit` clean, `bun test` full suite green, `python3
council/validate.py` clean. The new test file must be green (criterion 1,
full-suite). No threshold lowered, no finding suppressed. The owner must also
confirm the `grep` for network/capability: zero raw-HTTP imports in the
writer, and `getSupportedThinkingLevels` remains consumed only by
`extensions/catalogue.ts` (picker data), never by the writer.

## 8. Scope guard

Out of scope for EV-24: no command registration, no modal/UI (EV-23), no
EV-25 handler wiring or fetch (EV-25 owns the one `refresh()`/
`getAvailable()`), no capability gate (deliberately absent — it is picker
data only), no delete-override affordance in v1, no `--dry-run`, no JSON-Patch
emitter, no backup-tmp, no config-lock. These are expansions; add them only
when a real caller needs one.
