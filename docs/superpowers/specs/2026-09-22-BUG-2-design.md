# BUG-2 design — Usages tool creates its output directory before writing the cache

Card: `council/cards/BUG-2.md` (EPIC-15). This spec records the design the
Council settled in steps 2–6; the card's `goal` and `## Acceptance` remain
the judge's oracle and are not restated or modified here.

## The defect

In `council/skills/usages/scripts/usages.py`, `main` calls
`save_cache(cache_file, cache)` (in a `try/except OSError` that logs
`usages: could not write cache: {e}`) long before `ensure_out_dir(out_dir)`
runs. `save_cache` writes a temp file beside its target
(`p.with_name(p.name + f".tmp-{os.getpid()}")`) with no parent mkdir, so on
a first run — where `out_dir` does not exist yet — the cache write raises,
is caught, and logs the warning; the report then succeeds moments later
because `ensure_out_dir` creates the directory just before the report write.
One invariant is violated: **the output directory must exist before anything
is written into it.**

## The fix (settled: mechanism B)

Move the `ensure_out_dir(out_dir)` call above the first `save_cache` call:

- Insert `ensure_out_dir(out_dir)` in `main` **immediately after** the
  `out_dir` / `cache_file` resolution lines (~line 718–719), i.e. before
  `load_cache(cache_file)` runs. Verified safe: the
  `OPENROUTER_MANAGEMENT_KEY` check (the `return 2` path that T-U2 pins)
  sits earlier in `main` than the out_dir resolution, so the moved call
  cannot create directories on the exit-2 path.
- Delete the existing `ensure_out_dir(out_dir)` call immediately before the
  report write (~line 792).
- Do **not** touch `save_cache` — it stays a pure write-beside-target +
  atomic-replace primitive. (Mechanism A — `save_cache` mkdirs its own
  parent — was rejected: it silently creates arbitrary foreign parent
  directories implied by `--cache-file`, an unruled behavior change, and the
  acceptance oracle cannot distinguish the two mechanisms. The
  foreign-`--cache-file` absent-parent surface is follow-up-card material,
  not this card's scope.)

Known accepted limitation, recorded by the deliberation and not to be
changed by this fix: a `--cache-file` naming a parent directory that does
not exist (outside `out_dir`) keeps today's non-fatal warning behavior and
writes no cache. R4 (recorded human decision) scopes this card to the
write-ordering fix only: no cache-health report row, no hardening of the
`--cache-file` surface, cache-write failure stays non-fatal.

Side effect of the move (accepted, verified by the skeptic): the output
directory (and its `.gitignore`) is created before the network phase rather
than after, so a run that dies mid-network still leaves a gitignored
directory. The moved `ensure_out_dir` is unguarded and side-effecting and
sits outside the report-write `try`; its failure surface (exit 1
PermissionError traceback when the directory cannot be created) is the same
class before and after the move — do not change it in this card.

## Tests to add (`test/usages.test.ts`)

Two new tests, T-U7 and T-U8, exactly as the card's `## Acceptance`
specifies. Implementation guidance grounded in the skeptic's findings:

- **Use the async pattern (mandatory).** Both tests spawn the tool with a
  live `Bun.serve` stub on `--api-base`. The existing `runTool` helper uses
  `spawnSync`, which blocks the event loop so the stub cannot answer
  python's HTTP requests — the run deadlocks (`status: null`, timeout)
  instead of failing. Draft both tests on the T-U4 pattern: `Bun.spawn` +
  `await Promise.all([...stdout, ...stderr, proc.exited])`, `Bun.serve` with
  `port: 0`, `server.stop(true)` in a `finally`.
- **T-U7** (default path): fresh `mkdtemp` repo and agent;
  `--repo`, `--agent-dir`, `--config-dir .pi`; fixed `--start`, `--end`,
  `--today`; `OPENROUTER_MANAGEMENT_KEY` set; one seeded session file via
  the existing `sessionFile`/`assistant` helpers carrying one `responseId`;
  the T-U4-style `Bun.serve` stub serving `/analytics/query` (echoing the
  requested generation ids back with usage figures) and `/activity`;
  `--api-base http://127.0.0.1:<port>/api/v1`. Pass **neither** `--out-dir`
  nor `--cache-file`; do **not** pass `--offline`. A closed port is not a
  substitute for the stub — the stub's rows are what populate the cache.
  - Run 1 assertions: exit 0; stderr does not contain the literal
    `usages: could not write cache:`; `fs.existsSync(<repo>/.pi/council/usages/.cache.json)`
    is true; the paired `usages-<start>_<end>.json` and `.md` exist there;
    that directory's `.gitignore` contains `*`; `.cache.json` parses and its
    `generations` map holds the stubbed `generation_id`.
  - Run 2 (rerun, same repo/agent/stub, still no `--out-dir`/`--cache-file`):
    exit 0, stderr clean, parsed report `cache.hits === 1`. Note: this is
    the only load-bearing run-2 assertion — run 2's stderr is clean even at
    base (run 1's old post-report `ensure_out_dir` already created the dir),
    so `hits === 1` is what carries the red.
- **T-U8** (custom absent `--out-dir`): same setup as T-U7 run 1 but with
  `--out-dir <repo>/fresh-out` (directory absent) and `--cache-file` still
  omitted: exit 0, no `usages: could not write cache:` on stderr,
  `<repo>/fresh-out/.cache.json` exists. This is the test a scaffold-only
  `EMPTY_DIRS` seed cannot pass; name it in the PR body.
- Do not pre-create the output directory in either test. Do not touch
  `extensions/scaffold.ts`'s `EMPTY_DIRS`.
