# EV-23 — Token-only modal picker for per-seat provider and model selection (design)

Date: 2026-09-04. Card: `EV-23` (EPIC-5). This document is the settled
design for the token-only modal picker. It writes up what the EV-23
deliberation (rounds 1–3, Skeptic step 4, consolidator step 5) settled and
what rulings J-1/J-2 (step 6) ordered. It does not reopen either. An owner
reading only this file must not be able to reach two designs.

## 1. Deliverable

One new pure source file: `extensions/model-picker.ts`. It exports:

- `export interface SeatModelSelection { seat: string; model: string /* = ModelEntry.qualifiedId, verbatim */; thinking?: string }`
  — the selection-encoding type. `model` is the catalogue's `qualifiedId`
  (`${provider}/${id}`) byte-verbatim, never recomposed from `provider` +
  `id`. `thinking` is present **iff** the user picked a level (the
  cross-product row carried a `:level` suffix). This is the single `done`
  payload EV-25 flows through `ctx.ui.custom<SeatModelSelection | null>`
  and feeds to `writeSeatOverride({ repoRoot, catalogue, ...sel })`.
- `export class ModelPicker implements Component` — constructor
  `(catalogue: ResolverResult, theme: NavTheme, onConfirm: (sel: SeatModelSelection) => void, onClose: () => void, opts?: { maxRows?: number })`.
  Surface: `render(width)`, `handleInput(data)`, `invalidate()` — the same
  surface `CouncilTree` exposes.
- Small pure helpers used by both render and logic so echo == selection by
  construction: a single `resolveSelection()` implementing the confirm echo
  and the emitted tuple, `seatMarker(state: SeatState)`, `footerFor(level)`,
  and the ruled copy constants (`HEADER`, `FOOTER_SEAT_PROVIDER`,
  `FOOTER_MODEL`, `FOOTER_CONFIRM`, `EMPTY_NO_PROVIDERS`,
  `EMPTY_NO_MODELS`).

**Zero I/O by construction.** The modal takes no `repoRoot`, touches no
filesystem, and never calls `writeSeatOverride`. "Confirm commits" means
`onConfirm(sel)` fires exactly once. The component returns **content
lines** from `render(width)`; the EV-25 opener applies
`withModalFrame(theme, w, termRows, content, { maxPanelHeight: termRows - 2 })`
at `Math.min(96, Math.max(1, w-8))` via `ctx.ui.custom` with
`{ overlay: true, overlayOptions: { width: "100%", maxHeight: "100%", margin: 0, anchor: "top-left" } }`
— the `openTranscript` pattern. The modal source must not import
`focus-nav.ts`, `THINKING_LEVELS`, `parseQualifiedModel`,
`applySeatOverride`, `writeSeatOverride`, or `resolveCatalogue`
(display-equals-selection: the only level authority is the input
`ModelEntry.supportedThinkingLevels`).

## 2. The cascade

Four levels: `seat → provider → model → confirm`. One linear cursor per
level, clamped (`Math.max`/`Math.min`, **no wrap-around**). Enter descends;
Esc ascends one level; Esc at the seat level calls `onClose()`. Entering a
level resets that level's cursor to 0. After a confirm-Enter the picker
sets a `settled` flag and ignores all further input (no double-fire).

The seat is fixed at step 1; provider and model lists are the shared
resolver arrays (repo-wide — there is no per-seat catalogue). The seat row
renders `seatMarker` (R-3); the provider level lists `ResolverResult.providers`
in resolver order; the model level lists the focused provider's models as a
flat cross-product (below).

Windowed scrolling: when rows exceed `maxRows`,
`start = max(0, min(selected - floor((maxRows-1)/2), len - maxRows))`. No
sorting anywhere in the modal — resolver order verbatim.

## 3. The model level: flat cross-product rows (J-2)

The model level is one linear cursor over `(model, level)` pairs. For the
focused provider, in resolver order (models in the provider's array order,
which EV-22 defines as `name ?? id` ascending), and for each model its
levels in `supportedThinkingLevels` **array order** (no re-sort):

- `supportedThinkingLevels.length === 0` (`[]`) → **one** row: the model id,
  no `:suffix`. `selection.thinking` omitted. This is the **only** row that
  earns the `— thinking unchanged` echo.
- `length === 1` (e.g. `["off"]`) → **one** row: `<qualifiedId>:<level>` with
  `:levels[0]` appended, `selection.thinking = levels[0]`. The echo ends
  `:off` (or `:<level>`), never `— thinking unchanged` (Skeptic O-8
  resolution).
- `length >= 2` (an `N`-level model) → **exactly `N` rows**, one per level,
  each `:<level>` suffixed, in array order. **There is no level-less row for
  a ≥2-level model** (J-2). `selection.thinking = level`.

Boundedness: a real pi model offers at most 5 default levels
(`reasoning:false → ["off"]`; `reasoning:true` default 5),
so a model expands to at most 5 cursor rows; `[]` (all 7 `THINKING_LEVELS`
nulled) is essentially unreachable from real data — tests must construct it
by hand. Multi-level models therefore force an explicit thinking decision:
the cursor row *is* the decision, and `enter select` (R-2) is literally true
on every model-level row.

Enter on any model-level row → `confirm`. Esc at the model level → provider
level. The confirm footer (`enter confirm · esc back`) applies at confirm.

## 4. Ruled copy (R-1..R-4) — byte-exact, binding, untouched

- **R-1 header** (bold): `council models — pick a model per seat`.
- **R-2 footers** (dim): seat & provider levels
  `↑/↓ move · enter open · esc back`; model level
  `↑/↓ move · enter select · esc back`; confirm level
  `enter confirm · esc back`. These four are exhaustive — no fifth footer
  string ever renders, regardless of level counts.
- **R-3 seat-row markers** (dim suffix): override →
  `— using <currentModel>[:<currentThinking>] (override)`; frontmatter
  default → `— frontmatter default`. Keyed off
  `SeatState.hasOverride` (key presence). `currentModel` is already
  qualified; the suffix appends `:<currentThinking>` only when present. A
  `{}`-override entry (key present, model defaulted) renders
  `— using <frontmatter-effective-model> (override)`.
- **R-4 empty states**: no providers →
  `No providers configured — authenticate a provider in pi, then reopen
  /council-models.` (body, dim; no footer — no active keys); a provider
  with no models → `No models available for <displayName>.` where
  `displayName` is `ProviderGroup.displayName` (never a write key — it is
  render copy matching the row the user opened); a seat with no override →
  the R-3 frontmatter-default marker, **never** an empty panel. R-4#2 is a
  render-contract-only input: `resolveCatalogue` cannot produce a
  `ProviderGroup` with `models: []`.

## 5. Active-row marker

Selected row: `theme.fg("accent", "> " + row)`; unselected rows padded with
two spaces. This is byte-identical to `CouncilTree.render()` at
`extensions/navigator.ts:206`. `TREE_ROW_MARKER` (`▌`, U+258C) stays on the
inline tree; the modal does not import `focus-nav.ts`, and `render()`
output contains no `\u258C` at any level.

## 6. The confirm screen and echo (two-case, non-assertive)

`resolveSelection()` computes both the echo and the emitted
`SeatModelSelection` — same object construction, so the quoted tuple and the
committed tuple are identical by construction.

- **Picked** (any row carrying `:level`, including the `["off"]` single
  row): accent line `Set <seat> to <qualifiedId>:<level>`. `qualifiedId`
  byte-verbatim from the in-cursor `ModelEntry`.
- **Thinking omitted** (the `[]` row only):
  `Set <seat> to <qualifiedId> — thinking unchanged` (em-dash with spaces).
  This asserts only what this screen did — wrote no thinking value — and
  never quotes a preserved level (see §9, the seam).
- Dim second line (body, not footer): `Writes ${COUNCIL_CONFIG_FILE} —
  takes effect at the next dispatch.` — `COUNCIL_CONFIG_FILE` imported
  from `seats.ts`, never a literal.

`onConfirm(sel)` fires exactly once, on Enter at the confirm level, with
the echoed tuple. Esc at confirm returns to the model level; a second Enter
after settle fires nothing.

## 7. Theme discipline (AGENTS.md 9.6)

Color-bearing draws use only the `accent`, `dim`, and `bold` tokens via
`theme.fg`/`theme.bg`/`theme.bold`. Frame chrome (`border`,
`customMessageBg`, header) comes from `withModalFrame` as the tree does
today. The render cache is a `(width, signature)` pair —
`signature = level:cursors:top` — invalidated on every mutation; EV-25
owns `invalidate()` on theme change.

## 8. Tests (`test/model-picker.test.ts` + established patterns)

1. **Source audit** — no `\x1b`, no `#[0-9a-fA-F]{3,8}` in
   `extensions/model-picker.ts` post-comment-strip (the
   `theme-compliance.test.ts` grep pattern; the repo-wide audit auto-covers
   the new file, the per-file test is added anyway per the card acceptance).
2. **Palette** — materialize the dark `truecolor` theme; `colorAnsi(render(...))`
   is non-empty and every member ∈ the theme's own `fgColors`/`bgColors`
   ANSI sets, across all four levels and all three empty states.
3. **Ruled copy byte-exact** — R-1..R-4 strings; the `{}`-override edge.
4. **Key handling** — arrows move and clamp (no wrap); Enter descends
   seat→provider→model; Esc ascends one level and closes at seat; small
   per-level row erases; re-entry after Esc resets cursors to 0.
5. **Echo-then-run** — at confirm, the echo matches `resolveSelection()`
   and `onConfirm` has **not** fired; Enter fires `onConfirm` exactly once
   with the echoed tuple; a second Enter or Esc after settle fires nothing.
6. **Thinking matrix (with J-2)** — 0/1/N levels × exact row count and
   order; `[]` → 1 row, thinking undefined, echo `— thinking unchanged`;
   `["off"]` → 1 row `:off`, echo ends `:off`; `N ≥ 2` → exactly `N` rows
   (no level-less row), echo `:<level>`; every emitted `thinking` ∈ that
   model's `supportedThinkingLevels`.
7. **Verbatim qualifiedId round-trip** — emitted `model` byte-equal to some
   `ModelEntry.qualifiedId` (discriminating case: a provider whose `id`
   contains `/`, e.g. `openrouter/deepseek/deepseek-v4-pro-0813`), never
   `provider + "/" + id` recomposed.
8. **Marker bytes** — focused row's leading bytes `> ` with preceding ANSI
   `=== theme.getFgAnsi("accent")`; unselected rows two-space padded; no
   `\u258C` anywhere.
9. **Four-footer exhaustiveness** — across every `handleInput` transition,
   the footer (post-ANSI-strip) is always one of the four R-2 strings;
   never a fifth.
10. **Seam-aware echo** — seat whose override is object-form
    `{"model":"a/b:low"}` (no `thinking` key) with frontmatter thinking
    `high`; user picks the `[]` row and confirms → the confirm line is
    exactly `Set <seat> to <qualifiedId> — thinking unchanged` (never
    `keeps thinking low`) and the emitted tuple has `thinking` absent.
    (This is the modal's echo-level assertion; the writer fix is
    FLLWUP-10's goal and its test lives in FLLWUP-10.)
11. **Empty-state non-conflation** — `providers: []` → no-providers copy;
    a hand-built `ProviderGroup{models: []}` → exactly
    `No models available for <displayName>.`; a `ModelEntry{supportedThinkingLevels: []}`
    renders a selectable row (never skipped), whose selection omits
    `thinking`.
12. **No-side-effect boundary** — source contains no `writeSeatOverride`,
    `resolveCatalogue`, `getAvailable`, `repoRoot`, or `fs` (post-comment
    strip).
13. **Truncation never drops the thinking decision** — for every
    cross-product row whose unsuffixed id exceeds the content width, the
    truncated text still ends in `:<level>` when a level was picked (or the
    model's terminator when not); truncation must not silently clip the
    level.

## 9. Recorded seam: known-but-tracked, J-1 green-light

FLLWUP-10 (`council/cards/FLLWUP-10.md`, Backlog, EPIC-5, commit
`b9bc6b0`) carries the `existingThinking` object-form `:suffix` fix:
`existingThinking` in `extensions/council-config-writer.ts` parses the
object-form `.model` `:suffix` via the same `lastIndexOf(':')` +
`THINKING_LEVELS.has(...)` rule `applySeatOverride`
(`extensions/seats.ts:414-419`) already uses, so writer preservation matches
loader resolution. Today, an override `{"model":"a/b:low"}` (object form,
no `thinking` key) with a level-less write produces
`{"model":"c/d"}` and the post-write effective thinking falls back to
frontmatter (Skeptic O-1, closed-red). The modal cannot observe or repair
this (it holds `SeatState`, never the raw shape), so its echo is
non-assertive: `— thinking unchanged` is true under every writer regime and
survives the FLLWUP-10 fix either way. This seam is recorded on the card
face; step 9 verification must assert that record exists before any merge.

## 10. Explicitly out of scope

- **Clearing thinking**: no "clear thinking" affordance exists through
  `writeSeatOverride` (`thinking: undefined` preserves, never clears) —
  tracked separately as FLLWUP-9.
- **The write**: EV-25 owns `writeSeatOverride` wiring, the post-write
  notify (derived from a post-write file read-back, never from the
  selection tuple), the single `getAvailable()` snapshot handed to both
  `resolveCatalogue` and `writeSeatOverride`, and `invalidate()` on theme
  change.
- **The writer fix**: FLLWUP-10.
- **Capability validation**: none in the writer (EV-24 settled); the modal
  constrains selection by only offering rows inside
  `supportedThinkingLevels`.
- **R-4#2**: not reachable from the resolver; defensive render only.
