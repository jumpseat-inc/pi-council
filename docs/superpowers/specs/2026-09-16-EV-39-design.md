# EV-39 design — hub-level retry of a seat dispatch with exponential backoff

- **Card:** `EV-39` (epic `EPIC-9`), `council/cards/EV-39.md`
- **Status:** settled by the step-2–6 deliberation, the step-6 `product-owner`
  ruling (`job-20`, Q1–Q4) and the step-6 `steward` ruling (`job-21`,
  Escalation 1/2), both appended verbatim to `council/cards/EV-39.md` at commit
  `590f6d9`. This document is the write-up, not a re-derivation. Nothing settled
  in steps 2–6 is reopened here; where this document and a ruling disagree, the
  ruling wins.
- **Binding inputs:** the card's Phase 1 ruling **R4** (one row per dispatch,
  `attempt 2/3`, no extra rows) and the recorded retry inputs **R1** (the
  classifier), **R2/R3** (policy defaults/validation); the `product-owner`
  ruling's **Q1** (inject the init-time `RetryPolicy` snapshot), **Q3** (ratify
  2 s), **Q4** (disclose, don't silently ship); the `steward` ruling's
  mechanism correction and **Q4** disclosure form; the Skeptic's
  `closed-green`/`closed-red` results; the mandatory D1/D2 corrections; and
  the EV-40 §2.8 agreement that the manifest field is named `attempt` and
  neither loop reads the other's counter.
- **Scope:** `extensions/hub.ts`, a new `extensions/job-retry.ts`,
  `extensions/hub-tools.ts`, `extensions/runs.ts` (one additive field),
  `extensions/tree.ts`, `extensions/navigator.ts`, `extensions/index.ts`,
  `extensions/usage-block.ts` + the provider-report construction in
  `extensions/usage-store.ts` (the Q4 disclosure), and `test/stub-child.ts`
  (one mode). Not per-attempt provenance in the run substrate (EV-42), not the
  end-to-end forcing fixture (EV-41), not the parent-turn loop (EV-40), not the
  classifier (EV-37).
- **Line citations** are against `main` at the ruling-application commit
  `590f6d9`. Implementations may shift them; the cited symbol is authoritative.

## 1. Problem

The card's `goal`: *"A seat dispatch whose settled report is classified retry
is re-spawned with exponential backoff until the budget is exhausted or an
attempt settles without a retryable error, and the final report names how many
attempts were made."*

The deliberation and the Skeptic's step-4 runs established, each with a real
probe result, the facts the design must respect:

1. **`Hub` observes settles but does not own spawn.** `Job` carries no
   `command/args/cwd/env` (`hub.ts:11-30`); `council_dispatch` bakes the seat
   `input`, the tmp prompt file, the model and the MCP allowlist into `args`/`env`
   at spawn (`hub-tools.ts`). `settle()` runs and nulls `cleanup`
   (`hub.ts:251-259`), and that cleanup deletes the prompt tmpdir. The loop is
   therefore a **split ownership**: Hub = lifecycle + synchronous settle hook,
   dispatch = spawn inputs / respawn closure, a new supervisor = classification
   + counter + timer.
2. **The retry decision must run inside `settle()`, synchronously, before
   `writeJobManifest`/`onChange`** (owner round-2 concession; Skeptic O-1's
   gate-closed probe). `index.ts`'s hub `onChange` fires
   `flushUsage("forest-settle")`, whose gate (`usage-store.ts:392-397`) is
   `manifests.some(m => m.startedAt >= markerAt && m.exitCode === null)` →
   gate-closed, choose-once at `:398-402`. A decision armed after the fan-out
   would let the gate open on a settled manifest and persist a permanently-short
   record.
3. **Manifest cardinality (A) is forced.** One job id / one `<id>.json` /
   one row; `usage` carried cumulative across attempts. Per-attempt manifests
   (B) open the flush gate during every backoff and silently under-count
   (principal prediction 4; O-1/O-5). `(B)` without a group key also ships a
   two-rows-per-intent tree, which R4 forbids.
4. **`startedAt` must stay the first-spawn time** (O-1 `closed-red`: a
   re-based cumulative manifest is counted in two invocation subtrees, `M1 90 +
   M2 90`). Per-attempt `timeoutMs`/`stallMs` ceilings are expressed by an
   internal attempt clock, not by moving `startedAt`.
5. **Nulling `exitCode` during backoff while retaining the dead pid publishes
   it** (O-2 `closed-red`: `writePids`' filter is `exitCode === null && pid`
   with no state guard). Clear `pid` in the same step.
6. **A fresh session id per attempt is mandatory** (O-4 `closed-green`: a live
   two-arm `pi -p --session-id` probe resumed attempt 1's session and answered
   in its context). `sessionId` must be `<id>-attempt<N>` for `N ≥ 2`
   (provisional naming; EV-42 finalizes).
7. **A `retrying` job state is needed.** Keeping `state: "running"` through
   backoff renders `☠ orphaned` (`tree.ts:17`, `running` + dead pid) during
   exactly R4's labelled window, and a stale `timeout` flip would make
   `isSettledForWait` return true mid-retry (O-5 `closed-green`). `tick()`
   already `continue`s on non-`running` (`hub.ts:233`), so a new state leaves
   the battle-tested kill semantics untouched.
8. **The designer's sidecar carrier is dead** (O-3 `closed-red`:
   `readManifests` ingests `job-1.retry.json` and `buildTree` crashes at
   `runs.ts:114`). The carrier is one optional field on the manifest the
   renderers already read.
9. **No `loadRetryConfig` call exists in a render path** (O-8 `closed-green`),
   and a render-time re-read is forbidden (D3). The denominator reaches the
   renderers and the report through the one init-time snapshot (Q1).
10. **EV-29's provider-reported figure is final-attempt-only for a retried
    dispatch** (`usage-store.ts:426` builds the provider job list from
    `findSessionFile(input.repoRoot, runId, m.sessionId)` — one path per
    manifest; principal D4). The `steward` ruling requires that partial figure
    be disclosed machine-readably and durably, never rendered as the
    dispatch's whole figure.

## 2. Settled design

### 2.1 Module map and ownership

| Concern | Owner |
|---|---|
| Lifecycle state machine, `retrying` state, synchronous settle hook, `respawn`, cancel/wait clauses, pid-file discipline | `extensions/hub.ts` (`Hub`) |
| Classification (`classifyRetry`), attempt counter, unref'd backoff timer, `computeBackoffDelay` call, timer arbitration on cancel/dispose | new `extensions/job-retry.ts` |
| Spawn inputs (argv/env/prompt file/MCP allowlist), respawn spec, cleanup closure, policy injection | `extensions/hub-tools.ts` (`council_dispatch`) |
| One init-time `RetryPolicy` snapshot | `extensions/index.ts` |

Both pure functions are reused **verbatim** — no second copy:
`classifyRetry(report)` (`retry.ts:103-123`) and
`computeBackoffDelay(policy, attempt, rand)` (`retry.ts:155-168`). The
EV-40 §2.8 watch item forbids a second delay function, and `classifyRetry`'s
state-independent clause is the settled R1 semantics.

### 2.2 Hub deltas — `extensions/hub.ts`

**`JobState`** gains `"retrying"`:
`"running" | "done" | "failed" | "cancelled" | "stalled" | "timeout" | "retrying"`.

**`Job`** gains five fields (`attemptStartedAt` always set; the rest optional):

```ts
sessionId?: string;        // current attempt's session id; defaults to job.id
attempt?: number;          // current attempt ordinal; undefined ⇒ 1
attemptStartedAt: number;  // per-attempt clock for tick(); == startedAt at n=1
nextAttemptAt?: number;    // set only while state === "retrying"
retry?: RetrySupervisor;   // the settle hook + timer owner for this dispatch
```

`startedAt` is set once at first spawn and **never re-based** (D1). Every
respawn re-bases `attemptStartedAt` and `lastActivityAt`.

**`writeJobManifest`** writes the attempt's real session id and the two
conditional fields, in this order, so a non-retry manifest is byte-identical to
pre-EV-39:

```ts
sessionId: job.sessionId ?? job.id,
state: job.state,
startedAt: job.startedAt,
settledAt: job.exitCode !== null ? Date.now() : null,
exitCode: job.exitCode,
usage: job.usage,
...(job.stopReason !== undefined ? { stopReason: job.stopReason } : {}),
...(job.attempt !== undefined && job.attempt > 1 ? { attempt: job.attempt } : {}),
...(job.nextAttemptAt !== undefined ? { nextAttemptAt: job.nextAttemptAt } : {}),
```

**`spawnJob`** accepts `sessionId?: string` (defaults to `id`) and
`retry?: RetrySupervisor`, stores both on the `Job`, and sets
`attemptStartedAt = Date.now()`. Attempt 1 passes `sessionId: jobId`, so the
manifest is unchanged from today.

**`respawn(id, spec)`** — a new public method used only by the supervisor:

```ts
respawn(id: string, spec: {
  args: string[]; env?: Record<string, string>; cwd: string;
  sessionId: string; timeoutMs: number; stallMs: number;
}): Job | undefined
```

It carries the previous Job's `seat`, `model`, `usage` (**cumulative**),
`startedAt` (stable), `cleanup` and `retry`; sets `attempt = (prev.attempt ?? 1) + 1`,
`state = "running"`, `attemptStartedAt = now`, `lastActivityAt = now`,
`exitCode = null`, `pid = undefined`, `settledAt = undefined`,
`nextAttemptAt = undefined`, `stopReason/errorMessage = undefined`, and resets
`output`/`stderrTail`/`events` for the new attempt; spawns the process exactly
as `spawnJob` does (same stdout/stderr/close/error wiring) and replaces
`jobs.set(id, job)`. Returns `undefined` if the id is unknown. Factoring the
process wiring into one private helper shared by `spawnJob`/`respawn` is
expected; the observable behavior is what the tests pin.

**`settle(job)`** consults the hook first:

```ts
private settle(job: Job) {
  const report = this.report(job);              // captures the real exitCode/state/usage
  if (job.retry?.onSettle(job, report)) {       // synchronous, pre-manifest, pre-onChange
    this.procs.delete(job.id);
    this.writeJobManifest(job);                 // state=retrying, exitCode=null, settledAt=null
    this.writePids();                           // pid===undefined ⇒ attempt pid is omitted
    this.onChange?.();
    return;                                     // cleanup withheld; supervisor holds it
  }
  job.settledAt = Date.now();
  this.procs.delete(job.id);
  job.cleanup?.();
  job.cleanup = undefined;
  this.writeJobManifest(job);
  this.writePids();
  this.onChange?.();
}
```

The supervisor's `onSettle` is what sets `state="retrying"`, `exitCode=null`,
`pid=undefined`, `attempt`, `nextAttemptAt` and arms the timer. The Hub imports
no policy concern.

**`tick()`** — the only change is the clock the timeout branch reads:
`now - job.attemptStartedAt > job.timeoutMs` (was `job.startedAt`). The
`if (job.state !== "running") continue` guard stays first, so `retrying` jobs
are skipped: no stall kill, no timeout flip, no `killGroup` for a dead pid.

**`isSettledForWait`** gains the clause **first**, before the
`timeout`/`exitCode` checks:

```ts
if (job.state === "retrying") return false;
if (job.state === "timeout") return true;
if (job.state === "running") return false;
return job.exitCode !== null;
```

**`cancel(id)`** gains a `retrying` branch before the `exitCode !== null` bail:

```ts
if (job.state === "retrying") {
  job.retry?.dispose();        // clears the timer, runs the once-guarded cleanup
  job.state = "cancelled";
  job.exitCode = 0;            // synthetic settledness for wait (no close event will fire)
  job.nextAttemptAt = undefined;
  this.writeJobManifest(job);
  this.writePids();
  this.onChange?.();
  return true;
}
```

The supervisor's own post-dispose guard (`disposed`) makes the later timer fire
a no-op, so no second spawn ever occurs.

**`writePids`** needs no filter change: during backoff `pid === undefined`, so
`filter(j => j.exitCode === null && j.pid)` correctly omits the job (D2's
"clear `pid` in the same step" path).

**`shutdown()`**: for jobs in state `retrying` (no live pid), call
`job.retry?.dispose()` before the live-pid SIGKILL loop, so pending timers are
cleared and the held cleanup runs. Live-pid handling is unchanged.

**`get(id)`** — add a small public accessor returning `this.jobs.get(id)`, used
by the supervisor's timer fire to re-check state.

### 2.3 The supervisor — new `extensions/job-retry.ts`

A pure-decision module with injected clock/rand; it imports `Hub`, `JobReport`,
`Job`, `RetryPolicy`, `classifyRetry`, `computeBackoffDelay`.

```ts
export interface RetrySupervisorHandle {
  /** Hub settle hook. Returns true when the dispatch stays alive (retrying). */
  onSettle(job: Job, report: JobReport): boolean;
  /** Clears the pending timer and runs the held cleanup exactly once. Idempotent. */
  dispose(): void;
}

export interface RetryAttemptSpec {
  args: string[];
  env: Record<string, string>;
  cwd: string;
  sessionId: string;   // MUST be `${jobId}-attempt${n}`
  timeoutMs: number;
  stallMs: number;
}

export interface RetrySupervisorInput {
  hub: Hub;
  jobId: string;
  policy: RetryPolicy;
  /** Once-guarded real cleanup, shared with the Hub's non-retry settle path. */
  cleanup: () => void;
  /** Builds attempt n's spawn spec (n ≥ 2). Pure. */
  attemptSpec: (n: number) => RetryAttemptSpec;
  setTimer?: (fn: () => void, ms: number) => { cancel(): void; unref?: () => void };
  rand?: () => number;
}

export function createRetrySupervisor(input: RetrySupervisorInput): RetrySupervisorHandle;
```

`onSettle(job, report)`:

1. `const verdict = classifyRetry(report);`
   `const current = job.attempt ?? 1;`
   If `!policy.enabled` or `verdict !== "retry"` or
   `current >= policy.maxAttempts` → return `false` (final settle; the Hub runs
   the cleanup).
2. `const next = current + 1;`
   `const delay = computeBackoffDelay(policy, next, rand);`
3. Set `job.attempt = next`, `job.state = "retrying"`, `job.exitCode = null`,
   `job.pid = undefined`, `job.nextAttemptAt = Date.now() + delay`.
4. Arm the timer for `delay`; keep its handle. Return `true`.

Timer fire:
1. If `disposed` → return.
2. `const job = hub.get(jobId);` if `!job || job.state !== "retrying"` → return
   (disposed or cancelled).
3. `hub.respawn(jobId, attemptSpec(job.attempt!))`.

`dispose()`: set `disposed = true`; cancel the pending timer; call `cleanup()`
(the once-guard makes double disposal a no-op).

Cleanup ownership is exactly: the Hub's **non-retry** settle path runs it; the
supervisor runs it only when the Hub will not (cancel- or shutdown-during-backoff).
A single `once(realCleanup)` closure is shared by both, so it runs exactly once
in every path.

### 2.4 `council_dispatch` wiring — `extensions/hub-tools.ts`

`HubToolOptions` gains `retryPolicy?: () => RetryPolicy | null`.

Inside `council_dispatch` execute, after `jobId`/`dir`/`promptFile` are known:

```ts
const policy = opts.retryPolicy?.() ?? null;
const onceCleanup = once(() => { try { fs.rmSync(tmpDir, { recursive: true, force: true }); } catch {} });
const spawn = {
  id: jobId, seat: seat.name, model: seat.model, command: "pi",
  args: buildChildArgv(seat, params.input, promptFile, mcpToolNames, { sessionDir: dir, sessionId: jobId }),
  cwd: repoRoot, env: childEnv(spawnEnv, runId, jobId),
  timeoutMs: (params.timeout_minutes ?? 15) * 60_000,
  stallMs: (params.stall_minutes ?? 4) * 60_000,
  sessionId: jobId,
  cleanup: onceCleanup,
};
if (policy?.enabled && policy.maxAttempts > 1) {
  spawn.retry = createRetrySupervisor({
    hub, jobId, policy, cleanup: onceCleanup,
    attemptSpec: (n) => {
      const sessionId = `${jobId}-attempt${n}`;
      return {
        args: buildChildArgv(seat, params.input, promptFile, mcpToolNames, { sessionDir: dir, sessionId }),
        env: childEnv(spawnEnv, runId, jobId),
        cwd: repoRoot,
        sessionId,
        timeoutMs: spawn.timeoutMs,
        stallMs: spawn.stallMs,
      };
    },
  });
}
const job = hub.spawnJob(spawn);
```

`once(fn)` is a local helper `(fn) => { let ran = false; return () => { if (ran) return; ran = true; fn(); }; }`.

The retry MCP allowlist is the one resolved at dispatch (principal's blind
spot, accepted); the prompt file is the same tmpdir file across attempts (it is
not deleted until the chain ends).

### 2.5 Run substrate — `extensions/runs.ts`

`RunManifest` gains two optional fields, both conditional on a retry:

```ts
attempt?: number;        // current attempt ordinal; present only when >= 2
nextAttemptAt?: number;  // present only while the dispatch is between attempts
```

No `maxAttempts` field (Q1 ruling). `state` stays `JobState`, so `"retrying"` is
a valid manifest state. `readManifests` is unchanged — one file per dispatch,
so no sidecar and no ingest change.

### 2.6 Renderers

**`extensions/tree.ts` — `textTree`** gains an injected denominator:

```ts
export function textTree(repoRoot: string, runIds: string[], maxAttempts = DEFAULT_RETRY_POLICY.maxAttempts): string[]
```

For each node, when `m.attempt !== undefined && m.attempt > 1`, insert
` attempt ${m.attempt}/${maxAttempts}` between the seat and the state:
`<indent><glyph> <id> <seat> attempt N/M <state> <mins>m pid=<pid>`. When
`attempt` is absent the row is byte-identical to today. `GLYPH["retrying"] = "⏸"`.
`buildTree`'s orphan rule is unchanged (`state === "running"`), so a `retrying`
row is never orphaned.

**`extensions/navigator.ts` — `CouncilTreeWidget`**: add `GLYPH["retrying"] = "⏸"`,
`STATE_ORDER["retrying"] = 0`, `STATE_TOKEN["retrying"] = "warning"`. The
constructor `opts` gains `maxAttempts?: number` (default
`DEFAULT_RETRY_POLICY.maxAttempts`). `rowLine` appends
` attempt ${m.attempt}/${maxAttempts}` to the seat field when
`m.attempt !== undefined && m.attempt > 1` (the pad is applied to the combined
visible seat+label). `settledCopy` gains:

```ts
case "retrying": {
  const secs = m.nextAttemptAt != null ? Math.max(0, Math.ceil((m.nextAttemptAt - now) / 1000)) : 0;
  return { copy: `retrying in ${secs}s`, age: "" };
}
```

No new glyph, no new theme token, no new refresh ticker (the existing 2 s
widget refresh is the countdown tick — Q3).

`registerNavigator` gains a fourth parameter `maxAttempts?: () => number`;
`open`, `toggleWidget`, and the console `textTree` calls pass
`maxAttempts?.() ?? DEFAULT_RETRY_POLICY.maxAttempts` down to `textTree` and
the widget.

### 2.7 Report — `extensions/hub-tools.ts`

**`formatReport(r, attempts?)`** gains an optional second parameter
`attempts?: { n: number; max: number }`. When absent or `n <= 1` the output is
byte-identical to pre-EV-39 (EV-28's byte tests hold). When `n > 1`:

- head fragment appended to the identity prefix: ` attempts=${n}/${max}`,
  immediately after `elapsed=${mins}m`;
- one sentence appended after the `err` clause:

| Condition | Sentence |
|---|---|
| `classifyRetry(r) === "retry" && n === max` | `Retry budget exhausted after ${max} of ${max} attempts; last error: ${r.errorMessage}.` — the `; last error: …` tail is dropped when `errorMessage` is empty |
| `n === max` (terminal settle on the last attempt) | `Settled on attempt ${n} of ${max}.` |
| `r.state === "failed"` (classifier stopped early, terminal) | `Failed on attempt ${n} of ${max}.` |
| otherwise (clean settle before budget) | `Settled on attempt ${n} of ${max}.` |

The exhaustion copy deliberately does **not** mirror EV-40's R5 "Press Enter"
(the hub cannot honor it); the `--- provider error ---` clause already carries
the last error.

**`formatWaitReport(reports, manifests, maxAttempts = DEFAULT_RETRY_POLICY.maxAttempts)`**
looks up each report's manifest by `r.id`, derives `n = m?.attempt ?? 1`, and
calls `formatReport(r, { n, max: maxAttempts })`. Its `settled` set stays
`{done, failed, cancelled, stalled}` — `retrying` gets **no** usage block. The
`council_wait` execute passes
`opts.retryPolicy?.()?.maxAttempts ?? DEFAULT_RETRY_POLICY.maxAttempts`.

Tool descriptions: `council_wait`'s state list gains `retrying`;
`council_dispatch`'s description records that `timeout_minutes`/`stall_minutes`
are **per-attempt** ceilings (a 3-attempt dispatch may run `maxAttempts ×`
the per-attempt budget).

### 2.8 Init-time policy injection — `extensions/index.ts`

The one `loadRetryConfig(repoRoot)` call moves **before** `registerHubTools` and
`registerNavigator`, keeping its existing try/catch (a throw sets
`retryPolicy = null` and records `retryConfigError`; retry is disabled for the
session, never crashing init):

```ts
let retryPolicy: RetryPolicy | null = null;
let retryConfigError: unknown = null;
try { retryPolicy = loadRetryConfig(repoRoot); } catch (e) { retryPolicy = null; retryConfigError = e; }
const retryPolicyGetter = () => retryPolicy;

registerHubTools(pi, repoRoot, { retryPolicy: retryPolicyGetter });
registerNavigator(pi, repoRoot, () => getHub(repoRoot).runId,
  () => retryPolicy?.maxAttempts ?? DEFAULT_RETRY_POLICY.maxAttempts);
```

No other `loadRetryConfig` call is added anywhere. The session-start warning
copy broadens from "parent-turn retry disabled" to name both loops, e.g.
`council: retry disabled for this session — <error>`.

### 2.9 Q4 disclosure — provider sibling + usage block

The dispatch's provider-reported figure is, at EV-39, the final attempt's alone
(`usage-store.ts:426`). Per the `steward` ruling it is disclosed
**machine-readably and durably**, never as a prose-only note.

**Record** (`extensions/provider-cost.ts`):

```ts
export type ProviderPartialReason = "final-attempt-only";
export interface ProviderCostReport {
  status: "reported" | "unavailable";
  reason?: ProviderUnavailableReason;
  partial?: ProviderPartialReason;   // NEW — record-only literal, present iff the figure is partial
  totalCost: number | null;
  generations: ProviderGeneration[];
}
```

**Set at construction** (`extensions/usage-store.ts`, in the
`fetchProviderReport` call site): after the eligible jobs are built, if any
eligible job's manifest has `(m.attempt ?? 1) > 1`, the returned report gets
`partial: "final-attempt-only"` (applied to a copy before `persistInvocationUsage`,
so the persisted provider sibling carries it). This is deterministic and
offline-testable with an injected `fetchGeneration`.

**Render** (`extensions/usage-block.ts`): a conditional legend

```ts
const PARTIAL_LEGEND = "usage  partial = reported figure is final-attempt-only";
```

pushed once iff `input.provider?.partial !== undefined`, after the reported row
and before/instead-of the `n/a` legend. The reported row itself is unchanged, so
the partial figure is always accompanied by the qualifying legend and can never
render as the dispatch's whole figure unqualified. The `n/a` legend's
"present iff a slot rendered `n/a`" conditionality is the same mechanism.

Wholeness — persisting the per-attempt session pointers and summing every
attempt — is EV-42's closing deliverable.

### 2.10 Test fixture — `test/stub-child.ts`

Add `STUB_MODE=flaky` honoring `STUB_STATE=<path>` and `STUB_FAIL_TIMES=<n>`
(default 1): each invocation reads/increments a count in the state file; while
`count <= STUB_FAIL_TIMES` it emits the error assistant (`stopReason error`,
`Provider returned 502: upstream unavailable`) and exits 0; afterwards it emits
`stub result` and exits 0. This supports fail-once-then-succeed (`1`) and
budget exhaustion (`>= maxAttempts`).

### 2.11 Explicit out of scope

- Per-attempt provenance in the run substrate — persisting the attempt-session
  pointers, summing every attempt's provider figure (EV-42). EV-39 does **not**
  absorb it "while we're here" (steward ruling).
- The end-to-end forcing fixture for both retry paths (EV-41).
- The parent-turn retry loop and R5 copy (EV-40), the classifier (EV-37).
- `attemptGroupId` (dropped by the steward ruling).
- Any import-pipeline, server/API, tiles, or database concern — this repo
  defines none.
