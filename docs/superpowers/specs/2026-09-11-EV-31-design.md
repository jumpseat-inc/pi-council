# EV-31 design — durable usage store outside the pruned run directory, with session provenance

- **Card:** `EV-31` (epic `EPIC-7`), `council/cards/EV-31.md`
- **Status:** settled by the step-2–6 deliberation and the step-6
  `product-owner` ruling; this document is the write-up, not a re-derivation.
  Nothing settled in steps 2–6 is reopened here.
- **Binding inputs:** Phase 1 ruling **R-3 (store)** — store home
  `getAgentDir()/council/usage/`, record filename
  `<ISO-basic>_<runId>_<command>.json`, a `README.md` naming the format,
  directory mode `0700`, file mode `0600` — and the **step-6 product-owner
  ruling** appended verbatim to `council/cards/EV-31.md`. Where this document
  and the ruling disagree, the ruling wins.
- **Scope:** the durable store module, the provenance pointer and its
  never-throwing read-back, the write trigger/choose-once wiring, the README
  and modes, and the tests that hold them. Not exit-point rendering (EV-32),
  not provider-reported cost (EV-29), not store recompute, not retention.

## 1. Problem

`runs/` is ephemeral telemetry — self-gitignored (`runs.ts:88`) and pruned to
the last 15 runs at every parent `session_start` (`runs.ts:165-175`). EV-30
computes an invocation-scoped `SpendRecord` at exit but persists nothing, so
the record is lost the moment the run dir is pruned. EV-31 writes one durable
record per completed invocation into `getAgentDir()/council/usage/` — outside
the pruned directory — carrying EV-30's record verbatim plus a provenance
pointer (session JSONL path + entry range) whose read-back resolves to a
stated outcome.

The runner case is the motivating durability class, not an edge case: seat
children (including a council-runner's own session) are spawned with
`sessionDir: dir` where `dir = ensureRunDir(repoRoot, runId)`
(`hub-tools.ts:184-185`, `dispatch.ts:108`, `seats.ts:517`), so their session
JSONLs live *inside* the dir `pruneRuns` deletes. Read-back must therefore
distinguish absence-by-design from absence-by-defect, and must never throw.

## 2. Settled design

### 2.1 Module and store home

New module **`extensions/usage-store.ts`** — the I/O sibling of the pure
`extensions/spend.ts`, following the `extensions/mcp/auth-store.ts` pattern:
a `getAgentDir()`-derived default path as a default parameter, atomic
temp-file + rename, explicit `chmod`. It imports types from `./spend.ts` and
`./runs.ts`; it rewrites neither.

- **Root:** `usageStoreDir()` = `path.join(getAgentDir(), "council", "usage")`.
- **Injection (both seams, not either):** every exported entry point takes
  `storeRoot: string = usageStoreDir()` (parameter-with-default, so tests can
  drive the real code path with an explicit root), **and** the acceptance test
  isolates via `PI_CODING_AGENT_DIR` (read at call time — `oauth.test.ts:20-21`
  precedent), because only the env leg lets a test assert that the real default
  path was never written. No test may write into `~/.pi/agent/`.
- **Modes (R-3, literal):** directory `0700` (`mkdirSync(dir, {recursive:true})`
  plus an explicit `chmodSync` so the mode holds regardless of umask); record
  files `0600`; `README.md` `0600`.

### 2.2 Filename (R-3, byte-exact)

`<ISO-basic>_<runId>_<command>.json`.

- `<ISO-basic>` is rendered from the **marker's `at`** (`recordInvocationBoundary`
  stamps `at: Date.now()`, `spend.ts:261`) as `YYYYMMDDThhmmssSSS` — no
  separators, no trailing `Z`, milliseconds kept (they are the same-millisecond
  collision margin). **The prefix is the invocation's time, not the write
  time.** The record body's `writtenAt` carries write-time honesty and the
  README states the distinction.
- `runId` is already filename-safe (`mintRunId`); command names are `[a-z-]`.
- A helper `usageRecordName(markerAtMs, runId, command)` is exported so the
  grammar is asserted once, byte-exact.

### 2.3 Record shape (wraps the EV-30 record; adds nothing to it)

```ts
export const USAGE_RECORD_SCHEMA_VERSION = 1;

export type UsageTrigger = "forest-settle" | "agent-settled" | "session-shutdown";

export interface UsageProvenance {
  sessionId: string;
  sessionPath: string | null;      // absolute; null = unresolvable at write (never fabricated)
  firstEntryId: string | null;     // mirrors SpendBoundary
  lastEntryId: string | null;      // mirrors SpendBoundary
  boundaryResolved: boolean;       // mirrors SpendBoundary.resolved
  pointerSurvivable: boolean;      // write-time fact (ruling item 1 semantics)
}

export interface StoredUsageRecord {
  schemaVersion: number;           // USAGE_RECORD_SCHEMA_VERSION; records are self-describing
  spend: SpendRecord;              // EV-30's record, byte-verbatim
  provenance: UsageProvenance;
  runId: string;
  command: string;
  repoRoot: string;
  writtenAt: string;               // ISO-8601 write clock (invocation time lives on the key)
  basis: { trigger: UsageTrigger; manifestsObserved: number };
}
```

- **`spend` is EV-30's record byte-verbatim.** `SpendRecord` in
  `extensions/spend.ts` gains no field, loses none, and is not renamed. No
  `total` is introduced (EV-30 step-6 ruling item 2).
- **No resolution outcome is stored.** The read-time outcome is *derived*
  (§2.5) because a stored `resolvable`/outcome goes stale the moment the
  session file is pruned after the write (EV-30's rejected option 2a is the
  same argument one layer over). What is stored is the write-time fact the
  store can actually know: `pointerSurvivable`.
- `basis.trigger` / `basis.manifestsObserved` carry the write-time basis; there
  is **no recompute** (§2.4).

### 2.4 Write trigger and choose-once

- **Key = the marker's `at`**, not wall-clock. Choose-once is therefore
  *structural and durable*: the same invocation mints the same filename, the
  write is refused if that file exists (byte-identical no-op), and the property
  survives a process restart (an in-memory choose-once set does not — the
  resumed-session case mints a phantom duplicate). Marker durability is
  EV-30's: the `council-invocation` marker is a `custom` session entry
  (`spend.ts:255-274`), on-chain, recovered at exit by
  `findLatestInvocationMarker` when the in-memory id is gone.
- **No marker ⇒ no write.** EV-30's `recordInvocationBoundary` returns `null`
  fail-closed (stale/replaced session) and seats never stamp at all; a marker
  is the precondition for the invocation identity the key is built from. Never
  fabricate a marker time.
- **The gate decides, not the event (settles open objection O1c).** Hub
  `onChange` fires mid-turn (`hub.ts:163`, `:246`, `:258`) and `agent_settled`
  fires once per prompt-run, awaited before idle/teardown; neither event alone
  is invocation completion. The write runs on one **gated path** from three
  triggers — hub `onChange`, `agent_settled`, and the `session_shutdown` sweep
  — and the gate is:

  ```
  marker is on-chain (findLatestInvocationMarker)
    && forestFullySettled(marker)          // every manifest with startedAt >= marker.at has exitCode !== null
    && no file exists for this key
  ```

  The first trigger at which the gate holds writes exactly once, stamping
  `basis.trigger` with the trigger that fired. This is the owner's round-2
  composite stated as a single gated path: no write while the forest is
  unsettled (so a mid-turn `onChange` or an early `agent_settled` is a no-op),
  and exactly one write when it settles, with `session_shutdown` as the
  backstop. Its two settling tests are §4 T-U13 (seam order) and the
  `lastEntryId === leafId` oracle — `spendRecord` sets `boundary.lastEntryId`
  from `leafId` at compute time.
- **Never recompute, never overwrite.** The record is computed at the moment of
  the write and is thereafter immutable on disk. A second persist for an
  existing key returns the existing record unchanged.

### 2.5 Provenance and read-back (ruling item 1, byte-exact)

**Write-time facts:**

- `sessionPath = ctx.sessionManager.getSessionFile() ?? null` — public on
  `ReadonlySessionManager`, `undefined` for an in-memory session. Never
  fabricated, never guessed via `findSessionFile`.
- `sessionId = ctx.sessionManager.getSessionId()` — the **invoking** session,
  never a child job id.
- `firstEntryId` / `lastEntryId` / `boundaryResolved` mirror
  `spend.boundary` (all `null`/`false` on an unresolved boundary).
- `pointerSurvivable` (the ruling's operative semantics — see the ruling note
  in the card):

  ```ts
  pointerSurvivable =
    sessionPath !== null &&
    path.relative(runsDir(repoRoot), sessionPath).startsWith("..");
  ```

  i.e. `true` iff the session file was *outside* the pruned run dir at write
  time. The `sessionPath === null` case is caught by the mapping's first rule
  before `pointerSurvivable` is consulted.

**Read-time outcome — a never-throwing pure function:**

```ts
export type ResolveOutcome =
  | "resolved" | "pruned-expected" | "missing-unexpected" | "no-session-file" | "range-missing";

export function resolveProvenance(
  pointer: UsageProvenance,
  readEntryIds?: (sessionPath: string) => string[] | null,  // default: parse the JSONL via pi's parseSessionEntries
): ResolveOutcome;
```

Mapping, in order (the ruling's own table):

| condition | outcome |
|---|---|
| `sessionPath === null` | `no-session-file` |
| file present, both `firstEntryId` and `lastEntryId` are among the file's entry ids | `resolved` |
| file absent, `pointerSurvivable === false` | `pruned-expected` |
| file absent, `pointerSurvivable === true` | `missing-unexpected` |
| file present, one or both ids absent | `range-missing` |

- **Never throws.** A missing, unreadable, or unparseable session file is
  treated as *absent* for this mapping (the pointer cannot be resolved against
  it); the outcome is then one of the two survivability classes. `null`
  `firstEntryId`/`lastEntryId` with a file present is `range-missing`.
- Entry ids are stable under append and compaction (append-only JSONL;
  `appendCompaction` re-parents, never rewrites), so a session file that grows
  after the write still resolves.
- `readUsageRecords(storeRoot)` reads every `*.json` in the store, skips
  unparseable/partial files (the `readManifests` precedent), and returns them
  sorted by filename (chronological by the invocation-time prefix).

### 2.6 README

Written **non-clobberingly at first use** (a second persist does not rewrite
it; `scaffoldInto`'s never-overwrite spirit). Content requirements, in this
shelf order:

1. Names the directory in product voice ("council usage") and states the
   **empty state** ("first invocation pending") in its first paragraph.
2. States the filename grammar, including that the timestamp prefix is the
   **invocation** time, not the write time.
3. Surfaces the accounting asymmetry within the first 20 lines:
   `ownSession` is `session-reconciled`, `subtree` is `stream-assistant` — a
   **lower bound** over the manifest stream, not a reconciliation.
4. Teaches the provenance pointer's chain of custody and the **five
   `ResolveOutcome` values**, on the same shelf as the empty-state sentence —
   `pruned-expected` vs `missing-unexpected` is the distinction the store
   exists to make.
5. States the **unwritable behaviour**: a failed write surfaces the absolute
   target path (the literal wording is EV-32's; the path is not).
6. A closing "what this is **not**" paragraph (not the run transcripts, not the
   MCP secrets, not a transcript log).

Source: a template-literal constant **exported from the module** (asserted via
the exported constant), not a `PKG_ROOT` shipped asset — a new resource
mechanism the conventions caution against. Mode `0600` (R-3).

### 2.7 Write failure, notify presence (call site only)

- A write failure (e.g. `EACCES` on the store dir) is caught **per record**: it
  never crashes the session or teardown, never overwrites, and never silently
  drops the invocation. The failure line names the **absolute target path**.
- **Success:** exactly one `ctx.ui.notify` line per invocation (on the first
  successful write), naming the command, runId, and the record file.
- **Failure:** ≥1 `ctx.ui.notify` line on `EACCES` containing the absolute
  target path.
- **Wording of both lines is EV-32's** (ruling item 2; `smoke-test`'s ruled-copy
  precedent). EV-31 owns only the call site and these test-settleable presence
  properties, asserted with a stubbed `ctx.ui.notify`.

### 2.8 The store's answer to the EV-30 store-side handoff

- **A seat session already pruned at write time:** the record's `spend` half is
  already degraded by EV-30 (`readManifests` → `[]` ⇒ zero subtree,
  `manifestsObserved: 0`) and EV-31 persists it **unchanged, never recomputed**,
  stamping `basis` so a reader sees the moment and its horizon. The provenance
  pointer takes the ruling's mapping: `sessionPath` under the run dir ⇒
  `pointerSurvivable: false` ⇒ a later read reports `pruned-expected`, not a
  defect. The README states this class explicitly.
- **A write with no resolvable invoking-session JSONL** (in-memory ctx, or
  `getSessionFile() === undefined`): write anyway with `sessionPath: null`,
  outcome `no-session-file`. Never fabricate a path, never skip silently —
  EV-30's fail-closed applies to *values*, not to the existence of the
  invocation's record.
- **An unresolved boundary** (`spend.boundary.resolved === false`): persist the
  zero-both-halves record unchanged with `boundaryResolved: false`; the
  store carries EV-30's ruling into durability rather than inventing a boundary.

## 4. Test plan (owner meets a failing test first)

Every test roots its store under a fresh `fs.mkdtempSync` dir (explicit
`storeRoot`, or `PI_CODING_AGENT_DIR` set to one); no test writes to
`~/.pi/agent/`. Fixture sessions are real JSONL parsed with pi's exported
`parseSessionEntries`; manifests via `writeManifest`/`readManifests`.

1. **T-U1 — acceptance, end to end.** Real session JSONL in a tmp session dir
   *outside* the run dir + manifests in a tmp repo run dir → persist → `fs.rmSync`
   the run dir → `readUsageRecords` returns the record → `resolveProvenance` is
   `resolved` with both ids found. Fails any design that stores provenance into
   the run dir.
2. **T-U2 —** `pruneRuns(repoRoot, 0)` leaves the record byte-identical
   (`runs.ts:165` operates under `runsDir`; `getAgentDir()` is elsewhere).
3. **T-U3 — modes:** dir `0700`, record file `0600`, `README.md` `0600`.
4. **T-U4 — README:** present, names the format, contains the asymmetry
   (`lower bound` / `usageSource`) and the five outcome names, and is
   **unchanged** (mtime and bytes) after a second persist.
5. **T-U5 — filename byte-exact** against R-3's pattern, with ms-precision
   ISO-basic derived from the marker `at` (not `Date.now()`).
6. **T-U6 — no session file:** `sessionPath: null` → record written,
   `pointerSurvivable: false`, outcome `no-session-file`, no path fabricated.
7. **T-U7 — unresolved boundary:** zero both halves, `boundaryResolved: false`,
   persisted.
8. **T-U8 — run dir removed before the write:** record persisted with exit-time
   (zero) subtree, `basis.manifestsObserved: 0`, and the pointer class stated.
9. **T-U9 — choose-once across a simulated restart:** same marker, two persists
   with fresh module state and a different `now` → exactly one file, second call
   byte-identical. (Red for any wall-clock/monotonic key — Skeptic O2.)
10. **T-U10 — runner-shaped dangle (the class that motivates durability):**
    session file under `runDir`, persist, `pruneRuns(repoRoot, 0)` →
    `fs.existsSync(sessionPath) === false`; read-back returns the record with
    `resolveProvenance === "pruned-expected"`; **it does not throw**. Contrast
    the parent case (outside `runDir`): `resolved`.
11. **T-U11 — `missing-unexpected`:** parent-case pointer, delete the session
    file (not the run dir), re-read → `missing-unexpected`; the stored JSON
    bytes are unchanged from a pre-deletion snapshot (the outcome is derived,
    never stored — Skeptic T-D4).
12. **T-U12 — `range-missing`:** file present, one or both ids absent →
    `range-missing`, no throw.
13. **T-U13 — seam order (O1c):** a fake hub/agent loop where the settle trigger
    fires while one child job is still running → **no** record; when the last
    child's manifest completes → exactly one record; a second settle →
    byte-identical no-op. The record's `boundary.lastEntryId` equals the
    session's leaf id at invocation end.
14. **T-U14 — notify presence:** stubbed `ctx.ui.notify` — exactly one call on
    success; ≥1 call on `EACCES` whose text contains the absolute store path.
    (Wording not asserted — EV-32's.)
15. **T-U15 — EV-30 record purity:** the persisted `spend` `toEqual`s the
    in-memory `SpendRecord`, and `SpendRecord` gained no field
    (`!("schemaVersion" in spend)`, no `provenance` on it).
16. **T-U16 — env seam:** no explicit root, `PI_CODING_AGENT_DIR` = mkdtemp →
    the record lands at `<tmp>/council/usage/` **and** nothing was created at
    the default `getAgentDir()/council/usage`.
