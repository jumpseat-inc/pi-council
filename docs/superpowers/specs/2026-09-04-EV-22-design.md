# EV-22 Design — Resolve enabled providers and models for the picker from pi's registry

Date: 2026-09-04. Card: `EV-22`. Epic: `EPIC-5`. This is the settled design
written up from the Council deliberation (rounds 1–2, Skeptic, consolidator)
plus the two orchestrator-secured rulings J-1 and J-2. The deliberation
already played `brainstorming`; this file records its result. Do not reopen
anything settled below.

## 1. Purpose

EV-22 owns the catalogue side of the data-to-UI seam for the `/council-models`
picker. It turns pi's flat model registry (with optional `refresh()`) into a
provider-grouped, ordered catalogue of pickable model entries, and it exposes
each seat's current override state. Dispatch later validates against the same
`getAvailable()` set, so listing from it guarantees a picked model is accepted
by dispatch.

EV-22 ships a **pure resolver only** with **no live caller**. The fetch
(`await refresh()` then `getAvailable()`) happens once in the EV-25 handler;
the same flat catalogue array is passed to EV-22's resolver (here) and to
EV-24's writer-validation. No async wrapper ships in this card.

## 2. Rulings that bind this design (applied; do not re-argue)

- **J-1 ordering**: sort providers by `provider` id ascending, and models by
  `id` ascending. Tiebreaks are unnecessary (both keys are unique per
  namespace per the settled registry contract). No label-based sort key.
- **J-2 signature**: `resolveCatalogue(models, providerDisplayName, rawSeats,
  overrideMap)` — four flat-data arguments, nothing else. No `repoRoot`, no
  `source`, no filesystem, no network inside the resolver.

## 3. File

New module: `extensions/catalogue.ts`. It imports only:
- `type Seat` / `type AgentOverride` from `./seats.ts` (type-only — no runtime
  I/O pulled in, `applySeatOverride` is pure),
- `getSupportedThinkingLevels` from `@earendil-works/pi-ai/compat`.

The module must perform **no raw provider HTTP** (acceptance 2):
`grep -nE 'fetch|http|axios|https|undici|node:http' extensions/catalogue.ts`
must return nothing.

## 4. Types

```ts
/* The plain-data view of one registry Model that the resolver reads. The
   output of ctx.modelRegistry.getAvailable() is structurally assignable to
   this. */
interface CatalogueModel {
  provider: string;
  id: string;
  name?: string;                 // display label; falls back to id
  reasoning: boolean;
  thinkingLevelMap?: Record<string, string | null>;
}

interface ModelEntry {
  qualifiedId: string;           // `${provider}/${id}` — the selection/write key
  id: string;
  name: string;                  // model.name ?? model.id
  reasoning: boolean;            // passthrough; NOT consumer-contract — supportedThinkingLevels is the sole capability authority
  supportedThinkingLevels: string[];
}

interface ProviderGroup {
  provider: string;
  displayName: string;           // passthrough of providerDisplayName[provider] ?? provider
  models: ModelEntry[];
}

interface SeatState {
  name: string;
  hasOverride: boolean;
  currentModel: string;          // always the qualified provider/id
  currentThinking?: string;      // present only when a level resolves
}

interface ResolverResult {
  providers: ProviderGroup[];
  seats: SeatState[];
}
```

## 5. `resolveCatalogue` — behaviour

```ts
function resolveCatalogue(
  models: CatalogueModel[],
  providerDisplayName: Record<string, string>,
  rawSeats: Seat[],
  overrideMap: Record<string, AgentOverride>,
): ResolverResult
```

Steps, in order:

1. **Group**: bucket `models` by `provider`. If `providerDisplayName` has no
   entry for a provider, `displayName` falls back to the provider id
   (`providerDisplayName[provider] ?? provider` — the resolver never derives
   display names; it passes through what the caller supplies, O-7).
2. **Model entries**: for each model, `qualifiedId = \`${provider}/${id}\``;
   `name = model.name ?? model.id`; `reasoning = model.reasoning`;
   `supportedThinkingLevels = getSupportedThinkingLevels(<view of this model
   carrying exactly `reasoning` and `thinkingLevelMap`>)` imported from
   `@earendil-works/pi-ai/compat` (a cast as needed — `getAvailable()` output
   and plain test literals are structurally compatible with pi's `Model`).
   `supportedThinkingLevels` is populated **only** by pi's function; never
   synthesize a level list by hand and never add a "keys of thinkingLevelMap"
   fallback.
3. **Order** (J-1): providers sorted by `provider` id ascending; models within
   each group sorted by `id` ascending. This makes EV-23's rendering
   byte-consistent with pi's own `/models` picker ordering.
4. **Seats**: preserve `rawSeats` input order (the caller supplies them in
   `listSeatNames` order, which is already sorted). For each:
   - `hasOverride = overrideMap.has(seat.name)` — **key presence**, not
     effective-value divergence. An `{ "owner": {} }` entry counts as an
     override (`hasOverride === true`). An absent `.council.json` produces an
     empty `overrideMap`, so every seat has `hasOverride === false`.
   - `const effective = applySeatOverride(seat, overrideMap)` (pure; honors
     `thinking` key > `:suffix` on model > frontmatter, model and thinking
     independently). `currentModel = effective.model` (already a qualified
     `provider/id`); `currentThinking = effective.thinkingLevel` (may be
     `undefined`; omit the field then).
   - Empty-catalogue edge (no models at all) yields `providers: []` with **no
     throw**. A provider id present in `providerDisplayName` but absent from
     the model list yields **no** `ProviderGroup` for it.

## 6. Acceptance-test contract (unit test, plain data)

A new `test/catalogue.test.ts` calls `resolveCatalogue` with **plain
literals** — four arrays/maps of plain data. No registry stub object, no temp
directory, no filesystem, no network.

Assertions the test must make:

- **Grouping**: models grouped by provider; `displayName` = stubbed
  `providerDisplayName` value passes through verbatim (O-7); a provider id in
  the display map but absent from `models` produces **no** group; empty
  `models` input produces `providers: []` (no throw).
- **Ordering (J-1)**: providers appear in `provider` id ascending; models in
  each group in `id` ascending (O-3). Re-running twice is deep-equal.
- **Thinking-level extraction** (parity with pi's documented contract, O-7):
  - `reasoning: false` model → `["off"]` (never `[]`).
  - `reasoning: true`, missing `thinkingLevelMap` → `["off","minimal","low","medium","high"]` (no `xhigh`/`max`).
  - `deepseek-v4-pro`-style holes → includes `off..high`, excludes `xhigh`/`max`.
  - always-thinking model with `off: null` → excludes `off`.
- **qualifiedId round-trip**: every `qualifiedId` equals `` `${provider}/${id}` `` and belongs to the modelled `getAvailable()` set (construct the set from the same `models` fixture); the reverse (no `qualifiedId` outside the source set) holds by construction of grouping.
- **Per-seat current state**: fixture seat frontmatter `openrouter/a/fm:medium` with no `overrideMap` entry → `hasOverride === false`, `currentModel === "openrouter/a/fm"`, `currentThinking === "medium"`. With `overrideMap = { owner: { model: "openrouter/b/m:high", thinking: "low" } }` → `hasOverride === true`, `currentModel === "openrouter/b/m"`, `currentThinking === "low"` (explicit `thinking` beats the `:high` suffix). With `overrideMap = { owner: {} }` → `hasOverride === true`, `currentModel`/`currentThinking` equal the frontmatter values. Model-only override keeps frontmatter thinking and vice versa (independent resolution).
- **Seat order** preserved from `rawSeats` as passed.
