# EV-8 — Bidirectional arrow-key focus navigation between the input bar and the inline tree

**Card:** EV-8 (EPIC-2) · **Facilitator record:** this is a write-up of a
settled Council deliberation (steps 2–6 done), including a binding
product-owner ruling on the three open-judgment items. It does not derive a
fresh design and does not reopen anything the Council closed. The owner
reads only this file plus the card's `Intent`/`goal`.

Deliberation record: `council/cards/EV-8.md` (Rounds 1–2, Skeptic O1–O7,
consolidator synthesis, and the step-6 product-owner ruling appended
verbatim).

## Scope (settled)

While the EV-7 inline tree panel is visible, pressing **Down** from the
focused input bar moves keyboard focus into the tree (selection = row 0);
**Up/Down** move the highlighted selection across rows; pressing **Up** on
the topmost row (or **Escape**, or **Down** on the last row) returns focus
to the input bar. The below-editor inline tree panel stays **render-only /
passive**: it renders the selected-row highlight driven by a shared
controller; it never owns the TUI's real focus pointer and never receives
keys from the TUI runtime.

## Binding ruling (product-owner, on record — do not reopen)

- **OJ-1 (delivery model): editor-driven.** A `CustomEditor` subclass via
  `setEditorComponent` — **composing over `getEditorComponent()`** (per
  Skeptic O4) — is the **sole** delivery point for tree-focus keys.
  `controller.surface` is the **only** arbiter of tree focus. **No
  `setFocus(widget)`, no `onTerminalInput`.** The editor stays the TUI's
  always-focused component; "tree focus" is `controller.surface` state.
  While `surface === "tree"`, the override **consumes only
  Up/Down/Enter/Escape** and **calls `super.handleInput(data)` for
  everything else** (Ruling 2) — forward-unhandled.
- **OJ-2 (swallow-vs-forward)** — **forward-unhandled.** Never swallow
  unhandled keys. `ctrl+c`, `ctrl+d`, printables, PageUp/PageDown,
  Home/End, Backspace, Tab all go to `super.handleInput` while
  `surface === "tree"`.
- **OJ-3 (taste set)** — mode label **`-- TREE --`** (vim convention,
  hard rule); **no new keymap mechanism** (mooted — EV-7 hint line + EV-8
  mode label is the affordance set; forward-unhandled makes an overlay
  unnecessary); **j/k aliasing defaults to NO** (revisitable by designer);
  **▌ glyph U+258C** (hard rule).

No steward escalation was required.

## Settled design

### Vehicle

- **A `CustomEditor` subclass** registered as the session's editor via
  `setEditorComponent(...)`. It must **compose over any existing editor**:
  set `super` to the value of `getEditorComponent()` at construction (the
  global slot is last-writer-wins and holds a single factory; a subclass
  that replaces instead of composes clobbers other editor-wrapping
  extensions — O4). If `getEditorComponent()` returns an existing editor,
  compose over it; otherwise compose over the default editor pi supplies.
- The subclass overrides `handleInput(data)`. Override bodies never call
  TUI focus mutation on the widget. The below-editor EV-7 tree widget is
  **not** a `Focusable` and is never added to the focus chain; it remains
  render/selection-only.
- `controller.surface` (`"editor" | "tree"`) is the **sole** arbiter of
  tree focus — no `widget.focused`-derived state, no parallel boolean
  read from TUI focus pointer (the TUI's focused component is always the
  editor).

### Entry (Down-from-editor)

On `Key.down` while `surface === "editor"` and the tree is open:
- **Multi-line rule (O5, settled):** enter the tree only when the cursor
  is on the **last logical line**: `getCursor().line >= getLines().length - 1`.
  A single-line draft is always on the last logical line, so the rule
  covers single- and multi-line drafts with one predicate.
  - `isOnLastVisualLine`/`isOnFirstVisualLine` are **private** in pi —
    do not use them; the logical-line predicate is public and is the
    settling test. The wrap-edge (wrapped lines past the last logical
    line) is a documented, accepted trade-off; record the exact visual
    predicate as an upstream request (follow-up card at step 13).
- If the predicate holds and the tree is open: set `surface = "tree"`,
  set the selected row to Row 0 (or preserve the current `sessionId`-keyed
  selection if one exists — see Selection below), **consume** that Down
  (do NOT call `super.handleInput` for it), and `requestRender()`.
- Otherwise: `super.handleInput(data)` (normal editor behavior).

### Tree-focus routing while `surface === "tree"`

While `surface === "tree"`, `handleInput(data)` routes:
- **Up:** move the highlighted selection to the previous row (`row-1`).
  On **row 0**, return focus to the editor: set `surface = "editor"`,
  consume that Up, `requestRender()`, and (per the multi-line rule's
  sibling) return the caret to the input bar; the subsequent Up is then
  normal editor Up (move to line start / history).
- **Down:** move the selection to the next row (`row+1`), clamped at the
  last row (no wrap). On the **last row**, return focus to the editor:
  set `surface = "editor"`, consume that Down, `requestRender()`.
- **Enter:** keep the selection where it is and activate the row's
  existing action (open the row's transcript / navigate per the tree's
  established Enter behavior). On EV-8's scope, Enter invokes the
  existing row action; focus handling after that action is whatever the
  action itself establishes — do not change it here. (The card's
  observable contract is Up/Down/up-on-top focus return, not Enter.)
- **Escape:** return focus to the editor immediately: set
  `surface = "editor"`, `requestRender()`; caret unchanged.
- **Every other key** (printables, ctrl+c, ctrl+d, PageUp, PageDown,
  Home, End, Backspace, Tab): **call `super.handleInput(data)`** —
  forward-unhandled. This delivers the key to the (always-focused) editor,
  where it inserts / runs as a normal editor action. The mode label stays
  `-- TREE --` throughout (the signifier does not flip mid-flow).

### Shared controller

A controller component holds the mutable state that both sides read:
- `surface: "editor" | "tree"`
- `selectedSessionId: string | null` — the selected row **keyed by
  `sessionId`, never by index** (O6; the tree sorts running-first and
  re-sorts on its 2s refresh, so an index would slide under the user).
- `selectedIndex: number` (derived or cached for render; must be
  recomputed against the current sorted/capped view from
  `selectedSessionId`).
- May also hold the `open` flag the EV-7 widget already tracks, and any
  tree-row list the routing needs to map selection to `sessionId`.

The widget's `render()` reads `controller.surface` + `selectedSessionId` to
draw the selected-row highlight and the mode label. EV-7 previously added
no selection/highlight to the widget; EV-8 extends it.

### Selection survives refresh (O6)

Because the tree re-sorts running-first on its 2s refresh, the highlighted
row must be pinned to the **session**, not the visual row: store and update
`selectedSessionId`, and on each state change / render resolve that id to
its current row in the freshly-sorted list. A test must demonstrate the
highlighted session does not slide under a re-sort.

### Affordances (designer, settled)

- **Mode label `-- TREE --`** on the editor's bottom border, where the vim
  mode indicator goes — the editor's own border. It reads
  `controller.surface` (single source of truth). When
  `surface === "editor"`, the label shows the normal/insert indicator
  (NOT render). When `surface === "tree"`, it shows `-- TREE --`.
- **`▌` marker (U+258C)** prefixed to the highlighted row in the panel —
  the selected-row signifier. Single cell, never pushes a row past
  `MAX_WIDGET_LINES = 10`.
- **No new keymap mechanism / footer / overlay.** Discovery of the handled
  set is via EV-7's existing hint line + EV-8's mode label. Do NOT add a
  `?`-help header, footer row, or first-idle overlay.
- **No j/k aliasing** (defaults to no). Revisit only as a designer-led
  taste change, and never as part of this card.
- **Token-only** (AGENTS.md 9.6 + EV-4 settled): mode label and ▌ use
  existing theme tokens (`theme.fg`/`theme.bold`/`accent` etc.), no
  inline ANSI/hex.
- **▌ is a single cell** (one column even at narrow widths), no →/↓ direction connotation; reads as the selected-row signifier.

### Lifecycle / teardown

- On tree **open** (existing `/council-tree` toggle / `setWidget` path):
  register the CustomEditor subclass (composing per O4) if not already
  registered; initialize `controller.surface = "editor"`,
  `selectedSessionId = null`.
- On tree **close** / `setWidget("council-tree", undefined)` /
  `session_shutdown`: set `surface = "editor"`, clear any selection;
  unregister-trace any extension UI the subclass added (parity with the
  EV-7 teardown contract). If the CustomEditor subclass is no longer
  needed, restore the composed-over editor.
- **Close-with-focus** — if the tree closes while `surface === "tree"`
  (toggle, O3 dialog, reload), the controller must reset `surface =
  "editor"` on the same path that closes the widget, so the "tree" state
  never leaks past the widget's lifetime.

## Testable claims / acceptance mapping (what step 9 must close)

- **T1 (delivery pin / O1):** a fake TUI whose `focusedComponent` is the
  editor: while `surface === "editor"`, pressing Down on the last logical
  line routes into the tree (sets `surface = "tree"`, selects row 0);
  and key never reaches `widget.handleInput` (the widget is passive;
  0 calls).
- **T2 (multi-line gate, O5):** `shouldEnterTreeOnDown` predicate —
  single-line → true; 3-line draft line-0 → false; last-line → true;
  wrapped visual line past last logical line → false (documented edge).
- **T3 (state machine):** surface starts editor; `enter()` → tree row 0;
  down 0 → 1; down-at-last stays (no wrap); up-on-row0 → editor +
  reset selection; Escape → editor any row; down-on-last-row → editor.
- **T4 (forward-unhandled, OJ-2):** while `surface === "tree"`, a
  printable `"x"`, `ctrl+c`, and `Home`/`End` each reach
  `super.handleInput(data)` (forwarded) and do **not** mutate the mode
  label, and a stray letter lands safely in the editor buffer for the
  user to drop/recover.
- **T5 (O6, sessionId-keyed):** simulate a row set whose sorted order
  changes between ticks; the highlight follows the same `sessionId`, not a
  stale row index.
- **T6 (O4, composition):** register a prior editor via
  `getEditorComponent()`, then register EV-8's subclass; assert EV-8
  composes over the prior one (no clobber) and the prior editor's own
  `handleInput`/behavior still runs for the keys it handles.
- **T7 (teardown):** close `setWidget`-tree while `surface === "tree"`
  → controller resets to editor; post-close Down behaves as editor Down;
  the UI never shows `-- TREE --` when the tree is closed.
- **T8 (render):** the ▌ marker appears on the highlighted row only
  when `surface === "tree"`; no row overflows `MAX_WIDGET_LINES`.

Acceptance (from card): Interactive walkthrough (Down enters tree; Up/Down
cycles; Up on top row returns caret to input bar; typing lands in editor);
selected row visually distinct + unambiguous focus ownership; automated
component tests cover the Down/Up/Exit state machine; `bun test` +
`bunx tsc --noEmit` pass; repo gates (`python3 council/validate.py`)
clean.
