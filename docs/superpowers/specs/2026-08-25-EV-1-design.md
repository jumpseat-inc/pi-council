## Scope

Ship a theme pair for dark and light terminals in the pi-council package that
resolves through pi's theme loader with colors matching oh-my-pi's
`dark.json` / `light.json` (pinned SHA `eab72e88e447a4be45bea2bc302995844c0c51a2`).
This card covers only the shipped asset and its tests. Configuration
(`.council.json` theme section), activation, and compliance are EV-2 / EV-3 /
EV-4. Hot-reload machinery is explicitly out of scope — package-shipped
themes are immutable install data; pi's watcher only watches
`getCustomThemesDir()` and package themes are never file-watched. The
recolor surface is `.council.json` (EV-2); live repaint is EV-4.

## File shape contract

Each shipped file is a strict pi theme JSON. **No comments are possible** —
strict `JSON.parse` and schema `additionalProperties: false` reject them; the
"do not edit" notice lives in the README.

- **`name` field = filename = `pi-council-dark` / `pi-council-light`.** This
  is a correctness requirement, not a nicety: pi's registration, dedupe, and
  lookup all key off the JSON `name` field. A `name: "dark"` would collide
  with pi's built-in in `dedupeThemes` and silently resolve the wrong palette
  through `loadThemeJson` (builtins are checked before registered themes).
  The name must contain no `/`.
- **`$schema`** points at pi's theme-schema URL (not omp's).
- **51 color keys** per file — omp's live tokens, dead keys stripped:
  `link` (dark-only stale alias), `pythonMode` (both), `statusLine*` ×14
  (both). These carry zero 256-index integers; integers appear only in the
  dead `statusLine*` set, so the shipped files contain no 256-index values.
- **The 4 optional tokens are OMITTED** (`scrollbarThumb`, `searchMatchBg`,
  `searchMatchText`, `thinkingMax`). `withThemeColorFallbacks` fills them at
  construction from their fallback sources (`selectedBg`, `selectedBg`,
  `text`, `thinkingXhigh`), which happens before var resolution. Including
  them as var-refs in the file throws `Variable reference not found` at load
  (e.g. `"searchMatchText": "text"` — `text` is not a var). File = 51 keys;
  resolved = 55 keys. These are not in conflict.
- **Var-refs preserved verbatim with omp's real names** — never resolved to
  hex in the file. The omp look depends on the layered vars↔colors structure:
  dark `colors.accent: "accent"`, light `colors.accent: "teal"`,
  `colors.border: "blue"` in both. Each variant's `vars` map carries the
  declared var names (dark `accent` `#febc38`, `blue` `#178fb9`; light
  `teal` `#5a8080`, `blue` `#547da7`). The shared var **name** `blue` in both
  variants (different hex per variant) is the family anchor. No `amber` var
  exists anywhere; do not invent one.
- **Four `""` defaults survive verbatim**: `text`, `userMessageText`,
  `customMessageText`, `toolTitle`. Do not substitute hex for these — a hex
  substitution silently breaks the terminal-default rendering
  (`getFgAnsi("")` → `\x1b[39m`; the resolved map's `""`→`#e5e5e7`/`#000000`
  is the CSS export path, not terminal rendering).
- **`export` section verbatim** from omp (`pageBg`/`cardBg`/`infoBg`): dark
  `#18181e`/`#1e1e24`/`#26262e`, light `#f8f8f8`/`#ffffff`/`#fffae6`. These
  differ from pi's built-in dark export (`infoBg` `#3c3728` vs omp
  `#26262e`).
- **Brand anchors** (resolved values the files must produce): dark accent
  `#febc38`, border `#178fb9`, borderAccent `#0088fa`, customMessageLabel
  `#b281d6`, mdCodeBlock `#9CDCFE`, syntaxKeyword `#569CD6`; light accent
  `#5a8080`, border `#547da7`, syntaxString `#A31515`.

## Shipping mechanism

- `package.json`'s pi manifest gains `"themes": ["./themes"]`.
- **The manifest entry is required.** Under a pi manifest, pi's resource
  collection returns at the manifest branch before the convention-dir loop —
  a `themes/` directory alone collects 0 themes and `/settings` never lists
  the pair (a silent epic-wide no-op). T2/T3 prove this.
- Do NOT use `resources_discover`/`themePaths` for shipping the package's own
  static assets — that is an extension runtime hook, not the shipping path
  for package theme files.
- **Location pin:** the files live at `PKG_ROOT/themes/` where `PKG_ROOT` is
  the `import.meta.url`-resolved package root (`path.resolve(dirname(fileURLToPath(import.meta.url)), "..")`
  from `extensions/seats.ts`). EV-2 reads the base JSON off disk via
  `path.join(PKG_ROOT, "themes", ...)` — never `getPackageDir()`.

## Tests (test/theme.test.ts, T1–T8)

Loader: pi's real `theme.js` is imported via absolute path —
package-specifier deep imports are blocked by pi's exports map, so use
`import.meta.resolve("@earendil-works/pi-coding-agent")` + the dist path
`dist/modes/interactive/theme/theme.js` + dynamic import, in a shared
`test/theme-loader.ts` helper (EV-3 reuses it for `resolveThemeSetting`).

- **T1 package shape + location:** `pi.themes` lists both literal paths;
  files exist at `PKG_ROOT/themes`.
- **T2 discovery via real pi code:** drive
  `DefaultPackageManager.collectPackageResources(PKG_ROOT, acc, undefined, meta)`
  — both files land in `acc.themes` enabled.
- **T3 convention-dir refutation:** fixture package with `themes/` dir but no
  `pi.themes` entry collects 0; adding the entry collects them.
- **T4 validation + identity:** `loadThemeFromPath` no-throw (schema
  validation = the schema-validation acceptance); `name` is exactly
  `pi-council-dark` / `pi-council-light`.
- **T5 registration chain:** `setRegisteredThemes([...])` (exactly what
  interactive-mode.js:403 does) → `getThemeByName("pi-council-dark")`
  instanceof Theme; `getThemeByName("dark")` still resolves to the built-in
  (hijack guard); `getThemeByName("pi-council") === undefined`;
  `getResolvedThemeColors` has exactly 55 keys.
- **T6 full-map equality:** the shipped file's resolved color map ≡ the
  reference derived from the vendored omp fixture — both sides through pi's
  own resolver. Full 51+4-token map, key-for-key, both variants. "Matches
  omp" total, not sampled.
- **T7 raw-JSON invariants:** var-refs verbatim with real omp names (dark
  `colors.accent:"accent"`, `colors.border:"blue"`; light
  `colors.accent:"teal"`, `colors.border:"blue"`); every var-ref resolves to
  a declared var; the four `""` values survive in the raw file; no
  `link`/`pythonMode`/`statusLine*` keys; optional tokens equal their
  fallback sources after resolution.
- **T8 export section:** `getThemeExportColors` matches omp's export
  verbatim (pi's builtin dark export differs — `infoBg` `#3c3728` vs omp
  `#26262e`).

Brand-anchor spotlight: an explicit second assertion block for the five
dark anchors + the four light anchors + the four `""` defaults + the three
export tokens, so a brand regression fails loudly with a one-line
diagnostic (designer's composition; T6 remains primary).

Var-ref preservation probe: mutate `vars.accent` in the loaded JSON →
re-resolve → colors change (proves var-refs resolve by name at
construction, per EV-2's compositional merge need).
