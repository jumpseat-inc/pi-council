# EV-27 — `/`-triggered search input in the model selection modal

Date: 2026-09-05. Settled design from the EV-27 Council deliberation
(council/cards/EV-27.md, steps 1–5): three-seat exchange converged on the
structural core; the Skeptic closed all eight objections green; the
consolidator sorted no open judgment and no open objections. This file is
the owner's design contract — it states the settled design and nothing
reopens it.

## Scope

**Single seam:** `extensions/model-picker.ts` — the `ModelPicker` component
only. No changes to `extensions/council-models.ts` (wiring), no changes to
`resolveSelection`'s emitted tuple shape, no changes to the header
(`council models — pick a model per seat`), the three footer strings,
`seatMarker`, `echoFor`, `footerFor`, or the two R-4 empty states.

Builds on EV-26's `filterModelRows(rows, query)` (merged): case-insensitive
substring match on `qualifiedId` only; returns the identical `PickRow`
references; empty query → all rows; no match → `[]`. That contract is
unchanged.

## State

Level-2-local search state, three fields:

- `searchActive: boolean` — search mode open at the model level.
- `query: string` — the filter text ("" while empty).
- `inputFocused: boolean` — Esc routing bit ("focus in the input").

Lifecycle:

- **Trigger:** at level 2 with `!searchActive` and
  `group.models.length > 0`, a decoded `/` opens search:
  `searchActive = true`, `inputFocused = true`, `query` unchanged (it is ""
  in every reachable pre-trigger state). Gated on a non-empty model list so
  `/` never injects active keys into the deliberately keyless R-4#2 state.
- **1→2 re-entry resets** search state (`searchActive = false`,
  `query = ""`), mirroring the existing "entering a level resets its
  cursor" rule.
- **3→2 backout preserves** search state — Esc at the confirm level returns
  to the model level with the prior query, filtered rows, and `modelIndex`
  intact. Level 3's confirm screen never renders the search row; `query` /
  `searchActive` are **never zeroed on Enter** (non-mutation).
- Search state dies with the level on ascent: ascending from level 2 to
  level 1 clears it, so a later 1→2 re-entry shows the unfiltered list.

## Row source — the filter at `currentRows()`

At level 2, `currentRows()` returns
`searchActive ? filterModelRows(rowsForProvider(group), query) : rowsForProvider(group)`.
This is the **single row source**: `windowStart()`, the Up/Down clamps,
`pushRows`, the Enter guard (`currentRows().length === 0 -> return`), and
the Enter-pick (`currentRows()[modelIndex]`) all read this one list.
Filtering anywhere else (e.g. in `pushRows`) is a defect: cursor, window,
and visible rows would read three different lists and the byte-verbatim
`resolveSelection()` tuple would not hold.

`modelIndex` is re-clamped into the filtered set after **every** query
mutation (append and clear): `clamp(modelIndex, 0, filteredLength - 1)`.
This closes the shrink-crash: a stale index past a shrunken filtered set
would make Enter set `picked = undefined` and `resolveSelection()` throw.
The existing `currentRows().length === 0` Enter-guard covers shrink-to-zero
(Enter on an empty filtered set is a consumed no-op, no throw).

## Key handling — `handleInput(data)` order

1. `settled` → return (unchanged).
2. Level 3 branch → unchanged (Enter confirms, Esc → level 2).
3. **Search-mode interception (only when level 2 && `searchActive`):**
   - **Backspace guard first:** if `matchesKey(data, Key.backspace)` →
     swallow as a no-op (never append, never delete; covers `\x7f`, `\x08`,
     kitty `\x1b[127u`, modify-other-keys backspace). Esc-clear is the
     card's sole deletion mechanism; single-character deletion is out of
     scope.
   - Else decode the printable:
     `decodeKittyPrintable(data) ?? (data.length === 1 && code >= 32 && code <= 126 ? data : undefined)`.
     If it is a printable, append it to `query`, set
     `inputFocused = true`, re-clamp `modelIndex` into the new filtered
     set, clear the render cache. **The `/` character appends like any
     printable** (ordering makes capture-by-construction: the trigger and
     the query character are the same character, distinguished by
     `searchActive` state, so `anthropic/claude` is fully typeable).
   - **Esc:** if `inputFocused` → `query = ""` (already-empty stays
     empty), keep focus, keep search mode, clear the cache. Esc never
     loses input focus — the card rules "clears its text and keeps it
     focused"; there is no second-Esc-deactivate binding. If
     `!inputFocused` → ascend to level 1 exactly as the existing
     level-2 Esc does today, search state dies with the level.
4. **Existing up/down/enter/escape** handling, unchanged in shape —
   except the Up/Down branch additionally sets `inputFocused = false`
   when at level 2 with `searchActive` (a subsequent printable
   re-focuses). Esc-without-search and the ascend paths at
   `extensions/model-picker.ts:257-262` are preserved unchanged.
5. **Fall-through `/` trigger** (level 2, `!searchActive`,
   `group.models.length > 0`): a decoded `/` opens search (see State).
   At all other levels `/` is ignored exactly as today (no key handling
   change).

**Printable decode is shared** by the trigger and the search-mode append
(the first `/` may arrive as a kitty CSI-u sequence `\x1b[47u` on modern
terminals — pi-tui hands raw bytes through `ctx.ui.custom`'s
`handleInput`, and the repo's root export surface offers
`decodeKittyPrintable`; the kitty decode is the exported arm and the
length-1/printable-range fallback covers legacy bare bytes; see
`Skeptic objection 3` for the optional deep-import alternative
`@earendil-works/pi-tui/dist/keys` `decodePrintableKey`). The picker only
decodes; kitty-protocol activation remains pi's own.

## Rendering

- Level 2 with `searchActive`:
  - Line 0: `HEADER`, byte-exact, unchanged.
  - Line 1: the **search row**: `"▌ "` (U+258C at column 0) followed by
    the empty-input hint `/ filter · esc clears` when `query === ""`, or
    the query text otherwise. Byte-exact empty rendering:
    `▌ / filter · esc clears` (Phase-1 ruling EV-27 R-1; middot idiom
    matches the ruled footers). Truncation is from the right and must
    never clip the `▌` (the empty-input hint truncates with `/ filter`
    surviving). The row is **byte-identical in both focus states**
    (R-1's empty-input rendering is unconditional on focus — Skeptic
    objection 1 closed the "▌ iff focused" reading).
  - Then the filtered rows via the existing `pushRows` path (same `> ` / `  `
    markers, same `modelRow` truncation rule where the `:level` suffix
    never clips).
  - **No-match (third render branch):** when `searchActive` and the
    filtered rows are empty, the data-row area renders one dim line:
    `No models matching "<query>".` — byte-exact EPIC-6 R-1 literal,
    interpolated with the live query, byte-distinct from
    `EMPTY_NO_PROVIDERS` and `EMPTY_NO_MODELS(provider)`.
  - The footer is `FOOTER_MODEL`, rendered dim, in **every** model-level
    frame while search is active — including the no-match state (Esc-clear
    and Down are active keys there, unlike the keyless R-4 states). The
    search row is not a footer; the four-footer exhaustiveness rule is
    intact.
- Level 3 (confirm): unchanged; the search row is not drawn.
- `signature()` must include the search state: the existing
  `level:cursors:windowStart` fields **plus** `searchActive`,
  `inputFocused`, and `query`. Two states differing only in the query text
  (e.g. `claude` vs `claud`, same filtered row set, same cursor, same
  window) must produce different signatures — the query renders on the
  search row itself, so a query-blind signature serves a stale frame. The
  signature is compared by full-string equality, never parsed; query
  last keeps it unique by construction even with `/` and `:` in the query.

## Confirm and selection — unchanged

Enter at level 2 picks `currentRows()[modelIndex]` (the filtered list),
advances to level 3; the confirm screen's echo comes from the unchanged
`echoFor(resolveSelection())`; a filtered row emits the same
`SeatModelSelection` tuple — byte-verbatim `qualifiedId` plus thinking
level — as the unfiltered path, because `filterModelRows` preserves
`PickRow` references.

## Out of scope (explicitly)

- No backspace/single-character deletion (FLLWUP candidate).
- No `/ filter` addition to the model-level footer, no first-time hint row
  (four-footer exhaustiveness; pre-press `/` discoverability is an accepted
  gap).
- No `withModalFrame` changes (the +1 frame-line overrun at full window is
  a pre-existing tail-clip seam, tracked separately; driven tests assert
  `render()` frame-free).
- No change to `extensions/council-models.ts`, the opener wiring, or the
  kitty-protocol activation surface.
- Live-terminal kitty smoke (a manual `/council-models` run verifying `/`
  opens the input on a kitty-protocol terminal) is a named follow-up, not
  a gate.

## Test surface (driven `bun:test` contract)

Minimum assertions the implementation must satisfy (extends
`test/model-picker.test.ts` fixtures):

1. `/` at level 2 (`handleInput("/")`) opens the input; identical behavior
   for the kitty form `handleInput("\x1b[47u")`.
2. Typing `claude` narrows the rendered rows to `qualifiedId` substring
   matches (case-insensitive).
3. The input renders **between the header and the first data row** with the
   `▌` cell; empty input row is byte-exact
   `▌ / filter · esc clears`; after typing `claude` the row is byte-exact
   `▌ claude`.
4. The footer is the ruled `FOOTER_MODEL` string as the last line at every
   keystroke, including the no-match state.
5. `anthropic/claude` (containing `/`) is typeable into the input without
   leaving search mode (`/` appends as a literal).
6. Render cache: `render(width)` output differs after every keystroke —
   specifically `claude` vs `claud` (equal filtered set, cursor, window)
   must differ.
7. `handleInput("\x7f")` and `handleInput("\x1b[127u")` leave `query`
   unchanged (guard-only no-op).
8. Esc in the input with text empties the query and keeps focus (input
   still visible, still level 2); Esc again stays (no ascend); Esc with
   focus out (after Down) at level 2 transitions to level 1 and the search
   state dies with the level.
9. No-match: `/` + `zzzz` renders `No models matching "zzzz".` byte-exact
   with `FOOTER_MODEL` last, byte-distinct from both R-4 states; the
   no-match walk `/` `z` `z` `z` `z` `Down` `Esc` lands at level 1 (no
   dead-end).
10. `modelIndex` clamps on every keystroke: filter to an N < index set and
    Enter directly — no throw, `resolveSelection()` emits the surviving
    row's byte-verbatim `qualifiedId`; filter to 0 rows and Enter — no-op,
    no throw, query preserved.
11. Selection through a filtered set emits the same `resolveSelection()`
    tuple as the unfiltered path; confirm echo byte-equal.
12. B-7 round-trip: `/` `claude` `Down` `Enter` `Esc` (at confirm) →
    level 2 with row 1 byte-equal `▌ claude`, the same filtered rows, and
    `modelIndex` preserved; fresh 1→2 re-entry resets search state (no
    search row, unfiltered list).
13. The `▌` (U+258C) appears at no other level and in no non-search state
    (the existing 8.8 test keeps passing).
