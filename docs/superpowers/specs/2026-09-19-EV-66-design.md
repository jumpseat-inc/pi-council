# EV-66 — Advisory gate at features-new intake (design spec)

Status: settled by the council deliberation recorded on
`council/cards/EV-66.md` (rounds 1–2, skeptic attack O1–O12, consolidator
synthesis) plus the product-owner step-6 ruling (recorded verbatim on the
card; cited below as R(a), R(c), R(d)). This file writes up that settled
design; it derives nothing new. Phase-1 rulings R1–R4 on the card face are
binding and are not restated here except where they constrain a choice.

## 1. Contract (the card's goal, verbatim)

> With the gate in advisory mode a /features-new run records one ledger line
> per drafted card carrying advisory true while dispatching the same seat set
> as a pre-gate run, proven by a headless falsifier whose manifests show an
> unchanged dispatch set and whose ledger has a line for every card.

The card's Acceptance section on the card face pins the in-flight-line copy
constraints and the zero-lines-after-settle test. The gate verdict is
RECORDED here, never printed — the printed verdict line belongs to EV-67.

## 2. Intake seam — the `council_gate` tool

New parent-session tool `council_gate`, invoked once by the /features-new
facilitator after wave-3 aggregation and before step-3 (draft-then-confirm)
presentation, with all drafted cards as parameters.

- New module `extensions/gate-tool.ts`, mirroring the hub-tools registration
  pattern: closure over repoRoot, typebox params.
- Registration: its OWN registration call on index.ts's parent path only.
  It is never folded into `registerHubTools` (which child.ts also calls for
  hub-granted seats — folding it in would register the tool on the child
  path too; the child's `--tools` allowlist would still not advertise or
  execute it, but the own-registration mechanism is the stronger and
  settled one).
- Parameters: `cards: Array<{ id, title, goal, acceptance, touchedFiles? }>`.
  `touchedFiles` is optional in the tool contract. **R(c) applied:** the
  call site passes `touchedFiles: []` when the parameter is absent —
  `gate-state.ts` is NOT touched and no one-way door is opened. Nowhere in
  code, copy, or comments may `[]` be described as "touches nothing": intake
  makes no touched-file claim, `[]` merely carries that in a contract with
  no absent slot, and EV-69's re-check against the observed set is the
  enforcement. No `state` parameter. Epic card included: the gate call
  covers the epic card plus every drafted child card.
- Per card, SEQUENTIALLY: `buildGateState` → `runGate` with the production
  transport (apiKey resolution inside runGate). Thirteen cards = thirteen
  sequential calls; latency is traded for unambiguous copy.

## 3. Composition and modes

- `loadGatePolicy(repoRoot)` first.
- **Mode "off" (R3):** mechanical no-op returning
  `{ mode: "off", recorded: 0 }` BEFORE loading questions, building state,
  fetching, writing a ledger line, or touching any widget. Verified surface
  (skeptic O8): a repo-local off policy may omit `gateStateBudgetTokens`;
  the short-circuit must precede the loaders, which would otherwise throw.
- **Mode "advisory"** (and "active"): `loadGateQuestions` +
  `loadGateDecision`, then the sequential per-card loop. The advisory flag
  on the ledger line comes from `policy.mode` inside runGate — no second
  mode copy anywhere.
- Mode "active" is out of this card's contract except that it takes the
  identical mechanical path, records `advisory: false`, and still returns a
  verdict-opaque result. EV-69/EV-70 own making a verdict effective and
  amend the result shape if they need it.
- Advisory mode with `gateStateBudgetTokens` absent throws the named
  loadGatePolicy error (skeptic O2). Tests set the mode explicitly; the
  packaged default is never relied on to be on.

## 4. Result opacity

The tool result carries ONLY mechanical facts:
`{ policyMode, cards: [{ id, callId, status }] }` — never `resolvedMode`,
`basis`, `answers`, `decision`, `failure`, `reportedModel`, `modelDrift`,
or `include`. Residual channels pinned closed:

- (a) no verdict token (`Deliberate|Verify|Direct|Mode:`) appears in any
  returned string, including error and status strings;
- (b) the tool never passes `opts.callId` (default randomUUID keeps the
  callId opaque and uncorrelatable by the reading model);
- (c) a thrown pre-POST guard or appendGateCall failure is caught and
  re-surfaced as a GENERIC message, never runGate's own policy-mode /
  noul-join text.

The tool must never serialize any of the verdict-bearing fields above.

## 5. Non-interference falsifier (the card's hard part)

Two arm classes, byte-identical scripts and trees; only the repo-local
`policy.json` (and the scratch HOME / env for arm B) differs.

- **Arm A — loopback success (primary):** repo-local policy with
  `mode: "advisory"`, pinned model, endpoint `http://127.0.0.1:<port>/decisions`
  bound by the test process (`127.0.0.1:0`, fixture-http precedent), dummy
  non-empty OPENROUTER_API_KEY. The stub returns PER-CARD-KEYED canned
  answers, keyed on `body.state.card.id` in the POST. The falsifier asserts
  per-card resolved modes/basis are not all identical (a single canned body
  for all cards makes the success line degenerate and fails the bar —
  non-vacuity clause).
- **Arm B — credential-less failure (secondary):** OPENROUTER_API_KEY
  deleted from the harness env (actively — a runner-exported key would
  silently convert the arm into a live POST) and an empty scratch HOME →
  runGate fails closed pre-transport, zero POSTs, one v2 line per card with
  resolvedMode "Deliberate", failureClass no-api-key, `advisory: true`,
  basis byte-equal to the pinned failure string. Arm B proves count, v2
  shape, advisory marking, and fail-closed posture; arm A proves success-path
  resolvedMode derivation, the decide()-basis composite, and answers
  storage. Together the acceptance clause "exactly one ledger line
  carrying its resolved mode and basis" holds in the strong sense.
- **Headline observable — the ledger is the only engine-written diff:**
  recursive hash of both arm worktrees; the differing-path set, minus the
  harness-authored repo-local `policy.json` and minus `.pi/council/runs/**`
  (engine-written telemetry per AGENTS.md convention 12; the arms dispatch
  different seat sets by script, so runs/ differs by design), must equal
  exactly `{ .pi/council/gate-ledger.jsonl }`. A card-file, board, manifest,
  or any incidental write is a failure. Dispatch-set equality
  (same manifest id sets, unchanged seat set) is asserted as a corollary.
- **Steering-branch sensitivity clause (unit level):** a mock model whose
  post-gate step branches on the preceding toolResult's text — if it
  contains any verdict token, it dispatches a DIFFERENT seat set; assert the
  branch is never taken. At headless level, dispatch-set equality is the
  integration proof; the headless arm is not sold as a leak detector.
- **The arm B failure-arm scope is stated honestly** (ruling R(a) is about
  the surface, not the ledger): all of arm B's lines carry identical
  resolvedMode and basis; it proves the counting/shape/marking claims, not
  per-card verdict derivation.

The falsifier does NOT run the real features-new procedure end-to-end (no
human step-3 gate exists in `-p`). Procedure-text placement is asserted
separately (§7).

## 6. In-flight copy — the only surface this card adds

- Widget key **`gate-call`** (distinct from `"council"` and
  `COUNCIL_TREE_WIDGET_KEY`), set with NO placement argument — pi's
  documented default is aboveEditor, where the always-on jobs widget
  (`"council"`) already renders; the belowEditor plane belongs to the
  toggle-controlled tree. Owner and designer converged aboveEditor; the
  principal's belowEditor occupancy lean was withdrawn, so this is settled.
- Copy, exactly: **`gate: advisory call in progress · <id>`** — plain
  string[] form, no theme.fg call, no hex, no ANSI escape, no factory form.
  Names the card, states a call is in progress, no banned word
  (`thinking`, `deliberating`, `reasoning`, `judging`), no verdict, no mode
  suffix beyond the literal word `advisory` (not on the banned list; it is
  the exact word the goal's `advisory: true` hinges on).
- **R(a) applied:** the surface stays exactly the pending line — zero lines
  after settle for EVERY post-settle state including failures; no transient
  failure wording; no failure or duration wording added to the pending
  line; the line is drawn from in-flight call state only, never from the
  ledger. The designer's failure-invisibility gap is accepted as residual
  (filed as an EV-7x decomposition candidate at step 13; not a fold-in;
  EV-66 is not blocked on it).
- On settle: `setWidget("gate-call", [])` — the empty array renders zero
  lines and keeps the key registered (verified against installed pi-tui).
  Replacement, never append. Never `notify` (it appends to the transcript —
  the thirteen-orphaned-lines failure the card forbids).
- `ctx.hasUI` guarded before any widget call — headless (`-p`/json/rpc)
  shows nothing; the ledger still gets its line regardless of UI.
- Pinned test: the render function returns zero lines after settle
  (card Acceptance), plus banned-word scan, key/placement constants, hasUI
  guard, determinism (same input → same output, no Date.now/Math.random),
  length < 80.

## 9. Tests and evidence discipline

- `test/gate-tool.test.ts` (offline, mkdtemp, stub endpoint): off no-op (no
  ledger file, zero stub connections, zero widget lines); advisory — one
  line per card, `advisory: true`, resolvedMode + basis present, v2
  call-line shape exactly EV-65's union with no `record.outcome.*` facts;
  active — advisory:false, result shape unchanged; result opacity by shape;
  malformed card field fails loud naming the field; parent-mode-only
  registration.
- `test/gate-inflight.test.ts` (pure): pending → exactly one line, banned

  constants; hasUI guard; determinism; copy length < 80.
- `test/ev66-advisory-intake.test.ts`: the two-arm falsifier with the
  headline hash observable, per-card non-identical resolved modes, dispatch
  set equality corollary, and the arm B determinism assertions.
- Red-base obligation (red-base-evidence, seven fields): base = commit
  immediately preceding EV-66's first mechanism; at base the tool is
  unregistered → the scripted gate step is an unknown tool → immediate
  error toolResult, no hang, the ledger line never lands, the
  line-for-every-card assertion fails red — fail-loud and deterministic
  (skeptic O11, FLLWUP-56 precedent). Base role required; transplant =
  the falsifier file (+ harness knob diff) from head sha; command verbatim
  `bun test test/ev66-advisory-intake.test.ts` both halves; head half 0
  fail; detached-checkout worktree removed after; copy set stated
  affirmatively.
- No new live arms (the production transport is already live-proven under
  COUNCIL_INTEGRATION=1 by gate-run-live tests). Suite budget: the two
  offline arms ≈10–15s, far inside the ≈101s envelope and the 180s drift
  threshold (skeptic O12); FLLWUP-58 per-test ceiling discipline applies to
  the new falsifier file.
- Owner gates, in full, at head: `bash council/preflight.sh`,
  `bunx tsc --noEmit`, `bun test` (integration gated behind
  COUNCIL_INTEGRATION=1), `python3 council/validate.py`.
