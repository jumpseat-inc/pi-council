## 1. Problem

The card's `goal`: *"A parent turn that ends with stopReason error is continued
automatically after the configured backoff, and once the budget is exhausted
the session stops with a named terminal message rather than a bare Continue."*

The deliberation and the Skeptic's step-4 runs established, each with a real
probe result:

1. **Council must own the loop.** `isRetryableAssistantError` on the intake's
   real literal `Provider finish_reason: error` (with colon) returns `false`
   (Skeptic O1 `closed-green`); no retry-verdict hook exists in
   `ExtensionAPI.on` or `ExtensionContextActions`. Pi's own `_prepareRetry`
   honors no `maxDelayMs`/`jitter` for the agent-turn loop (O2, with
   correction: the key exists and is honored on the provider-level loop).
2. **The literal is exactly `Provider finish_reason: error`** — the EV-43
   falsifier's colon-less string is classify-negative on **both** clauses and
   tests nothing (O3 `closed-green`).
3. **The `context` hook exists and clones** (`structuredClone`), so identity
   filtering is dead; the filter must be structural/index-delimited, armed for
   exactly one provider request (O4 `closed-green`).
4. **Settle ordering:** `_isAgentRunActive` is cleared *before* `agent_settled`
   handlers run, so `ctx.isIdle()` is already `true` during the settle emit and
   cannot by itself distinguish "settled, safe to send" from "nothing
   happening" (O5 `closed-green`; the corollary the headless pattern must
   respect).
5. **The input-bar surface is producible without clobbering typing.**
   `setEditorComponent`/`setCustomEditorComponent` snapshots and restores the
   draft; `CustomTreeEditor` already appends an extra line to
   `super.render(width)` and composes over `getEditorComponent()`
   (`focus-nav.ts:277–289, 348–357`). There is **no** input-bar text setter, and
   `setEditorText` is forbidden (O6 `closed-green`).
6. **`message_end`-rewrite is rejected** (persists a falsified `errorMessage` in
   the JSONL, corrupting EV-42 identity and `runs/` transcripts,
   `agent-session.js:515–525` before `appendMessage` `:395–401`).
7. **Reachability is closed only for send-inside-handler** (EV-43). The
   as-designed mechanism needs a timer-deferred TUI variant and an
   await-inside-handler headless variant; P1 and the TUI counterpart smoke are
   the settling runs (Skeptic method finding, ruling "carried testable gap").

## 2. Settled design

### 2.1 The pure retry additions — `extensions/retry.ts`

Two new exported pure functions, beside `classifyRetry` (O3 literal reused
verbatim; no new literal).

**`classifyParentTurnRetry(message)` — the parent-loop predicate (D2).** The
parent loop must retry *only* the council-widened intake class and must **not**
retry a message pi itself retries: pi already spent its own budget before
`agent_settled` (`agent-session.js:776–784`). Signature and semantics:

```ts
export function classifyParentTurnRetry(
  message: { stopReason?: string; errorMessage?: string },
): "retry" | undefined {
  if (message.stopReason !== "error") return undefined;
  const text = message.errorMessage ?? "";
  if (RETRYABLE_PROVIDER_ERROR.test(text)) return undefined; // pi owns these; it already retried
  return text === PROVIDER_FINISH_REASON_ERROR ? "retry" : undefined;
}
```

`RETRYABLE_PROVIDER_ERROR` is the existing module-private regex over
`RETRYABLE_PROVIDER_ERROR_PATTERNS`. The test asserts `"retry"` for
`PROVIDER_FINISH_REASON_ERROR` and `undefined` for a matched pi-retryable
message (e.g. `"Provider returned 502: upstream unavailable"`) — D2, static and
runnable.

**`computeBackoffDelay(policy, attempt, rand)` — the policy.** `attempt` is the
council attempt number being awaited (2..`maxAttempts`). The delay before
entering attempt *N* is the value the R5 countdown interpolates:

```ts
export function computeBackoffDelay(
  policy: { baseDelayMs: number; maxDelayMs: number; jitter: boolean },
  attempt: number,
  rand: () => number = Math.random,
): number {
  const raw = policy.baseDelayMs * 2 ** Math.max(0, attempt - 2);
  const capped = Math.min(raw, policy.maxDelayMs);
  // jitter: multiplier in [0.5, 1.5) -> "halved to one-and-a-half", rounded.
  return policy.jitter ? Math.round(capped * (0.5 + rand())) : capped;
}
```

The `attempt - 2` exponent matches pi's own first-retry-delay = `baseDelayMs`
semantics (`agent-session.js:2306–2311`, where pi's `_retryAttempt` starts at
1 for the first retry) and the R5 example (`baseDelayMs = 2000` → "Retrying in
2s (attempt 2 of 3)"). With defaults `2000/30000/true`, attempt 2 is in
`[1000, 3000)` ms, attempt 3 in `[2000, 6000)` ms. The function is pure given
`rand`; tests pass `rand = () => 0` (lower bound), `() => 0.5` (≈0.75×), and a
`jitter: false` policy (exact `capped`), and assert the `maxDelayMs` cap.

### 2.2 Copy formatters — `extensions/parent-retry.ts`

Both strings interpolate, never hardcode (R5 ruling: "interpolation, not
substitution"). The em dash is U+2014.

```ts
export function formatRetryCountdown(attempt: number, maxAttempts: number, remainingMs: number): string {
  return `Retrying in ${Math.max(0, Math.ceil(remainingMs / 1000))}s (attempt ${attempt} of ${maxAttempts}) — Esc to abort`;
}
export function formatRetryExhausted(maxAttempts: number): string {
  return `Retries exhausted after ${maxAttempts} attempts. The provider kept failing. Press Enter to try again.`;
}
```

`HEADLESS_RETRY_EXHAUSTED_EXIT_CODE = 75` is also exported here (Q5,
`EX_TEMPFAIL` semantic).

### 2.3 Detection, caching, and the re-issue point

`agent_settled` has **zero payload**; the signal is cached from the events that
fire before it. Registered in parent mode (`extensions/index.ts`), alongside the
existing `agent_settled` handler (`:379–385`):

- **`message_end`** (`MessageEndEvent.message`): if the message is an assistant
  turn, record the verdict — `classifyParentTurnRetry(message) === "retry"` →
  `pendingError = message`; `stopReason === "aborted"` → `pendingError = null`
  (never schedule, owner P3); `stopReason === "stop" | "length"` →
  `pendingError = null`.
- **`agent_end`** (`AgentEndEvent.messages`): the authoritative turn-boundary
  snapshot. Recompute the same verdict from the last assistant message, and
  capture `originalPrompt` as the text of the last `role: "user"` message in
  `event.messages`. (This is what Enter re-sends and what the continuation
  sends.)
- **`agent_start`**: if the run is **not** our continuation
  (`expectContinuation === false`), reset the per-turn retry state
  (`attempt = 1`, `pendingError = null`, `originalPrompt = null`), disarm any
  armed send timer, clear the retry surface, and restore the retry editor
  (restore-if-still-ours, §2.6). A user/procedure-initiated run always starts
  a fresh budget.
- **`agent_settled`** (`:379–385`): first `await flushUsage("agent-settled",
  ctx)` (unchanged), then the retry decision. Act only when
  `pendingError` is set, `policy.enabled`, and the verdict is `"retry"`:
  - `attempt < maxAttempts` → schedule the next attempt (`attempt + 1`).
  - `attempt >= maxAttempts` → exhaust (terminal state).
  When no retry is scheduled (verdict not `"retry"`, or `policy.enabled`
  false), the retry surface is cleared and the editor restored
  (restore-if-still-ours) — this is the successful-continuation exit.
  Nothing is sent from `message_end`/`agent_end`: pi's own `_prepareRetry` can
  still interleave there; settle is the only event documented as "no automatic
  retry, compaction, or queued continuation will run".
- **`session_shutdown`**: clear the send timer and tick, clear
  `expectContinuation`/`pendingError`/`originalPrompt`, restore the editor.

`attempt` starts at 1 for the failed turn; retries are attempts
`2..maxAttempts` — R5's copy reads "attempt 2 of 3" on the first retry, and the
terminal copy reports "after 3 attempts" (1 initial + 2 retries).

### 2.4 The structural context filter (Q2 axis 2, O4)

A `pi.on("context", handler)` registered in parent mode:

- A closure boolean `filterArmed` is set to `true` immediately **before** each
  continuation send and immediately before an Enter re-arm send. It is never
  set at any other time.
- On every `context` event, if `filterArmed` is `false`, return `undefined`.
  If `true`, return a message list with **every** assistant message whose
  `stopReason === "error"` and `errorMessage === PROVIDER_FINISH_REASON_ERROR`
  removed (structural match — identity is dead under `structuredClone`), then
  set `filterArmed = false` (exactly one pass). If no such message is present,
  still clear the flag and return `undefined` (no accidental second pass).
- The filter never touches non-assistant messages; tool-result pairing is
  unaffected (D1 arm B asserts "no extra/missing toolResult").
- Dropping **every** matching errored assistant message, not just the trailing
  one, is required: a 3-attempt chain persists one errored assistant turn per
  attempt (each continuation appends a user message, and each failed run
  appends its own errored assistant turn), so a trailing-only filter would leave
  the earlier errored turns in attempt 3's request. This is the multi-attempt
  generalization of D1's singular phrasing; D1 arm B asserts the payload
  contains no errored assistant message at all.

The errored assistant message itself is **never** un-appended: it persists in
the JSONL (`appendMessage`, `agent-session.js:395–401`) and remains visible in
the transcript (Q2 axis 2; designer P3 reads it from the produced JSONL).

### 2.5 The continuation send and the timer

The send timer lives in the parent-mode closure in `extensions/index.ts`
(sibling of `flushChain`, `:289`), never in `navigator`/`focus-nav`. Scheduling
an attempt:

- `delay = computeBackoffDelay(policy, attempt + 1)`.
- **TUI (`ctx.hasUI === true`):** install/compose the retry editor (§2.6), arm
  the `RetryController` backoff surface for `attempt + 1` with `deadline =
  Date.now() + delay`, start the controller's 1 s render tick, and arm an
  **unref'd** `setTimeout(delay)` that on fire: disarms the tick and surface,
  sets `attempt += 1`, sets `expectContinuation = true`, arms the context
  filter, and calls `pi.sendUserMessage(originalPrompt)` (fire-and-forget —
  the TUI branch pattern at `:442–447`).
- **Headless (`ctx.hasUI === false`):** **await the backoff and the send inside
  the `agent_settled` handler** (principal's mitigation; the falsifier's
  send-inside-handler pattern): print the countdown line to stdout at `t = 0`
  and once per whole second thereafter (never more often than 1/s), `await` the
  remaining delay in bounded slices, then set `attempt += 1`,
  `expectContinuation = true`, arm the filter, `pi.sendUserMessage(originalPrompt)`,
  poll `ctx.isIdle()` until the nested run becomes active, and await
  `waitForIdle` **only if the event context exposes it** (it does not on this
  tree — EV-43; the poll plus print mode's outer await of
  `_runAgentPrompt`'s `finally` is the guarantee). This is what makes the
  headless countdown line observable (P4).
- Either branch: the timer callback must not touch a captured `ctx` unguarded —
  `pi.sendUserMessage` is the stable `ExtensionAPI`; any `ctx`/`uiCtx` access
  is guarded and swallows the stale-session `assertActive` throw
  (`wiki/headless-pi.md` §"Stale ctx after session replacement").
- **SIGINT during a headless backoff terminates the runtime; the unref'd timer
  does not fire because the process is gone.** Disarming falls out of teardown;
  no explicit SIGINT handler is installed (Q3). T-H1 is the settling run.

**Floor re-entry (owner P2):** a continuation is an ordinary provider request
and re-enters `before_provider_request` (`:66–81`); a floored model's
continuation payload carries `max_completion_tokens = 131072`. No special
handling; one test asserts it.

**Usage (D4):** the continuation's settle re-enters the `agent_settled` handler
→ a second `flushUsage("agent-settled")`. EV-31's choose-once key makes a
second flush a byte-identical no-op; no code change is expected, and the live
3-attempt run asserts exactly one usage record per session.

### 2.6 The TUI surface — `RetryEditor` (Q1)

`extensions/parent-retry.ts` exports a `RetryEditor extends CustomEditor`
(exported from `@earendil-works/pi-coding-agent`). Installed via
`setEditorComponent` and **composing over** `getEditorComponent()` exactly like
`CustomTreeEditor` (`focus-nav.ts:283–357`):

- Constructor takes the `RetryController` plus an optional prior factory;
  when present, constructs the prior editor instance and forwards unhandled
  keys to it. The editor's draft is read from the prior instance when present
  (`prior.getText()`), else from `this.getText()`.
- `render(width)`: `const lines = super.render(width)`, then, when the
  controller surface is non-idle, append one new line:
  `truncateToWidth(style(lineText), width)` where `style` is the editor's theme
  color (`this.borderColor ? this.borderColor(lineText) : lineText`; the
  `focus-nav` precedent). Plain text, no literal hex/ANSI (AGENTS.md 9.6;
  `test/theme-compliance.test.ts` is a live gate). Never buffer text, never a
  placeholder (pi-tui `Editor` has none), never `setEditorText`.
- `handleInput(data)` — the surface state machine:
  - **backoff surface:**
    - `Escape` → consumed: abort the remaining retries (disarm the send timer,
      clear the filter flag) and move the surface to **exhausted** with
      `formatRetryExhausted(maxAttempts)` (designer P2: identical terminal copy
      to natural exhaustion, not a distinct "cancelled" copy).
    - `Enter` with an empty draft → consumed no-op; the retry continues.
    - `Enter` with a non-empty draft → disarm the send timer, clear the
      surface, then forward to `super`/prior so pi submits the typed text
      through the normal turn path (Q4: the user's prompt wins; the council
      continuation is aborted).
    - every other key → forwarded to `super`/prior (printables accumulate,
      ctrl+c reaches pi's normal abort path, EV-8 Ruling 2 forward-unhandled).
  - **exhausted surface:** `Enter` with an empty draft → consumed: re-arm —
    reset the attempt budget to 1, clear the terminal surface, arm the filter,
    and re-send `originalPrompt` immediately (Q2 axis 1: re-send the original
    prompt with a fresh budget; the loop runs again from attempt 1). `Enter`
    with a non-empty draft and every other key → forward to `super`/prior
    (typing still wins; the terminal state clears when the user's own run
    starts).
- Install/restore lifecycle (`installRetryEditor`/`restoreRetryEditor`):
  - `installRetryEditor(ui, controller)` is idempotent; on first install it
    records `retryPrior = ui.getEditorComponent()` and installs the factory.
  - `restoreRetryEditor(ui)` restores **only if the currently configured
    factory is still ours**, then clears the recorded refs. If another overlay
    (the tree) installed over us, it is left in place — the O6 single-slot
    hazard is handled by "restore-if-still-ours", not by clobbering.
  - The editor is installed when a retry first arms and restored when the loop
    ends without exhaustion (a successful continuation, a user submit, session
    shutdown, or a disarming reset). It stays installed through the exhausted
    state so Enter can re-arm.
- **Tick source:** the `RetryController` owns a 1 s `setInterval` (unref'd)
  that recomputes `remainingMs` and calls a `requestRender` hook (the TUI's
  `tui.requestRender()`); the editor reads the current line at render time.
  The interval stops on any surface transition out of backoff.

### 2.7 Headless exhaustion (Q5)

At exhaustion in the headless branch: print `formatRetryExhausted(maxAttempts)`
as the final stdout line, then set
`process.exitCode = HEADLESS_RETRY_EXHAUSTED_EXIT_CODE` (75). A wrapper or the
operator reads the code and re-invokes the same prompt — the headless equivalent
of "Press Enter". No JSONL marker; no stay-alive-and-read-stdin mode
(`wiki/headless-pi.md` §"Single-shot teardown"). If the installed pi runtime
clobbers `process.exitCode`, the owner uses the least-destructive means that
yields the asserted code and records the mechanism in the plan; the asserted
observable is the child process's exit status `75`.

### 2.8 Explicit out of scope

- Nuancing pi's own retry loop or the provider-level `retryProviderRetry`; the
  upstream retryable-verdict hook is a follow-up, not a dependency (O1).
- The hub/seat retry loop, its attempt counter, and the run-substrate
  `attempt` manifest field (EV-39, EV-42). Only the **field name `attempt`** is
  agreed here; neither loop reads the other's state (`runs/` is ephemeral,
  AGENTS.md 12).
- A distinct "cancelled by Esc" terminal copy (the ruling's P2 gate pins the
  exhaustion copy).
- A transient toast naming the provider failure before the countdown (designer
  round-2 position, endorsed by owner, **not** ruled and **not** adopted here;
  deferred as a follow-up card candidate).
- `setStatus` / status-row rendering (Q1 rejected it; reversing R5 is steward
  territory).
- A JSONL abort marker (Q3 rejected).
- Any import-pipeline, server/API, tiles, or database concern — this repo
  defines none.
