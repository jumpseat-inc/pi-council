# EV-7 — Inline job tree beneath the input bar with per-row last activity

**Card:** EV-7 (EPIC-2) · **Facilitator record:** this is a write-up of a
settled Council deliberation (steps 2–6 done), including two binding
product-owner rulings. It does not derive a fresh design. The owner reads
only this file plus the card's `Intent`/`goal`.

## Scope (settled)

Replace `/council-tree`'s current modal presentation (backdrop + centered
panel over `ctx.ui.custom` with `overlay: true`) with an **inline full-width
panel in pi's below-editor region** (the status-bar area beneath the input
text bar). Message content is pushed **up** instead of dimmed/covered. The
no-UI (headless) fallback — text tree to console — is preserved. Display
only: focus and key navigation are EV-8.

## Binding rulings (product-owner, on record — do not reopen)

- **OV-1 (coexist):** both the new inline below-editor tree panel AND the
  existing ambient above-editor council widget render simultaneously when
  the tree is open. No collapse/hide behavior on this card. The ambient
  widget's EV-4 plain-text/zero-ANSI contract is untouched; the existing
  `renderWidget()`/`widgetLines()` timer in `index.ts` is NOT modified by
  this card. Closing the inline panel "restores normal layout" — the ambient
  widget remains the always-visible status line, unchanged.
- **OV-2 (RPC scope):** EV-7 fixes **only** the new inline path's guard —
  it MUST guard on `ctx.mode === "tui"` (settled O5, non-optional). The
  pre-existing `navigator.ts:57` `!ctx.hasUI` modal path is **out of EV-7's
  scope** — do not fix it here. It lands in a follow-up card (step 13),
  "Repair /council-tree RPC silent-no-op in `navigator.ts:57`".

## Settled design (from deliberation)

### Vehicle

- `ctx.ui.setWidget("council-tree", factory, { placement: "belowEditor" })` —
  the **factory/function form**, type-valid under strict `tsc`
  (`types.d.ts:97-98`; `ExtensionWidgetOptions.placement: "aboveEditor" |
  "belowEditor"` at `types.d.ts:43`).
- TUI-only surface. Guard the widget path with `ctx.mode === "tui"` (NOT
  `!ctx.hasUI` — `hasUI` returns true in RPC-modes, which would silently walk
  the widget path whose factory is dropped). When not TUI (headless/RPC),
  route to the existing console `textTree` fallback, unchanged.
- No EV-4 §8 reopening: that rejection was scoped to the plain-string widget
  surface (`index.ts`); the tree path (factory form, belowEditor) is
  unaffected (C3 closed-green).

### Data source / last-activity seam

- **Transcript is the authoritative last-activity source.** Extend
  `TranscriptBlock` with `at: number = Date.parse(e.timestamp)` (falling
  back to `message.timestamp`), threaded through `parseTranscript`. The ISO
  `timestamp` already sits on every JSONL transaction line; the parser
  currently discards it (C2 closed-green).
- `lastActivity(seat)` = the block with the max `at`; age = `now - at`.
- **NaN-safety (mandatory):** every existing fixture stamps
  `"timestamp":"t"` → `Date.parse("t")` === NaN. `lastActivity` must treat
  NaN as absent and fall back to manifest `startedAt` (→ "spawned"). Age
  assertions in tests need real ISO stamps in fixtures.
- **Tail-read (not full parse):** per-refresh read of last-activity for N
  running sessions must be a tail-read (cached `TranscriptTail` or last-line
  seek), not a full `parseTranscript` per node per 2s tick (O(rows × file)
  is unacceptable).
- Manifest (`readManifests`/`buildTree`/`flattenTree`) contributes
  seat/id/state/parent for tree shape and for **non-running** rows:
  non-running rows collapse to manifest state + `settledAt` copy (no
  transcript needed — state and `settledAt` are never absent).
- **No hub.ts write change** (C1 closed-green: `RunManifest` has no
  `lastActivityAt` and `writeJobManifest` never writes one; do not add
  coupling to hub memory). AGENTS.md #7 guards `hub.ts` stability.
- **Current-run scoping (Q4, OJ-3):** default to the current run
  (`scopeAll=false`, parity with the modal). For re-spawned seats, scope
  `lastActivity` to the current run's session. OJ-3 is an engineering scope
  note the owner resolves during implementation; no PO ruling needed unless
  a visible behavior change surfaces.

### Rendering / copy (designer GLANCE — final, from Phase 1 ruling)

- **Token plan per row state:** RUNNING `accent`, DONE `success`, FAILED
  `error`, STALLED `warning`, CANCELLED `dim`, TIMEOUT `warning`, ORPHANED
  `error`.
- **Row layout / stable left edge:**
  `[glyph 3][seat 14][sep ' · ' 3][activity flex-truncate][elapsed right 6]`.
  Seat field padded to 14 (longest seat name); left edge fixed across the
  2s refresh.
- **Activity copy, verb-first from `TranscriptBlock.kind`:**
  - `toolCall` → `ran <name> [first-arg <= ~30c]` [+ age]
  - `thinking` → `thinking` [+ age]
  - `assistant` → `replied` [+ age]
  - `toolResult` → `got <name>` [+ age] (only if last block; usually
    `toolCall` preempts)
  - `user` → `idle` [+ age]
  - Age format: `<60s → 'Ns'`, `<60m → 'Nm'`, `>=60m → 'Nh Mm'`.
  - Fallback (no timestamp reachable): same templates, **no age suffix**;
    never fabricate an age.
- **Non-running rows (dim):** collapse to manifest state + `settledAt` copy —
  `settled <age>`, `failed`, `stalled <age>`, `cancelled`,
  `timeout <secs>`, `orphaned`.
- **Dim / ordering:** running-first (running → stalled → failed → done);
  running = full color with seat name bold; done/failed/cancelled = dim;
  stalled/timeout = warning (eye-catcher); seat name bold for stalled, dim
  for settled.
- **Close / forcing function:** no in-panel button. `/council-tree` toggle
  calls `setWidget("council-tree", undefined)` (EV-8 layers keys).
- **Hint line (bottom, dim):** `up/down move · enter view · /council-tree to
  close`.
- **Empty state:** a single dim line `no council jobs this session` — the
  invocation is acknowledged (not zero-line collapse).
- **Budget / cap:** `MAX_WIDGET_LINES = 10` = 1 hint line + 9 rows hard cap;
  overflow → dim `... N more`, never draw past the cap.
- **Token-only (AGENTS.md 9.6 + EV-4 settled):** every color/bold via
  `theme.fg`/`theme.bold`, no inline ANSI/hex; `truncateToWidth` ANSI-safe.

### Lifecycle / refresh

- **2s `setInterval` in the factory** drives the live refresh; cleared in
  `dispose()` (factory `dispose()` is called on `setWidget(key, undefined)`
  and by `clearExtensionWidgets()` — `interactive-mode.js:1715-1724`).
- **`session_shutdown` teardown (O4, block-to-confirm):** the extension MUST
  call `setWidget("council-tree", undefined)` on `session_shutdown`
  (index.ts:121-128 currently lacks it), not just rely on the interval, per
  the stale-ctx rule.
- **Stateful toggle (Q5):** parent-side stateful toggle; `ctrl+shift+t`
  reuses it; console fallback prints once; teardown on `session_shutdown`.
- **Repaint on theme change (O3/T3, block-to-confirm):** the factory is
  invoked once. The component's `render()` must re-read theme tokens at
  render time (never bake them in the factory body). The 2s refresh calls
  `refresh()` → clears width cache → repaints with new tokens on a normal
  tick after a mid-session `.council.json` recolor, WITHOUT a second factory
  invocation. Mirror `theme-repaint.test.ts:116-127`.
- **Live refresh parity:** panel refreshes live while visible, on par with
  the modal's 2s polling.

## Testable claims / acceptance mapping

- A. `parseTranscript` preserves ISO `at`; max-by-`at` yields the last block
  (fails today on current `parseTranscript`).
- B. `setWidget("council-tree", factory, { placement: "belowEditor" })`
  compiles under strict `tsc` + an acceptance-mode `--mode tui` no-fallback
  pin (T2/T4): RPC/headless routes to console `textTree`, never calls the
  factory; guard `ctx.mode === "tui"` asserted.
- C. NaN fallback: `"t"` timestamp → NaN → manifest `startedAt` fallback (T1).
- D. Repaint pin (T3): theme swap → re-render with new tokens on a normal
  tick, no second factory call.
- E. Session teardown (O4): `setWidget("council-tree", undefined)` on
  `session_shutdown`.
- F. Render tests cover the new row format and last-activity text against
  fixture manifests and transcripts.
- Acceptance (from card): with a live job, `/council-tree` shows the panel
  beneath the input bar, message area pushed up; each row shows seat name +
  last-activity that updates; re-invoking removes the panel and restores
  normal layout (ambient widget unchanged per OV-1); render tests +
  `bun test`/`bunx tsc --noEmit` pass.
