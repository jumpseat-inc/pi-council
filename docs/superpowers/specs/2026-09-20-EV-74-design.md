# EV-74 Design — `/council-gate` to enable or disable the decisions gate

Settled by the EPIC-14 card 3/5 deliberation (2026-09-20). Every decision here
was closed in deliberation rounds 1–3, the skeptic attack, and consolidation
(`council/cards/EV-74.md` run record). Binding rulings applied: R5 (operator
copy says "gate", never "jev"; the echo names the resolved mode and states it
applies to dispatches after the echo) and the card-context PO ruling (TS
command; only the mode key inside `.council.json`'s reserved top-level `gate`
section; echo resolves through `loadGateConfig`; every other byte and
top-level key byte-preserved; redundant set byte-identical; unknown arg fails
loud; share the EV-24 writer's byte-region splice, never hand-roll a second
merge).

## 1. The writer: `writeGateMode` in `extensions/council-config-writer.ts`

```ts
export function writeGateMode(args: {
	repoRoot: string;
	mode: GateMode; // imported from ./gate.ts — GATE_MODES; never re-declared
}): { ok: true; unchanged?: true } | { ok: false; error: string };
```

- **Same-file placement (option C, converged round 3).** The function lives in
  `council-config-writer.ts` beside `writeSeatOverride`/`clearSeatOverride`
  and reuses the module's private machinery (`parseValue`, `skipSpace`,
  `scanString`, `scanScalar`, `lineIndentAt`, `lineStartAt`, `detectIndentUnit`,
  `writeAtomic`, `existingMode`) unexported. The module's existing export set
  grows by exactly this one function. A doc-note line is added to the module
  header naming the gate sibling (the header already opens "EV-24: the first
  `.council.json` write path").
- **Vocabulary import.** `GATE_MODES` (and the `GateMode` type) are imported
  from `gate.ts`. Direction writer → gate is a peer edge (both sit above
  `seats.ts`); no cycle (verified: gate.ts imports only seats.ts and
  gate-ledger.ts). Never a local `["off","advisory","active"]` re-declaration.
- **Validation, ordered first, pure (the writer's only stricter-than-runtime
  surface, mirroring the loader's grammar — gate parity):** `mode` must be a
  member of `GATE_MODES`. Nothing else is stricter than `loadGateConfig`.
- **The no-op decision is the writer's own fresh read+parse** (not a
  command-side pre-read — the round-2 owner withdrawal):
  1. File absent → greenfield: requested `off` ⇒ `{ ok: true, unchanged: true }`
     (file stays absent — a redundant set never materializes a gate section);
     requested `advisory`/`active` ⇒ create
     `{ "gate": { "mode": "<mode>" } }` canonically (2-space indent, trailing
     newline), same greenfield rule as `writeSeatOverride`.
  2. File present: read + `JSON.parse`. Malformed JSON, non-object root, or a
     `gate` member that is not an object ⇒ `{ ok: false, error }`, nothing
     written. Error text follows the loader's grammar shapes (single line,
     names file and key) so a pre-existing invalid section fails here exactly
     as it would at `loadGateConfig` — before any splice.
  3. Resolve the mode from the file's own bytes per `loadGateConfig`'s
     grammar (absent/`{}` ⇒ `off`; `mode` value must be in `GATE_MODES`).
     `resolved === requested` ⇒ return `{ ok: true, unchanged: true }` — no
     write, mtime untouched.
  4. Splice: replace the **last** `gate.mode` value span with
     `JSON.stringify(mode)` (duplicate keys are last-wins per JSON.parse —
     the splice must target the winning span, not the first); or insert
     `"mode": ...` after the last member of an existing `gate` object (or
     re-emit the `{}` span); or insert a `"gate": { "mode": ... }` member
     after the last root member (append-after-last; no scaffold-order rule is
     invented — the canonical-order question is a follow-up). Indent unit via
     `detectIndentUnit`; only the spliced span changes; atomic tmp+rename
     write with `existingMode` chmod. Only filesystem failures throw
     (EV-24 failure asymmetry).

## 2. The command: `extensions/council-gate-cmd.ts` + registration

- Pure helper on the `/council-models` pattern:
  `runGateCommand(args, repoRoot, emit, write = writeGateMode)` — args is the
  raw command string; `emit(line)` is the single sink for TUI
  (`ctx.ui.notify`) and headless (`console.log`) alike. No TUI/headless
  behavioral fork; no modal (a three-value toggle needs none).
- Arg grammar: trim, split on whitespace. Zero tokens → status read. One
  token → must be a member of `GATE_MODES`. More than one token → the
  unknown-arg error. **O3 pin:** a single token with trailing whitespace
  (`"off "`) is trimmed by the split and is VALID (the owner's trim/split
  grammar wins — the step-9 test pins the success/unchanged echo, not an
  error).
- Handler flow: call `runGateCommand`; on `{ok:false}` print the error line;
  on success read back via `loadGateConfig(repoRoot)` and emit the echo from
  THAT resolution. **Fail-soft read-back:** if the post-write
  `loadGateConfig` throws after a successful write, the command still
  reports the successful write (emit the success copy with the requested
  mode; never surface a FAIL for a write that landed — non-assertive echo
  rule: never assert state the screen cannot compute, and equally never
  un-assert a write that happened).
- Registration in `extensions/index.ts` next to the other TS commands:
  `pi.registerCommand("council-gate", { description, handler })`. Test pins
  registration by source-contains
  `pi.registerCommand("council-gate"` (the `test/council-models.test.ts:240`
  precedent — NOT the ev72 policy-pre-registration pattern).

## 3. Operator copy (R5-constrained; literals pinned in round 3)

- Success (write occurred):
  `council-gate: gate mode is now <mode> in .council.json — applies to dispatches after this echo.`
- Redundant (no-op):
  `council-gate: gate mode is already <mode> in .council.json — no change.`
- Status (no args): `[council-gate] gate mode is <mode>.`
- Unknown arg (fail loud, single line):
  `[council-gate] error: unknown mode "<arg>" — usage: /council-gate [off|advisory|active]`
- Extra args (>1 token) land on the same error line.
- All error echoes are single-line (`not.toMatch(/\n/)`); the module never
  interpolates a newline into any emitted string.
- "gate" everywhere; "jev" appears in no operator-facing string of the new
  module (grep falsifier; the `typesafe/jev-1.13` code constant in gate.ts is
  not operator copy).
- Timing-precision note for EV-77's docs (NOT the echo): the mode is read
  lazily at gate-tool-call time, so a flip is visible to the current
  dispatch's next gate read; R5's "applies to dispatches after this echo" is
  the binding copy and deliberately undershoots that precision.
- Designer P9 residual (step-13 note): `.council.json` is named on the
  write/no-op forms; the status read names only the mode (a status read, not
  a write record).

## 4. Semantics recorded for the record

- `off` is not "ungated": `resolveRoute` returns `Deliberate` (the full
  panel) for `off`; enabling the gate can REDUCE seat count. The echo names
  only the mode, so it never claims the opposite; the explanation lives in
  EV-77's docs sweep, which must call out off-as-Deliberate explicitly.
- The merge check reads the ROOT manifest's dispatch-time mode; a flip never
  retroactively changes an in-flight card's recorded mode or merge-check
  input.
- Theme-watcher side effect: any `.council.json` write triggers a theme
  reload on repos with a theme section (pre-existing, benign); none on
  theme-less repos.

## 5. Test obligations (TDD, red first; `test/ev74-council-gate-command.test.ts`; mkdtempSync roots)

Writer (writeGateMode):
1. Greenfield absent file: `off` ⇒ unchanged, file still absent;
   `advisory`/`active` ⇒ file created with only the gate section, loads via
   `loadGateConfig`.
2. Gate-less file (council + theme + an injected UNKNOWN top-level key +
   tab indentation): insert ⇒ outside-span sha256 identity (theme block,
   unknown key, every council.<seat> block, trailing newline byte-identical).
3. `gate` present without `mode` (and `gate: {}`): member inserted, rest
   byte-identical.
4. `gate.mode` present: value span replaced (last-wins on the O2
   duplicate-key fixture `{"gate":{"mode":"active","mode":"off"}}` ⇒
   `loadGateConfig` resolves the written mode and the LAST span's bytes were
   replaced).
5. Redundant set: `{ok:true, unchanged:true}`, file bytes AND mtime
   unchanged (includes gate-less file + `off`).
6. Malformed JSON / non-object root / non-object gate / invalid resolved
   mode ⇒ `{ok:false, error}`, file untouched.
7. Permission bits preserved; no `.tmp-*` leftover.
8. Export-surface guard (O1): `Object.keys(await import("../extensions/council-config-writer.ts"))`
   deep-equals the 3 post-change RUNTIME names
   (`["clearSeatOverride","writeGateMode","writeSeatOverride"]`).
9. Single-source vocabulary: the writer's source contains no
   `"advisory"`/`"active"` string literal (mode set flows only through the
   gate.ts import).

Command (runGateCommand / registration):
10. No-arg on a gate-less fixture prints `[council-gate] gate mode is off.`
    and writes nothing.
11. Round-trip off→advisory→off→active: after each leg the echoed mode equals
    `loadGateConfig(repoRoot).mode` (echo-then-run), and the exact literal
    matches §3.
12. Unknown arg / extra args: exact error literal, no write, file
    byte-identical; single line.
13. O3 pin: `"off "` (trailing whitespace) behaves as a valid `off` request.
14. O4 fail-soft: inject a write that returns `{ok:true}` but writes
    malformed JSON ⇒ the command emits the success copy (not an error).
15. O5: all four copy forms exact-literal; error echoes contain no `\n`.
16. Lazy-resolver proof: resolve, mutate file, resolve again ⇒ different
    mode (pins "applies to dispatches after this echo" mechanically).
17. `"jev"` absent from every emitted string of the new module.
18. Registration: source-contains `pi.registerCommand("council-gate"`.
