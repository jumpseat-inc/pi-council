# EV-20 — Matrix runner with repeat aggregation (design)

Settled design for card EV-20 (epic EPIC-4). This document is the write-up
of the Council's deliberation (rounds 1–2, Skeptic verification,
consolidation) plus the product-owner rulings that closed the three
open-judgment items (Q1 VerdictRecord schema/key + dependents, Q2 snapshot
policy, Q3 smoke-test policy) and the standing Phase 1 rulings R-1/R-2/R-3
and the grader-topology ruling. It derives nothing new; it records what the
deliberation settled and what the rulings bound. An owner reading only this
file, with no memory of the deliberation, must not be able to reach two
different designs.

## Goal (from the card)

> A slash command runs a declared task-and-model matrix with a configurable
> repeat count, writes one results record per run, and aggregates mean and
> variance per cell so a comparison is reproducible from the records alone

## The three binding rulings (Q1/Q2/Q3, verbatim substance)

### Q1 — VerdictRecord schema/key + two dependents

- **`VerdictRecord` gains `repeat: number`.** Store key `(cellId, repeat,
  gradedBy)`, first-write-wins per `(cellId, repeat, gradedBy,
  fixtureVersion, rubricVersion)`. Three grader dispatches for repeats 1..3
  of one cell → three readable verdict records.
- **D1 version-axis-in-key:** `cellId` is the stable aggregation identity
  `(taskId, model, thinking)`; fixture/rubric versions ride the store key
  alongside `repeat`/`gradedBy`. On-disk filename key for a verdict:
  `(cellId, repeat, gradedBy, fixtureVersion, rubricVersion)`; for a
  ResultRecord: `(cellId, repeat, scoredUnder, fixtureVersion,
  rubricVersion)`. A fixture bump produces a *new* version-keyed set; EV-21
  renders it as a sibling row / version badge (R-7).
- **D2 gate-only `scoredUnder` sentinel = `"self"`.** For the seven gate-only
  fixtures (`council`, `features-deliver`, `owner`, `judge`, `skeptic`,
  `wiki-lint`, `council-runner`), the grader dispatch is **not** invoked;
  the harness stamps `scoredUnder: "self"` on the ResultRecord and writes
  **no** VerdictRecord for that cell/repeat. `"self"` is not a model id —
  it is the assertion the cell was gate-only and no judge ran. EV-21 treats
  `scoredUnder === "self"` as gate-only.
- **CellId string form:** `taskId|model[:thinking]` (pipe separator; stable
  across fixture bumps because the version pair rides the key, not the
  cellId).

### Q2 — Snapshot policy

- **Persist the scratch snapshot per cell × repeat, `treeDigest =
  sha256Tree(snapshot)` on the ResultRecord's `cellScope` block, per-
  invocation persistence flag default ON.** Path:
  `council/eval-results/<cellId>/r<repeat>/snapshot/`. Default ON with
  `--no-persist-snapshot` as the documented escape hatch.

### Q3 — Smoke-test policy

- **The end-to-end smoke falsifier for `/council-eval` is in-scope for
  EV-20 and lands in this card** — a fourth phase on the existing
  `smoke/run.sh` / `driver.sh` / `assert.sh` pattern, seeding a minimal
  gate-only fixture and driving `/council-eval` headlessly. EV-20 does not
  merge without smoke Phase 3 green from a fresh container.

## 1. Command surface (assembled from settled items + R-3/R-4)

- Command `/council-eval`, argument hint `[task] [model...] [--repeat N]`.
  Registered in `extensions/index.ts` like other commands.
- Handler is a TypeScript handler (**NOT an LLM-orchestrated loop**, EV-16
  §3.1) that drives dispatch→wait→grade→aggregate synchronously.
- **No args** → print `listFixtureTasks(repoRoot)` as a sorted list + usage
  line; return immediately. (No-arg third column: the designer delegated
  the choice; `fixtureVersion` over `target shape` — implementer's call,
  recorded.)
- **`task`** → first positional, resolved via `loadFixture(repoRoot,
  taskId)`; unknown task throws loudly naming the available list.
- **`model...`** → remaining positionals, each through the shared
  `parseQualifiedModel`, pre-validated against
  `ctx.modelRegistry.getAvailable()` up front. Bare id or unknown
  `:thinking` suffix fails at parse, naming the model. No implicit
  all-models sweep (R-4). No seat-name→model resolution.
- **`--repeat N`** → also accept `--repeat=N`; N positive integer, default 3
  (R-4). Reject N above a hard cap of **20** with a loud error.
- Errors render in the transcript, non-fatally, via the existing
  `ctx.ui.notify` / print pattern.

## 2. A pure argument parser

`parseEvalArgs(args) -> { task, models: string[], repeat: number }` lives as
a pure, unit-testable function (in `extensions/eval-runner.ts`): one
positional `[task]`, `[model...]` ≥1 (or zero for the no-arg list form), and
`--repeat`/`--repeat=N` as a positive integer. It must not live inside the
I/O handler.

## 3. Progress + summary; recompute from records (settled)

- **Pre-dispatch echo-then-run** (not a blocking gate): before any cell
  spawns, print a confirmation line naming the resolved taskId,
  fixtureVersion, model ids, repeat count, and total dispatch count
  (models × repeat). The misspelled-model-id slip and the hours-of-cost
  forcing function are both closed by this echo.
- **Progress** during the run: per-repeat transcript lines with a
  `[council-eval]` prefix (greppable, durable), e.g. `[council-eval] cell
  <cellId> repeat 1/3 dispatched`, `✓ repeat 2/3 score=0.67`, and for a
  non-`done` settle `⚠ repeat 3/3 stalled — not graded`. **No second
  progress widget** — the existing council live widget + inline job tree
  already show active jobs (designer retracted the matrix pseudo-row). The
  transcript lines are the additive, durable record.
- **Summary** — a record-derived projection table, per cell: `n` (graded
  repeats), `mean`, **sample σ** (Bessel-corrected, EV-16 §8), `n_attempted`
  vs `n_graded`, `lengthFlagged`, and the terminal-state histogram (E3).
  TRIAGE/tie (E1) comes from the 95% CI on the **mean difference excluding
  zero**, never a mean-sort and never per-cell CI overlap. A
  majority-`stopReason=length` cell renders as `indeterminate (length
  majority)`, never a low number (E2 — length is flagged, never scored 0).
- **Recompute from records alone** — the summary is computed by a pure
  `aggregateCell(records) -> CellSummary` over the on-disk ResultRecords for
  that cellId (per `scoredUnder`), **not** from in-memory loop counters.
  This is the shared pure aggregate module both EV-20's summary and EV-21's
  leaderboard import (same-function-both-sides; byte-identical output).

## 4. Engine module(s)

New modules under `extensions/` (match the `eval*.ts` glob):

- **`extensions/eval-runner.ts`** — the I/O harness. Imports
  `loadFixture`/`listFixtureTasks`/`applyRulings` from `eval-fixtures.ts`
  and `gradeCell`/`replayJudgeVerdicts`/`projectVerdictRecord` + the record
  types from `eval-rubric.ts`. Calls `hub.spawnJob`/`hub.wait` and
  `buildChildArgv` directly (convention 7 — reuse, don't fork the hub).
- **`extensions/eval-stats.ts`** (aka `eval-aggregate.ts`; name is an
  implementer call) — the **pure** shared aggregate module: mean, n−1
  sample σ, CI-on-mean-difference triage, terminal-state histogram,
  length-flag. Reads **only** records, never the forest. Imported by both
  EV-20's summary and EV-21's leaderboard.
- **`extensions/dispatch.ts`** (settled latitude: the dispatch-primitive
  extraction) — extract from `council_dispatch`'s `execute()` body the
  override resolution → catalogue check → spawn-env construction →
  `childEnv` → spawn, parameterized by `cwd`, into a reusable function the
  harness calls directly. If the owner chooses option A (direct
  `hub.spawnJob({ cwd: scratch })` without the full extraction), that is
  within the settled latitude **provided** the driver is spawned with
  `cwd = scratch` and the override path is not forked into a second
  implementation (see §5).
- **`extensions/eval-runner.ts` store writers** — thin I/O boundaries that
  implement the store contract (§6).

## 5. Cell execution and scratch isolation (settled)

Per cell × repeat:

1. Seed a disposable scratch tree from `fixture.seed.dir` (verify
   `sha256Tree ≥` the pinned digest).
2. Run the cell driver with the model override (the effective model rides
   `COUNCIL_EVAL_MODEL` env, EV-16 §4).
3. **Spawn the cell driver with `cwd = scratch`** — `hub.spawnJob({
   cwd: scratch, ... })` through the extracted dispatch primitive (or the
   direct-call option A), **not** an external headless `pi` subprocess.
   In-process keeps the `parentJobId` chain + shared `COUNCIL_RUN_ID` so
   both roots share one runId and the forest can be joined on `parentJobId`
   (EV-16 §7/§3.1; this is what keeps A1 tree-isolation while keeping
   telemetry readable).
4. After settle, **read both-roots manifests** — `readManifests(caller,
   runId)` ∪ `readManifests(scratch, runId)`, join on `parentJobId`
   (COUNCIL_JOB_ID/COUNCIL_RUN_ID propagate so both roots share the runId).
5. **Grade** through a `GradeIO` bound to the scratch tree: settle → read
   both-roots manifests → write records → persist snapshot → rm scratch,
   all inside `runCellAndGrade(scratchDir, runId, caller, persist)`'s
   try/finally body.
6. For a judge-bearing fixture, **the harness owns the grader dispatch**:
   dispatch the judge seat once per (cell, repeat) with the fixture-pinned
   `graderModel` as an explicit `model` param (beats the env) and `cellId`
   set. Write a VerdictRecord with `repeat` projected from `meta.repeat`.
7. Write the ResultRecord with the `cellScope` block (§6), whose
   `repoState` is `sha256Tree(scratch)`.
8. If `persist` (default ON): `fs.cpSync(scratch,
   council/eval-results/<cellId>/r<repeat>/snapshot/)`; then rm scratch.

**Cell drivers have NO grader authority** (step-6/D3): the runner owns every
grader dispatch; `judge`'s `spawns: []` stays.

**Forest telemetry / three cost columns (EV-16 §7):** `cellCost =
callerSide(cellDriver.usage) + sumSubtree(readManifests(scratch, runId),
rootId = cellDriverId)`; the command column sums cells + grading; the
grading column is the grader-subtree spend. Requires the **§7 RunManifest
extension** — add `usage` and `stopReason` to `RunManifest` at `settle()`
and a pure `sumSubtree(rootId)` in `extensions/runs.ts`. This touches the
`hub.ts is stable` boundary (AGENTS.md convention 7) and ships **with a
failing test first**, never a silent field addition (F2).

## 6. Store contract (the writer lands the ruling's spec text)

Writes to `council/eval-results/` in the caller's repo, self-gitignored
exactly like `ensureRunDir`'s `.gitignore = "*\n"` pattern, idempotent and
non-clobbering (scaffold convention 6/12). Atomic writes via `writeAtomic`.

1. **`extensions/eval-rubric.ts` VerdictRecord gains `repeat: number`**
   alongside `cellId, gradedBy, fixtureVersion, rubricVersion,
   perCriterion, gradedAt, gradingUsage`. `projectVerdictRecord` projects
   `repeat` from `meta.repeat`. The store writer (`eval-runner.ts`) reads
   `record.repeat` and includes it in the filename.
2. **VerdictRecord store key `(cellId, repeat, gradedBy,
   fixtureVersion, rubricVersion)`** — three grader dispatches for repeats
   1..3 of one cell → three files, all readable. Within an existing key
   tuple, first write wins; a divergent payload for an existing key throws
   (defect). Absent key → new file.
3. **ResultRecord store key `(cellId, repeat, scoredUnder,
   fixtureVersion, rubricVersion)`** — same atomic write semantics; the
   version pair rides the key. (This extends the O1 triple with the version
   pair per Q1-D1.)
4. **`scoredUnder: "self"` sentinel** for the seven gate-only fixtures;
   no VerdictRecord is written for a gate-only cell/repeat. EV-21 renders
   `scoredUnder === "self"` rows as gate-only (score over gate criteria
   alone), real-model-id rows as graded.
5. **`cellId` string form `taskId|model[:thinking]`**; existing `cellId`
   semantics from `hub-tools.ts:75` unchanged.
6. Filenames keyed from the key tuple, sanitized for filesystem safety
   (cellId/scoredUnder contain `/` and `:`).

**`cellScope` block on ResultRecord** (settled schema):
`{ usage: { input, output, cost, turns }, elapsedMs, stopReason?,
repoState: "sha256:<64 hex>" }`. Attached by the EV-20 writer at
persistence (NOT in `gradeCell`'s signature — purity sacred). `cellScope`
is on the **ResultRecord only**; the VerdictRecord already carries the
grader-side `gradingUsage`. `n_attempted`/`n_graded`/terminal-state
histogram are **derived at read time** from the repeat set (keep R-5 crisp,
single source of truth).

## 7. Snapshot persistence (Q2)

- Flag `--persist-snapshot` default ON; `--no-persist-snapshot` to disable.
  Passed to `runCellAndGrade(scratchDir, runId, caller, persist)`.
- `runCellAndGrade` try/finally body: settle → read both-roots manifests →
  bind `GradeIO` to `scratch/` → write VerdictRecord + ResultRecord (with
  `cellScope.repoState = sha256Tree(scratch)`) → if `persist`:
  `fs.cpSync(scratch, council/eval-results/<cellId>/r<repeat>/snapshot/)`
  → rm scratch. If `!persist`: skip the copy; document that C1 cross-run
  form is not assertable for that invocation.
- EV-21's cross-run re-grade reads `treeDigest` from the persisted snapshot
  (or asserts against `seed.dir.treeDigest` if `!persist`, with a
  "deterministic-only re-grade" label).

## 8. Smoke-test phase (Q3) — in scope for EV-20

A fourth phase on the existing `smoke/run.sh` / `smoke/driver.sh` /
`smoke/assert.sh` pattern:

1. Install the package into `smoke/fixture/` (Phase 0 already does this).
2. Seed a minimal `council/fixtures/` override with one fixture (gate-only
   rubric, one model `openrouter/deepseek/deepseek-v4-flash-0731`, two
   repeats) — standard fixture loader; no new fixture-authoring machinery.
3. Drive `pi -p "/council-eval <task> <model> --repeat 2"` headlessly.
4. Assert (a) `council/eval-results/<cellId>/r1/` and `r2/` exist with
   `snapshot/` directories, (b) the transcript carries `[council-eval]`
   lines, (c) `aggregateCell(readAll(cellId))` byte-identical between the
   live call and a re-derivation, (d) `validate.py` green after the matrix
   runs.
5. Existing kill-shot probes stay green.

The smoke seeds a **gate-only fixture** — it exercises every load-bearing
seam (dispatch, scratch isolation, snapshot persist, store write, summary
render) without invoking a judge. A judge-bearing fixture smoke is a
later-card concern (lands when EV-21 needs a `scoredUnder != "self"` row to
render). **EV-20 acceptance extends to "smoke Phase 3 green from a fresh
container" — if Phase 3 cannot run, the card does not merge.**

## 9. EV-21's need (satisfied by this card)

EV-21 reads `council/eval-results/`, groups by `cellId` (which carries
task/model/thinking; the version pair rides the store key, so cellId does
not fragment across fixture bumps), aggregates on the explicit `scoredUnder`
dimension (one row per grader per cell; `"self"` rows gate-only), and
derives mean/σ/n/histogram/TRIAGE purely from records via the shared
`aggregateCell`. No in-memory or cross-run state.

## 10. Testable claims (new tests, failing first)

New test file `test/eval-runner.test.ts` (plus the RunManifest-extension
failing test first per convention 7):

1. **A1 scratch isolation** — a cell run against a seeded scratch tree
   leaves the caller's tree byte-identical (`sha256Tree(repoRoot)` before/
   after across the imported fixture set).
2. **VerdictRecord-repeat round-trip (fails against today's schema)** —
   a judge-criteria fixture at `--repeat 3` with a recording harness yields
   three distinct VerdictRecord files keyed `(cellId, 1/2/3, gradedBy)` and
   three ResultRecords each carrying a different judge verdict for that
   repeat. Today this cannot pass (keys collide at `(cellId, gradedBy)`).
3. **ResultRecord store key** — the version pair rides the key; two graders
   re-grading under the same version pair both survive (two files); a
   fixture bump produces a new version-keyed set.
4. **Gate-only sentinel** — a gate-only fixture produces `scoredUnder ===
   "self"` on the ResultRecord and no VerdictRecord.
5. **Snapshot persistence (Q2)** — after the matrix, `sha256Tree` of the
   persisted snapshot equals the cell's seed+delta; `--no-persist-snapshot`
   skips the copy and the record still carries `repoState`.
6. **Mean/σ recompute-from-records (EV-21 contract / same-function-both-
   sides)** — `aggregateCell(readAll(cellId))` equals the hand-computed mean
   and Bessel σ over graded scores; feeding the same records into EV-20's
   summary and EV-21's leaderboard path yields byte-identical `{n, mean,
   sigma}`.
7. **RunManifest extension round-trip (F1)** — extend `RunManifest`; write →
   `readManifests` round-trips usage/stopReason; `sumSubtree(rootId)` over a
   3-deep chain equals the hand-computed sum.
8. **E2** — records `[{done, score:1.0}, {done, stopReason:"length"},
   {timeout}]` yield `{n_attempted:3, n_graded:1, lengthFlagged:1,
   mean:1.0}` — never `{mean:0.33}`.
9. **E1** — two n=3 cells with overlapping score CIs render as tied; the
   summary function returns `{triage:true}`, never an asserted rank; triage
   derives from CI-on-mean-difference-excluding-zero, not per-cell overlap.
10. **Grammar** — `parseEvalArgs` unit tests: `--repeat N` and
    `--repeat=N`; default 3; cap 20 rejected loudly; unknown task refuses at
    parse naming the available list; invalid `:thinking` suffix refuses.

## 11. Acceptance mapping (the ruling extends card acceptance)

- Card acceptance 1 (accepts a task, one or more models, a repeat; runs the
  matrix; per-cell summary): §1/§2/§3 + test claims 10.
- Card acceptance 2 (one record per run; records alone recompute every
  aggregate): §3/§6 + test claims 6/8/9.
- Card acceptance 3 (progress + final summary in the transcript): §3 + echo
  + `[council-eval]` lines.
- **Extended acceptance (Q3 ruling):** smoke Phase 3 green from a fresh
  container (§8) — a hard merge gate, in addition to the owner gates.

## 12. Scope guard

This card ships the matrix runner (`eval-runner.ts`), the pure aggregate
(`eval-stats.ts`/`eval-aggregate.ts`), the dispatch-primitive extraction
(§4), the §7 RunManifest extension, the VerdictRecord/ResultRecord store
writers with the Q1/Q2 key semantics, the cellScope block, the snapshot
persistence, and the smoke Phase 3. It implements **no leaderboard UI** (that
is EV-21). Nothing in this spec asserts a design choice as settled that the
deliberation, the rulings, or the EV-16/EV-19 specs left open. No external
headless `pi` subprocess for cell execution (settled: in-process
`cwd=scratch`). No second progress widget (settled). The smoke seeds a
gate-only fixture only (§8 scope).
