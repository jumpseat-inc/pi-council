# EV-32 design — usage reported at every autonomous exit point

- **Card:** `EV-32` (epic `EPIC-7`), `council/cards/EV-32.md`
- **Status:** settled by the step-2–6 deliberation and the **step-6 rulings**
  (`product-owner` on items C–J, `steward` on items A/B/I), appended verbatim
  to the card's run record. This document is the write-up, not a
  re-derivation. Nothing settled in steps 2–6 is reopened here, and nothing a
  Phase 1 ruling owns is restated with a different shape.
- **Binding inputs:**
  - Phase 1 rulings **R-1** (money signifier), **R-2** (unavailable marker +
    legend text), **R-4** (boundary label bytes), **R-5** (empty/failure
    literals), **R-6** (one deterministic block, identical in shape), and
    **R-SCOPE** (FLLWUP-31 stays `Backlog`).
  - The **step-6 `steward` ruling** — A(c) `boundaryMode: "marker"`, B (three
    whole-block states, precedence failed > unresolved > empty), I (point-4
    acceptance amendment + the unresolved-boundary fixture).
  - The **step-6 `product-owner` ruling** — C (R-6 = grammar identity; point-5
    runner block omits `ownSession`), D (`n/a` via explicit per-half input; the
    literal is struck from the acceptance test until EV-29), E (legend
    conditional), F (`basis=` from data; fixed-column half label; bracket
    annotations rejected; ≤160 cols), G (render at the flush `written`
    transition), H (`notify`/`console.log` counts), J (block replaces the
    EV-31 flush notify; failure reason composes the absolute path).
  - EV-30 step-6 ruling items 3 (unresolved label form), 4 (zero-both, never an
    error), 7 (`lastEntryId = leafId`); EV-28 Q1/Q4/Q5 and its byte-tested
    `formatUsageSegment`; EV-31 spec §2.3 (`SpendRecord` gains no field),
    §2.4 (the one gated write path), §2.7 (the notify wording is EV-32's).
  - Where this document and a ruling disagree, the ruling wins.
- **Scope:** the pure block renderer, the runner-shaped block, the
  `boundaryMode` extension to `spendRecord` + the pending ledger, the five
  render sites, the one `features-deliver` Phase 3 sentence, and the tests
  that hold them. Not exit-point **provider** reporting (EV-29), not per-node
  subtree reconciliation into seat session files (FLLWUP-31), not store
  recompute, not retention, not a wiki page (optional step-14 follow-up).

## 1. Problem

EV-28 gave the hub a full usage tuple and a provenance-labelled money literal;
EV-30 gave an invocation a `SpendRecord` (two halves, two bases, a resolved or
unresolved boundary); EV-31 made that record durable outside the pruned run
directory. None of the three **prints** it. The five autonomous exits today end
in either a scalar (`cost=$X` on the `council_wait` head line, EV-28) or
nothing at all:

| exit | artifact | what it prints today |
|---|---|---|
| `/features-new`, `/features-deliver`, `/council` | scanned procedure handler (`index.ts:275–303`) + EV-31 flush | a store-path notify (`usage-store.ts:362-364`) or nothing |
| `/council-eval` | TS command handler (`index.ts:437–503`) | the matrix summary; **stamps no marker, so it has no record** |
| council-runner card execution | `council_wait`'s `formatReport` (`hub-tools.ts:64–79`) | the per-job EV-28 head-line segment |

The card's goal is a usage block — token split, provenance-labelled dollar
value, accounting boundary — present in the concluding output at all five, with
a test asserting the numbers equal the fixture accounting record. The block
must be deterministic engine output (same input, same bytes), which rules out
the procedures' own LLM prose and rules in a pure renderer plus deterministic
emission sites.

## 2. Settled design

### 2.1 The block grammar (byte level)

Every line of every block carries the ruled `usage` + **two spaces** prefix
(implied by R-5's two bound literals, which both begin `usage  `). The block is
a whole-block replacement in each of three states; state 1/2 are R-5's bound
literals, state 3 is steward B's new literal.

**Resolved state** (session-boundary form, points 1–4) — rows in this order:

```
usage  ownSession  basis=session-reconciled  turns=<t> tokens=in <i>/out <o>/cR <cR>/cW <cW>/reason <r>/total <T> cost≈$<c> (catalogue)
usage  subtree     basis=stream-assistant   turns=<t> tokens=in <i>/out <o>/cR <cR>/cW <cW>/reason <r>/total <T> cost≈$<c> (catalogue)
usage  boundary=session=<sessionId> entries=<firstId>..<lastId> jobs=<n>
usage  n/a = provider figure unavailable
```

Fixed grammar, per the rulings:

- **Row prefix / label column** (PO F): `usage  ` + half label
  (`ownSession` | `subtree`) padded with spaces to a fixed 10-column field +
  two spaces + `basis=<record.<half>.usageSource>` read from data. `ownSession`
  (10 chars) renders `usage  ownSession  basis=…`; `subtree` (7 chars) renders
  `usage  subtree     basis=…`. The `basis=` value is never hardcoded — a half
  can therefore never be mislabelled.
- **Token/money fragment** (R-1 verbatim; EV-28 Q5 field order): the segment is
  `turns=<t> tokens=in <i>/out <o>/cR <cR>/cW <cW>/reason <r>/total <T>` + one
  space + `formatMoney(half)`. `formatMoney` renders
  `cost≈$<c.toFixed(4)> (catalogue)` with U+2248, or
  `cost=$<c.toFixed(4)> (reported)` — the R-1 literals byte-exact. Labels
  collapse `cacheRead`/`cacheWrite`/`reasoning` to `cR`/`cW`/`reason`; no
  thousands separators.
- **Boundary row** (R-4): `usage  ` + `formatBoundaryLabel(record)` verbatim —
  never re-rendered. `formatBoundaryLabel` keeps R-4's shape unchanged
  (steward A).
- **Legend row** (R-2 text, PO E conditionality): `usage  n/a = provider figure
  unavailable`, present **iff** at least one half was named in the renderer's
  `unavailableCost` input. Absent in the runner form and in every whole-block
  state.
- No ANSI, no locale, no clock, no I/O. Every line ≤160 columns (EV-28 T5).

**Runner state** (point 5 only) — same prefix, same label column, same
`basis=` field, same boundary line position; the `ownSession` row is **omitted**
(PO C; R-SCOPE leaves FLLWUP-31 in `Backlog`), and the boundary row is a
job-scope label:

```
usage  subtree     basis=stream-assistant  turns=<t> tokens=in <i>/out <o>/cR <cR>/cW <cW>/reason <r>/total <T> cost≈$<c> (catalogue)
usage  boundary=session=<jobId> entries=unresolved jobs=<n>
```

`entries=unresolved` is honest: the parent cannot resolve a session entry range
for a job, and the runner never stamps a marker (seats return into
`runChildMode` before procedure registration). `jobs=<n>` is the true subtree
node count. The row is composed by `formatRunnerUsageBlock`; EV-30's
`formatBoundaryLabel` is **not** called for it (its unresolved branch hardcodes
`jobs=0`, which would be false here), and is not modified.

### 2.2 `formatUsageBlock` (session-boundary form)

New pure leaf module **`extensions/usage-block.ts`** — no `node:fs`, no `ctx`,
no hub import; types only from `./runs.ts` / `./spend.ts` / the shared formatter.

```ts
export type Half = "ownSession" | "subtree";

export type UsageBlockInput =
  | { record: SpendRecord; unavailableCost?: Half[] }
  | { failed: string };

export function formatUsageBlock(input: UsageBlockInput): string;
```

- The signature is PO effect item 1, verbatim.
- **Composition, never forks** (PO effect item 1): `formatUsageBlock` reuses the
  token/money fragments and the boundary label rather than re-implementing
  them. The token and money fragments are extracted out of `formatUsageSegment`
  (`hub-tools.ts:51`) into a shared pure module — `extensions/usage-format.ts`
  with `formatTokensFragment(u)` and `formatMoney(u)` — and `formatUsageSegment`
  is re-exported from `hub-tools.ts` so EV-28's landed import and byte test are
  untouched. A byte-identity test pins `formatUsageSegment`'s output across the
  refactor (the EV-28 regression guard, owner T-B7).
- The `{failed}` variant renders state 2 (§2.3). `<reason>` is call-site data,
  newline-normalized so the state stays exactly one line.

### 2.3 The three whole-block states and their precedence (steward B)

`formatUsageBlock` on `{ record }` selects exactly one state, in this precedence
order — **failed > unresolved > empty**:

| # | Output (whole block, exactly one line) | Condition |
|---|---|---|
| 1 | `usage  no usage recorded` | `record.boundary.resolved === true` **and** every numeric metric of both halves is 0 |
| 2 | `usage  accounting failed — <reason>` | the caller's `{ failed }` variant (U+2014 in the literal) |
| 3 | `usage  accounting boundary unresolved` | `record.boundary.resolved === false` |

- A measured zero is claimable only once the boundary resolved; an unresolved
  boundary has no measured zero; a failure has no record to read. Hence the
  precedence.
- State 3 is the surface counterpart of the durable record's
  `boundary.resolved: false` + EV-30's `entries=unresolved` label, which stay on
  the record for forensics (steward B).
- No state renders a legend or a boundary row.

`formatRunnerUsageBlock` (point 5) does **not** use this state machine: it
scopes by `sumSubtree(job.id)`, not by a session boundary, and its zero state
**remains state 1** (steward I) — every numeric metric of its single `subtree`
half zero → exactly `usage  no usage recorded`.

### 2.4 `boundaryMode` on `spendRecord` (steward A(c))

`spend.ts` gains one optional parameter, default `"user-message"`, preserving
today's behavior **byte-for-byte** for every existing call site and test:

```ts
export function spendRecord(opts: {
  entries: SessionEntry[];
  leafId: string | null;
  sessionId: string;
  markerId: string | null;
  manifests: RunManifest[];
  boundaryMode?: "user-message" | "marker"; // default "user-message"
}): SpendRecord;
```

- **`"user-message"` (default, unchanged):** the boundary is the first on-chain
  user message after `markerId` in `getEntries()` append order; unresolvable ⇒
  the identical zero-both record as today.
- **`"marker"` (new, opt-in, for invocations whose handler awaits and never
  injects a user message):** the anchor **is** `markerId`, required present and
  on the active chain. Then `boundary.resolved = true`,
  `boundary.firstEntryId = markerId`, `boundary.lastEntryId = leafId`
  (EV-30 ruling item 7, unchanged). The forest gate's clock is the on-chain
  marker entry's own recorded timestamp — the same `timestamp` field the
  default mode reads off the boundary entry (in this mode the marker entry *is*
  the boundary entry). No new `Date.now()` call, no invented timestamp. If the
  marker is absent or off-chain, `"marker"` returns the identical unresolved
  zero-both record as today.
- **`SpendRecord` and `SpendBoundary` shapes are not touched** (EV-31 spec
  §2.3; EV-30 ruling item 2): the mode is a call-site discriminator, and the
  schema-versioned store record describes itself.

The pass-through point is EV-31's pending ledger:

- `PendingInvocation` (`usage-store.ts`) gains `boundaryMode?: "user-message" |
  "marker"`.
- `flushPendingInvocations` forwards it to `spendRecord`
  (`boundaryMode: p.boundaryMode ?? "user-message"`).
- The scanned-procedure push (`index.ts:275–303`) sets `"user-message"` (or
  omits it — the default).
- The `/council-eval` push sets `"marker"`.

### 2.5 The five render sites

**Points 1–3 — `/features-new`, `/features-deliver`, `/council`.** No procedure
prose changes. The scanned handler already stamps the marker and pushes the
pending invocation. The block **is** the flush's `written`-transition notify,
replacing the store-path success notify at `usage-store.ts:362-364` (PO G, J):

| flush outcome | emission |
|---|---|
| `written` | `formatUsageBlock({ record: res.record.spend })` — one block |
| `failed` | `formatUsageBlock({ failed: \`write failed for ${file}: ${msg}\` })` → state 2, absolute path preserved (EV-31 T-U14) |
| `existing` | **silent** — choose-once already satisfied at a prior settle (PO G) |
| `gate-closed` | no emission; the entry stays pending (not a concluding output) |
| `unkeyable` | unchanged existing warning; no block (no marker time to key a record) |

Sink is the existing dual route: `ctx.ui.notify` (TUI) / `console.log`
(headless) (PO H). **Never `sendUserMessage`** — an injected turn would land
inside the boundary's own-session range and be counted by the next
reconciliation, falsifying the card's "cannot include the cost of its own
generation" clause.

**Additional failure emission (item 6).** In the scanned handler, when
`recordInvocationBoundary` returns `null`, the handler synchronously emits
`usage  accounting failed — invocation boundary unresolvable` (state 2) — the
today-silent fail-closed path is never blank. No pending entry is pushed.

**Point 4 — `/council-eval`.** The handler (`index.ts:437–503`) gains, **after
the no-arg listing early-return and after arg/model validation, before the
first cell spawns**:

1. `recordInvocationBoundary(pi, ctx, "council-eval", runId)` and, when it
   returns a marker id, a pending push with `boundaryMode: "marker"` (the
   marker's `at` read back off the on-chain entry, exactly as the scanned push
   does). When it returns `null`, the same state-2 emission as item 6.
2. At the awaited post-`runMatrix` tail, an explicit `flushUsage(...)` drain
   before `emit(summaryLines(...))`. This is idempotent: if the forest-settle
   flush already wrote the record, the outcome is `existing` and nothing is
   emitted; if it had not (a race, a skipped event), the tail writes and emits
   exactly one block. No `rendered` set (PO G rejected it).

Net effect: exactly one block per eval invocation, landing in the same
concluding output as the summary. The default mode is untouched, so O1's
default-mode probe stays `closed-red` — correctly, because the default must
remain fail-closed (steward A).

**Point 5 — council-runner card execution (`council_wait`).** The parent
renders; the runner never self-computes (Skeptic O5/O6: the runner's job is
null-rooted but its session has no marker, and a null marker zeroes both
halves). In `council_wait`'s `execute`, after `hub.wait(...)`:

```
manifests = readManifests(repoRoot, hub.runId)
for each report whose state is settled (done | failed | cancelled | stalled):
    subtree, jobCount = sumSubtreeUsage(manifests, report.id)   // inclusive, all metrics
    text += "\n\n" + formatRunnerUsageBlock({ sessionId: report.id, jobCount, subtree })
```

- `sumSubtreeUsage` is a new **additive** pure helper (in `runs.ts` or
  `usage-block.ts`; the owner chooses) that walks `parentJobId` descendants
  inclusive and sums every `UsageMetric`; it does not change `sumSubtree`
  (EV-16 §7). `costBasis: "catalogue-estimate"`, `usageSource:
  "stream-assistant"` (the manifest tuple's machine vocabulary).
- `report.id` **is** the job's session id (the hub writes
  `sessionId: job.id`, `hub.ts:94–106`).
- A running or timed-out job gets **no** block (not a conclusion). A settled
  job with no manifest (pre-EV-16) renders state 1 — never blank.
- The EV-28 head-line segment in `formatReport` stays untouched (settled,
  byte-tested, and it answers a different question).

### 2.6 `features-deliver` Phase 3 (PO item 5)

`council/procedures/features-deliver.md` Phase 3 gains exactly one sentence:

> Carry each card's runner usage block verbatim from the `council_wait` report
> into this ledger's per-card entry.

The block remains engine-rendered; the orchestrator only transports it.

### 2.7 The `deps`-injected matrix runner (PO item 7)

`/council-eval`'s run path must be exercisable in a unit test with **no
network**. The handler's matrix runner (default = the real `runMatrix`) is
injected through a `deps` seam (an exported handler factory, or a registration
helper taking `deps`) so a test can drive the real path with a double that
returns fixture summaries and seeds fixture manifests. The test asserts: the
marker is stamped and the pending invocation pushed with
`boundaryMode: "marker"`; the no-arg listing form pushes nothing; and exactly
one block is emitted.

## 3. Acceptance (as amended by the step-6 rulings)

The card's own `Acceptance` bullets stand; the step-6 rulings bind how they are
read:

1. **For each of the five points, a fixture accounting record renders a usage
   block whose numbers equal the record.** Points 1–3 through the flush seam
   (fixture entries + manifests + a temp `storeRoot`); point 4 through the
   eval path (marker mode); point 5 through `council_wait`'s report.
   **Point 4, for a non-empty matrix fixture, additionally requires**
   `boundary.resolved === true`, `boundary.firstEntryId !== null`,
   `boundary.jobCount >= 1`, and `subtree.totalTokens > 0` — joined to, not
   replaced by, the equality (steward I).
2. **The block is byte-stable across repeated renders of the same input.**
   `formatUsageBlock` called twice, and on a `structuredClone`, yields identical
   bytes; the module contains no clock, locale, random, or I/O.
3. **The block names its accounting boundary.** The resolved session block
   contains `formatBoundaryLabel(record)` verbatim; the runner block contains
   its job-scope boundary row.
4. **Zero-usage and accounting-failure inputs render explicit, non-blank
   states.** State 1 for a measured zero, state 2 for a failure, and — added by
   steward B — state 3 `usage  accounting boundary unresolved` for an
   unresolved boundary. The fixture set gains an unresolved-boundary fixture
   that must render state 3, distinct from the measured-zero fixture rendering
   state 1 (steward I).
5. **`bun test`, `bunx tsc --noEmit`, `python3 council/validate.py` stay
   green.**

**R-2 is not in the acceptance test until EV-29.** The `n/a` literal is struck
from the acceptance test (PO D): until EV-29 supplies the in-band signal, no
slot renders `n/a` and no legend renders against real data. The renderer takes
`unavailableCost` today and is testable with a **fixture-supplied** signal at
the pure-renderer seam only.

## 4. Test plan

Module `test/usage-block.test.ts` (new) plus additions to `test/usage-store.test.ts`
and `test/spend.test.ts`:

- **T1 (per exit):** a fixture `SpendRecord` → every metric parse-back-equals
  the record field; no line contains a sum of the two halves.
- **T2 (byte stability):** two calls + a clone → identical bytes.
- **T3 (state 1):** all-zero resolved record → exactly `usage  no usage
  recorded`.
- **T4 (state 2):** `{ failed }` → exactly `usage  accounting failed — …` with
  U+2014 asserted by code point, one line after newline normalization.
- **T5 (state 3):** unresolved-boundary record → exactly
  `usage  accounting boundary unresolved`, and **not** equal to the
  measured-zero render (the steward-I distinction).
- **T6 (R-1):** catalogue → U+2248 `cost≈$…(catalogue)`; reported →
  `cost=$…(reported)`.
- **T7 (R-4):** resolved block contains `formatBoundaryLabel(record)` verbatim.
- **T8 (`n/a` hook):** `unavailableCost: ["subtree"]` → that slot reads
  `cost=n/a` and the legend line is present; no `unavailableCost` → no legend;
  no legend in any whole-block state.
- **T9 (EV-28 regression):** `formatUsageSegment` byte-identical before/after
  the helper extraction.
- **T10 (runner block):** fixture manifests (runner + ≥1 descendant) →
  `council_wait`'s report contains **no ownSession line**, **one subtree line**
  whose every metric equals `sumSubtree(manifests, job.id)`, and the boundary
  row `entries=unresolved jobs=<true count>`.
- **T11 (runner zero):** settled job with no manifest usage → state 1.
- **T12 (one emission):** `written` → exactly one notify equal to
  `formatUsageBlock(record)`; `existing` → zero; a second `agent_settled` after
  a written invocation → zero.
- **T13 (no session turn):** entry count and leaf id unchanged across an
  emission; `sendUserMessage` never called with a block.
- **T14 (marker mode):** `spendRecord({ boundaryMode: "marker", markerId })`
  with a non-empty fixture matrix → `resolved: true`,
  `firstEntryId === markerId`, `lastEntryId === leafId`, `jobCount >= 1`,
  `subtree.totalTokens > 0`; marker absent/off-chain → the identical zero-both
  record; default mode unchanged on the same fixture.
- **T15 (eval path):** the `deps` double drives the real run path → marker
  stamped, pending pushed with `boundaryMode: "marker"`, no-arg form pushes
  nothing, exactly one block emitted.
- **T16 (width):** every line of every fixture render ≤160 columns.
- **Gates:** `bash council/preflight.sh`, `bunx tsc --noEmit`, `bun test`,
  `python3 council/validate.py`; the network integration test stays behind
  `COUNCIL_INTEGRATION=1`.

## 5. Out of scope (named, not done here)

- **EV-29** — the in-band "provider figure unavailable" signal and the
  provider-reported path. EV-32 ships the renderer hook + conditional legend.
- **FLLWUP-31** — per-node subtree reconciliation against seat session files
  (the real `ownSession` half for point 5). R-SCOPE keeps it `Backlog`; the
  omission is the card-satisfying minimum.
- **Store recompute / retention** — EV-31's store owns those; no change.
- **A usage/accounting wiki page** — the vault has none; a natural step-14
  candidate, not a deliverable of this card.

## 6. Standing constraints honored

- `SpendRecord`'s shape is untouched; EV-30's zero-both invariant and
  rejected-option-4 stand; `formatBoundaryLabel` keeps R-4's shape.
- `spendRecord`'s new parameter defaults to today's behavior byte-for-byte, so
  every existing call site and test is byte-preserving.
- No new resource mechanism (AGENTS.md convention 5); the renderer is a plain
  pure module and the shared formatter is a module move with a re-export.
- Main-repo immutability: the owner implements in a dedicated
  `git worktree add` worktree, never the main checkout.
