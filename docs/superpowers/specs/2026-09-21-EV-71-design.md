# EV-71 — Decisions-aware gate spend accounting (design spec)

Status: settled (full council, 3 rounds + skeptic attack + O9b follow-up + PO
ruling 2026-09-21). This document writes up what the deliberation settled;
it derives nothing. The card's `goal:` (as amended by the ruling) is the
judge's contract and is reproduced verbatim below.

## 0. The contract

**Goal (verbatim, judge reads this):**

> Gate spend is journalled by the ledger's single writer storing the
> decisions response's usage.cost figure verbatim, with no synthesised and no
> second cost field on the emitted call line, and journalled with the
> decision generation id that response reported, and the provider
> reconciliation accounts for gate spend by accepting decision generation ids
> sourced from the gate ledger, proven by an injected-fetch-double test in
> which a ledger-sourced generation id beginning gen-dec- is looked up and
> its reported total_cost resolves into the gate total while a seat
> transcript that carries no decision generation id triggers no decision
> lookup and no gate call's cost is ever derived from a catalogue estimate.

**Grammar scoping (PO ruling, verbatim — binds the Acceptance and every
golden's header):**

> "The block's grammar is unchanged" means row grammar and state exclusivity,
> not line count. A render is grammar-preserving iff, for every input: (1)
> every emitted line is one of the three bound whole-block state lines (or
> the usage  accounting failed — <reason> prefix line) or a row carrying the
> literal "usage  " prefix; (2) every row keeps its ruled key and "key = short
> definition" shape, label column unpadded as ruled; (3) row order is the
> ruled order and each conditional legend keeps its slot, the stack reading
> reported → partial → n/a → gate with gate last; (4) at most one whole-block
> state line appears, never two, precedence failed > unresolved > empty
> unchanged, and the state line is always the block's first line; (5) with
> zero gate calls in window the block is byte-identical to the pre-EV-71
> render.

**Binding acceptance clarification:** "Present iff ≥1 gate call falls in the
window" scopes to blocks rendered from a persisted record; `{ failed: string
}` is a named, chosen exception, and its golden comment must read "chosen: no
persisted record to render from", NEVER "impossible" (skeptic O10 closed-red
against the impossibility wording — the caller's probe printed the second
line).

**Adopted (O-C):** `sumGateSpend` goldens compare through one float path
(`0.0042 − 0.001 = 0.0031999999999999997`), never a hand-written decimal.

**PO ruling J1:** no `costBasis` field. `gate-ledger.ts` is not touched.
Enforced by T-B (round-trip `0.0042` in, `0.0042` out exactly), T-C (the
emitted line carries no cost-bearing key other than `usage.cost`), T-D (no
catalogue-cost path reachable from the gate path).

**PO ruling J2 (framing B):** whole-block-state relaxation is an application
of R-6 ("grammar identity, not line-count"), not an amendment. Legend granted
after the state line in `no usage recorded` and `accounting boundary
unresolved`; denied in `accounting failed`. Not a general license.

## 1. Settled design

### 1.1 Vehicle (settled — the card's central convergence)

A **separate gate-spend reconciliation** whose result persists as a
**top-level `StoredUsageRecord.gate` sibling parallel to `provider`**. It
shares only `fetchGeneration` (the injected transport type and the real
transport) with the seat reconciliation. `fetchProviderReport`,
`ProviderCostReport`, `jobs`, `sessionPath`, `generations[]`, `totalCost`,
`routedMultiset`, `partial`, `unaccountedAttempts`, and `status` stay
**byte-identical** when gate calls are present. Gate generations NEVER enter
the seat `generations` array — the no-fold-in property is structural, not
test-enforced.

Why (settled by T1/T2, both proved against base code by skeptic O2/O4/O5):
nesting the gate result inside `ProviderCostReport` (a) marks the subtree
half `cost=n/a` via `usage-block.ts`'s `status === "unavailable"` branch even
when the subtree's catalogue cost is a real measured number, and (b) loses
the legend on a failed-call-only window (zero callable ids ⇒ the early return
still yields `null` ⇒ the predicate source is `undefined`). The top-level
sibling dissolves both by construction: `provider` stays `null` when no seat
job ran; `gate` is set by `callsInWindow > 0` independently.

### 1.2 The ledger half — `extensions/gate-ledger.ts` is NOT touched

`appendGateCall` remains the sole writer of the v2 call line and computes
nothing: it stores the decisions response's `usage.cost` (and
`generationId`) verbatim, as they arrived. No `costBasis` key, no schema
bump, no writer change (PO J1). The reported basis is structural. A failed
call (`failRun`) carries neither `usage` nor `generationId` — absent, never
zero-derived.

### 1.3 The reconciliation half — `extensions/provider-cost.ts`

New exported function (working name `reconcileGateSpend`; any clear name
satisfies the spec):

- **Input:** `gateCalls?: { callId: string; generationId: string }[]` —
  values passed in by the caller (this module stays ledger-agnostic: no
  `gate-ledger` import; the source pin "ids enter only through the
  ledger-sourced input" is then structural). Lookups run through the same
  injected `fetchGeneration` / `apiKey` / `timeoutMs` seam, after any seat
  work. A `null` id contributes nothing (failed call — no lookup).
- **Result (the `GateSpendReport` that becomes the record's `gate`
  sibling):**
  - `callsInWindow: number` — windowed gate call lines (the call-claim
    count; a failed call counts).
  - `totalCost: number | null` — **ledger-authoritative**: Σ of finite
    `usage.cost` over the windowed calls (`sumGateSpend` semantics: absent /
    null / non-finite contribute nothing; `null` iff none carried; never
    zero-derived from absence).
  - `lookupCost: number | null` — Σ over looked-up generations' reported
    `total_cost`. **A distinct observable field** — ledger Σ and lookup Σ
    must be separately observable so a verification can disagree; a
    mismatch is record-only, never rendered.
  - `failedLookups: number` — lookups that timed out or returned a
    non-OK/erroring response. A failed gate lookup never poisons anything
    else; the ledger carries the cost.
- `api_type` is **inert**: `GenerationResponse` does not carry it,
  `toGeneration` never reads it, and no field is added (grep = 0 hits in
  `extensions/` and `test/`; skeptic O6 closed-green). The double may return
  it; behavior must be byte-identical with and without it. Spec correction
  vs. the original card context sentence is recorded here and at
  merge-check.

### 1.4 The store half — `extensions/usage-store.ts` (`flushPendingInvocations`)

- One `readGateLedger(input.repoRoot)` per flush pass (outside the pending
  loop; the ledger is repo-scoped).
- Per pending invocation, window predicate: `Date.parse(call.recordedAt) >=
  p.markerAt`. Lower-bound exclusion is the only rule; O9b settled
  closed-green that sequential same-session over-attribution does not occur
  (each invocation's `markerAt` comes from its own marker entry, and a later
  marker exceeds any call the earlier invocation issued). The surviving
  residual — later calls entering an earlier window on a deferred re-read —
  is the already-documented T8 drift, accepted-and-named in a test comment.
- The windowed calls build `gateCalls` (id non-null only) and the
  `callsInWindow` count; the reconciliation result persists as
  `record.gate`, **present iff `callsInWindow > 0`**, independent of
  `provider` (which stays `null` when no seat job ran). Advisory-mode calls
  are included (an advisory call still spends; `callsInWindow` counts it).
- `USAGE_RECORD_SCHEMA_VERSION` stays 2 — additive optional sibling, the
  EV-29 `provider` precedent. No schema bump.
- The write-transition notify composes the block from the **persisted**
  record (`res.record`), so "shown == disk" holds by construction — exactly
  the current pattern for `provider`.
- The `{ failed: string }` notify path stays byte-identical to today: the
  failure render is single-line, no gate legend (chosen exception, §1.5).

### 1.5 The surface half — `extensions/usage-block.ts`

- `UsageBlockInput`'s record variant gains an optional
  `gate?: { callsInWindow: number; totalCost: number | null; ... }` member
  (the record's `gate` sibling, passed through). `SpendRecord` itself is
  untouched (byte-verbatim, never extended).
- New legend literal: `usage  gate = excluded from this total` —
  `usage  ` prefix (literal `usage` + two spaces) + key `gate` + ` = ` +
  `excluded from this total`. Label column unpadded, key = short definition
  shape, per grammar-scoping clause (2).
- **Slot: last** in the conditional stack — `reported → partial → n/a →
  gate` — pushed after `LEGEND_LINE`, iff `gate !== undefined &&
  gate.callsInWindow > 0`.
- **Whole-block states (PO J2):**
  - `no usage recorded` + ≥1 gate call in window → state line, then the gate
    legend (two lines).
  - `accounting boundary unresolved` + ≥1 gate call in window → unresolved
    line, then the gate legend (two lines).
  - `accounting failed` → single line, never a legend. Golden comment MUST
    read: `// Decision: chosen: no persisted record to render from` — never
    "impossible".
  - Rationale: in the empty and unresolved states a gate call missed at this
    flush is permanently off the surface (the next invocation's window will
    not re-include it), and suppressing the legend there would assert that
    nothing was recorded when something was — the exact failure class the
    card exists to kill. Measurement rows, the boundary row and the reported
    row NEVER appear in a whole-block state.
- Gate-absent renders are byte-identical to the pre-EV-71 render (existing
  goldens stay green untouched).
- Docstring note to land in the implementation (designer's ask): "block =
  exclusion surface, ledger = trace surface" — the legend's job is the
  exclusion; the ledger is the audit trace.

### 1.6 Runner form — untouched

`formatRunnerUsageBlock` gains nothing. Structurally impossible for a runner
to issue a gate call: `council_gate` is registered parent-side, no seat
grants the `gate` tool, and the runner form is parent-rendered (skeptic O11
closed-green). One test comment pins this; no code change.

### 1.7 Precedence and totals (settled)

- Ledger-authoritative: `gate.totalCost = sumGateSpend(windowedCalls)`.
- `lookupCost` is the independent verification figure. The acceptance
  property ("its reported total_cost resolves into the gate total") is the
  equality test on a fixture where they agree; a disagreement fixture pins
  that both figures remain separately observable and the render is
  unaffected.
- No catalogue estimate is ever consulted for gate spend: no catalogue rate
  table or `calculateCost` import is reachable from the gate path (T-D).

## 2. Test plan

New file `test/gate-spend-reconcile.test.ts`; additions to
`test/usage-block.test.ts` and `test/usage-store.test.ts`. All mkdtemp +
injected doubles; no network, no timers. Every golden carries the
grammar-scoping wording in its header comment. **O-C: every Σ golden
compares through one float path — `0.0042 − 0.001 = 0.0031999999999999997`
— never a hand-written decimal.**

Mandatory set (designer's 11, plus the ruling's three):

1. **Red-at-base C1 (seven-field record):** no `gate` sibling and no gate
   reconciliation exist at base — the sibling test cannot compile/pass at
   base. Record per the red-base convention.
2. **T-B (J1):** `appendGateCall` round-trip — `usage.cost = 0.0042` in,
   `0.0042` out exactly.
3. **T-C (J1):** the emitted line carries no cost-bearing key other than
   `usage.cost`.
4. **T-D (J1):** no catalogue-cost path reachable from the gate path
   (source canary).
5. **Stack order, all conditions normal:** ≥1 gate call + reported + partial
   + n/a → exact byte-equality with the seven-row block in canonical order.
6. **`no usage recorded` + ≥1 gate call** → state line + gate legend
   (load-bearing G6; red at base).
7. **`accounting boundary unresolved` + ≥1 gate call** → unresolved line +
   gate legend.
8. **`accounting failed` + ≥1 gate call** → single line, with the
   `// Decision: chosen: no persisted record to render from` comment.
9. **No-gate byte-identity:** zero gate calls in window → byte-identical to
   the pre-EV-71 render (existing goldens untouched).
10. **Legend without `provider`:** `provider` null/absent + `gate.callsInWindow
    > 0` → legend renders (regression check; structural under the sibling).
11. **Gate-only, no-seat-job window, real catalogue cost** (principal T1):
    proves `provider.status` is computed over seat generations only and the
    nested-poisoning shape cannot recur.
12. **Failed-call-only window still renders the legend** (T2/C4/C5): zero
    callable ids, `usage: null`, no `generationId`, `record.gate` set, legend
    present, zero lookups, `gate.totalCost === null` — call-claim, not
    spend-claim.
13. **Injected-fetch-double resolution (the acceptance property):** the
    ledger-sourced `gen-dec-…` id is looked up exactly once through the
    injected double; its reported `total_cost` equals `gate.totalCost` and
    the ledger Σ through one float path.
14. **Seat-transcript silence:** entries carrying only ordinary `responseId`s
    trigger no decision lookup — no `gen-dec-` id is ever fetched from a
    transcript source.
15. **`api_type` inert:** doubles with `api_type: "decisions"` vs `"chat"`
    resolve byte-identically.
16. **Window predicate:** calls with `recordedAt < markerAt` excluded,
    `>= markerAt` included (equality inclusive); a prior invocation's call
    never contributes to the current flush's record.
17. **Ledger authority vs lookup:** double returns a divergent `total_cost`
    → `gate.totalCost` stays the ledger Σ; `lookupCost` keeps the lookup Σ;
    both observable; render unaffected.
18. **Mixed ledger:** v1 lines, v2 lines, `usage: null`, failed lines, torn
    tail → sum counts only finite `usage.cost` values via the real
    `readGateLedger`; expected Σ through one float path (`0.0031999999999999997`
    for the 0.0042/−0.001/0 fixture).
19. **Block purity:** a ledger file with gate calls on disk + a record
    lacking `gate` → no legend (the predicate is persisted, never fs-read at
    render).
20. **Persisted-sibling integration:** the flush writes `record.gate` and the
    write-transition notify composes the block from the persisted record.
