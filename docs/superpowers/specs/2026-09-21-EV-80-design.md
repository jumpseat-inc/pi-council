# EV-80 — Follow-up review state packing: candidate + board/open cards + same-run siblings

Design spec, written from the settled deliberation record
(`council/cards/EV-80.md`, rounds 1–3 + skeptic + consolidator) and the
binding product-owner ruling of 2026-09-21
(`vault/raw/2026-09-21-po-ev80-state-packing-ruling.md`). Everything below was
closed in deliberation or by the ruling; the implementer re-derives nothing.

## 1. Deliverable

One new pure module `extensions/followup-state.ts`, sibling to
`extensions/gate-state.ts`, exporting:

```ts
export function buildFollowupState(
	candidate: FollowupCandidate,
	repoRoot: string,
	siblings: FollowupCandidate[],
	boardPath: string,
): FollowupState;
```

`boardPath` is a **required** 4th parameter — a missing `boardPath` is a
compile-time type error, never a runtime throw and never a derived default.
(The derived default was killed in round 2: it reintroduces the ambient-input
class the card's acceptance bans.)

### Import edges (fixed, do not alter)

- `loadGatePolicy` (value) from `./gate.ts`.
- `estimateTokens` (value) and `ParsedCard` (type) from `./gate-state.ts`.
- `parseCardFile` (value) from `./gate-route.ts` ("the ONLY card extractor in
  the engine" — no second frontmatter parser).

The module must **not** live inside `gate-state.ts`: that module's header pins
type-only imports from `./gate.ts` (the FLLWUP-81 decoupling), and the budget
seam needs a value import of `loadGatePolicy`. `extensions/gate-state.ts`,
`extensions/gate.ts`, and `extensions/gate-route.ts` stay byte-untouched; EV-80
only imports from them.

### The pair rule (ruling Q2, one module comment, near-verbatim)

> The board and its cards are one resource; the cards dir is derived from
> `boardPath`, never from `repoRoot`.

Open-card goals resolve at
`path.join(path.dirname(boardPath), "cards", "<id>.md")`. `repoRoot` anchors
the policy load and nothing else in the board-pair resolution.

## 2. Types

```ts
export const FOLLOWUP_SECTIONS = ["candidate", "board", "siblings"] as const;
export type FollowupSection = (typeof FOLLOWUP_SECTIONS)[number];

export interface FollowupCandidate { title: string; goal: string; }

export interface FollowupDropRecord { /* fresh, section: FollowupSection */ }

export interface FollowupState {
	stateBytes: Uint8Array;
	stateHash: string;
	drops: FollowupDropRecord[];
	sections: /* structured per-section kept entries, see §4 */;
	sources: {
		board: { present: boolean; skippedLines: number };
		cards: { missingGoal: string[] };
	};
}
```

- `FollowupCandidate` fields are non-empty; empty/whitespace `title` or `goal`
  throws naming `candidate.title` / `candidate.goal` (fail loud on contract
  inputs).
- `FollowupDropRecord` is a **fresh** type (the shipped `gate-state.ts`
  `DropRecord.section` cannot carry `"board"`/`"siblings"`; `GateDropRecord` in
  `gate-ledger.ts` is the precedent). `FollowupState.drops` must be
  structurally assignable to `GateDropRecord[]` — pinned by test.
- `sections` is returned beside `stateBytes` exactly as `drops` already is
  (`FollowupDecision` is only `{disposition, basis}`, so the packed entries are
  the only carrier of merge-target identity for EV-82; it must not re-parse
  `stateBytes`). `stateHash` stays over `stateBytes` only.
- `sources` is **not hashed** and never in `stateBytes`
  (`!('sources' in JSON.parse(stateBytes))` pinned). It makes
  absence-vs-emptiness visible: `kept: 0, truncated: false` on an absent board
  must never read as "no duplicates found". Fail loud on contract inputs
  (budget, candidate fields); tolerate repo-state drift (board↔card-file pair)
  but make the drift visible.
- `missingGoal` is sorted and canonical: the open ids whose resolved goal is
  empty — which covers both a missing card file and absent/empty frontmatter,
  both degrading via `parseCardFile` to `goal: ""`.

## 3. Caps and the budget seam

Section caps (measured tokens, `estimateTokens` reused verbatim from
`gate-state.ts`):

| Section    | Cap    |
|------------|--------|
| candidate  | 2,000  |
| board      | **22,000** (raised from 16,000 by the ruling) |
| siblings   | 6,000  |

- Caps sum `30,000 < 32,000`; the packaged `council/gate/policy.json`
  `gateStateBudgetTokens` is **not touched**. The caps-sum invariant test keeps
  its agreed form: `2000 + 22000 + 6000 < gateStateBudgetTokens` read through
  `loadGatePolicy` from the packaged `policy.json` — never a literal — so a
  future budget reduction cannot turn every pack into a silent budget cut.
- Budget resolution: `buildFollowupState` calls `loadGatePolicy(repoRoot)` and
  reads `gateStateBudgetTokens`. Absent → the packer's own single-line FAIL
  naming `gateStateBudgetTokens`; no code-side default. Two reachable arms,
  both tested: (i) resolved mode `off` + absent key → the packer's own FAIL
  (`loadGatePolicy` returns the key as `undefined` under `off`); (ii) mode
  non-off + absent key → `loadGatePolicy`'s EV-75-class FAIL surfaces through
  the seam unchanged. Packing itself is mode-independent, and the packaged
  `policy.json` carries the key explicitly, so arm (i) cannot fire on real
  packaged data. The budget value is never packed into the state. EV-81/82's
  call site owns the mode-off short circuit (mirroring `resolveRoute`'s
  off ⇒ fallback before the state build); the packer's undefined-budget FAIL
  is the loud backstop.

## 4. Sections, order, shapes

Order fixed `candidate → board → siblings`, grounded in the packaged question
set (`duplicate` needs open cards + siblings; `alreadyDone` needs the board
with state; `actionable` needs the candidate's own text).

- **candidate (2,000):** `{title, goal}` from the caller. Over-budget →
  truncate to a field prefix and stay non-empty (a degenerate over-budget
  candidate is tested, never a crash).
- **board (22,000):** every board entry in **file order**, shape
  `{id, title, state}`; `state` = the `##` column; **open** = column ≠ `Done`;
  open entries additionally carry `goal`. The candidate's own board entry is
  included — no self-exclusion (only siblings exclude self). Done entries
  carry **exactly** `{id, title, state}` — pinned by test so the shape cannot
  drift back to `{id, state}`. Non-conforming lines are skipped, never crash.
- **siblings (6,000):** `{title, goal}` per sibling, in `(title, goal)`
  canonical order (caller order is caller-discovered and would leak). Duplicate
  sibling titles throw naming the title; a sibling title equal to the
  candidate's title throws. Entries carry **no `id` key** — no fabricated
  identity for a draft-time artifact (title-as-id is settled; EV-82 owns target
  resolution and the board-id-exact-before-sibling-title-exact order).

### Board reader — grammar parity with `council/validate.py`

Mirrors `validate.py`'s `board_columns` exactly: strip-then-match, em dash
U+2014 only, entries before the first `## ` header skipped as column `None` →
not packed; a hyphen-minus line parses as nothing (parity test pins it).
Duplicated ids keep every column — the first occurrence wins for the packed
entry. Absent board file → empty board section `kept: 0` and
`sources.board.present: false` (tolerant-empty posture, made visible by
`sources`). `sources.board.skippedLines` counts non-conforming lines.

## 5. Determinism

- `stateBytes = new TextEncoder().encode(JSON.stringify(stateWithoutSources))`;
  `stateHash = sha256(stateBytes).digest("hex")` — computed packer-side so
  transported bytes and recorded hash never diverge.
- Round-trip pin: `JSON.parse(stateBytes)` deep-equals the canonical
  serialization of `sections`.
- Canonical JSON of relative identities, explicitly sorted, no clock, no
  absolute paths, no readdir order, no ledger read, budget not packed.
- Never reads: git commands/diff, anything under `.pi/council/runs/`, network.
  Accessor canary: no `runs/`, `fetch(`, or `".pi"` in module source; a runtime
  sentinel written under `.pi/council/runs/` never appears in `stateBytes`.
  EV-80 is the first engine reader of `council/board.md` — no other TS module
  reads it.

## 6. Pack loop and drop mechanics

The pack loop is **forked** from `gate-state.ts`, not shared-core extracted
(gate-state's loop carries a section-coupled wiki-tag-selection side effect;
refactoring a shipped packer mid-epic buys abstraction, not behavior — drift is
contained by a cross-module parity test). Same algorithm shape as
`buildGateState`: empty-frame measurement first; forward-greedy cap fill;
`truncated: false | "cap" | "budget"`; on budget bind, largest whole-entry
prefix, later sections dropped entirely (`kept: 0, measuredTokens: 0`).

One cross-module parity test feeds identical `(section, caps, budget, measure)`
shapes through **both** implementations and asserts identical drop semantics —
this is the substitute for the shared core.

## 7. The headroom probe (ruling Q1, binding)

A test measures **through the packer itself** — never test-local arithmetic;
the round-3 figures were two independent undercounts, so a second measurement
path *is* the defect class. The fixture is this repo's **own**
`council/board.md`, resolved via `PKG_ROOT` (a read-only pin over packaged
data, continuous with `test/ev77-gate-docs.test.ts` / `test/fllwup25-agents-page.test.ts`;
it writes nothing, so the tmpdir convention is not owed). The probe calls
`buildFollowupState` with `boardPath = <PKG_ROOT>/council/board.md` (minimal
synthetic candidate, no siblings) and asserts each of the three sections'
measured tokens ≤ its cap. The day the real board outgrows the cap, this goes
red instead of silently cutting Done titles. (Mode-independence holds on this
path because packaged `policy.json` carries `gateStateBudgetTokens`.) Per-section
measured tokens must be observable from the packer's own output (drop records
or `sections` carry them) — the probe reads packer output, not recomputed
figures.

## 8. Test plan

One file `test/ev80-followup-state.test.ts` (bun:test, tmpdir fixtures for any
write, EV-75-clean), covering:

1. Pack shape + section order.
2. Byte/hash identity + independent sha256 recompute.
3. Round-trip pin (test 3 above) + `sources` not in `stateBytes`.
4. Hash sensitivity: open-card goal change → hash changes; sibling change →
   changes; **Done-card change → unchanged**; unrelated repo file
   create/rewrite → unchanged; `sources` changes → hash unchanged.
5. Accessor canary (module-source strings; runs sentinel never in
   `stateBytes`).
6. Budget two-arm (packer FAIL naming the key under `off`; EV-75 FAIL surfacing
   under non-off).
7. Budget mechanics: tiny budget → budget cut, siblings kept 0; cap overfill →
   `"cap"` trim, later sections unaffected; frame > budget → throw.
8. Degenerate over-budget candidate → non-empty prefix truncate.
9. Validation FAILs naming `candidate.title` / `candidate.goal`; missing
   `boardPath` is a compile-time type error.
10. Board-grammar parity: U+2014 strip-then-match; hyphen-minus line parses as
    nothing; pre-header skipped; first-occurrence-wins duplicates.
11. Drift visibility: absent board → `present: false`; skipped-line count;
    open id with absent/empty-goal card → `missingGoal`.
12. Sibling canonicalization + duplicate-title throw + sibling==candidate
    throw + structural no-`id` pin.
13. Cross-module drop parity (§6).
14. Done-entry shape pin `{id, title, state}`.
15. Caps-sum invariant through the loader (§3).
16. **Discriminating cards-dir fixture** (ruling obligation 4, also fixes the
    R0 headline fixture shape): a relocated `boardPath` whose sibling `cards/`
    directory carries a distinctive goal **and** a *different* goal at
    `<repoRoot>/council/cards/` for the same id; assert the dirname-derived
    goal packs. The R0 headline proofs (hash changes on board-card change and
    sibling change; unchanged on unrelated file change) run over this single
    relocated pair.
17. **Headroom probe over the real board** (§7).

## 9. Justification language fixed by the ruling

The raised board cap is justified as "the kept entries carry real evidence" —
**never** as "the cut only drops stale work". `board-create-card.md` §6 pins no
positional rule inside a column, so this board's newest-first Done order is a
fact about this board, not a property of the mechanism. If the cap ever binds,
the sacrifice stays visible: a `FollowupDropRecord` with `truncated: "cap"` and
the kept count — never a silent thin pack.

## 10. Out of scope

- A recency window of Done entries (growth past the cap) — expressly **not** an
  EV-80 fold-in; the probe is its tripwire. Named-not-carded for step 13.
- Per-candidate board cost — same future card.
- Within-column board ordering conventions — not EV-80's surface.
- Target *selection* (only packing) — EV-82's.
- The mode-off short circuit at the call site — EV-81/82's.

## 11. Ship discipline

- Conventional commit, `feat(gate): EV-80 ...`; bump `version` in
  `package.json` in the same PR.
- Gates in full: `bunx tsc --noEmit`, full `bun test`,

- Work is committed to a dedicated worktree branch and a PR to `main`; the main
