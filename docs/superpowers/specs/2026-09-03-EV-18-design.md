# EV-18 — Shipped benchmark fixtures for commands and seats (design)

Settled design for card EV-18 (epic EPIC-4). This document is the write-up
of the Council's deliberation (rounds 1–2, Skeptic verification) plus the
resumption rulings (product-owner Q1–Q3/Q5, steward convention-5). It
derives nothing new; it records what the deliberation settled and what the
rulings bound. An owner reading only this file, with no memory of the
deliberation, must not be able to reach two different designs.

## Goal (from the card)

> A shipped fixtures directory provides one pinned and reproducible task
> input per council procedure and per packaged seat, each runnable from a
> fresh checkout with no manual setup

Binding design authority that stays in force and is **not** reopened here:
the EV-16 spec (`docs/superpowers/specs/2026-09-03-EV-16-design.md`),
specifically §9 (fixture schema), §3.4 (task-id → fixture-dir → rubric-file
wiring), §1 (cell-invariance contract), §3.3 (harness-as-human structured
policy), §5 (rubric shape: deterministic gate vs recorded judge verdict),
and §10 acceptance A1–A4/C3. Phase 1 rulings R-1/R-2/R-3. EV-17's merged
seam: the `provider/id[:thinking]` qualified-model grammar
(`parseQualifiedModel`/`resolveEffectiveModel` in `extensions/seats.ts`).

## Binding rulings (resumption, immutable for this run)

- **Q1 — forbid-list extension: `model-floors.json`.** The seed forbid-list
  gains `model-floors.json`. Floors vary behavior orthogonally to the
  (model, thinking) pair; `extensions/index.ts:38–39` (`loadModelFloors`)
  reads `<repo>/$CONFIG_DIR_NAME/council/model-floors.json` at module load —
  a read-time side channel. `PKG_ROOT/council/model-floors.json` (the
  shipped default) is exempt by definition; a seed carrying
  `model-floors.json` at any loader-reachable path fails load.
- **Q2 — `treeDigest` CRLF robustness: ship `.gitattributes`.** Ship
  `council/.gitattributes`. "Runnable from a fresh checkout with no manual
  setup" cannot tolerate a per-platform re-seed path; digest verification
  is not best-effort. The file contains `* text=auto eol=lf`, or tighter
  text-only file globs if binary files live in seeds — the owner inspects
  the actual seed contents and pins the exact lines on EV-18's diff.
- **Q3 — `:thinking` suffix load-time validation: fix `parseQualifiedModel`
  itself.** The bug exists at three sibling sites in `extensions/seats.ts`
  (`parseQualifiedModel`, the frontmatter parser in `parseSeatFile`, and
  `applySeatOverride`) — all sharing the identical
  `if (colon > 0 && THINKING_LEVELS.has(suffix))` fold, by which an unknown
  suffix (e.g. `:MediuM`, `:MEDIUM`, `:maxx`) silently stays part of the
  model id and passes load. The fix is a one-line sibling to the existing
  check at all three sites: when the colon suffix is non-empty, it must be
  in `THINKING_LEVELS`; an unknown suffix **throws**. (A trailing colon with
  an empty suffix keeps today's behavior — not covered by the ruling.) This
  is a bug fix to the shared grammar, fail-loudly on invalid input; it may
  touch EV-17's merged seam, which is intended. The fixture validator's
  role reduces to importing and using the now-throwing parser.
- **Q5 — `.pi/settings.json` config surface: deferred.** `~/.pi/settings.json`
  and project-local `.pi/settings.json` are project-trust/scope settings,
  not model/output/seed-pin surfaces; explicit `--model` in argv
  neutralizes any indirect override. Not addressed on this card, and **not**
  a step-13 follow-up card unless a real card hits it.
- **Steward — AGENTS.md convention-5 amendment lands on EV-18's diff.** The
  amended convention 5 writes `$CONFIG_DIR_NAME/council/fixtures/` — the
  repo-local override dir, described alongside the packaged default
  `council/fixtures/`, exactly as convention 5 already does for agents
  (`<repo>/$CONFIG_DIR_NAME/agents/`) and procedures
  (`<repo>/$CONFIG_DIR_NAME/council/procedures/`). Landing in the same
  commit as the loader code, not as a separate docs commit. Convention 3
  applies: no hardcoded `.pi`.

## 1. Fixture directory layout and resolution (spec §3.4, settled)

- Packaged default: `council/fixtures/<task>/` (16 dirs at `PKG_ROOT`).
- Repo-local override: `<repo>/$CONFIG_DIR_NAME/council/fixtures/<task>/`
  (i.e. `.pi/council/fixtures/<task>/` — `$CONFIG_DIR_NAME` from
  `@earendil-works/pi-coding-agent`, never a hardcoded `.pi`).
- Resolution order, **whole-task-dir first-hit** (mirrors `seatDirs` and
  `proceduresDir` in `extensions/seats.ts`): a task dir present on the repo
  side resolves entirely from the repo side — `fixture.json`, `rubric.json`,
  and `seed/` together. A repo-side `fixture.json` without its own repo-side
  `rubric.json` is a loud load error; **never** a silent fallback to the
  packaged rubric (mixing halves would break pinning and the digest
  couples `fixture.json` + `seed/`).
- No scaffold seeding: `/council-init` performs **no copy** of fixture
  trees (spec §3.1's "seeded by the scaffold" is read as "the packaged dir
  is the shipped default"). Non-clobber scaffold re-runs would freeze a
  consumer on install-time fixture versions; packaged resolution gives
  fresh-checkout runnability at zero setup.
- `listFixtureTasks(repoRoot)` unions both sides (packaged + override),
  per-task first-hit, and validates each task's self-description
  (`taskId == dir basename`).
- Repo-local fixture dirs **skip** the `treeDigest` pin (consumer-owned);
  the pin is enforced on packaged fixtures at every load.

## 2. `fixture.json` schema (spec §9, settled + rulings)

```jsonc
{
  "schemaVersion": 1,                 // reject anything else, loudly
  "taskId": "council",                // must equal dir basename; ^[a-z0-9][a-z0-9-]*$
  "name": "Create a council card from a pinned intent",
  "fixtureVersion": "1.0.0",          // semver string, required
  "kind": "procedure" | "seat",       // disjoint target shapes, schema-enforced
  "target": {                          // exactly one of the two below
    "type": "procedure", "command": "/council", "arguments": ["EV-1"]
    // XOR:
    "type": "seat", "seat": "skeptic" // seat name must resolve via loadSeat(repoRoot, name)
  },
  "inputFile": "input.md",            // required iff kind=seat: the exact pinned turn input
  "seed": { "dir": "seed", "treeDigest": "sha256:<hex>" },
  "env": { "TZ": "UTC", "GIT_AUTHOR_NAME": "...", "GIT_AUTHOR_EMAIL": "..." }, // optional, pinned
  "timeoutMinutes": 240,              // optional ceiling hint for EV-20; runner-side default exists
  "policy": { "gates": [ ... ] },     // harnessAsHuman; empty gates array allowed when no human gate
  "graderModel": "openrouter/qwen/qwen3.6-35b-a3b:medium", // from the file, never .council.json
  "graderThinking": "medium"          // optional
}
```

- **Required keys:** `schemaVersion`, `taskId`, `name`, `fixtureVersion`,
  `kind`, `target`, `seed`, `policy`, `graderModel`. **New/unknown keys →
  throw** (strict, mirrors `seats.ts` frontmatter strictness).
- **`target` is exactly-one**: procedure ⇒ `command` + `arguments`; seat ⇒
  `seat`. Procedure inputs are short and pinned inline in
  `target.arguments`; seat turn inputs are long and pinned as `inputFile`
  (a file in the fixture dir). No `rubricFile`/`rubric` ref field — spec
  §3.4 fixes `council/fixtures/<task>/rubric.json`; a second field is drift
  surface.
- **`graderModel`** is authored in the `provider/id[:thinking]` grammar and
  validated at load through `parseQualifiedModel` (exported from
  `seats.ts` — see §5), which rejects bare ids and (after the Q3 fix)
  unknown `:thinking` suffixes. Default for all fixtures unless a rubric
  requires otherwise: **`openrouter/qwen/qwen3.6-35b-a3b:medium`** (the
  packaged judge seat's resolved default — verified
  `loadSeat(repoRoot, "judge")` → `{ model: "openrouter/qwen/qwen3.6-35b-a3b",
  thinkingLevel: "medium" }`).
- **`env`** and **`graderThinking`** are the §1 environment and
  (model, thinking) pins; `target.arguments` feeds `$args[N]` expansion
  (see §4).

## 3. `rubric.json` schema (spec §5, settled vocabulary)

```jsonc
{ "schemaVersion": 1, "rubricVersion": "1.0.0",
  "criteria": [
    { "id": "c1", "type": "gate", "check": {
        "kind": "gates", "argv": ["python3", "council/validate.py"],
        "expect": { "exitCode": 0, "stdoutContains": "All council artifacts valid" } } },
    { "id": "c2", "type": "gate", "check": { "kind": "artifact-present", "path": "council/cards/EV-1.md" } },
    { "id": "c3", "type": "gate", "check": { "kind": "artifact-contains", "path": "council/board.md", "contains": "- EV-1 —" } },
    { "id": "c4", "type": "judge", "prompt": "..." } ] }
```

- **1–5 criteria, ≥1 required** (schema-enforced). Ordered.
- **Check kinds — a closed, frozen vocabulary:**
  `gates | settled | artifact-present | artifact-contains`.
  - `gates` — a pinned command exits 0 (carries `argv` + `expect.exitCode`
    and optional `expect.stdoutContains`).
  - `settled` — a dispatch finished `done`, not `stalled`/`timeout`
    (carries the role/path it applies to).
  - `artifact-present` — a pinned path exists.
  - `artifact-contains` — a pinned path matches a pinned token/regex.
- **Depth rule:** procedures are gate-dominated (re-runnable, stable:
  `validate.py` clean, `bun test` green, board state, artifact probes) with
  0–1 judge criterion; seats are **gate-dominant where a deterministic
  mechanical probe exists** (skeptic's planted bug, judge's met/not-met —
  the gate is the score, a judge criterion is 0–1 corroboration that does
  not move it) and **judge-only where no mechanical probe exists**
  (consolidator, designer, principal, product-owner, steward — exactly 1
  judge criterion, success *is* the seat's output).
- The rubric schema/validator home is `extensions/eval-fixtures.ts`; EV-19
  imports `validateRubric` from here (one authority, no drift window).
  Late gate-kind additions on EV-19 would invalidate shipped data — the
  vocabulary freezes here.

## 4. Harness-as-human policy (spec §3.3, settled)

`fixture.json.policy.gates[]` is a structured-rulings block, not prose
(the smoke driver's prose-persuasion technique is explicitly **not** the
precedent; only the smoke *seed shape* is: `cp -R` + `git init -b main` +
one commit is EV-20's materialization).

```jsonc
"policy": { "gates": [
  { "id": "merge-gate", "humanStep": 11,
    "when": [
      { "kind": "job-state", "role": "owner", "state": "done" },
      { "kind": "job-state", "role": "skeptic", "state": "done" },
      { "kind": "report-contains", "role": "judge", "token": "PASS" },
      { "kind": "board-column", "cardId": "$args[0]", "notIn": ["Needs Human"] },
      { "kind": "file-exists", "path": "docs/superpowers/specs/2026-09-03-EV-18-design.md" } ],
    "verdict": "approve", "then": "merge" },
  { "id": "confirm", "humanStep": 1, "verdict": "answer",
    "answerText": "<pinned canned takeaway>" } ] }
```

- **Condition kinds — enumerated, finite:** `job-state {role, state, negate?}`,
  `report-contains {role, token, negate?}`, `board-column {cardId, in?|notIn?}`,
  `file-exists {path, negate?}`, `file-contains {path, token, negate?}`.
- **Verdicts:** `approve | hold | answer` (`answerText` required iff
  `answer`).
- **`then`** names the mechanical act for EV-20 (e.g. `merge`, `skip`,
  `answer`), optional, closed vocabulary, load-validated.
- **`$args[N]`** expands from `target.arguments` at load. Per-procedure
  semantics: `/council` args[0] is a cardId; `/board-create-card` and
  `/features-new` args[0] is intent text (the resulting card id is not
  known at authoring) — conditions reference `$args[N]` **only** where the
  arg is a stable id.
- The engine (`applyRulings`, §5) decides verdicts **from cell state only**;
  the mechanical act (git merge, confirm write, inject text) is EV-20's to
  perform per gateId. Interactive gates get canned `answer` texts because a
  pure engine cannot converse; grading then scores the **artifact** (card
  written, wiki updated), never conversation quality.
- Verbose-shaped policy with **no** human gates (e.g. wiki-lint,
  wiki-query, the seat fixtures) uses an empty-or-minimal `gates` array.
- Fixture rubrics never touch `gh`/network: the "no network-dependent
  state" acceptance holds by authoring (see §7).

## 5. `extensions/eval-fixtures.ts` (new module)

One engine module in `extensions/` (AGENTS.md layout); data lives in
`council/fixtures/`.

- `listFixtureTasks(repoRoot): string[]` — union of packaged +
  `$CONFIG_DIR_NAME/council/fixtures` (per-task first-hit), each task's
  self-description validated (`taskId == dir basename`).
- `loadFixture(repoRoot, taskId): { fixture, rubric, seedDir }` — loud
  failure on: unknown task; missing `rubric.json` (C3 — never silent `[]`);
  schema violation; `schemaVersion ≠ 1`; digest mismatch on a packaged
  seed; forbidden seed files (§6); procedure-kind command not in the 7
  shipped procedures; seat-kind seat not resolvable via `loadSeat`.
- `validateFixture`, `validateRubric`, `validatePolicy` — the schema
  validators, authored here with the data (one authority). EV-19 imports
  `validateRubric` from here.
- `applyRulings(policy, state): verdict` — **pure, no I/O** (A4). `state`
  is a normalized view supplied (by EV-20) in terms of the condition
  vocabulary — job manifests by role, board columns, file facts. The engine
  is a finite matcher; `$args` already expanded at load.
- `sha256Tree(dir)` — sha256 over (sorted relpath, bytes) pairs used to
  verify/author `treeDigest` (deterministic; see §6).
- The loader is **read-only** w.r.t. `repoRoot` (A1-adjacent: loading
  fixtures leaves the caller tree byte-identical).

**Engine fixes on EV-18's diff:**

- **Export `parseQualifiedModel`** from `extensions/seats.ts` (one-line
  change) so the fixture validator reuses it — no fork. The validator
  imports it; a bare id `qwen3.6-35b` fails **at load** naming the file.
- **Q3 fix — three sibling sites in `extensions/seats.ts`:**
  `parseQualifiedModel` (~line 275), the frontmatter model parser inside
  `parseSeatFile` (~line 232–240), and `applySeatOverride` (~line 398–407).
  Each shares the fold `if (colon > 0 && THINKING_LEVELS.has(suffix))`
  where an unknown non-empty suffix silently stays part of the model id.
  Change each to: when `colon > 0`, if the suffix is a known level → split
  as today; else if the suffix is non-empty → **throw** naming the bad
  suffix and the context/file. Empty suffix (trailing colon) keeps today's
  behavior. These throw on invalid input rather than silently misrouting —
  a grammar bug fix, not a behavior change. Run the full existing suite:
  no current fixture or override uses an unknown suffix (verified:
  `test/override.test.ts:135` uses `:xhigh`, a valid level), so no existing
  test should change except any that asserted the bug.

## 6. Seed representation, digest, forbid-list

- **`seed/` is a plain directory subtree inside the fixture dir.**
  Self-contained — every fixture owns its complete starting state. No
  shared archetype (shared bases would couple 16 digests; any archetype
  edit would invalidate every pin). `type: "full"` is the only supported
  kind; `"overlay"` is reserved and **rejected** at load.
- **`treeDigest`** = sha256 over (sorted relpath, bytes) pairs, recomputed
  and verified by the loader at **every** load of a packaged fixture —
  a cheap pin that catches accidental seed edits without a version bump
  and gives EV-20 upstream proof the scratch started from the authored
  tree. No git-commit pinning (fresh `git init` re-derives SHAs); no git
  history in seeds — plain files only.
- **Newline normalization (Q2):** ship `council/.gitattributes` so a fresh
  checkout produces the authored LF bytes on every platform. The owner
  inspects the final seed trees for binary files; if any live in seeds,
  scope the attributes to text globs (otherwise `* text=auto eol=lf`).
- **Seed forbid-list (settled + Q1):** a seed **fails load** if it
  contains any of:
  - `.council.json` **with a named model** (a `.council.json` without one,
    e.g. theme-only, is allowed);
  - `.pi/council/mcp.json` that is **non-empty** (empty
    `{"servers": {}}` is allowed — smoke precedent);
  - `.env`;
  - **`model-floors.json` at any loader-reachable path** (Q1) — i.e.
    `<seed>/.pi/council/model-floors.json` (which materializes as
    `$CONFIG_DIR_NAME/council/model-floors.json`, read by
    `extensions/index.ts:38–39` at module load) and any other copy inside
    the seed. `PKG_ROOT/council/model-floors.json`, the shipped default, is
    exempt by definition — it is not inside any seed.
  - Also rejected for determinism: `.pi/git/`, `.pi/npm/`, `node_modules/`,
    symlinks, timestamps — seeds are plain deterministic trees.
- The smoke fixture (`smoke/fixture/`) is **not** an eval fixture; it may
  carry `.council.json`/empty mcp.json today (it is a fixed-model run, not
  a cell-invariance seed) — the forbid-list applies to `council/fixtures/`
  seeds only.

Bare task-id naming (no prefix; spaces are disjoint today, a future
collision is a loud load-time error). `taskId == dirname`.

## 8. Tests (failing first, per repo TDD conventions)

New file `test/fixtures.test.ts` (plus seats.ts-fix tests where they live —
see Q3). Tests use `bun:test`, import engine modules via relative paths,
take `repoRoot` as a parameter with `fs.mkdtempSync`, and resolve packaged
resources via `PKG_ROOT` as `test/seats.test.ts` does. The Q1–Q3 Skeptic
closed-red tests below are the **failing tests to write first and turn
green**:

1. **Q1 (forbid-list)**: a fixture whose seed contains
   `.pi/council/model-floors.json` fails `loadFixture` naming the file; a
   seed with `model-floors.json` anywhere else in the tree fails too; the
   shipped `PKG_ROOT/council/model-floors.json` (outside any seed) never
   trips the check.
2. **Q2 (CRLF/.gitattributes)**: assert `council/.gitattributes` exists in
   the package with the ruling's content (`* text=auto eol=lf` or the
   owner's pinned tighter globs); the digest-determinism probe — same
   relpath/bytes computed from LF versus CRLF byte streams differ, and the
   authored seeds recompute to their pinned `treeDigest` on this checkout.
3. **Q3 (suffix validation)**: `parseQualifiedModel("openrouter/q/q:MediuM")`,
   a `parseSeatFile` frontmatter `model: openrouter/q/q:MediuM`, and an
   `applySeatOverride` `.council.json` override with `:MediuM` all throw;
   valid levels still split (`:xhigh`, `:medium`); bare ids still throw
   "must be qualified".
4. **C3**: a fixture dir whose `fixture.json` exists without `rubric.json`
   throws naming the file; never returns `[]`/partial.
5. **A4**: `applyRulings` is pure — identical policy + identical state →
   identical verdict twice, no I/O; a decision-table test pins expected
   verdicts for a fixed policy/state pair (approve/hold/answer, negate,
   `$args` expansion, `board-column` in/notIn).
6. **Inventory**: `listFixtureTasks(PKG_ROOT)` returns exactly the 16 ids
   (7 procedures + 9 seats) in sorted order; every fixture loads clean
   (digest self-check, schema, rubric present); every `taskId == dirname`;
   procedure-kinds reference real shipped commands (the 7 under
   `council/procedures/`); seat-kinds resolve via `loadSeat`.
7. **Determinism (this card's A1 half)**: materialize each shipped seed to
   a tempdir → recompute digest → equals the pinned `treeDigest`. (Full A1
   — caller tree byte-identical — is EV-20's; the fixture half is proven
   here.)
8. **No network-dependent state (card acceptance)**: static scan — no
   `http(s)://` anywhere in `fixture.json`/`rubric.json`; no rubric `gates`
   argv references `gh`/`mcp`/`curl`/`wget`; no seed contains
   `.council.json` (named model) / non-empty `mcp.json` / `.env` /
   `model-floors.json` (the same check, inverted, is the loader's refusal
   test).
9. **Shadowing**: repo-side `$CONFIG_DIR_NAME/council/fixtures/<task>/`
   (marker-edited) resolves repo-local for that task; an unoverridden task
   resolves packaged; `listFixtureTasks` unions both, repo wins on
   collision; a repo dir missing its own `rubric.json` fails loudly rather
   than falling back to packaged.
10. **graderModel grammar**: for each of the 16 fixtures,
    `parseQualifiedModel(fixture.graderModel)` passes; a deliberately bare
    fixture (e.g. `"qwen3.6-35b"`) fails load; a fixture with an unknown
    suffix fails load (Q3).
11. **Green gate (A2)**: after all 16 fixtures load clean,
    `python3 council/validate.py` in the package root exits 0 with
    `All council artifacts valid` (guards validate.py's non-recursive
    `CARDS.glob("*.md")`; fixture seeds live under
    `council/fixtures/<task>/seed/council/cards/`, never top-level
    `council/cards/`).

## 10. Scope guard

grading, no leaderboard, no scaffold seeding, no running of any fixture
