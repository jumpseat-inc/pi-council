# EV-20 Designer First Pass (2026-09-03)

Frames the `/council-eval` surface as the answer to three gulfs a person
faces during a hours-long matrix: (1) what is happening right now, (2)
whether the matrix is on the path they intended, (3) what the matrix
learned, honestly. Two hard scope decisions land here:

1. **The command is not a markdown procedure.** R-3 named `/council-eval`
   and EV-16 §3.1 commits "NOT an LLM-orchestrated loop" — the harness
   owns parse/dispatch/accumulate/render from a TypeScript handler
   registered like `council-init`/`council-jobs`. This broke the
   seven-command markdown pattern and became the precedent for
   `/council-leaderboard` (see [[procedures vs commands]]).
2. **Pre-dispatch confirmation echo as a forcing function** — quote the
   resolved taskId/fixtureVersion/model ids/repeat/total before any spawn;
   "the cost is hours, the typo is one keystroke." Later settled as
   echo-then-run (not a blocking gate) because the surface must stay
   unattended-capable.

Also: TRIAGE semantics from CI overlap (later corrected by the binding
EV-16 §8 text to CI-on-mean-*difference*); `stopReason=length` majority
renders `indeterminate (length majority)`, never a low mean; 13
falsifiable predictions filed.
