`AGENTS.md` is the repository's operating manual for AI agents. It names the
what-this-repo-is, the commands (`bun install`, `bun test`, `bunx tsc --noEmit`),
the CI-timeout policy (the gates `bun test` backstop → [[test-suite-budget]]),
the layout, and — critically — **thirteen hard conventions** that encode the
product's deliberate constraints.

## Hard conventions

1. **Seats are domain-neutral by design.** Seat bodies are written for any
   repository; product-specific grounding comes from the
   `<repository_grounding>` block, never a hardcoded product domain.
2. **Seat schema is fixed** — frontmatter fields are `name`, `description`,
   `model`, `tools`, `spawns`, `mcp`; no `autoloadSkills`.
3. **No hardcoded `.pi`.** Repo-local paths use `CONFIG_DIR_NAME`.
4. **No hardcoded clone paths.** The package resolves its own root via
   `import.meta.url` (`PKG_ROOT`).
5. **Override semantics** — repo-local resources shadow packaged ones by
   filename; eval fixtures follow a whole-task-dir first-hit pattern with a
   pinned `treeDigest`. The scaffold provenance record
   (`<repo>/$CONFIG_DIR_NAME/council/scaffold.json`, FLLWUP-50) is one such
   record type: a consumer-side file at that path is honored as the record —
   never merged or shadowed by the package — written only when `scaffoldInto`
   creates files, and committed by default (a consumer may gitignore it and
   fall back to the conservative ask-once bootstrap). The tooling-drift state
   file (`<repo>/$CONFIG_DIR_NAME/council/tooling-drift.state.json`) is the
   session-start notification's once-per-condition state — engine-written,
   transient, never a consumer override surface.
6. **Scaffold writes are non-clobbering.** `scaffoldInto` never overwrites an
   existing file — a consumer's board and wiki survive reinstalls. The one
   sanctioned exception is `/council-update`'s consent-gated refresh path
   (FLLWUP-50): tooling-class files only (`council/validate.py`,
   `council/cards/_template.md`), only after an explicit consent act (`--apply`
   for `↑ behind`; per-file `--accept` for `~ diverged`), with a timestamped
   backup first. Data-class files — board, cards other than `_template.md`,
   `vault/**`, `.council.json`, `preflight.sh`, `mcp.json` — are never written.
   See [[council-update]].
7. **`hub.ts` is stable.** Stall/timeout/kill semantics battle-tested; change
   only with a failing test.
8. **Tool-grant vocabulary** — the omp-style names
   (`Read`, `Grep`, `Glob`, `Edit`, `Write`, `Bash`, `task`, `hub`) mapped by
   `BUILTIN_MAP`.
9. **Model output floors are data** — `council/model-floors.json`,
   repo-mergeable.
9.5. **Agent model/thinking can be overridden per-repo via committed
   `.council.json`** — field-level override of a seat's model + thinking (see
   [[council-config]]); frontmatter stays the default; malformed JSON or an
   invalid `thinking` value throws.
9.6. **The council theme is configured per-repo via a top-level `theme` key in
   committed `.council.json`** — reserved sibling of `council`; `enabled: false`
   is the off switch; council-drawn UI uses pi theme tokens only (see
   [[council-theme]]).
10. **MCP secrets never go in `mcp.json`** — auth lives in
    `getAgentDir()/council/mcp-auth.json` (0600).
11. **`--tools` is an exact-name allowlist** — granted MCP tool names, no lazy
    MCP connect.
12. **`runs/` is ephemeral telemetry.** Per-job manifests + seat transcripts
    under `$CONFIG_DIR_NAME/council/runs/`, self-gitignored, pruned to the
    last 15 runs.
13. **Local gate evidence is trusted only after `council/preflight.sh` passes
    on the current tree** — prefer rerunning preflight over trusting local
    evidence (see [[preflight]]).
