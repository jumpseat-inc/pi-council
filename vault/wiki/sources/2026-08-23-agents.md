`AGENTS.md` is the repository's operating manual for AI agents. It names the
what-this-repo-is, the commands (`bun install`, `bun test`, `bunx tsc --noEmit`),
the layout, and — critically — **eleven hard conventions** that encode the 
product's deliberate constraints.

## The eleven hard conventions

1. **Seats are opinionated on purpose** — do not generalize/soften seat bodies.
2. **Seat schema is fixed** — no `autoloadSkills`; grounding via
   `<repository_grounding>` block.
3. **No hardcoded `.pi`** — use `CONFIG_DIR_NAME` from the pi package.
4. **No hardcoded clone paths** — resolve package root via `import.meta.url`
   (`PKG_ROOT`).
5. **Override semantics** — repo-local shadows packaged by filename.
6. **Non-clobbering scaffold** — `scaffoldInto` never overwrites (ev-guide's
   board + wiki survive reinstalls).
7. **`hub.ts` is stable** — semantics battle-tested; change only with a failing test.
8. **omp-style tool-grant vocabulary** — `Read/Grep/Glob/Edit/Write/Bash/task/hub`
   mapped by `BUILTIN_MAP`.
9. **Model output floors are data** — `council/model-floors.json`,
   repo-mergeable.
10. **MCP secrets never in `mcp.json`** — auth lives in
    `getAgentDir()/council/mcp-auth.json` (0600).
11. **`--tools` is an exact-name allowlist** — never lazy MCP connect in seats.

## Other sections

- **Commits** — Conventional Commits, no history rewriting, breaking changes
  need `!` and the version bump together.
- **Testing** — `bun:test`; filesystem-touching tests take `repoRoot` param +
  `fs.mkdtempSync`; TDD; the integration test stays gated.
- **Adding a seat/procedure** — add the file, update seat-count assertions.
