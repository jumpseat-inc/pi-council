# EV-3 Round 1 — Designer Position

The design seat's independent first pass on EV-3 (Activate the council theme
on session start). Reads the wiki then the code, argues from the artifact. The
raw doc is the designer's *position*, not the final decision — some positions
here were superseded in round 2 or the settled spec.

## Grounded reading

- Pi's `setThemeInstance(instance)` → `setGlobalTheme` +
  `currentThemeName = "<in-memory>"` + `stopThemeWatcher` — **zero
  settingsManager calls** (theme.js:705-714). The string branch
  `setTheme(name)` DOES write settings.json — must be avoided (spec §4
  no-settings-mutation).
- `applyFromSettings` (theme-controller.js:38-49) persists a high-confidence
  auto-detect `dark`/`light` into settings.json — so detection must read the
  **raw** value off disk (project wins), not `ui.theme.name` (which becomes
  `"<in-memory>"` after any setTheme).
- `ExtensionUIContext` exposes `theme`, `getTheme`, `setTheme(theme: string |
  Theme)`, `getAllThemes` — the public activation path.
- `/council-tree` reads theme via the `ctx.ui.custom` factory's second arg, so
  activation must precede any first render of council UI.

## Position

1. **One new module** `extensions/activate-theme.ts` (pure decision + glue),
   one new `session_start` hook **before** `initHubIdentity`/`pruneRuns`/
   `connectParentServers`, `await`-ed, wrapped so it can never throw out of
   `session_start`.
2. **Pure tagged-union decision:** `decideActivation({themeSection,
   projectSettingsRaw, globalSettingsRaw, terminalTheme})` →
   `{noop} | {block, themeName} | {activate, variant}`. Caller does the disk
   read; project wins; "any other concrete name" blocks.
3. **Auto-variant via sync `detectTerminalBackgroundFromEnv()` (COLORFGBG)**,
   rejecting async OSC-11 (TUI hasn't rendered at session_start — flash-of-
   wrong-palette hazard). Explicit pin honors verbatim.
4. **Construction:** tempfile + `loadThemeFromPath` (recommended) vs strict
   in-memory reimplementation — *flagged for escalation to product-owner*
   (this exact dispute is what the settled spec resolves as in-memory).
5. **Notify tri-state:** info on activate (`council theme: pi-council-{v}`),
   warning on block (names the pinned theme), silent on noop — the notify is
   the user's only verification surface for an in-memory (nameless) theme.
6. **Failure modes ranked:** silent block, auto-variant mismatch on light
   terminal, flash of wrong palette, no-op without scaffold, `/council-tree`
   wrong colors, re-activation leaks.

## Falsifiable predictions P1–P8

Cover merged-color resolution, in-memory namespace (`getAllThemes` still holds
only the two shipped files), settings.json byte-identity, activation ordering,
block-notify text, pair non-blocking, custom-theme retention, tempfile cleanup.
