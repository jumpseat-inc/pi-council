The README frames pi-council around the author's motivating question — *"How do
I get prompted instead of prompting?"* — and four reinforcings concepts:
**Prompt Then Get Prompted**, **LLM Wiki** (long-term memory for product-building),
**Board & Cards** (local kanban holding the source of truth), and **The Council**
(diverse LLM roles that prove positions with tests and code).

## Key content

- **Install** default is user-scope (`~/.pi/agent/settings.json`, clone under
  `~/.pi/agent/git/…`); `-l` installs project-local (`.pi/settings.json`,
  `.pi/git/…`). Same package in both scopes → project entry wins.
- **`/council-init`** scaffolds the data layer **and** ensures the superpowers
  skills package is pinned project-locally — the council refuses to run without it.
- **Seat → superpowers skill pointers** (owner, skeptic, council-runner,
  designer, principal, judge point at skills; consolidator/product-owner/steward
  rule on judgment and get none).
- **Commands table** — the council loop, board/feature/wiki commands, and MCP.
- **Seats table** — 9 seats and their roles.
- **Requirements** — pi, `bun` on PATH, models must exist in pi's catalogue.
- **Git: what to commit** — `.pi/settings.json` and repo-local overrides are
  committable; `.pi/git/` and `.pi/council/.pids.json` are ignored.
- **MCP** — Context7 and Tavily ship by default; secrets live user-global.
