The designer's first-pass position on EV-8 (arrow-key focus navigation
between the input bar and the inline tree), grounded directly on the EV-7
`CouncilTreeWidget` (`extensions/navigator.ts`), pi's TUI surface docs, and
the modal-editor precedent. This is a generator position feeding the
deliberation; the binding outcome is the [[2026-08-26-po-ev8-ruling]].

## Core position

- **Focus is a signifier, not a runtime acquisition.** Pi's TUI only ever
  calls `setFocus(this.editor)` — belowEditor widgets live in the same
  `VStack` and never receive keyboard ownership. So tree "focus" for EV-8
  must be *symbolic*, applied at render time, NOT a real `Focusable`
  implementation (that would be design-scope creep / runtime redesign).
- **Two co-visible signifiers bound to the same state:** a `▌` (U+258C)
  indicator in column 0 of the selected row (only when the tree holds
  focus) plus a vim-style ` NORMAL ` / ` INSERT ` label on the editor's
  bottom border — both read one ground-truth boolean. Norman's rule:
  never ask the user to bind two *distant* signifiers to one state.
- **The multi-line rule derives, never redefines.** "Down steals to the
  tree only on the last visual line; Up steals only on the first." Pi's
  editor already owns `isOnFirstVisualLine()` / `isOnLastVisualLine()`; on
  a single-line draft both hold, so the rule degenerates cleanly and the
  card's "multi-line rule" deliberation largely folds into one rule.
- **Safe default for unhandled keys:** while the tree holds focus, a stray
  printable/PageUp/PageDown/etc. releases focus back to the editor *and
  replays into it* (the Escape-exits-NORMAL shape). Slips are recoverable.

## Falsifiable predictions

Rendering ones (testable): R1 `▌` adds exactly one width-column when
focused; R2 the editor's last border line ends ` INSERT ` vs ` TREE `
exactly; R3 no new theme tokens; R4 `MAX_WIDGET_LINES=10` unchanged; R5 the
widget has no `Focusable` (input comes via the editor path, not pi).
Comprehension ones (human-settled, not smoke): C1 a first-time person
infers the `▌`+` TREE ` pairing means focus moved; C2 no flashing under a
2s refresh when focus is on the editor; C3 Esc wins as the exit affordance;
C4 the multi-line rule holds mid-draft.

## Preferences, ranked last

`▌` (0x258C) preferred over `▶`/`→` (one column, no direction connotation);
label on the editor's bottom border (vim precedent) over an external status
row.
