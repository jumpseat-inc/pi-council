## J1 — RULING: the gateFail-tail sentence is IN

One sentence, placed adjacent to the byte-reproduced EV-75 migration literal (inside the
migration paragraph, never in the operator's how-to-turn-it-on section), and it must carry the
*reason* — the standard tail's "set a valid value or remove the key to use the packaged
default" is wrong advice for this key — not a description of the helper. Page copy only;
`extensions/gate.ts:186-189` is not touched.

- **Rejected:** omitting it as "migration detail / operator-first clutter." The page
  reproduces the literal byte-for-byte by house practice (designer P7), so the absence of the
  tail becomes visible on the page itself. Unexplained, a reader who knows the `gateFail`
  template (`extensions/gate.ts:136`) reads it as truncation — and the likely "consistency
  fix" would re-attach advice that tells an operator to remove the key and fall back to a
  packaged default that no longer carries a mode. That is a mechanism risk to the reason the
  asymmetry exists, not a taste question.
- **Also rejected:** putting it in the operator section — the operator sees one FAIL line and
  never learns `gateFail` has a tail to miss.

## J2 — RULING: the docs card ships mechanical pins, all in `test/`, not `council/validate.py`

T1 (cited-path existence + index reach) joins T2–T6 as bun tests over the real
`vault/wiki/*.md`.

- **Rejected (Position B — "docs cards don't carry test files"):** its premise is false on
  this tree. `test/fllwup25-agents-page.test.ts` was shipped by a docs card to pin a wiki page
  against `AGENTS.md`, and `test/fllwup58-gates-backstop.test.ts` reads the real
  `vault/wiki/test-suite-budget.md` and asserts its machine-parity marker against `gates.yml`.
  FLLWUP-25's settled item even recorded "consistency check under `test/`, not `council/`."
- **Rejected (validate.py as T1's home, the three-seat convergence):**
  1. `council/validate.py` is packaged tooling (`TOOLING_FILES` in
     `extensions/scaffold.ts:26`, seeded by `/council-init`, refreshable by
     `/council-update`); a check keyed to `extensions/**` citations hardcodes this package's
     layout into every consumer repo, where a legitimate wiki citation of package internals
     resolves under the install clone, not the consumer root — the consumer's wiki would go
     red for doing nothing wrong.
  2. Extending it means the repo copy and `council/scaffold/council/validate.py` diverge
     unless a docs card also ships a tooling-payload change — consent-gated refresh,
     `/council-update` surface, semver territory.
  3. Enforcement parity is exact: CI runs `bun test` and `python3 council/validate.py` back to
     back (`.github/workflows/gates.yml:17,19`), and neither `wiki-ingest.md` nor
     `wiki-lint.md` runs validate.py at all — validate.py has no timing advantage at the
     moment a wiki page is written; the moment that protects the wiki is the merge gate, and
     `test/` is already in it.
  4. The principal's `vault/`-absent no-op seam constraint disappears entirely: `test/` runs
     only in a repo that always has `vault/`.
- **Not creep, and not optional:** the goal's own clause is "every cited code path existing,"
  the Acceptance says "resolve mechanically," and the skeptic's failure injection proved the
  check is genuinely absent today. Without new surface, "mechanically" is decoration for a
  human eyeball.
- **The how stays with the owner:** one file or several; fllwup58's marker shape (test defines
  the string, page carries it verbatim) is the proven pattern for copy pins; a new live-arm
  file owes the `[[test-suite-budget]]` header rule. If consumer repos are also to be
  protected, that is a SEPARATE tooling-class card with the layout-generalization decided as
  tooling design — a step-13 candidate, not a fold-in (EV-77's goal is met without it).
