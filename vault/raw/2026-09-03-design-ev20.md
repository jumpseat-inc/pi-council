# EV-20 — Designer first pass (Don Norman seat)

Card: `council/cards/EV-20.md` (Matrix runner with repeat aggregation).
Spec authority: `docs/superpowers/specs/2026-09-03-EV-16-design.md`,
`2026-09-03-EV-19-design.md`, `2026-09-03-EV-18-design.md`. Rulings R-3/R-4/R-5
on the card face are binding.

This file is the design seat's independent first pass on the user-visible
surface of `/council-eval`. It is a position the owner builds against,
not a patch.

## 0. The constraint that frames everything

The matrix is isolating. A full 16-fixture × M-models × 3 sweep is hours of
dispatch, and a person watching it has no way to tell three things that
matter:

1. **What is happening right now** — which cell, which repeat, which model,
   what the last activity was.
2. **Whether the matrix is on the path they intended** — model id spelled
   correctly, fixture version they expected, repeat count right, no
   surprise "all models" sweep.
3. **What the matrix learned, honestly** — when it finishes, can they tell
   a real difference from variance noise, and can they tell a confident
   pass from a "1/3 succeeded, 1/3 length-flagged, 1/3 stalled" cell
   that should not collapse to a single number?

The interface is the only answer to all three. Every rendering decision
below closes one of the two gulfs for the person sitting in front of it.

## 1. The command is **not** a markdown procedure

Phase 1 ruling R-3 names `/council-eval` and EV-16 §3.1 commits it is
"**NOT an LLM-orchestrated loop**." This rules out the markdown-procedure
path the seven shipped commands use (`council/procedures/*.md` →
`renderProcedure` → `sendUserMessage`). The harness must own the loop:
parse the arguments, fan out `council_dispatch` calls, accumulate reports,
write records, and render progress/summary — all from a TypeScript handler
registered the same way `council-init` and `council-jobs` are in
`extensions/index.ts`. **Mark this as a hard scope decision the
deliberation should adopt immediately**, because every surface decision
below depends on it: a markdown procedure that delegates to an LLM turns
progress into prose and variance into narrative, which is the worst place
to put both.

## 2. Argument grammar (deliberation item 1)

### 2.1. Surface form

R-3 already settles: `/council-eval [task] [model...] [--repeat N]`, no-arg
form lists available tasks. The interaction the surface owes the person is
*what the command thinks you meant before it spends an hour on it*. Two
distinct moments deserve distinct signifiers:

**Argument hint in the command palette (`/council-eval <TAB>` or `?`):**

```
/council-eval  [task] [model…] [--repeat N]
  No args: list available fixtures.
  Tasks resolve to fixture dirs under council/fixtures/.
  Models are provider/id[:thinking], e.g. openrouter/qwen/qwen3.6-35b-a3b.
```

The second line is the *signifier* the affordance "argument parser" needs
to convey — the format of the values, not just their slots.

**Confirmation echo on dispatch (before any cell runs):**

```
council-eval matrix
  task:        council
  fixture:     council/fixtures/council/ v1.0.0  (rubric 1.0.0, grader pinned)
  models:      openrouter/qwen/qwen3.6-35b-a3b:medium   (3 requested)
  repeat:      3   (default; --repeat overrides)
  total runs:  3 cells × 3 repeats = 9 dispatches
  est. ceiling: ~3 × repeat × fixture.timeoutMinutes + grader per cell

Run this matrix? [Y/n / edit args]
```

This is a forcing-function for the Gulf of Execution: by the time the
person sees "9 dispatches" and a time ceiling they have already lost,
they can stop before anything burns. **The confirmation must quote back
the resolved taskId (with its `fixtureVersion`), the model ids verbatim,
the repeat count, and the total dispatch count** — not the original
typo. A misspelled model id on a 9-dispatch sweep is an hour of waste
that one echo would have prevented.

### 2.2. Parsing

The grammar the spec requires:

- `[task]` is the **first positional argument**, task-id-validated against
  `listFixtureTasks(repoRoot)`. Unknown task id → "no fixture named
  `<id>`. Run `/council-eval` with no args to list available tasks."
- `[model...]` collects **every positional after `[task]` and before the
  first `--flag`**. Each model is `parseQualifiedModel`-validated. An
  invalid id (bare id, unknown `:thinking` suffix) → refuse with the file
  context, no partial run.
- `--repeat N` is a **named flag**, integer, ≥ 1, with a hard upper bound
  (recommend **20**, because above that the 95% CI on `σ/√n` stops
  shrinking fast and the cost stays linear). Out-of-range → refuse.
- **No flag-equivalent positional for repeat.** Mixing `--repeat 3` and
  a positional "3" silently double-uses the 3, and that's the kind of
  design debt the surface owes nothing to.

### 2.3. The no-arg form

Per R-3, no-arg lists available tasks. The list is the **empty state for
"what can I run?"** and must answer three questions:

```
council-eval · available fixtures
  7 procedures · 9 seats · 16 tasks total

  PROCEDURES (7)            kind   graderModel                    fixtureVersion
  council                   proc   openrouter/qwen/qwen3.6-35b-a3b:medium  1.0.0
  features-deliver          proc   …                                          1.0.0
  …
  SEATS (9)
  skeptic                   seat   …                                  1.0.0
  …

  Run: /council-eval <task> <model…> [--repeat N]
```

Three signifiers matter here, **in this priority**:

1. **taskId + kind** (proc/seat) — the disambiguator. Two fixtures can
   share a name across consumer overrides; the kind column says which
   target shape it runs against.
2. **graderModel** — the cell's grader is fixture-pinned (EV-18 §2). A
   person who does not see the grader model on the list cannot know what
   their re-grade will use. This is the standing "corrected data"
   signifier from the re-grounding block: the score a person sees is the
   merged output of two models, and the surface must keep them separable
   on first glance.
3. **fixtureVersion** — semver, the identity used to compare across
   matrix runs.

**Rendered as plain text via `ctx.ui.notify`**, not as a widget — this is
a one-shot lookup, not a live surface. The notification form (already
used by `/council-jobs`) keeps the no-arg form consistent with the rest
of the Council's voice.

## 3. Progress during the matrix (deliberation item 2)

### 3.1. What progress is, and what it isn't

The cell-invariance contract (EV-16 §1) means a cell is **disposable
scratch worktree seeded from the fixture, runs the cell driver, the cell
driver settles, the harness dispatches the grader**. From the person's
seat:

- They do not see the cell driver think (the transcript lives in
  `runs/` — convention 12 — and the matrix forbids reading it from any
  surface code outside that closed quarantine).
- They **do** see, at minimum: the cell started, the cell settled
  (`done`/`stalled`/`timeout`/`failed`), the score computed, the
  terminal-state histogram updated.

### 3.2. The progress surface

The progress surface lives in the **inline job tree**, the EV-2/EV-7/EV-9
panel that is now the project's standing chrome. Concretely:

- The matrix command **uses `council_dispatch`**, which spawns the cell
  driver as a regular Council job. Each cell driver shows up in the tree
  as a row (✓ done, ⏳ running, ⚠ stalled, ✕ failed — the glyph set
  `widgetLines`/`jobLines` already draws).
- **The matrix also creates a top-level "matrix" pseudo-row** above the
  cell rows that names the matrix (e.g. `eval council × 3 models × 3
  repeats`, with a cell-count progress bar `●●●○○○○○`). This row is the
  aggregate signifier — without it, a person looking at 9 simultaneous
  cell rows cannot tell whether they are 30% or 90% through the matrix.
- The grader dispatch shows up as a row too — but **as a child of the
  matrix pseudo-row, not of the cell driver** (EV-16 §6.2 ruling 1: the
  grader is harness-dispatched with `parentJobId = command job`). The
  tree's existing `parentJobId`-based nesting gives this for free.

### 3.3. Per-cell progress line

Each cell row's last-activity must be the **state the person needs to
plan their next move**, not whatever verb the seat happened to use last.
That means the harness writes the row's `events` array, not the seat.
Suggested verbatim text per cell state:

- on spawn: `seeded worktree from fixture v1.0.0`
- on cell-driver settle: `cell <state> · <stopReason if any>`
- on grader spawn: `grading under <graderModel>`
- on grader settle: `score <s> · <n_graded>/<n_attempted> graded · <lengthFlagged> length-flagged`
- on row final state (after all repeats done or terminal): the one-line
  cell summary (see §4.2)

The harness is the only thing that knows all of this — the cell driver
does not, and the grader does not — so the harness is the only thing
that should be writing it.

### 3.4. What progress must NOT do

- **No LLM-generated narrative.** "I'm now comparing how the three
  models handle the council fixture…" — the person cannot trust that
  prose and cannot cite it later. A 16 × 3 × 3 sweep with prose in the
  transcript is an unauditable artifact.
- **No percentile-of-budget counter that ticks up faster than work
  happens.** A progress bar that races ahead of the matrix trains
  people to disbelieve it; once disbelieved, the bar is gone as a
  signal.
- **No "ETA: in 2h 14m" extrapolation.** Cell cost is bimodal at the
  fixtures' timeout ceiling — a `timeoutMinutes: 240` fixture will
  spend 240 minutes on stalls. ETA is a hallucination surface; the
  progress signifier is *cells done* / *cells remaining*, full stop.

### 3.5. Error and partial states

- A cell that stalls is **not** retried by the harness silently — the
  spec does not authorize a re-dispatch loop and the dispatch discipline
  the harness reuses (`hub.ts` is stable, AGENTS.md #7) caps the
  re-dispatch at one. The cell's row goes to `⚠ stalled`, the matrix
  continues to the next cell, and the final summary tallies
  `n_stalled_cells` up front, not buried in the per-cell row.
- A grader that errors or times out is **fatal for the cell**, not for
  the matrix — the cell record is written with `n_graded: 0,
  n_attempted: <repeat>` and the score is `indeterminate`, not 0 (see
  §4.4). The matrix continues; the summary flags the cells.
- A load failure (fixture missing, rubric invalid, model unparseable) is
  **fatal before any dispatch** — refused in argument parsing, never
  partial.

## 4. The final summary (deliberation item 2)

### 4.1. The summary is a table, not prose

The matrix cost is hours; the person returns to it wanting to **act**,
not to read. The summary is a per-cell table that opens with a header
they can read in two seconds and then a body where every cell carries
the four numbers they need:

```
council-eval · council · 3 models · 3 repeats · finished in 2h 14m
  cells: 9   scored: 8   indeterminate: 1   length-flagged: 1
  aggregate cost: $X.XX · tokens: Y · gradings: 9 under qwen3.6-35b-a3b:medium

  MODEL                                       MEAN     σ      n   TRIAGE
  openrouter/qwen/qwen3.6-35b-a3b:medium    0.92    0.06    3    ▮▮▮▮▮  leader
  openrouter/anthropic/claude-sonnet-4.5     0.88    0.08    3    ▮▮▮▮▯  tied (±CI)
  openrouter/google/gemini-2.5-pro           —       —       1/3  indeterminate (length ×1, stall ×1)
```

Three principles drove every column:

1. **Indeterminate is its own column, never a 0.** A cell with
   1/3 graded and 2/3 length-flagged is not `mean=0.33, σ=0`. It is
   `indeterminate`, and the surface says so. The standing design hazard
   (re-grounding §1) — the gap between what the surface implies and what
   the data knows — is widest here, and collapsing it costs the person's
   trust in the rest of the table.
2. **TRIAGE between close cells, not ordering.** EV-16 §8's first-class
   rule: "do not claim an ordering whose variance doesn't support it."
   When two cells' 95% CIs overlap, the surface says `tied (±CI)`,
   never sorts them by mean, and never prints a "winner". The TRIAGE
   glyph (`▮▮▮▮▯`) is a rank class, not a number — five bars for cells
   whose CI sits entirely above the next-best, four bars for the next
   rank when the gap is real, three for tied-with-leader, two for
   indeterminate.
3. **Terminal-state histogram lives next to mean/σ, not in a footnote.**
   EV-16 §8 commits the histogram "alongside mean/σ". A footer means
   the person never sees it; a column means they read it on the same
   glance. Spec sentence: `done × 2 · length × 1`.

### 4.2. Per-cell line shape

For each cell, the one-line table row reads:

```
<model id padded>   <mean>    <σ>    <n>/<n>   <triage glyph>  <terminal histogram>
```

Where:

- `<mean>` and `<σ>` are computed **only from completed repeats** (EV-16
  §8 E2: `stopReason=length` is flagged, never scored 0; score is over
  completed repeats only). Rendered to 2 decimals.
- `<n>/<n>` is `<n_graded>/<n_attempted>`. A row like `2/3` is honest —
  the person sees the matrix did not get three answers.
- `<triage glyph>` is one of: `▮▮▮▮▮` (leader, CI clear of next), `▮▮▮▮▯`
  (next, CI clear of next), `▮▮▮▯▯` (tied with leader), `▮▯▯▯▯`
  (tied with next), `—` (indeterminate).
- `<terminal histogram>` is the compact form: `done×2 · length×1`. Empty
  histogram is `done×3`.

### 4.3. The CI computation the surface owes

The matrix prints CIs when there is anything to triage. Concretely: a
cell with `n_graded ≥ 2` and `σ > 0` gets a 95% CI on the mean
(`mean ± t_{0.975, n-1} · σ/√n`); cells with `n_graded = 1` get
`σ = —` and no CI; cells with `n_graded = 0` are indeterminate. **The
TRIAGE glyph is derived from the CIs on pairs of cells, not from a
single threshold on `σ`**. This is the literal rendering of "a
difference is real iff the CI on the mean difference excludes zero" —
and the surface's job is to show that derivation, not to hide it.

The surface does **not** print the underlying t-statistic. The person
needs to know whether to trust a claim of difference; they do not need
to recompute it.

### 4.4. Failure modes the summary must name, not bury

- `stopReason=length` on a majority of repeats → **cell renders as
  indeterminate, not as a low number** (EV-16 §8 majority-flagged
  cell). Surface text: `indeterminate (length majority)`.
- `n_graded == 0` (cell driver never settled) → **cell renders as
  indeterminate, not as 0**. Surface text: `indeterminate (no graded
  repeats)`.
- `n_attempted < repeat` → surface text: `<n_attempted>/<repeat>
  attempted` (the matrix gave up on this cell, the person should know).
- A grading that fails (judge dispatch errored) → the verdict record
  is absent; the cell's score is **over gate criteria only**, and the
  summary line flags `judge-failed: graded gates only` so the person
  knows the score is partial.

### 4.5. Empty state on a fresh checkout

A person who has never run the matrix and types `/council-eval` sees
the no-arg list form (§2.3). A person who *has* run it before sees the
last matrix's summary on the same first line of the command output —
because the last summary is the most useful single answer to "what is
the current state?" That reuse is the smallest cost the surface can
charge.

A person who has never written a record under `council/eval-results/`
sees:

```
council-eval · no results yet
  council/eval-results/ does not exist.
  16 fixtures available — run `/council-eval <task> <model…> [--repeat N]`.
```

The empty state is **truthful, not apologetic**. It tells them the
directory does not exist (so they know it is not just empty); it
points them at the same list the no-arg form produces; it does not
link to documentation they would have to open.

### 4.6. Voice

The voice is the same voice the rest of the Council uses: terse,
factual, no hand-holding. No emoji beyond the existing glyph set. No
"Please run" or "You may want to". The first-person reader is an
operator who already paid for the sweep; address them as one.

## 5. The records-themselves-are-the-aggregate invariant

EV-16 §8's first sentence is load-bearing: "per-cell mean, sample σ,
and n computed from records alone." This is the only path that makes a
re-grade (re-running the matrix with a different grader) reproducible
from the on-disk artifact. The summary is the *projection* of the
records; the records are the truth.

That has a surface consequence the deliberation must not lose: **the
summary's cell lines render only fields that can be derived from the
records**. A mean is fine because `Σscore / n` is reproducible. A
`tokens` total is fine because it is in the record. A "model was
feeling confident today" is not. This is what stops LLM-narrative
progress (§3.4) from contaminating the durable artifact.

## 6. The two gulfs, named

- **Gulf of Execution, moment 1 (typing the command):** the person does
  not know what arguments the harness will accept, what models are
  legal, or what the matrix will cost. → Closed by the argument hint
  and the confirmation echo (§2.1).
- **Gulf of Evaluation, moment 1 (during the matrix):** the person
  cannot tell which cell is running, whether it is healthy, how far
  through the matrix they are. → Closed by the matrix pseudo-row in
  the inline tree + per-cell last-activity lines (§3.2–3.3).
- **Gulf of Evaluation, moment 2 (the summary):** the person cannot
  tell a real difference from noise, an indeterminate cell from a
  failure. → Closed by the table with TRIAGE glyphs, CI-derived
  rank, and terminal-state histogram next to mean/σ (§4).
- **Gulf of Execution, moment 2 (after the summary):** the person
  cannot tell what to do next (rerun with `--repeat 5`? swap a
  model? investigate the indeterminate cell?). → The summary
  surfaces the next action implicitly: `tied (±CI)` says
  "increase n"; `indeterminate` says "investigate the model
  config".

## 7. Falsifiable predictions (CDP-smoke-able)

These are the predictions that would be falsified by an out-of-band
CDP smoke or by a pure-seam unit test. Stated as hypotheses with the
exact smoke that would falsify each.

1. **Argument hint renders with the model-grammar hint.** `> /council-eval`
   in the command palette shows `[task] [model…] [--repeat N]` plus a
   `provider/id[:thinking]` example. Falsifier: smoke renders the
   command palette and asserts the hint text.
2. **Confirmation echo names the resolved taskId + fixtureVersion +
   model count + dispatch total before any cell spawns.** Falsifier:
   hook the harness's pre-dispatch path; assert a notify with all four
   values is on the bus before any `council_dispatch` call.
3. **An unknown task id refuses at parse time with the no-arg
   pointer.** Falsifier: pure unit on the parser — `parseArgs(['nope'])`
   throws naming the suggestion `/council-eval` (no args).
4. **An invalid `:thinking` suffix on a model refuses at parse time
   with the EV-18 Q3 fix's behavior** (the unknown suffix throws, not
   silently survives). Falsifier: pure unit on the parser using the
   shared `parseQualifiedModel` from `extensions/seats.ts`.
5. **The matrix pseudo-row appears above the cell-driver rows in the
   inline job tree.** Falsifier: CDP smoke renders the tree mid-matrix
   and asserts the matrix row's first-position and the cell rows'
   parentJobId = matrix job.
6. **The per-cell last-activity line never contains LLM prose.**
   Falsifier: smoke asserts the `events` array on a settled cell row
   matches the harness-written verb set in §3.3 only.
7. **The summary's per-cell `n`/`n_attempted` equals the count of
   records written under `council/eval-results/<cellId>/<repeat>/
   <scoredUnder>.json`.** Falsifier: pure unit — re-derive mean/σ/n
   from the records and assert deep-equal to the rendered row.
8. **The summary never sorts close cells by mean alone.** Falsifier:
   smoke with two cells whose CIs overlap (e.g. mean=0.92 σ=0.06 vs
   mean=0.88 σ=0.08 at n=3 — overlapping at 95%); assert the rendered
   table shows `tied (±CI)`, not an asserted order.
9. **A cell with majority `stopReason=length` renders as
   `indeterminate (length majority)`, not as a low mean.** Falsifier:
   pure unit on the cell-summary projection — input `[{length, done},
   {length, done}, {ok}]`; assert output `indeterminate (length
   majority)`.
10. **The TRIAGE glyph derivation is reproducible from the records.**
    Falsifier: pure unit — given two cells' records, compute the 95%
    CI on the mean difference; assert the rendered glyph is `tied`
    iff the CI includes zero.
11. **A grader dispatch error yields `indeterminate` with `n_graded=0`
    on the cell, never `score=0`.** Falsifier: pure unit on the
    cell-summary projection with empty `verdicts`.
12. **Empty `council/eval-results/` renders the truthful empty state
    pointing at the no-arg list.** Falsifier: smoke with a fresh
    checkout asserts the empty-state text and the pointer line.
13. **The summary's "last matrix" line is reproducible from the records
    alone** — given the same records, two runs render byte-identical
    summaries. Falsifier: pure unit comparing two renders.

## 8. Preferences, ranked last

- **Glyph set.** `▮▮▮▮▮`/`▮▮▮▮▯`/… is a taste choice; the existing
  Council chrome uses plain `✓`/`⏳`/`⚠`/`✕`. I lean toward keeping the
  matrix summary's TRIAGE glyph set consistent with the Council
  (glyphs rather than unicode bars) and using **letter rank classes**
  (`A` / `B` / `T` tied / `—` indeterminate) instead. Taste, not
  principle.
- **Confirmation echo before dispatch.** I prefer the explicit
  `Run this matrix? [Y/n]` gate; the owner could argue the
  argument-validation step + the model-id spelling check already
  make a confirmation redundant, and the cost-of-a-sweep is in the
  *time*, not the *money*. I think time is enough.
- **No-arg form's third column.** I lean toward `fixtureVersion`
  over `target shape` (`{command, args}` vs `{seat}`) as the
  third-most-important column for first-time users. Counterargument:
  an experienced operator cares about target shape more. Tie.

## 9. What this seat hands the owner and the other seats

- A scoping decision the deliberation must adopt on day 1:
  `/council-eval` is a TypeScript handler, not a markdown procedure.
- An argument grammar + a confirmation echo + a no-arg list form.
- A progress surface that lives in the existing inline job tree, with
  a matrix pseudo-row the harness writes directly.
- A summary table whose every column is a record-derived projection,
  with TRIAGE glyphs and terminal-state histograms that never
  collapse to a number an honest reading of the data would not
  support.
- An empty state that points at the same list the no-arg form
  produces, and does so truthfully on a fresh checkout.
- Falsifiable predictions numbered 1–13 for the skeptic to either
  falsify or close-green.

What I am **not** handing the owner: an LLM-narrative progress
narrative, an ETA, a percentile-of-budget bar, an asserted ordering
between close cells, or a 0 score on a `stopReason=length` cell. Those
are the design decisions this card has already paid for not having.
