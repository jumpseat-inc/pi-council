# Product-owner ruling — EV-40 open-judgment (Q1–Q6) and the carried constraints

Run: `/features-deliver` step 6 ruling on card **EV-40** (epic EPIC-9) at
origin/main `934d406`, `validate.py` clean. Consolidator's step-5 synthesis
(`council/cards/EV-40.md` §Step 5) routed six open-judgment items; this
ruling settles each. Step 6 (PO) decides the *what*; the owner keeps the
*how* within the constraints recorded here.

The card's `goal` is immutable; R5 is immutable. R5's *copy* and *terminal
message* are binding. R5's *surface* — "the input bar reads … and `Esc`
aborts" — is read here as binding on the rendering surface, because
re-pinning to a different surface would change R5's recorded per-branch
observable ("input bar's text delta in the TUI"). Reversing a recorded
human decision is the steward's authority, not this seat's.

## Q1 — R5 surface: implement the input bar literally

**Ruling.** R5's surface is binding. The countdown is rendered in the
*input bar* via a `CustomEditor` subclass installed by
`setEditorComponent`. The `CustomEditor`:

- extends pi's exported `CustomEditor` base (`types.d.ts:139–170`),
- composes over `getEditorComponent()` (the O6 single-slot composition
  hazard — same discipline as EV-8 O4 in
  `vault/raw/2026-08-26-po-ev8-ruling.md`),
- renders R5's countdown line as an **extra editor-region line**
  appended to `super.render(width)` (the `focus-nav.ts:277–289`
  precedent — `CustomTreeEditor` already does this for the tree's label
  line),
- intercepts Escape *before* `super.handleInput(data)` to disarm the
  retry timer,
- forwards every other key to `super.handleInput(data)` (the
  forward-unhandled discipline from EV-8 Ruling 2, so ctrl+c still
  reaches pi's normal abort path and printables still reach the buffer),
- explicitly **forbids** `setEditorText` for the countdown (per Skeptic
  O6 — `setEditorText` clobbers the buffer).

### Why not the status-row alternative

The designer's `setStatus("council.retry", …)` argument has merit on
three counts: (i) the status row is the platform's established retry-
indicator lane (`RetryStatusIndicator` extends `Loader` and lives in
the status-indicator slot at
`dist/modes/interactive/components/status-indicator.js:27–41`), (ii)
R5's copy differs from pi's own indicator copy only cosmetically,
(iii) the route is one call rather than a `CustomEditor` subclass with
composition over `focus-nav`. Each is true, and the platform-precedent
argument is consistent with my EV-9 ruling (`vault/raw/2026-08-26-po-ev9-tiny-regime-floor.md`)
on "follow platform precedent for refusal-to-render at degenerate
heights."

It is **not chosen here**, because R5 explicitly names "the input bar
reads …" as the per-branch observable and "input bar's text delta" as
the goal-observable. Re-pinning the rendering to the status row would
change that observable. That is a reversal of a recorded human decision,
which is escalation territory under this seat's contract — see
[[product-owner]] §"Grounding and escalation" and
`vault/raw/2026-09-11-epic7-run-ledger.md` for the goal-as-defect
precedent. **The designer's status-row route is not adopted; it is
filed for steward escalation separately, if the designer wishes to
pursue it.** Card stays consistent with R5 as written.

The designer's P1 contradiction (R5's countdown cannot render in the
input bar because the API has no input-bar text setter) is **not
adopted** — the `CustomEditor` approach renders the countdown as an
*extra editor-region line*, not as input-bar buffer text or a buffer
placeholder. Skeptic O6 confirmed `setEditorComponent`
snapshot-restores the draft and the `CustomTreeEditor` precedent for
the extra-line render; the API does not need a text setter, and the
countdown does not need to be buffer text.

### Constraints from Skeptic O6, carried forward

- Single editor slot — `focus-nav.ts:348–357` already swaps the editor
  via `installTreeEditor`/`restoreTreeEditor`, saving `installedPrior`.
  The retry editor must compose over `getEditorComponent()` and restore
  identically on disarm, or the two overlays clobber each other.
- pi-tui's `Editor` has **no** `placeholder` field. R5's string can only
  render as an extra line in the editor region, never as buffer text or
  an empty-buffer placeholder.
- R5's wording is **preserved verbatim**; no cosmetic copy-edit against
  pi's `Retrying (2/3) in 2s... (Esc to cancel)`. The literal string is
  `Retrying in <Ns> (attempt <n> of <N>) — Esc to abort` with the
  computed backoff delay (not hardcoded `2s`), the attempt number, and
  the max attempts — interpolation, not substitution.

### Reversibility

Medium. If the editor-slot composition with `focus-nav` proves to be a
live blocker, the implementation can split (per owner's A/B split) and
the editor overlay (card B) can be re-routed to the status row via a
steward escalation that overturns R5. The A card's mechanism
(detection, context filter, agent_settled re-issue, headless await,
terminal message) stands independently of the editor overlay.

## Q2 — the three "Press Enter" axes at exhaustion

R5's terminal copy is `Retries exhausted after 3 attempts. The provider
kept failing. Press Enter to try again.` "Press Enter to try again"
**means what it says**: pressing Enter at the terminal-copy state
re-arms the retry loop with the original user prompt and a fresh
attempt budget (back to `1 of 3`).

A copy that says "Press Enter to try again" with an inert Enter is the
class of ruling this seat's contract calls a failure regardless of how
clean the implementation is: the mechanism is satisfied, but the value
is not — the person is told one thing and the runtime does another.
R5 is immutable, so the only honest reading is to make Enter mean what
the copy promises. Owner implements accordingly; the editor-capture
work that owner flagged as "would require [it] to build" is in fact
required to honestly meet R5 and is folded into A (no new card).

### Axis 1 — what Enter does

**Re-send the original prompt and re-arm the loop.** The
`CustomEditor` override intercepts Enter at the exhaustion state
(before `super.handleInput(data)`), fetches the *original* user prompt
from the parent-closure state (stored alongside the timer when
detection fires at `message_end` / `agent_end`), clears the timer
state, resets the attempt counter to 1, and re-arms the loop. The
countdown returns; the loop runs again through backoff/countdown/Esc/
abort semantics from the top.

### Axis 2 — what survives in the transcript

**The errored assistant message remains in the persisted JSONL
transcript; it is filtered from the next provider request only.** Two
binding facts, not rulings:

- The errored assistant message is appended to JSONL by `appendMessage`
  in `agent-session.js:395–401` *before* `agent_settled` fires. It
  cannot be un-appended. The persisted transcript therefore shows the
  partial errored turn forever.
- The parent-loop's `context` hook handler (registered alongside the
  `agent_settled` handler in `extensions/index.ts:379–385`; filter
  built per Skeptic O4 — *structural, not identity*, since
  `runner.emitContext` `structuredClone`s the messages list at
  `runner.js:791–804`) drops the errored assistant message from the
  next provider call only. Armed for exactly one request via a closure
  flag set at detection and cleared after one pass.

### Axis 3 — attempt budget reset

**Yes. Enter resets the attempt counter to 1.** Fresh `1 of 3` after
Enter. The session does **not** carry an internal "4th attempt" beyond
the budget — the budget is reset, the loop re-enters backoff at
attempt 1.

### Constraints carried forward (already settled, restated)

- **O3 literal hygiene:** every test exercising `classifyRetry` must
  use the **with-colon** literal `Provider finish_reason: error`. The
  EV-43 falsifier's colon-less string is classify-negative on both
  clauses (`extensions/retry.ts:54–60` and `pi-ai/retry.js:20–60`) and
  tests nothing. Named acceptance criterion.
- **O4 structural filter:** `context`-hook filter is structural (role +
  content + stopReason + errorMessage) or index-delimited; identity
  comparison is dead. Closure flag, exactly one pass.
- **O5 corollary:** `ctx.isIdle()` in a settle handler cannot
  distinguish "settled, safe to send" from "nothing happening." The
  headless pattern (Q3 below) must not rely on `isIdle()` alone.

## Q3 — headless abort equivalent of `Esc`

**SIGINT to the parent process.** No new surface; no JSONL marker.

In `-p` / `--mode json` / `--mode rpc`, `Esc` does not exist. The
established operator signal channel is **SIGINT** (or SIGTERM via
process management); pi's runtime defaults to terminating on SIGINT.
The headless retry pattern awaits backoff + send *inside* the
`agent_settled` handler (per principal's mitigation; per
`extensions/index.ts:448–454`'s own "print mode would tear the
runtime down mid-turn" warning). When SIGINT arrives during that
await, the runtime terminates and the unref'd timer (carried from
the TUI path) does not fire because the process is gone. **Disarming
falls out of teardown** — no explicit disarm code is required.

### What the headless countdown line advertises

**Nothing new.** The R5 countdown string in headless is the
stdout-line equivalent of the TUI's input-bar line. It does **not**
advertise "Ctrl-C to abort" — headless operators already know SIGINT
is available; advertising it would add affordance surface that is
already universal in `-p` invocations. The terminal copy at exhaustion
in headless follows Q5 below.

### Reversibility

Trivial. Adding a JSONL marker or a different signal later is
additive — no existing call site changes.

## Q4 — input-bar edit semantics during backoff (TUI)

**The input bar is interactive during backoff. Typed text accumulates
in the buffer; pressing Esc aborts the retry; pressing Enter on a
non-empty buffer submits the typed text and aborts the retry.
Enter on an empty buffer is a no-op.** The user's prompt always wins
over the council's auto-retry.

Concretely, in the `CustomEditor.handleInput` override during the
`backoff` state:

- **Escape** → intercept before `super.handleInput(data)`, disarm the
  timer, render a fresh-idle state. (Already specified in Q1.)
- **Enter on empty buffer** → intercept, no-op. The retry continues.
  Pi's normal submit path is not invoked. The user can press Esc if
  they want to abort; or type something to send.
- **Enter on non-empty buffer** → intercept, disarm the timer, *then*
  forward to `super.handleInput(data)`. The editor submits the typed
  text through pi's normal turn path. The typed text becomes the next
  user message; the council's continuation is aborted.
- **All other keys** → forward to `super.handleInput(data)`. Printables
  accumulate in the buffer; ctrl+c reaches pi's normal abort path;
  ctrl+d, PageUp, PageDown, Home, End, Backspace, Tab all reach their
  normal editor destinations. (Forward-unhandled per EV-8 Ruling 2.)

### Why this and not "discard typed text" or "override the
continuation send"

- "Discard typed text" loses user input — a real failure of user
  value. The countdown is transient visual noise in the editor region,
  not a buffer lock.
- "The continuation send is authoritative" means any typed text is
  dropped or pre-empted by the retry. But if the user types during
  backoff, they're already telling the system something; suppressing
  that is silent failure.
- The "user's prompt wins" rule is the editor-driven analog of
  EV-8's forward-unhandled policy
  (`vault/raw/2026-08-26-po-ev8-ruling.md` Ruling 2): interactive
  surfaces give the user safe, defined behavior for every action;
  council's defaults defer to user actions at any sign of life.

### Owner/principal reservation

Owner's round-2 design has "sends the continuation unconditionally and
clears the timer on a human prompt" — the "human prompt" being a
non-empty Enter submit. This ruling is consistent with owner's intent
and tightens the trigger: **any non-empty Enter during backoff is a
human prompt that preempts the retry.** Empty Enter is a no-op (does
not preempt). Owner implements accordingly.

## Q5 — headless "Press Enter to try again" equivalent

**Process exits with a non-zero exit code (council-specific; the
implementation picks the constant, suggested `75` / `EX_TEMPFAIL` for
the POSIX-correct semantic). The terminal copy is the final stdout
line. A wrapper (or operator) sees the exit code and re-invokes the
same prompt. No JSONL marker; no new surface.**

### Why not "stay alive and read stdin"

Headless `-p` has **no stay-alive-and-read-stdin mode**. Per
[[headless-pi]] §"Distinct rules" / "Single-shot teardown": "After the
initial prompt resolves, the runtime is disposed. Any async work
started by a command handler must be **awaited to completion inside
the handler** or it dies with the process." The post-resolution state
is teardown. A live stdin reader would be a new `-p` mode that does
not exist.

The honest reading of "Press Enter to try again" in headless is
therefore: the *operator* (or a wrapper script) "presses Enter" by
re-invoking the same prompt. The process signals "the situation is
recoverable with a retry; I'm done; re-run me" through the exit code,
and the operator's tooling translates that into a re-invocation. This
matches the unix convention for transient failures (`EX_TEMPFAIL` is
the canonical code) and is what CI/CD wrappers and the smoke harness
already understand.

In headless, "Press Enter" in the copy is a human-direction in the
runtime's output, not a runtime affordance — the human reads it and
re-runs the command at their own shell prompt (which is the editor in
headless). Enter at the shell prompt re-invokes the command.

### Wrapper contract

The wrapper layer (council's own smoke harness, or an operator's shell
loop) is responsible for translating the exit code into a
re-invocation. This is **not** council's job to build — the smoke
harness already exposes exit codes; the wrapper convention is
operator-side. The named exit code is the hand-off.

### Reversibility

Trivial. The exit code is a constant in the headless branch; changing
it later is a one-line edit. The wrapper convention is operator-side.

## Q6 — headless-abort testability

**Partly testable. The settling test is named and rides into the
step-7 spec as a gate.**

### Settling test (named, ride as gate)

**T-H1: SIGINT during headless backoff disarms the timer.**

- **Setup:** stub-child `STUB_MODE=finish_error` (the EV-41 forcing
  fixture) drives a `-p` invocation with `retry.enabled=true,
  maxAttempts=3, baseDelayMs=2000, maxDelayMs=30000, jitter=true`.
- **Action:** during attempt-2's backoff window, send SIGINT to the
  parent process.
- **Assertions:**
  1. No attempt-3 fires (no second continuation `sendUserMessage` is
     observed; transcript ends with attempt-2's countdown stdout line
     and no further assistant message).
  2. The process exits cleanly (status reflects SIGINT termination or
     a council-installed handler's chosen exit code, not a crash
     trace).
  3. No JSONL corruption (the run's transcript is well-formed up to
     the SIGINT).

### Why partly testable, not pure ruling

The semantics ("SIGINT disarms via runtime termination") is the
ruling. Whether the runtime terminates cleanly under SIGINT during
the awaited backoff — and whether the unref'd timer is in fact gone
before SIGINT can race — is an empirical fact only a run can settle.
T-H1 is the run.

The remaining headless-abort question (whether a *JSONL marker a
wrapper watches* would be a better affordance than exit codes) is
pure ruling. It is rejected above; a future card can reopen it.

## Carried constraints (recap from consolidator §"Carried constraints",
binding for the spec)

- **O3 literal hygiene** — with-colon literal in every test.
- **O2 correction** — implementation must not claim pi "ignores"
  `maxDelayMs`; the key exists and is honored by the provider-level
  `retryProviderRequest` loop. The agent-turn `_prepareRetry` applies
  no cap and no jitter — that is the precise claim.
- **O4 structural filter** — `context` filter must be structural /
  index-delimited, armed for exactly one pass.
- **O6 surface bans** — `setEditorText` forbidden; pi-tui `Editor`
  has no `placeholder`; single editor slot, must compose over
  `getEditorComponent()`.
- **O5 corollary** — `ctx.isIdle()` cannot distinguish "settled,
  safe" from "nothing happening"; the headless pattern must not rely
  on `isIdle()` alone.
- **Attempt identity (principal D3)** — no prompt-run id exists
  (`ExtensionContext` `types.d.ts:200–245`; manifests carry only
  `sessionId`/`jobId`; `hub.ts` has zero attempt notion today).
  Parent loop mints its own from `sessionManager.getSessionId()` +
  monotonic counter; EV-39 adds its own manifest field; only the
  **field name `attempt`** must be agreed now. A ruling, not code.
- **`runs/` is ephemeral (AGENTS.md §12)** — neither loop reads the
  other's counter; both stamp the same field names.

## Open objections — what rides into step 7 as named gates

- **P1 — headless timer-deferred send.** Two-arm `-p` probe from the
  `ev43/` falsifier base. Arm A: send-inside-handler. Arm B:
  send-after-1s-timer. Assert whether a second assistant message

  premise is inferred, not verified** — the
  `context`-filter design's load-bearing assumption is unverified. The
  probe must run before the `context`-filter implementation lands.
