## Intent

The human asked that the spend be reported explicitly at every autonomous exit,
and said over-reporting is good and explicit beats implicit. This card reports a
usage block at five autonomous exit points — `/features-new`, `/features-deliver`,
`/council`, `/council-eval`, and a council-runner's card execution (its
return-contract report, surfaced through features-deliver's Phase 3 ledger) —
replacing today's scalar `cost=$X` with the invocation's token split, a
provenance-labelled dollar value, and the accounting boundary the block covers.
The block is produced by a deterministic handler, not by the procedure's own
prose, so the same input yields the same block and a test can assert string
equality. The block is rendered after the accounting function returns, so it
cannot include the cost of its own generation; the boundary label names the
included range instead of implying completeness. Zero usage and accounting
failure each render an explicit state, never a blank. `board-create-card` is out
of the set — it is a single human-driven write, not an autonomous run.

## Acceptance

- For each of the five points, a fixture accounting record renders a usage block
  whose numbers equal the record.
- The block is byte-stable across repeated renders of the same input.
- The block names its accounting boundary.
- Zero-usage and accounting-failure inputs render explicit, non-blank states.
- `bun test`, `bunx tsc --noEmit`, `python3 council/validate.py` stay green.

## Approach

One pure renderer, two emission sites, five covered exits. **`formatUsageBlock(spend: SpendRecord): string`** lives in `extensions/spend.ts` (pure, next to `formatBoundaryLabel`, which it reuses verbatim). It is the only place the block's bytes exist. Emission site A is EV-31's gated flush: on the transition to `written`, the success notify **becomes** the block, rendered from the persisted `StoredUsageRecord.spend` — this covers `/features-new`, `/features-deliver`, `/council`, and `/council-eval` (the latter after we add the marker stamp it currently lacks). Emission site B is `council_wait`'s report (hub-tools): for a settled job with a manifest, the wait handler builds a manifest-derived SpendRecord over the job's subtree (`sumSubtree`) and appends the block — this is the fifth exit: the block lands in the orchestrator's context at the exact moment each runner's card concludes, and features-deliver's Phase 3 gains one sentence mandating it be carried into the ledger verbatim. The EV-28 head-line segment stays untouched — it is a settled, byte-tested surface, and it answers a different question (this job's instantaneous report) than the block (invocation-scoped accounting).

The timing property the card demands holds structurally: the flush renders only **after** `spendRecord()` returns and `persistInvocationUsage` has written, so the block can never contain the cost of its own generation, and the numbers shown are the numbers on disk. The `forestFullySettled` gate means the block for `/features-deliver` lands exactly when the last runner settles — i.e., at the Phase 3 moment — which is the correct "concluding output" for a hours-long epic, not a mid-run interruption.

## The block, byte-exact

Normal state (both halves measured), four-space-indented-free, `usage` + **two spaces** prefix matching R-5's literals:

```
usage  boundary=session=<sessionId> entries=<firstId>..<lastId> jobs=<n>
usage  ownSession [session-reconciled]: turns=<t> tokens=in <in>/out <out>/cR <cR>/cW <cW>/reason <r>/total <tot> cost≈$<cost> (catalogue)
usage  subtree [stream-assistant, lower bound]: turns=<t> tokens=in <in>/out <out>/cR <cR>/cW <cW>/reason <r>/total <tot> cost≈$<cost> (catalogue)
```

- Line 1 is `formatBoundaryLabel(spend)` output verbatim — R-4 already ruled it; the renderer composes, never re-renders.
- The `tokens=…` and money fragments are **extracted** from `formatUsageSegment` into shared helpers (`formatTokensFragment`, `formatMoney`) in spend.ts; hub-tools imports them, and a byte-identity test pins `formatUsageSegment`'s output through the refactor. `≈` is U+2248; `toFixed(4)`; reported basis renders `cost=$<cost> (reported)` — R-1 verbatim.
- **Provenance labels**: the bracketed `usageSource` values are the record's own machine vocabulary (store README teaches exactly these two names); `lower bound` is carried on the subtree line because the README already commits to surfacing that asymmetry prominently and the block is the most-read surface the record ever gets.
- **R-2**: when a measured half has activity (`turns > 0`) but `cost === 0`, its money slot renders `cost=n/a` and one final legend line is appended — `usage  n/a = provider figure unavailable` — iff the block contains any `n/a` (byte-stable either way). No basis signifier on an n/a slot.
- **R-5 zero state**: when both halves are all-zero (which covers the ruled unresolved-boundary case — EV-30 zeroed both halves, never an error), the entire block is the single line `usage  no usage recorded`. Boundary omitted; the durable record still carries `boundary.resolved: false` for forensics.
- **R-5 failure state**: `usage  accounting failed — <reason>` (U+2014 em dash). `<reason>` for a flush write failure is composed as `write failed for <absolute target path>: <error>` — this deliberately preserves EV-31's T-U14 property (the absolute store path appears in the notify) while adopting the ruled wording.

Runner-block variant (fifth exit), same grammar, one ruled difference:

```
usage  boundary=session=<runnerSessionId> entries=unresolved jobs=3
usage  subtree [stream-assistant, lower bound]: turns=<t> tokens=… cost≈$… (catalogue)
```

The parent structurally cannot session-reconcile a runner's own session (it lives inside the pruned run dir; the runner never stamps; per-node reconciliation is already filed as FLLWUP-31). So the `ownSession` half is **omitted, never zero-fabricated** — a zero line labelled `[session-reconciled]` would assert a measurement the parent never performed, which is exactly the kind of plausible-but-false number this card exists to kill. The boundary line uses R-4's already-ruled unresolved form with the true subtree job count. I take "identical in shape" (R-6) to mean one grammar — same prefix, same labels, same ordering, same ruled states — not a fixed line count; the alternative (a zeros ownSession line in the runner block) is the version I'd reject.

## Rendering at each of the five exits

1–3. **`/features-new`, `/features-deliver`, `/council`** — no procedure prose changes at all. The scanned-procedure handler already stamps the marker and pushes to `pendingInvocations` (index.ts:275–295). The first flush trigger at which the gate holds (normally `forest-settle` when the last dispatched seat settles) writes the record and emits the block via `ctx.ui.notify` (TUI) / `console.log` (headless). Zero-usage runs (e.g. `/council` stopping at step 1 on a non-Ready card) still flush a zero record → explicit `usage  no usage recorded`. **New failure emission**: when `recordInvocationBoundary` returns null (fail-closed), the handler synchronously emits `usage  accounting failed — invocation boundary unresolvable` — closing today's silent-blank path, which would otherwise violate "never a blank."
4. **`/council-eval`** — add `recordInvocationBoundary(pi, ctx, "council-eval", …)` + the pending-ledger push at the top of the run path (after arg validation, before `runMatrix`). Everything else is inherited: the last matrix job's settle trips the gate, the block emits before `summaryLines`. Ordering accepted: block, then eval summary — both in the concluding output.
5. **Runner card execution** — `council_wait`'s handler, after collecting a settled job: read `readManifests(repoRoot, runId)`, build the runner-shaped SpendRecord (boundary as above; subtree = `sumSubtree` over the job id, all metrics), append `"\n" + formatUsageBlock(...)` to the report. A job with no manifest usage (pre-EV-16 manifests, or nothing ran) renders `usage  no usage recorded` — never blank. `council/procedures/features-deliver.md` Phase 3 gains exactly one sentence: carry each card's runner usage block verbatim from the council_wait report into the ledger. The block remains engine-rendered; the orchestrator only transports it.

Double-emission is impossible by construction: the flush emits only on the `written` transition (`existing` is silent, honoring choose-once), and the runner site only renders at wait-collection time. The three flush triggers cannot produce two blocks for one invocation.

## Where the handler lives and how it's invoked

- `extensions/spend.ts`: `formatUsageBlock(spend: SpendRecord): string`, plus extracted `formatTokensFragment(u)` / `formatMoney(u)` reused by `formatUsageSegment`. Pure; no new resource mechanism (convention caution).
- `extensions/usage-store.ts`: flush success/failure notify wording → block forms (EV-31 ruled this wording is EV-32's; the call site is already there).
- `extensions/index.ts`: null-marker failure emission in the scanned handler; marker stamp + pending push in `council-eval`.
- `extensions/hub-tools.ts`: runner block appended in the wait path; `formatUsageSegment` refactored onto the shared helpers with a byte-identity test.
- `council/procedures/features-deliver.md`: one Phase 3 sentence.

## Tradeoffs accepted

- **Block-before-summary ordering in `/council-eval`'s output** (the flush fires inside the last job's onChange): accepted — forcing the block after the summary would need a second render site or a deferred queue, and both ends up in the same concluding output.
- **`n/a` trigger is a heuristic** (`turns > 0 && cost === 0`): a genuinely free catalogue model mislabels as n/a. EV-29 (provider-reported cost) is the real fix; until it lands, explicit-and-slightly-over-inclusive beats implicit, per the human's stated preference.
- **Runner block omits ownSession**: one line fewer than the session-exit shape; the honest alternative to a fabricated zero. Named as the one byte-shape question product-owner may rule differently.
- **Redundancy at the runner point** (EV-28 head-line segment + block in one wait report): accepted; they answer different questions and EV-28's surface is settled.

## Rejected alternatives

- **Deleting the head-line usage segment** ("block replaces the scalar"): reopens EV-28's byte-ruled surface for no acceptance gain.
- **Rendering the block from the model's prose** (procedures print it themselves): violates the card's own determinism requirement; untestable by string equality.
- **Runner stamps its own marker / seats stamp**: breaks the parent-mode-only stamping rule and puts a write path in child mode; per-node reconciliation is already FLLWUP-31.
- **Extending `SpendRecord` with an "unavailable" cost state** so the renderer needn't heurist: EV-31 froze the record shape byte-verbatim (`SpendRecord` gains no field); the heuristic is reversible when EV-29 lands.
- **A sixth per-job block surface for every attended dispatch**: the card's set is five; attended `/council` gets its block via the invocation flush; per-job blocks beyond the runner point are scope creep.

### The block I would render (byte level)

Prefix is ruled-consistent: both R-5 literals are `usage` + two spaces, so every line of the block carries `usage  `. Rows in order: measurement, measurement, boundary, legend. No header — the record (`SpendRecord`) carries no command/runId, and anything I printed beyond it could not be asserted against "the fixture accounting record".

```
usage  ownSession  basis=session-reconciled  turns=1 tokens=in 100/out 10/cR 900/cW 0/reason 7/total 1010 cost≈$0.0013 (catalogue)
usage  subtree     basis=stream-assistant  turns=4 tokens=in 9000/out 2100/cR 44000/cW 800/reason 700/total 55900 cost≈$0.2010 (catalogue)
usage  boundary=session=ses_abc entries=e12..e57 jobs=5
usage  n/a = provider figure unavailable
```

Byte rules: `usage`+2 spaces; half label `ownSession`|`subtree` padded to 10; 2 spaces; `basis=` + `record.<half>.usageSource` (**read from data, so a half can never be mislabelled**); 2 spaces; then `formatUsageSegment(record.<half>)` verbatim — the token split is `turns` / `in / out / cR / cW / reason / total` with no thousands separators, money rightmost (`≈` U+2248 catalogue, `$` reported), exactly EV-28 Q5. Row 3 = `usage  ` + `formatBoundaryLabel(record)` verbatim. Row 4 = `usage  n/a = provider figure unavailable` (em dash with two spaces before the legend text is *not* the same glyph as R-5's `—`; R-5 uses U+2014 with a space). No trailing newline, no ANSI, no locale. Every line ≤160 cols (EV-28's T5 discipline; wide fixture → follow-up card, as EV-28 ruled).

States, precedence **failed > empty > full**:

```
usage  no usage recorded
usage  accounting failed — <reason>
```

Both are **whole-block replacements** (one line), for the same reason R-5 pairs them: a failed accounting has no boundary to name, and zero usage has no numbers. The failure reason is call-site data, newline-normalized so the state stays one line. No legend in either state.

Renderer contract (new pure leaf `extensions/usage-block.ts`; `formatUsageSegment` moves to `extensions/usage-format.ts`, re-exported from `hub-tools.ts` so EV-28's landed import/test are untouched — this also breaks the hub-tools↔block import cycle that point 5 would otherwise create):

```ts
formatUsageBlock(input: { record: SpendRecord; unavailableCost?: Half[] } | { failed: string }): string
```

`unavailableCost` is R-2's `n/a` hook (`cost=n/a (reported)` for that half via an optional second arg to `formatUsageSegment`, kept to one composition); EV-29 — the card that actually makes a provider figure absent — populates it. Everything else about the block is derived from the record.

### Where each point renders it

- **Points 1–3 (`/council`, `/features-new`, `/features-deliver`):** from the **one** `agent_settled` handler EV-31 already owns (`index.ts:189-193`), after `flushUsage`. Same ledger, keyed by markerId, with a **`rendered` set** separate from the flush's `remaining` (a gate-closed *write* must not suppress a *render* — rendering computes from live memory, not the store). In TUI the handler has long returned, so `agent_settled` is the only engine-observable conclusion; in headless it fires too, and the sink falls back to `console.log` (the `flushUsage`/`emit` precedent already in this file). Emit out-of-band — `ctx.ui.notify(block, "info")` / `console.log(block)` — **never** `sendUserMessage`: an injected turn appends a session entry that the boundary's own-session range would then be able to pick up, which is the "cannot include the cost of its own generation" clause failing by construction.
- **Point 4 (`/council-eval`):** the handler stamps the same marker (so it gets a durable record and a real own=~0/subtree=cells split), and renders from its awaited post-`runMatrix` tail — the only point with an in-hand conclusion — then marks the marker rendered so `agent_settled` skips it. The no-arg listing form renders no block (it is not a run). To make the AC's five-point test reachable I'd inject the matrix runner into the command registration (a `deps` default to the real `runMatrix`) rather than hitting the network in a unit test.
- **Point 5 (runner card execution):** rendered **by the parent**, at `council_wait`, appended to that job's report — i.e. into exactly the text `features-deliver`'s Phase 3 ledger reads. The record is built from the runner's **own session JSONL**: `findSessionFile(repoRoot, runId, job.id)` (`runs.ts:134`, already exists) → `parseSessionEntries` (precedent `usage-store.ts:defaultReadEntryIds`) → marker via `findLatestInvocationMarker` → `spendRecord` with the run dir's manifests. Own half = the runner's reconciled session (basis `session-reconciled`); subtree half = **its own job and descendants** (basis `stream-assistant`). Two additive changes ride along: child mode appends a `council-invocation` marker on `session_start` for container seats (gated on the seat declaring `spawns` — no seat name hardcoded), and `spendRecord` gains an optional `rootJobId` whose default preserves today's null-rooted rule byte-for-byte. EV-30 ruling item 6 already contemplates recompute-from-the-same-run-dir with "the basis decision owned by the recomputing side", so this is anticipated, not novel.

**The trap this avoids, and it is the reason I am writing this:** computed *inside* the runner, `spendRecord`'s forest rule ("roots = manifests with `parentJobId === null`") finds **nothing** — a runner's own job is not null-rooted; its manifest is written by the *parent's* hub. The subtree half would then read as a small, plausible, completely wrong number (the runner's own turns only, hiding every seat the card dispatched), and the card's acceptance test as literally written — "the block is present and its numbers equal the fixture accounting record" — **passes**. That is the same failure class EV-31's principal named (`council/cards/EV-31.md:177`): a successful acceptance test hiding the cross-seam defect.

## Blind spots (named separately, not mirrored)

- **Owner/engine slice:** sees the renderer and five call sites; cannot see that the TUI procedure handler returns before the turn concludes, so an owner's natural design emits from the handler, passes a headless test, and never fires for a real TUI `/council`.
- **Accounting slice (spend.ts vantage):** sees records and bases; cannot see that a container's job is not a forest root, so the child-scope subtree is structurally empty and its undercount is invisible to a fixture-shaped test.
- **Designer/surface slice:** sees the copy; cannot see that R-5's literals have two plausible homes (whole-block vs one-row replacement), that EV-31's store-notify lands at the same moment as the block (two lines, ordering racy — the obvious-but-wrong fix is dropping one), or that R-2's marker is unreachable until EV-29 lands — a designer's likely instinct ("print the legend only when `n/a` appears") would break R-6's single shape and the `[[smoke-test]]` precedent of grepping ruled literals.
- **Card/product slice:** sees "the block names its accounting boundary" and cannot see that EV-30's two ruled boundary forms leave one real case uncovered — entry ids unavailable while jobs are known (`formatBoundaryLabel` hardcodes `jobs=0` when unresolved).

## Reframe

Not a taste difference — a scope reframe: **the work is not "render a block five times"; it is "obtain a resolved `SpendRecord` for *this* invocation" at five points, then render once.** Four points have a session boundary (marker + `agent_settled`); the fifth is a job, and its only truthful boundary is the runner's own session JSONL — not the parent's manifest forest. Stating it that way makes the framing testable: each point's contribution is "does a resolved record exist here, and does its boundary name the right range", and the block's bytes are then point-independent, which is what R-6 actually asks for. (Card title says "entry point"; goal and Intent say exit point — the five are exits.)

## Testable claims
