## Intent

A Council run surfaces work it did not do — a deferred idea, an out-of-scope
objection, a "we should also…" — and step 13 of
`council/procedures/council.md` currently turns every surfaced item into its
own card: "Everything the run surfaced but did not do … becomes its own
`FLLWUP-<n>` card." Nothing in the step asks whether a board card already
covers the item, or whether two items the same run just surfaced are one
piece of work under two descriptions, so near-duplicates accumulate and each
one buys a separate run through the loop.

This card adds the missing disposition step: before a follow-up is drafted,
the run checks `council/board.md` and every open card, plus the candidate
items the same run has surfaced but not yet drafted, and records a
technically-close item on the existing card or on one combined card instead
of emitting a second.

The rule is one contract with more than one emitter, and every emitter
carries it. The attended emitter is `council/procedures/council.md` step 13.
The autonomous emitter is `council/agents/council-runner.md`, which runs that
same step inside a card container and re-homes the draft confirmation to a
ruling seat; `council/procedures/features-deliver.md` Phase 3 states the
follow-up contract for a whole run and must agree with both. The guidance of
the seat that rules a fold-in-versus-new-card decision, and of the container
that drafts step-13 candidates, carries the rule in its own text rather than
relying on the procedure that invokes it.

Surface: the merge feedback channel — a chat line naming the merge target,
and a `## Merged from:` section on the merged-into card — plus the
consolidated-ruling step. The guards under `test/` read every packaged seat
and procedure body and already forbid hardcoded product domains and specific
stack names, so any new prose stays domain-neutral and stack-neutral.

## Acceptance

- `council/procedures/council.md` step 13 instructs the run to check
  `council/board.md` and every open card — plus the candidates the same run
  has surfaced but not yet drafted — before drafting a follow-up, and to
  record a technically-close item on the existing card or on one combined
  card instead of emitting a second.
- `council/agents/council-runner.md` carries the same merge-before-draft
  obligation for the autonomous path, including what the container does when
  the close card already exists on the board.
- `council/procedures/features-deliver.md` Phase 3's follow-up sentence
  agrees with step 13 rather than restating an unbounded per-item rule.
- The guidance of the seat that rules a fold-in-versus-new-card decision and
  the guidance of the container that drafts step-13 candidates both state the
  dedup rule.
- A test under `test/` pins the file's actual line `becomes its own
  \`FLLWUP-<n>\` card` (single backticks, `council.md:316`) and asserts it no
  longer stands unqualified in step 13: `grep -Fc` returns 1 at base (red)
  and 0 after the clause is qualified (green).
- A fixture run surfaces two technically-close follow-up candidates; the run
  asserts the count of `FLLWUP-` cards written by that run equals 1, not 2,
  and the surviving card's `## Merged from:` section names both source
  candidates.
- The run emits a chat line naming the merge target (`merged X into EV-<n> —
  same file/behavior`), and the merged-into card gains a `## Merged from:`
  section.
- The consolidator seat rules `merge into EV-X or draft new` before drafting,
  in attended mode at the step-13 draft-and-confirm, and in container mode via
  `ESCALATION` to product-owner with the consolidator's read appended.
- The repo's typecheck, the full test suite, `python3 council/validate.py`,
  and the repo's preflight pass.
