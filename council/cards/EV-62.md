## Intent

The question set, the policy weights, the confidence floors, the model id, and
the endpoint must be per-repository data, not code, or tuning becomes a
prompt-and-commit exercise and a consumer cannot point the gate somewhere else.
This card lands that data surface on the repository's existing
packaged-default-plus-repo-override pattern: whole-file first-hit resolution, so
a repo that supplies a policy gets its file and never a half-merged mixture,
and a repo that supplies nothing gets the packaged default.

Two facts drive the fail-loud validation. The model id must be pinnable to a
versioned id — confidence floors tuned against a version must not silently move
when the alias rolls, which is exactly what the intake recorded: the response
reports the versioned model that answered, and that version is logged. And the
policy carries a version of its own, because a threshold change without a
version is a change nothing can cite.

Malformed JSON, an unknown key, and an invalid value all throw naming the file
and the key rather than degrading to a default — a silently defaulted policy is
an untested policy.

## Acceptance

An absent repo file yields the packaged policy with a non-empty `policyVersion`
and the pinned model id; a repo file shadows the packaged one whole-file with
no field-level merge between them; a malformed file, an unknown key, and an
invalid value each throw an error naming the offending file; and a test asserts
the alias string `~typesafe/jev-latest` is never the resolved default model id.
policy.json carries a `mode` key with values `off`, `advisory`, `active`; `off`
issues no gate call and writes no ledger line; an absent key resolves to `off`;
and a validation failure surfaces as a single line of the form `FAIL: <file> has
an invalid <key> — <what was found> — set a valid value or remove the key to use
the packaged default`, never as a stack trace.

## Phase 1 Rulings (recorded before dispatch — binding for this run)

- **R1 — merge authorization, every card in this run.** The human authorized
  the run-scoped admin bypass: the merge is `gh pr merge <PR> --squash --admin
  --match-head-commit <X>`, where `<X>` is the exact head SHA the `gates`
  workflow `SUCCESS` (merge-check criterion 2) was read against. This
  authorization is for this run only and is not extended to any later run; a
  SHA mismatch is a HALT, not a retry.
- **R3 — packaged gate default.** The packaged `council/gate/policy.json` ships
  `mode: "off"` (no gate call, no ledger line by default); consumers opt in per
  repo via a repo-local `policy.json`. Tests that exercise the gate set the
  mode explicitly; the default is never relied on to be on.
