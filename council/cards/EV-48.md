## Intent

The council's model-selection opinion expressed as shipped data: an ordered named tier set with per-tier capability predicates, a seat-to-tier map, a vendor-family diversity floor, and the judge/skeptic independence constraints. It must resolve against a live catalogue that churns, and be overridable per repository without forking the package. The vendor-family axis is the first path segment after `provider/` of a model's qualified id, because every shipped seat pins `openrouter/...` and a provider-based metric would be degenerate. `loadModelTiers(repoRoot)` follows `loadCouncilConfig`'s throw-don't-degrade discipline, explicitly not `loadModelFloors`' silent `{}` fallback: a malformed constraint file must never fail open and turn the hard gate into theatre.

## Acceptance

One-family roster → `diversity-floor` breach class exists; packaged roster → validates; override keys win; malformed JSON throws; a missing seat throws; the packaged map covers every seat `listSeatNames` returns.
