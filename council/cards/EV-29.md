## Intent

OpenRouter fronts many upstream inference providers, so a single catalogue rate
per model id can diverge from what was actually charged, and the human's
evidence localises to the cache component. This card asks the provider what it
actually charged and records the per-component figures alongside the catalogue
estimate, so divergence is visible per component rather than denormalised into
one total. When actual figures cannot be retrieved, each component carries the
same explicit, non-empty unavailable marker rather than silently standing on the
estimate. The marker literal and its placement are decided at design time and
surfaced through the EV-32 usage block; the store location and record shape are
EV-31's.

## Acceptance

- A fixture provider response carrying per-component values that differ from the
  catalogue estimate is persisted with the response's values.
- A fetch-failure fixture persists the same non-empty unavailable marker for
  every component.
- An implementation that never fetches fails the first test; an implementation
  that always returns the estimate fails the second.
- `bun test`, `bunx tsc --noEmit`, `python3 council/validate.py` stay green.

## Phase 1 rulings (features-deliver, binding for this run)

- **R-1 money signifier** — a reported actual figure renders
  `cost=$0.1234 (reported)`; the catalogue estimate renders
  `cost≈$0.1234 (catalogue)`.
- **R-2 unavailable marker** — an unavailable component renders the literal
  `n/a` in that component's slot, with the legend line
  `n/a = provider figure unavailable`; never a blank.
- **R-7 scope** — persist the routed upstream provider id alongside the
  per-component actual cost, so divergence is attributable.
