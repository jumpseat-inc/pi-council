## Intent

`buildSystemPrompt` appends only the procedures *directory path* to a seat, so every `council-runner` opens its turn by reading `council.md` and `features-deliver.md` from disk before doing anything — a cost paid on every cold start, including every escalation resumption. The engine already renders procedures with substitution for the parent slash-command path; this card routes the same rendered bodies into the runner's dispatch input and updates the seat block to affirm that its input already carries them. The operator-observable surface is the transcript, not the copy: `/council-tree` today opens a runner with `Read council.md` / `Read features-deliver.md`, and after this change those reads are gone — the first visible actions are the deliberation dispatches. The seat block should say what the input carries rather than prohibit a read, so a later editor does not drift around a negative rule. Nothing else about the dispatch changes.

## Acceptance

1. One exported function composes the runner dispatch input from the resolved procedure bodies under `renderProcedure` substitution (the same `procDir` and `$ARGUMENTS` the parent slash-command path uses — both procedures carry `$ARGUMENTS` but not `$COUNCIL_PROCEDURES`).
2. A test asserts the composed input contains both substituted bodies byte-identical to `renderProcedure`'s output for the same args.
3. The packaged `council/agents/council-runner.md` `<procedure>` block no longer mandates reading `council.md`/`features-deliver.md` in full; a prose pin asserts the read-in-full instruction is gone and names the in-input text instead.
4. `renderProcedure`'s substitution set and `buildSystemPrompt`'s block order are unchanged — no new token, no new block.
5. Everything else about the dispatch is byte-identical: same seat, model, tools, timeouts.
6. `bun test` and `bunx tsc --noEmit` pass.

## Cross-seam reading

**What the contract is right now, on both sides:**

- `renderProcedure` is `extensions/index.ts:148–153`: `.replace(/\$COUNCIL_PROCEDURES/g, procDir).replace(/\$ARGUMENTS/g, (args ?? "").trim())`. Substitution is per-body; there is no body registry.
- The parent slash-command path (`extensions/index.ts:847–886`) reads procedures as `[repoOverride, packaged]`, **dedupes per filename**, strips frontmatter with `raw.replace(/^---\n[\s\S]*?\n---\n/, "")`, then calls `renderProcedure(body, procDir, args)`. So the parent's *body* is per-file override-first, while `procDir` is `proceduresDir(repoRoot)` (`seats.ts:557–560`) — a **directory-level first hit**.
- The runner's input is `params.input`, passed straight into `buildChildArgv(seat, params.input, …)` at `hub-tools.ts:254` (and `:278` for retries). **No code composes it today** — the parent LLM writes it from prose in `features-deliver.md` Phase 2. `buildChildArgv`/`buildSystemPrompt` must be left alone (AC4/AC5).
- The eval path is separate: `eval-runner.ts:557–565` dispatches `council-runner` via `dispatch.ts`'s `spawnSeatJob`, not `council_dispatch`. Any composition wired into `buildChildArgv` or `buildSystemPrompt` leaks into eval cells; it must live at the `council_dispatch` call site only.
- The runner's `<procedure>` block (`council/agents/council-runner.md`, ~lines 58–64) mandates reading `council.md` and `features-deliver.md` **from the procedures directory named in `<council_runtime>`** — exactly the block AC3 rewrites. `buildSystemPrompt` still appends that dir (`seats.ts:598–604`).
- **`$ARGUMENTS` is not one value across the two bodies.** In `council.md` every use is the **card id** (`council/cards/$ARGUMENTS.md` ×2, `preflight.sh $ARGUMENTS`, "run on card `$ARGUMENTS`"). In `features-deliver.md` every use is the **epic key** (`orchestrator delivering $ARGUMENTS`, "`$ARGUMENTS`'s scope — the epic and every child"). Neither body carries `$COUNCIL_PROCEDURES`, so `procDir` does not affect rendered bytes — it only affects where a naive implementation *looks*.

## Blind spots

- **The engine/owner vantage** sees `params.input` as "the task text" and does not see that the *parent is an LLM*. "The dispatch input contains the bodies" therefore requires a **named call site**; an exported function with a unit test but no caller satisfies AC1/AC2 and fails the goal. The card names neither the call site nor the arg source.
- **The procedure-scan vantage** sees `proceduresDir` as "the procedures dir" and cannot see that it is directory-level while the scan is per-file. `path.join(proceduresDir(repoRoot), "council.md")` reads the right file in this repo (no `.pi/council/procedures`) and **throws or reads wrong in any consumer repo that overrides even one procedure**, because the override dir then wins outright and may not contain `council.md`.
- **The seat-prose vantage** sees `features-deliver.md` as "the autonomous overlay" but cannot see it is written **to the orchestrator**, not the runner. Rendering it with the runner's card id turns "delivering EV-90" / "every card in EV-90's scope — the epic and every child" into a false statement inside the runner's own input.
- **The test-author vantage** cannot see that AC2's byte-identity assertion is **tautological**: if the test picks the args and passes the same args to `renderProcedure`, `composed.includes(render(councilBody, dir, args))` passes even when the implementation bound the *wrong* args to `council.md`. The test as specified has no falsifier for the load-bearing substitution.

## Reframe

The card's shape is right, but AC1's "the same … `$ARGUMENTS` the parent slash-command path uses" is not implementable as a single value, and the implementation seam is unnamed. Concrete design, all inside EV-90:

1. **One helper, called from one place.** Add `composeRunnerInput(repoRoot, runnerArgs, taskInput): string` (pure, exported) in `seats.ts` (near `proceduresDir`), and call it in `hub-tools.ts` immediately before `buildChildArgv` **only when `seat.name === "council-runner"`**, producing the string that becomes `params.input` to the child. Touch neither `buildSystemPrompt`, `buildChildArgv`, nor `dispatch.ts` (AC4/AC5; keeps eval cells untouched).
2. **Bind each body its own args.** `council.md` renders with the **card id**; `features-deliver.md` renders with the **epic key**. If the card truly refuses a second arg, then render only `council.md` and append the `features-deliver.md` overlay **un-substituted** (its `$ARGUMENTS` slots are non-load-bearing prose) — do not render the overlay with a card id. State this in the deliberation record; it is the one real contract decision here.
3. **Resolve bodies per-file, override-first, exactly like the scan.** Extract a `readProcedureBody(repoRoot, name)` helper that walks `[repo-local, packaged]` and applies the same frontmatter strip, and have the command scan use it too — one source for the strip/override seam. Do **not** use `path.join(proceduresDir(repoRoot), name)`.
4. **Append the parent's task text verbatim, do not substitute it into the bodies.** On escalation resume the ruling must still arrive as `taskInput`. (Also avoids feeding free text through `.replace`’s replacement-string `$&`/`$n` metacharacters.)
5. **Rewrite `<procedure>` (AC3)** to say the input carries both bodies (naming the two in-input blocks) and drop the read-in-full instruction; the block may still note `council.md` is the procedure and `features-deliver.md` the overlay, so the runner isn't confused that features-deliver addresses an orchestrator.

**Design position.** This card closes the Gulf of Evaluation that today sits between "runner dispatched" and "runner deliberating" — the two `Read council.md` / `Read features-deliver.md` tool calls the runner emits on every cold start are pure noise in `/council-tree`'s verb-first activity row, and they cost a tool round-trip plus two file parses per runner invocation (and again per escalation resumption). The card routes the same `renderProcedure`-substituted bodies the parent slash-command path already uses into the dispatch input, asserts the input is byte-identical to that rendered form, and rewrites the seat's `<procedure>` block to *affirm* what its input carries rather than prohibit a disk read. The smallest change that closes the named gulf.

**Gulf closed.** Evaluation, for the operator opening `/council-tree` (or the in-line `CouncilTreeWidget`) on a fresh runner or an escalation resumption. At the moment "the runner is in flight," the activity row stops reading `ran Read council/procedures/council.md` and reads whatever the runner actually does first — a seat-resolution `Bash` / `Read` of `council/agents/<seat>.md`, then `Bash python3 council/validate.py`, then the first deliberation `council_dispatch`. The "spinning up on procedure files" beat disappears.

**Principle and evidence.**

- **Knowledge in the world beats knowledge in the head.** The runner is currently paying two disk round-trips on cold start to re-load ~hundred-line procedure bodies its dispatcher is already about to hand it. Today: `council/agents/council-runner.md:48-51` (the `<procedure>` opening line: "Before doing anything else, read `council.md` and `features-deliver.md` from the procedures directory named in your `<council_runtime>` system-prompt block, in full"). After: the dispatch input carries both bodies already rendered by `renderProcedure` (`extensions/index.ts:149-153`) with the same `procDir` and `$ARGUMENTS` the parent slash-command path used — and `buildSystemPrompt` (`extensions/seats.ts:598-604`) stays untouched, so `<council_runtime>procedures directory: ${procDir}</council_runtime>` remains the directory pointer for any *other* file the runner may still legitimately read (none currently does at startup, but the pin matters for override-shaped edge cases).
- **Affirmation over prohibition in the seat block.** The card's Intent is explicit and correct: name what the input carries, do not write "do not read X." A negative rule reads as redundant on review and gets deleted by an editor trying to tighten the file; a positive rule ("your dispatch input carries the rendered bodies of `council.md` and `features-deliver.md` — execute its steps under its substitutions") drifts by amendment, not by deletion. The rewrite keeps the substantive prose that follows (skip step 0, two environment facts) byte-anchored and only swaps the first paragraph.
- **No `buildSystemPrompt` change, no new block, no new token.** Acceptance 4 is the seam pin and is the right call: the dispatch input is per-dispatch and per-seat (only `council-runner` needs these bodies); the system prompt is shared and would over-deliver to every `council-runner`-shaped dispatch and to any future seat that aliases it. FLLWUP-112 (open, EPIC-20) owns the substitution-set widening; EV-90 consumes the same `renderProcedure` and adds nothing.
