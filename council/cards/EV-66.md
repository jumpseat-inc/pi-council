## Intent

This is the free-label step. The gate computes and journals its verdict on each
card as the epic is decomposed, the council runs exactly as it does today, and
the verdict is compared afterwards against what actually happened to the card —
how many rounds it took, whether it escalated, whether deliberation found
anything. The comparison is what turns a calibrated probability into a measured
policy, and it costs nothing because the labelling runs alongside work already
being done.

The only copy this card adds is the in-flight line shown while a gate call is
pending. The verdict itself is recorded, not printed — the printed verdict line
belongs to the approval gate, and printing it twice from two cards would give
one decision two faces. The in-flight line is transient editor-region copy,
never a chat append: a thirteen-card epic must not leave thirteen orphaned
status lines in the transcript.

The hard part of this card is the falsifier, and it is stated in the goal: the
advisory run must be provably non-interfering. Same seats, same dispatches, same
card text; only the ledger gains lines. If advisory mode alters a single
dispatch, the labels it produces describe a different system than the one that
will later be governed by the policy.

The verdict is recorded rather than re-derived, so a later consumer can read the
decision instead of spending another call on the same frozen card text.

## Acceptance

A headless run in advisory mode produces the same manifest dispatch set as a
run of the same epic with the gate disabled; every drafted card has exactly one
ledger line marked `advisory: true` carrying its resolved mode and basis; no
card's state, body, or board line differs from the gate-disabled run; and the
recorded line makes no policy change effective. The in-flight line names the
card being evaluated and states that a gate call is in progress, uses no word
implying thought or deliberation (`thinking`, `deliberating`, `reasoning`,
`judging`), is replaced rather than appended when the call settles, and a test
asserts the render function returns zero lines after settle.

## Phase 1 Rulings (recorded before dispatch — binding for this run)

- **R1 — merge authorization, every card in this run.** The human authorized
  the run-scoped admin bypass: the merge is `gh pr merge <PR> --squash --admin
  --match-head-commit <X>`, where `<X>` is the exact head SHA the `gates`
  workflow `SUCCESS` (merge-check criterion 2) was read against. This
  authorization is for this run only and is not extended to any later run; a
  SHA mismatch is a HALT, not a retry.
- **R3 — packaged gate default.** The packaged `council/gate/policy.json` ships
  `mode: "off"` (no gate call, no ledger line by default); consumers opt in per
  repo via a repo-local `policy.json`. Tests that exercise the gate set the
  mode explicitly; the default is never relied on to be on.
- **R4 — panel seat inclusion.** Verify = owner + skeptic + judge (an explicit
  adversary and ruling authority, plus the fresh-context goal evaluation; no
  branch-verification dispatch, principal, consolidator, or designer). Direct =
  owner only; the test suite is its only gate. Deliberate = the full panel.
  These sets satisfy EV-63's constraints: every set contains the owner, every
  reduced set contains an adversary and a ruling authority, and Direct contains
  no judge.
