## Intent

Additive seat tuning by construction: a repo emphasis note never forks or replaces a packaged conviction body, and <repository_grounding> is never replaced — the emphasis block is a fourth join element in `buildSystemPrompt`, sibling to the existing `groundingBlock`. The resource is consumer-side-only, like the scaffold provenance record: a consumer file honored as-is with no packaged counterpart and no merge. The non-vacuity proof is the stray-packaged-directory test; the byte-identity assertion is demoted to a regression guard because a consumer note never touches `PKG_ROOT` and so that assertion alone would pass against a dead feature. The recut gives the note its subject: the real human persona the interview uncovers for the seat — a consumer-side note, never a packaged-body fork.

## Acceptance

Both blocks present for a seat with a note; the emphasis note's subject is the seat's real-human persona and no packaged `council/agents/*.md` is read or forked; a stray packaged `seat-emphasis/` directory is ignored; packaged `council/agents/*.md` byte-identical before and after; precedence list is exactly one directory.
