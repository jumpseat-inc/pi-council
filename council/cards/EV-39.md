## Intent

This card does not address the intake; it fixes a child seat's provider error.
Council already owns this path — the child's error is captured at
`hub.ts:196-205` and the parent can re-spawn the job — so it is the second,
easier half of the epic.

The budget source is the `retry` section's `maxAttempts`, `baseDelayMs`,
`maxDelayMs`, and `jitter` fields (R2), and the delay follows pi's existing
shape (`baseDelayMs * 2^(attempt-1)`, capped at `maxDelayMs`, jittered when
`jitter` is true). The final report carries an explicit attempts sentence.

## Orchestrator rulings (Phase 1, binding)

Recorded human decisions for this run. Immutable and binding on every seat,
`steward` included; a runner that hits one applies it and cites the ruling
rather than re-asking.

- **R4 (intermediate-attempt visibility).** One job-tree row per dispatch,
  labeled `attempt 2/3` while retrying — no extra rows and no separate status
  line, so the tree never shows two rows for one intent. The final report
  still names the attempt count.

- **Grounded facts carried into deliberation (inputs, not a settled design;
  the Council verifies them at this tree):**
  - `Hub.spawnJob` (`extensions/hub.ts`) takes the full child spec
    (`id`, `seat`, `model`, `command`, `args`, `cwd`, `env`, `timeoutMs`,
    `stallMs`, `cleanup`) and stores it on the `Job`; the `Job` object holds
    `startedAt`, `lastActivityAt`, `timeoutMs`, `stallMs`, accumulated
    `usage`, `stopReason`, `errorMessage`. **The Hub never sees the seat
    `input` or the prompt file — those are baked into `args` and `env` by
    `council_dispatch`.** A Hub-owned re-spawn therefore either reuses
    `command`/`args`/`env` or must move the loop up to the tool layer.
  - `Hub.report()` returns the `JobReport` shape `classifyRetry` consumes;
    `Hub.settle()` is the single settle point (`proc.on("close")` → state
    `done`/`failed`, `writeJobManifest`, `onChange`); `Hub.tick()` sets
    `stalled` (kills the process group) after `stallMs` of no activity and
    informational `timeout` after `timeoutMs` (never killed).
  - `extensions/retry.ts` already exports `classifyRetry(report)` (EV-37,
    keys on state+stopReason+errorMessage) **and** the pure
    `computeBackoffDelay(policy, attempt, rand)` (EV-40). A hub loop reusing
    these two is the path of least divergence; minting a second delay
    function would create the two-loop divergence EV-40's watch item warns
    about.
  - `loadRetryConfig(repoRoot)` (EV-38, `extensions/seats.ts`) always returns
    a full policy and throws on malformed input; this repo's `.council.json`
    carries **no** `retry` section, so the R2 defaults apply here.
  - `RunManifest` (`extensions/runs.ts`) has **no** `attempt` field today;
    `writeJobManifest` writes `id/seat/model/parentJobId/pid/sessionId/state/
    startedAt/settledAt/exitCode/usage/stopReason`. The `attempt` field and
    the sibling-binding id are EV-42's named deliverable; EV-39 precedes it
    in the build order.
  - The tree row text is `tree.ts`'s `textTree` (`glyph id seat state Xm
    pid=`) and the navigator's row renderer; R4's `attempt 2/3` is a new
    fragment on that existing row.
