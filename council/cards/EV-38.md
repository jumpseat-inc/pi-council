## Intent

Follow `loadThemeConfig`'s validate-loudly shape — a falsy `enabled` is the off
switch, and a malformed value throws naming the file and the offending key.
The policy is a new top-level `retry` sibling of `council` and `theme`.
`council-config-writer.ts` preserves unknown top-level keys by construction,
so a `council.<seat>` write must leave the `retry` bytes untouched.

Defaults visibility is settled as concrete JSON in
`council/scaffold/.council.json` rather than a runtime announcement — visible
in place, no new code path, consistent with the `loadThemeConfig` precedent.

## Orchestrator rulings (Phase 1, binding)

Recorded human decisions for this run. Immutable and binding on every seat,
`steward` included; a runner that hits one applies it and cites the ruling
rather than re-asking.

- **R2 (shipped defaults).** The `retry` block, surfaced as concrete JSON in
  `council/scaffold/.council.json`:

```json
{
  "retry": {
    "enabled": true,
    "maxAttempts": 3,
    "baseDelayMs": 2000,
    "maxDelayMs": 30000,
    "jitter": true
  }
}
```

- **R3 (validation set).** An invalid value throws naming the file and the
  offending key. `maxAttempts` is an integer ≥ 1, `baseDelayMs` an integer
  ≥ 100, `maxDelayMs` an integer ≥ `baseDelayMs`, and `enabled` / `jitter`
  are booleans. Any other type or range is invalid.
