## Intent

Direct mode is for deterministic work where the test suite is the only gate:
rename a flag, bump a dependency, add a fixture, move a path. Nothing about such
a change needs judgment, and the suite's own pass or fail is a stronger and
cheaper verdict than a fresh-context evaluation of a goal that already names the
exact literal it must produce.

That creates a hard coupling this card exists to resolve. The autonomous merge
check currently requires, unconditionally and with no seat permitted to
substitute judgment, that there be no blocking objection and that the goal
evaluation return a pass — neither of which exists in a Direct run. A Direct
card therefore cannot merge at all under the check as written, and the fix is
not to bypass the check but to make it mode-aware: the mode recorded on the run
substrate determines which criteria apply, a Direct card merges on green owner
gates and green CI, and a card in any other mode still halts without its goal
evaluation. The HALT stays the honest outcome for a missing verdict in a mode
that requires one.

Direct is a third mode, not a redefinition of the other two, and making the
merge check mode-aware is the price of admitting it. The check stops being one
unconditional ruleset and becomes one ruleset keyed by the mode the run recorded;
a mode with no recorded value halts rather than defaulting, because inferring a
mode is exactly the discretion the check exists to remove.

## Acceptance

A fixture run merges a green Direct card with no goal-evaluation record and
halts an otherwise-identical non-Direct card with no goal-evaluation record; the
mode is read from the run substrate rather than from a seat's report; the CI
criterion remains read from the workflow field with the merge pinned to the
checked head commit; and no run merges a card whose recorded mode is absent. A
card with no recorded mode halts with the single line `HALT: EV-<n> has no
recorded execution mode — the merge check cannot infer one; route the card at
the approval gate`; a card in a mode that requires a goal evaluation halts with
`HALT: EV-<n> — mode <mode> requires a goal evaluation and none is recorded`;
both lines name the card and the remedy, follow the `FAIL:`/`HALT:` convention
already used for drift, and are asserted verbatim in the fixture run.
`/features-deliver`'s Phase 3 per-card entry names the card's recorded execution
mode beside its merge basis, proven by a fixture ledger line; this is the only
Phase 3 report change in the epic.

## Phase 1 Rulings (recorded before dispatch — binding for this run)

- **R1 — merge authorization, every card in this run.** The human authorized
  the run-scoped admin bypass: the merge is `gh pr merge <PR> --squash --admin
  --match-head-commit <X>`, where `<X>` is the exact head SHA the `gates`
  workflow `SUCCESS` (merge-check criterion 2) was read against. This
  authorization is for this run only and is not extended to any later run; a
  SHA mismatch is a HALT, not a retry.
- **R3 — packaged gate default.** The packaged `council/gate/policy.json` ships
  `mode: "off"` (no gate call, no ledger line by default); consumers opt in per
  repo via a repo-local `policy.json`. Tests that exercise the gate set the
  mode explicitly; the default is never relied on to be on.
- **R4 — panel seat inclusion.** Verify = owner + skeptic + judge (an explicit
  adversary and ruling authority, plus the fresh-context goal evaluation; no
  branch-verification dispatch, principal, consolidator, or designer). Direct =
  owner only; the test suite is its only gate. Deliberate = the full panel.
  These sets satisfy EV-63's constraints: every set contains the owner, every
  reduced set contains an adversary and a ruling authority, and Direct contains
  no judge.
