## Intent

The user-visible surface addressing the stated pain: with providers like
OpenRouter serving hundreds of models, the model-selection level of the
`/council-models` modal (`ModelPicker`, `extensions/model-picker.ts`) is
hard to scan. The surface is the modal's model-selection level (level 2).

Ruled contract for the surface:
- `/` (a printable key on the existing `handleInput` path) opens search
  mode at the model level only; the input renders below the top row — the
  R-1 header `council models — pick a model per seat` stays byte-exact.
- Focus is signified by a `▌` (U+258C) cell at column 0 of the
  search-input row (EV-8's signifier precedent) plus the input row's own
  affordance hint naming the `/` trigger; the four-footer exhaustiveness
  rule stays intact — the search row is never a fifth footer.
- `/` is typeable inside the input: within search mode every printable
  character appends to the query (capture by construction — the trigger
  key and the query character are the same character, handled by
  ordering, and `qualifiedId` values contain `/`).
- The list renders from EV-26's filtered rows; `modelIndex` clamps into
  the filtered set; the render-cache signature at
  `extensions/model-picker.ts:96` includes the query so no keystroke can
  serve a stale frame.
- Esc with focus in the input clears the input's text and keeps it
  focused; Esc elsewhere at the model level ascends to the provider level
  unchanged (`extensions/model-picker.ts:257-262` preserved).
- A query matching no rows renders a no-match empty state distinct from
  the two R-4 ruled empty states; its copy is the ruled literal
  `No models matching "<query>".` (EPIC-6 R-1).
- On Enter at the model level with the input visible, search state clears
  and the picked row advances into the confirm level; backing out of
  confirm (Esc at level 3) returns to the model level with the prior
  search state preserved. This floor is not pinned further.
- Confirm echo and `resolveSelection` are unchanged — a filtered row
  still emits the byte-verbatim `qualifiedId` plus thinking level.

## Acceptance

- Driven tests: `/` opens the input at level 2; typing `claude` narrows
  the rendered rows to `qualifiedId` substring matches; the input renders
  between the header and the first data row with the `▌` cell and an
  affordance hint naming `/`; the footer remains the ruled model-level
  string at every keystroke, including the no-match state.
- `anthropic/claude` (containing `/`) can be typed into the input without
  leaving search mode.
- Render cache: after every keystroke `render(width)` differs (query is
  part of the signature).
- Esc in the input empties the query and keeps focus; Esc at level 2
  outside the input transitions to level 1.
- The no-match state's string is byte-distinct from the two R-4 empty
  states and is asserted byte-exact.
- Selection through a filtered set emits the same `resolveSelection()`
  tuple as the unfiltered path; the confirm echo is byte-equal.

## Phase 1 rulings (features-deliver, binding for this run)

- **R-1 (affordance hint copy)**: while the search input is empty, the
  search row renders `▌ / filter · esc clears` — the `▌` focus signifier
  at column 0, then the hint text `/ filter · esc clears` byte-exact,
  matching the ruled footer's middot idiom. The hint is the empty-input
  rendering; typed query text replaces it.
