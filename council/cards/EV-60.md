## Intent

The first rollout step is measurement only: no policy change until a number
exists. Today the cost surface is a flat per-job tuple on the run manifest
(`Usage` in `extensions/runs.ts`) plus `sumSubtree` for command-level cost over
the job forest; nothing aggregates that to the two units this feature spends in
— a card and an epic. This card adds that aggregation as a pure function over
manifests, with a report surface a human can read, so the ratio of a gate call
to a full council run is grounded in this repository's own history rather than in
the intake's single live sample.

The read posture is part of the card. The run directory is ephemeral telemetry,
pruned to the last 15 runs, and its reads are confined by convention to a small
module set; this module must consume the exported accessors in
`extensions/runs.ts` (`readManifests`, `sumSubtree`) and never touch the run
directory itself. If the intent is instead for this module to be a direct
reader, the convention must be amended in the same change rather than quietly
violated.

## Acceptance

A fixture forest of two epics with known per-card spend yields per-card sums
equal to `sumSubtree` at each card root, and a card with no manifest usage is
present as `0`; the report names every epic in scope and its child cards; and a
test asserts the module performs no direct run-directory access — it imports its
manifest accessors from the run-substrate module. `formatCostBaseline(report)`
returns the report as plain text lines — one per epic and one per child card
carrying its summed cost and the number of runs behind it — from a pure function
with no model call, and a golden test pins its bytes over the two-epic fixture
forest; no new interactive surface is introduced.
