## Intent

This card owns the pure resolver that computes the identity of the pi-council
package that is actually running. The version comes from the `version` field of
that package's own `package.json`; the hash comes from
`git -C <pkgRoot> rev-parse --short HEAD` on that package root — never from the
consumer repository's cwd and never from a forked second reader whose `unknown`
fallback could leak into the identity line (the package already reads a running
package version in `scaffoldPackageVersion`, `council-update.ts:235-241`; this
card owns the identity reader, and `unknown` is neither of the two degraded
states the goal names). Because git's `rev-parse` walks up the filesystem, the
resolver must confirm the revision belongs to the package root itself and must
return a named degraded state rather than throw or hand back a hash for code
that is not running. This is the chain head EV-58 and EV-59 consume.

## Acceptance

- A fixture package root returns a `version` that byte-equals that fixture's
  `package.json` `version`.
- On a fixture pinned to `git config core.abbrev 8`, the hash byte-equals
  `git -C <fixture> rev-parse --short HEAD` (length 8); a `slice(0, 7)`
  implementation fails byte-equality.
- A consumer-repo fixture at a different commit yields the package root's
  identity, not the consumer cwd's.
- A `git worktree` fixture (`.git` is a file) still returns the hash.
- A `.git`-absent fixture returns `no-git-metadata`.
- An ancestor-repo fixture (package root with no `.git` whose parent directory
  is a git repository) returns `no-git-metadata` and never the ancestor hash.
- An injected git reader that throws returns `git-unavailable` with no
  exception escaping the resolver.
- An injected git reader returning exit 128 ("not a git repository") returns
  `no-git-metadata`, distinct from `git-unavailable`.
