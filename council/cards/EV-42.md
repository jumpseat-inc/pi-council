## Note

Re-scoped in place (same id, same slot) before dispatch, under the EV-39
step-6 steward ruling, because the settled cardinality — one job id, one
manifest, and one job-tree row per dispatch, with an `attempt` field and
carried cumulative usage — made this card's original premise false. `attempt`
is fixed by the EV-40 design agreement and may not be renamed; `attemptGroupId`
is dropped, because under that cardinality the dispatch's job id is already
the group key.

## Intent

A retried dispatch keeps one job id, one manifest, and one row. What is still
missing is per-attempt provenance: each attempt's session transcript and spend
must be recoverable from the manifest alone, and the dispatch's
provider-reported figure must sum every attempt rather than reflecting only
the final one.

EV-39 discloses the interim partial reported figure machine-readably (a
record-only reason on the provider sibling, rendered through the usage
block's conditional legend); this card closes that disclosure by persisting
the per-attempt session pointers on the manifest and walking that list in
`usage-store`, so the reported figure becomes whole.

- **Grounded facts carried into deliberation (inputs, not a settled design;
  the Council verifies them at this tree):**
  - **Cardinality (A) shipped.** One job id, one `<id>.json` manifest, one
    job-tree row per dispatch. `Hub.respawn` (`extensions/hub.ts:186-221`)
    reuses the id, carries `prev.usage` cumulative, keeps `startedAt`, and
    re-bases `attemptStartedAt`; `writeJobManifest`
    (`extensions/hub.ts:111-128`) writes `sessionId: job.sessionId ?? job.id`
    (the **current** attempt's session id only), `attempt` (present only when
    `> 1`), and `nextAttemptAt`.
  - **Per-attempt session ids exist on disk but are unlinked from the
    manifest.** `council_dispatch` arms `createRetrySupervisor` with
    `attemptSpec: (n) => { sessionId = \`${jobId}-attempt${n}\`; … }`
    (`extensions/hub-tools.ts:269-276`); each attempt spawns
    `pi -p --session-id <id>-attemptN` into the same run dir. The run dir
    therefore already holds attempt 1's and attempt 2's JSONLs, but
    `RunManifest` (`extensions/runs.ts:44-62`) carries no list of them — this
    is the gap.
  - **The provider figure is built from one session path per manifest.**
    `extensions/usage-store.ts:421-427` builds
    `jobs = manifests.filter(openrouter ∧ startedAt ≥ markerAt).map(m => ({
    jobId: m.id, model: m.model, sessionPath: findSessionFile(repoRoot,
    runId, m.sessionId) ?? null }))` — `m.sessionId` is the final attempt's,
    so only the final attempt's generations are fetched. Line 443-448 then
    marks `partial: "final-attempt-only"` when any eligible manifest is at
    `attempt > 1`. **This is the exact line EV-42 replaces.**
  - **The reason vocabulary is record-only, rendered once.**
    `ProviderPartialReason = "final-attempt-only"`
    (`extensions/provider-cost.ts:40`), optional on `ProviderCostReport`
    (`:73`); `extensions/usage-block.ts:32` holds the legend literal and
    `:118-120` pushes it iff `provider.partial !== undefined`. `partial` has
    no place in the goal's rendered copy — it is a durable, machine-readable
    qualifier.
  - **`findSessionFile` resolves by scanning the run dir for a JSONL whose
    first line's `id` matches** (`extensions/runs.ts:139-160`) and returns the
    first hit, `undefined` when absent. `ProviderGeneration.jobId` is the R-7
    attribution key (`extensions/provider-cost.ts:52-56`); the transport is
    injected and the production one is the only network code
    (`provider-cost.ts`).
  - **Worst-of `status` is existing semantics.**
    `fetchProviderReport` sets `status: failures.length > 0 ?
    "unavailable" : "reported"` (`extensions/provider-cost.ts`), with a C3
    reason precedence (`no-api-key` > `session-missing` > `no-generation-id`
    > `timeout` > `fetch-failed:`). Under a multi-attempt job list, an attempt
    that produced no assistant generation (the ordinary shape of a
    provider-errored attempt) contributes a `no-generation-id` failure and
    can flip an otherwise summable report `unavailable`.
  - **The run dir is pruned to the last 15 runs** (`pruneRuns`,
    `extensions/runs.ts`); the durable store at
    `getAgentDir()/council/usage/` is what outlives it (wiki
    [[usage-store]]). "Recoverable from the manifest alone" is therefore
    bounded by run-dir pruning — the manifest can index the transcripts, it
    cannot outlive their deletion.
  - **The flush gate keeps the write whole.** `forestFullySettled` refuses to
    write while any manifest in the invocation window has `exitCode === null`
    (`extensions/usage-store.ts`), and a mid-backoff manifest is
    `state: retrying` with `exitCode: null` — so a retried dispatch is only
    ever persisted after its final attempt settles (EV-39 G3).
  - **Tests that pin today's behavior:** `test/usage-store.test.ts:845`
    ("a retried openrouter/ manifest persists
    provider.partial='final-attempt-only' … a non-retried one does not"),
