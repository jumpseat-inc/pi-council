is fixed by the EV-40 design agreement and may not be renamed; `attemptGroupId`
is dropped, because under that cardinality the dispatch's job id is already
the group key.

## Intent

A retried dispatch keeps one job id, one manifest, and one row. What is still
missing is per-attempt provenance: each attempt's session transcript and spend
must be recoverable from the manifest alone, and the dispatch's
provider-reported figure must sum every attempt rather than reflecting only
the final one.

EV-39 discloses the interim partial reported figure machine-readably (a
record-only reason on the provider sibling, rendered through the usage
block's conditional legend); this card closes that disclosure by persisting
the per-attempt session pointers on the manifest and walking that list in
`usage-store`, so the reported figure becomes whole.

# EV-42 — owner first-pass position

## Approach

**The substrate is one field away from done; the store's walk is the second half.** At this tree the manifest already carries `attempt` (runs.ts:58) and cumulative usage (carried by `respawn`, hub.ts:183 `...prev`), and every attempt already writes its own session JSONL under a distinct session id (`${jobId}-attempt${n}`, hub-tools.ts:270, O-4 naming — I would finalize it exactly as-is). What is missing is the *pointer list* on the manifest and the *walk* in the flush. Four seams, in dependency order:

**1. `extensions/runs.ts` — the manifest field.** `RunManifest` gains:

```ts
/** EV-42 — per-attempt provenance. Present iff attempt > 1 (same gate as
 * `attempt`); complete across attempts 1..N, ordered by n. */
attempts?: { n: number; sessionId: string }[];
```

Deliberately **minimal**: `n` + `sessionId`. No `startedAt`, no per-attempt exitCode, no per-attempt usage (see tradeoffs). Invariant, test-pinned: `attempts[attempts.length-1].sessionId === manifest.sessionId` (the current-attempt `sessionId`, hub.ts:115, keeps its existing meaning for `findSessionFile` consumers — navigator.ts:341/464 tail the live attempt through it).

**2. `extensions/hub.ts` — bookkeeping only, no behavior change.** `Job` gains `attempts?: {n, sessionId}[]`; `spawnJob` seeds `[{n:1, sessionId: opts.sessionId ?? id}]`; `respawn` appends `{n: prev.attempt ?? 1 + ...}` — concretely, `respawn` (hub.ts:164-215) appends the new attempt's record from `spec.sessionId` when it re-bases the clock; `writeJobManifest` (hub.ts:96-118) emits `attempts` under the same `attempt !== undefined && attempt > 1` gate as `attempt` itself. This is additive inside a §7-stable file, and each piece is reachable by a failing test first. No retry-semantics line changes.

**3. `extensions/usage-store.ts` — the one-manifest-to-N-jobs mapping.** Today the flush resolves **one** session path per manifest (usage-store.ts:421-427: `findSessionFile(..., m.sessionId) ?? null`) — which is why the figure is final-attempt-only. Replace with an expansion: for each invocation-window OpenRouter manifest, if `attempts` is present, emit **one job entry per attempt** `{jobId: m.id, model: m.model, attempt: a.n, sessionPath: findSessionFile(repoRoot, runId, a.sessionId) ?? null, zeroSpendOk: true}`; else the legacy single entry (no `attempt`, `zeroSpendOk` false) with byte-identical behavior. Then **delete the `retried` heuristic** (usage-store.ts:437-448) — but with one backward-compat carve-out below.

**4. `extensions/provider-cost.ts` — per-attempt entry semantics + attribution stamp.** `FetchProviderReportInput.jobs` entry gains optional `attempt?: number` and `zeroSpendOk?: boolean`; `ProviderGeneration` gains optional `attempt?: number` stamped by `toGeneration` (provider-cost.ts:231-260). Attribution stays R-7: **every generation of every attempt carries the same `jobId` — the dispatch id**; the attempt ordinal disambiguates without forking the id space, which is exactly why `attemptGroupId` could be dropped. The per-entry rule in the fetch loop (provider-cost.ts:282-300) becomes:

- `sessionPath === null` → `session-missing` failure (unchanged);
- readable, zero ids, `zeroSpendOk` → **contributes zero, not a failure** (new — see justification below);
- readable, zero ids, legacy entry → `no-generation-id` (unchanged, byte-identity);
- unreadable/corrupt file on a `zeroSpendOk` entry → `session-missing` (indistinguishable from missing once you own a pointer to it; legacy stays `no-generation-id`).
- `totalCost` = Σ over reported generations across all attempts — the existing reduce (provider-cost.ts:345-352) needs no change beyond the entry expansion.

**Per-attempt spend: derived, never persisted.** The goal says "transcript **and spend** recoverable from the manifest alone" — the manifest alone plus the session file it names. Each attempt owns a private session id, so attempt N's spend is the assistant-usage sum over *its* JSONL (the read side already exists: spend.ts:214 accumulates `e.message.usage` from session entries). Persisting per-attempt usage tuples would require the Hub to snapshot its accumulator per attempt (new state), would duplicate the cumulative tuple's numbers, and buys nothing: the manifest and the JSONLs live in the same run dir and are pruned together — after pruning, neither survives, and the durable usage-store record (with the now-whole provider figure) is the only survivor by design ([[usage-store]]: `pointerSurvivable`/`ResolveOutcome`). The basis honesty is preserved too: derived spend is `session-reconciled`, the manifest tuple stays `stream-assistant` — two persisted numbers with one provenance each, never re-collapsed.

**`provider.partial` and the legend once whole.** The write path stops setting `partial` whenever the attempts list was walked completely — a reported report is whole *by construction*, so `partial: "final-attempt-only"` has no remaining true producer. But **do not delete the literal or the legend**: stored records are choose-once immutable (usage-store.ts:388-392), records persisted pre-EV-42 carry `partial` on disk (pinned by test/usage-store.test.ts:845-884), and `formatUsageBlock` must keep rendering `PARTIAL_LEGEND` for them (usage-block.ts:32, 120). The carve-out that keeps the fallback honest: an EV-39-era manifest (`attempt > 1`, no `attempts` list — the window between EV-39 and EV-42, or a provenance-less shape) still walks only the final attempt, so the flush **keeps marking `partial` for exactly that shape** (`attempt > 1 && attempts === undefined`). Without it, deleting the heuristic silently upgrades a still-partial figure to whole — the exact falsification EV-39's Q4 ruling exists to prevent.

**Missing attempt session file.** The figure is **whole or absent, never short-and-labeled**: a missing/unreadable attempt JSONL yields `session-missing` → report `unavailable` → the existing worst-of machinery (usage-block's C4 path, T-B4 semantics) renders the reported row for what *was* fetched plus `cost=n/a` on subtree and the n/a legend. I reject the alternative (sum resolvable attempts under a new `partial` reason): it re-opens the EV-39 falsification class with new copy and a new literal, for a case (one file of one run dir missing while its siblings survive) that `ResolveOutcome` already names a **defect signal** (`missing-unexpected`), not a by-design state. Nothing throws; no path is ever fabricated.

**Byte-identity / backward requirements.** (1) A single-attempt dispatch: no `attempts` key (snapshot-test the manifest bytes), legacy jobs entry, identical provider sibling, identical block. (2) `USAGE_RECORD_SCHEMA_VERSION` stays **2** — the record shape gains nothing new beyond optional `attempt` on generations; v1/v2 read tolerance untouched. (3) Old stored records with `partial` render identically. (4) Old manifests without `attempt`: legacy path. (5) `formatReport`/`formatWaitReport` untouched.

## Tradeoffs accepted

- **Minimal `attempts` entries (`{n, sessionId}`) omit per-attempt timing/exit state.** If someone later wants per-attempt timelines, that's an additive extension; I'm not pre-purchasing it. What I *am* deliberately giving up: a persisted per-attempt spend (argued above — divergence risk with zero post-pruning recoverability gain).
- **The unreadable-vs-empty asymmetry** (legacy `no-generation-id` vs `zeroSpendOk` `session-missing`) is two subtly different failure classes for single- vs multi-attempt manifests. I accept it because the legacy literal set and behavior are pinned by EV-29's C3 tests, and the new semantics are only *provable* when the manifest attests the attempt existed. If round-2 prefers one unified rule, the cost is changing legacy semantics for readable-empty single-attempt sessions from `unavailable/no-generation-id` to a zero-contributing report — a visible byte change to non-retried records I won't make silently.
- **`hub.ts` grows three small deltas** (seed/append/emit) inside a §7-stable file. The alternative — sidecar files written by the retry supervisor — fragments the substrate and violates the settled cardinality (one manifest per dispatch). The deltas are individually test-able and touch no kill/stall semantics.
- **Navigator browsing of *past* attempts' transcripts is explicitly out of scope** — the tree tails the current attempt via `manifest.sessionId`, which stays correct. Per-attempt transcript browsing in the navigator is a natural follow-up card, not this one.

## Testable claims

All failing-first; the harnesses exist (`test/hub.test.ts:419-441` fail-once stub; `test/usage-store.test.ts:845+` G4 retried-flush harness; injected `FetchGeneration` doubles per `test/provider-cost.test.ts`).

5. **T5 (missing file):** delete attempt-1's JSONL → `status:"unavailable"`, `reason:"session-missing"`, block renders reported row (attempt 2's) + subtree `cost=n/a` + the n/a legend — and **no** `partial` legend, no short-sum-labeled-whole record.

**Falsifiable predictions:**
- **P1:** Post-EV-42, a fully-retried dispatch's persisted provider figure equals the sum of its per-attempt generation costs — settled by T3; a green T3 falsifies the current tree, where the same fixture yields `partial:"final-attempt-only"` and c2 alone (test/usage-store.test.ts:877).
- **P2:** Derived per-attempt spend sums to the manifest's cumulative tuple within the stream-projection caveat: Σ assistant usage over both attempts' JSONLs ≈ final `manifest.usage`. Settle with a stub that emits usage in both attempts (the ACC_FIXTURE pattern, test/hub.test.ts:167-181).
- **P3:** Zero-generation-id attempts are *common*, not exotic — any attempt that dies on spawn error before the first assistant message produces one. T4's semantics (zero, not failure) therefore decide whether most real retried dispatches render `reported` or `n/a`.
- **P4:** No record is ever persisted mid-retry with a timing-partial figure: `forestFullySettled` (usage-store.ts:408-411) stays closed through the backoff window because `respawn`/`onSettle` retract `exitCode` to null (hub.ts D2). Test: drive the flush between attempts, assert `gate-closed`.

**Split judgment: keep the card whole.** The attempts list has exactly one consumer — the flush walk — and the walk has exactly one source: the list. Split, either half ships dead: a pointer field no reader resolves, or a reader of an unpublished shape. The invariant being delivered ("whole or absent, never short") lives across both seams and is only testable end-to-end (T3/T5). The one legitimate follow-up split is navigator-side per-attempt transcript browsing — surface work, zero coupling to the accounting invariant, and it should be named as out-of-scope rather than split out now.

## Cross-seam reading — what the contract is right now

Both sides opened first-hand at HEAD `5ac8b77`.

**Producer side (hub → manifest).** `respawn` reuses the job id, carries `usage` cumulatively, and sets the *next* attempt's session id (`hub.ts:186-221`); the manifest writer emits exactly one `sessionId` = the **current** attempt's, plus `attempt` only when `>1` and `nextAttemptAt` only while `retrying` (`hub.ts:111-128`, `runs.ts:44-62`). `council_dispatch` mints `${jobId}-attempt${n}` (`hub-tools.ts:269-278`), attempt 1 being the bare job id (`hub-tools.ts:249-254`, `hub.spawnJob` default `hub.ts:172`). `job.usage` accumulates in place (`hub.ts:255-275`) and `respawn`'s `...prev` spread (`hub.ts:197-201`) means the new Job **shares the same usage object** as the old one. Attempt-1 JSONL and attempt-2 JSONL both land in one run dir; `findSessionFile` matches on the header `id` (`runs.ts:140-159`).

Per-attempt spend is therefore **not retained anywhere**: only the cumulative tuple survives, and per-attempt identity is discarded at respawn.

**Consumer side (manifest → store → block).** The harvest maps *one job per manifest*, resolving `m.sessionId` — the final attempt's — to one session path (`usage-store.ts:421-427`), then post-hoc copies `partial:"final-attempt-only"` onto the report whenever any eligible manifest has `attempt>1` (`:443-448`). The module itself sets `status = failures.length>0 ? "unavailable" : "reported"`, where a per-job `sessionPath===null` contributes `session-missing` (`provider-cost.ts:285`) and zero ids contributes `no-generation-id` (`:297`) — so **a retried attempt that produced no generation can flip an otherwise fully-reported dispatch to `n/a`**. `ProviderGeneration.jobId` is the R-7 row key (`provider-cost.ts:52-56`); no attempt granularity exists on generations. The block renders the partial legend iff `provider.partial !== undefined` (`usage-block.ts:120`) from a single literal (`:32`).

## Blind spots, per slice

- **Hub/retry slice** cannot see that the store keys one session path per manifest, so it cannot know that "cumulative usage is enough" is false; and it cannot see that at the retrying settle the ordinal has *already advanced* (`job-retry.ts:75-80` mutates `job.attempt` before the hub's `writeJobManifest` at `hub.ts:341-347`) — inside its slice `job.attempt` reads as "the attempt that just ran".
- **Run-substrate slice** sees the manifest as the record; it cannot see the render legend or the report's worst-of, and so cannot see that "recoverable from the manifest alone" is time-bounded — `pruneRuns` deletes the run dir (`runs.ts:182-193`), and the manifest is *inside* it.
- **usage-store slice** sees the harvest and the choose-once write; it cannot see the hub's delta arithmetic (nothing in its view says whether a persisted per-attempt tuple sums to the top-level), nor the *pending* vs *completed* ordinal skew during backoff.
- **provider-cost slice** discovers the "no ids" fact but does **not own** the disclosure — `partial` is stamped one layer up (`usage-store.ts:443-448`), so the module cannot express "this attempt is unaccounted, that one is not".
- **Render slice** sees a `partial` literal; it cannot tell *which* attempts are missing, and it cannot see that durable records on disk carry literals a later vocabulary may not know — with `partial !== undefined` as the trigger, an unknown literal silently drops the qualifier (fail-open).
- **Navigator slice** resolves the same field two ways: the inline tail/view keys on `manifest.sessionId` (`navigator.ts:335,341,464`), while the modal `openTranscript` resolves `manifest.id` (`navigator.ts:869`) — which is attempt 1's session, not the current one. (Inferred, but grep-backed: `onActivate` is stored in `CustomTreeEditor` (`focus-nav.ts:282`) and has no call site in `focus-nav.ts`; Enter routes to `enterProgress` (`focus-nav.ts:318`), so the `manifest.id` path is latent, not live.)

The wiki has **no page for hub-level retry, the retry policy, or per-attempt identity** — the last ingest is EPIC-8 (2026-09-15, `vault/wiki/log.md`); EPIC-9's EV-37…EV-43 landed without an ingest. So the substrate authority is the code plus `council/cards/EV-39.md` §Step 6 (steward Ruling 2: the disclosure must be "machine-readable and durable … a stored figure that looks whole a month later is the defect") — which is itself the argument against treating `partial` as retiring.

## Reframe

The card's mechanism is right; two of its claims are wrong, and it misses that the real seam is a *field with three meanings*.

1. **"the dispatch's provider-reported figure sums every attempt" — not unconditionally.** An attempt that was stall-killed or died before a `responseId` was persisted may have been charged with no recoverable generation; `no-generation-id` is not evidence of zero. So wholeness must be *falsifiable*: `partial` does not retire, it **narrows**. It becomes an observable of the *unaccounted* attempt rather than an unconditional consequence of `attempt>1`.
2. **"recoverable from the manifest alone" is an index claim, not a durability claim.** The manifest can name the attempts while the run lives; only the store record outlives pruning. Per-attempt *provider* attribution must therefore also land on `ProviderGeneration` (record-only), or the provenance dies exactly where it is needed a month later.
3. **The seam is `RunManifest.sessionId`'s three meanings:** the store wants *all* attempts, the tail wants the *current* one, the legacy transcript path takes `manifest.id` (attempt 1), and during backoff `attempt` is the **pending** ordinal while `sessionId` is the **completed** attempt's (`hub.ts:126-127` + `:119`). One accessor in the substrate — not two derivations per consumer.

Concretely:

- **Manifest field:** `attempts?: AttemptRecord[]`, present only when `attempt > 1` (non-retried manifest byte-identical, EV-39 G1), each `{ attempt, sessionId, usage }` where `usage` is **this attempt's delta** over the stream tuple (`usageSource:"stream-assistant"`), so `Σ attempts[].usage == manifest.usage` metric-wise for all twelve numeric fields. `manifest.usage` **stays cumulative** — if it becomes the final attempt's, `spend.ts:250`/`sumSubtreeUsage` silently halve every retried dispatch's subtree half. "Settled attempts, in order" is the documented meaning; the pending attempt is `attempt` with `state==="retrying"`.
- **Substrate accessor:** `attemptEntries(m)` in `runs.ts` (returns `m.attempts ?? [{attempt: m.attempt ?? 1, sessionId: m.sessionId, usage: m.usage}]`) — the single derivation both the store and the UI consume.
- **Harvest:** flatten to one job entry per attempt, `{jobId: m.id, model: m.model, attempt, sessionPath: findSessionFile(…, a.sessionId) ?? null}`; prices nothing, changes no key. `delete` the `retried` block at `usage-store.ts:443-448` — the harvest no longer *computes* any disclosure.
- **`ProviderGeneration`:** `attempt?: number` additive (absent for a single-attempt job ⇒ old records byte-identical); `jobId` **stays the tree-row id** — do not mint `${jobId}-attempt2` as a job key, that is a key pointing at no row. `attemptGroupId` being dropped is only correct because this field now carries the attribution.
- **`status`/`reason` for an attempt with no generation:** the report is `reported` iff at least one entry reported; an entry contributing zero ids is **unaccounted**, not a failure flip. `status:"unavailable"` is reserved for (a) `no-api-key`, (b) a harvested generation that could not be fetched (`fetch-failed:`/`timeout`), (c) **every** entry unaccounted (which reproduces today's single-attempt shape byte-for-byte, so T-P8 and `provider-cost.test.ts:361-389` stay green). A **gap** (max ordinal > entry count for a jobId, i.e. a pre-EV-42 manifest) is fail-closed to the old literal.
- **`partial` and the legend:** `ProviderPartialReason = "final-attempt-only" | "attempts-unaccounted"`, plus record-only `unaccountedAttempts?: number[]`; legend lookup becomes a **total** map (unknown literal → a generic "figure is not whole" line), because choose-once means old records are never rewritten. The legend lives in the module's output, not in the caller's post-hoc copy, so `usage-block.ts:32,120` reads the same conditional as today with two literals; `partial`'s *absence* becomes meaningful for the first time — it now asserts "every attempt's generations were fetched".

## Testable claims

1. **Delta, not reference** (`hub.ts:197` aliasing): two attempts with distinct assistant usage → `manifest.attempts[0].usage.output === attempt1Output` and `Σ attempts[].usage[X] === manifest.usage[X]` ∀ numeric metrics. An implementation storing `prev.usage` by reference fails immediately.
2. **Ordinal at settle:** after a retryable attempt-1 settle, the `retrying` manifest reads `attempt: 2`, `nextAttemptAt` set, `attempts: [{attempt: 1, …}]` — never `attempts:[{attempt: 2}]`. (Requires the hub to snapshot the ordinal *before* calling `job.retry?.onSettle`.)
3. **Byte-identity:** a non-retried dispatch's manifest has neither `attempts` nor `attempt`; its persisted record equals today's fixture bytes (no generation `attempt`, no `partial`).
4. **Module-level disclosure:** two entries, attempt 1 `sessionPath:null`, attempt 2 with a generation → `status:"reported"`, `partial:"attempts-unaccounted"`, `unaccountedAttempts:[1]`, `totalCost` = attempt 2's, and no `n/a` legend. Single entry with `attempt:2` and a reporting session → `partial:"final-attempt-only"` (reproduces `usage-store.test.ts:845-885` at module level).
5. **All-unaccounted:** both entries null/empty → `status:"unavailable"`, C3 worst reason, `totalCost:null`, `n/a` legend — byte-identical to the pre-card path.
6. **Read-compat:** the block emits a legend for a report whose `partial` is the *old* literal — the fail-open guard.
7. **No double count:** 2-attempt manifest → `sumSubtreeUsage(...).subtree.cost === manifest.usage.cost` and `spendRecord`'s subtree half equals it.
8. **Attempt-1 reachability:** after a 2-attempt run with two JSONLs (`id` `job-1`, `id` `job-1-attempt2`), the harvest's transport call list contains **both** generation ids.
9. **G4 live (`COUNCIL_INTEGRATION=1`):** real 2-attempt openrouter dispatch → `reported` with generations from both attempts and `Σ = both`; negative arm (stall-killed attempt 1) → `partial` present.

## Split judgment

**Keep whole.** The goal's two clauses share one input, and the legend copy is a *claim about the harvest*: changing the copy without the harvest yields copy that is false or uncomputable, and shipping the field without the harvest ships a substrate nothing reads — EV-39's own test for splitting. The single item that must not be deferred even though it looks like polish: the legend map's totality over old literals (test 6), because that is the one place the change can make an existing durable record read as whole.

## Hazards the card does not name

- **Off-by-one at the retrying settle** (ordinal advanced before the write) — §above, test 2.
- **`partial` lost on old records** if the renderer's condition stays "presence of a literal" while the vocabulary changes.
- **Pre-EV-42 manifests inside the 15-run window** after a package upgrade carry `attempt>1` and no list: the harvest must fail closed to `final-attempt-only`, not assert wholeness.
- **Pruning bound, restated precisely:** the manifest list is ephemeral; per-attempt *token* spend is not durable at all — `SpendRecord` is frozen (`usage-store.ts:62-64`, EV-31) and the store's `subtree` half is a whole-forest sum (`spend.ts:250`), so durable per-attempt *spend* would require a wrapper-level field, a scope expansion the Note does not authorize. If the team reads "recoverable" as durable, this is a steward goal-wording question, not an implementation choice. (Also note `pid:null` during backoff makes the run look non-live to `pruneRuns`'s check at `runs.ts:186`.)
- **Flush cost:** the harvest becomes Σ attempts × generations on a serial loop with a 5 s per-generation `AbortSignal.timeout` (`provider-cost.ts:305`), inside awaited drains (`index.ts:751,765`); bounded, but linear in attempts in the teardown path.
- **Navigator divergence** (`navigator.ts:869` vs `:341/464`) — latent only; recommend a named follow-up rather than folding a navigator fix into this card.
