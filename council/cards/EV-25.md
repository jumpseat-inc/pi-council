## Intent

User-visible surface: the slash command itself, the headless console
listing, and the post-write notification copy. The command registers as a
TypeScript command via `pi.registerCommand` — the LLM-obedience path per the
procedures-vs-commands ruling, matching `/council-eval` and
`/council-leaderboard` (`extensions/index.ts:304-362`) — because a
deterministic file write must not be delegated to model judgment.

In a TUI session it refreshes the catalogue, opens EV-23's modal with
EV-22's data, and hands the selection to EV-24's writer. In a headless or
RPC session it prints a usage block with a per-seat current listing,
parallel to the `/council-eval` usage block (`extensions/index.ts:333-341`).
The post-write notification names the file, the seat, the new model, and
that the change takes effect at the next dispatch — overrides apply at seat
load, and a mid-session reload is deliberately out of scope for v1 (a
follow-up card could add it if a need surfaces).

## Acceptance

- Tests exercise both the headless handler-write path and the
  modal-picker-to-writer wiring path, with the modal picker mocked at its
  selection-encoding contract.
- An end-to-end smoke exercises `/council-models` in a real overlay.
- The notify copy names the file, the seat, the new model, and the
  next-dispatch timing.

## Phase 1 rulings (features-deliver, binding for this run)

- **R-1 (headless grammar)**: `/council-models` with no arguments prints
  the usage block and the per-seat current listing; `/council-models
  <seat>` prints that seat's current line plus the usage line;
  `/council-models <seat> <provider>/<model>[:thinking]` validates and
  writes, then notifies.
- **R-2 (usage block)**: parallel to the `[council-eval]` block —
  `[council-models] usage: /council-models [<seat>
  [<provider>/<model>[:thinking]]]` followed by `Current per-seat
  models:` and one line per seat — `<seat>: <provider>/<model>[:thinking]
  (override)` when an override exists, `<seat>: frontmatter default`
  otherwise.
- **R-3 (notify copy)**: after a write in either surface —
  `council-models: wrote <seat> → <provider>/<model>[:thinking] in
  .council.json — takes effect at the next dispatch.`

These are recorded human decisions — immutable for the run and binding on
every seat, `steward` included. Any change to the ruled wording routes
through the orchestrator as an escalation.
