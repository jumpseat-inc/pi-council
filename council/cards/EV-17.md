## Intent

Today `council_dispatch` resolves a seat's model from frontmatter, shadowed
by the committed `.council.json`; there is no per-invocation model input.
Measuring a model means running a seat or procedure under an arbitrary model
id without mutating committed files (editing `.council.json` between runs is
slow and corrupts the comparison). This card builds that seam — the one
piece every later eval child depends on — and covers both directions: a
seat dispatched under a caller-chosen model, and a procedure driven under
one.

Not surface-touching: the model id is an internal dispatch detail; no
person-facing screen or copy changes.

## Acceptance

- Dispatching the eval path with a model id spawns a session whose argv
  carries that model (and thinking level, if any) — verifiable from the run
  transcript.
- The override works without writing to seat frontmatter or `.council.json`.
- A test proves the spawned argv reflects the override for at least one seat
  and one procedure, and that an omitted override falls back to the seat's
  resolved model unchanged.
