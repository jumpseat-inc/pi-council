## Intent

Cross-model comparison is worthless if runs differ in anything but the
model, so each fixture is a pinned, self-contained task: for a procedure, a
fixed input (e.g. a specific card draft or a specific repo state) whose
success is observable in produced artifacts; for a seat, a fixed turn input
whose success is observable in the seat's output. One fixture per shipped
procedure (board-create-card, council, features-deliver, features-new,
wiki-ingest, wiki-lint, wiki-query) and per packaged seat (consolidator,
council-runner, designer, judge, owner, principal, product-owner, skeptic,
steward). Repo-local `.pi/` overrides shadow packaged fixtures per
convention 5, so a consumer can add fixtures without forking the package.

Not surface-touching (test data; no person-facing surface).

## Acceptance

- The fixtures directory ships one fixture per packaged seat and per shipped
  procedure, each pinning its inputs and any seed or commit it depends on.
- Each fixture is runnable from a fresh checkout with no manual setup or
  network-dependent state, and produces a deterministic starting state.
