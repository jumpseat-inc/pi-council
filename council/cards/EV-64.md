## Intent

State is packed deliberately because the transport's context cap forces it: the
model is calibrated against what it is given, so thin state produces confident
wrong answers rather than visible uncertainty. The declared sections are the
card's goal and acceptance criteria; a touched-file manifest as paths and
changed-line counts, never file contents; the top-k wiki pages selected for the
card's patterns; the recent rulings relevant to those patterns; and the names of
existing tests covering the area. Each section has a token cap, the order is
fixed, and an over-budget state drops from the tail by a documented rule.

One premise needs correcting here. There is no retrieval substrate behind
`/wiki-query` to reuse — that command is prose instructing a model to read the
wiki index and drill in, and no selector function exists in the engine. Page
selection must therefore be a new deterministic matcher over the wiki pages'
own frontmatter (tags, aliases, summary) and the repository's doc-to-page map;
it must not call a model, because a model call inside state assembly would
reintroduce the cost and the nondeterminism the gate exists to remove.

Packing is pure and testable: the same card and repo state must yield the same
state bytes, and the recorded drop must name which section was truncated so a
reader can tell a thin state from a full one.

## Acceptance

The returned state's measured token count never exceeds the configured budget;
with an oversized tail section the earlier sections are byte-identical to the
untruncated pack; the drop is recorded with the section name; wiki page
selection is deterministic for a fixed repo tree and performs no network or
model call; and file contents never appear in the touched-file section.

## Deliberation

### Round 1 — owner (job-8.1)

- Location: new pure module `extensions/gate-state.ts`; gate.ts keeps its "resolution + validation, never dispatches, never writes" purity; packer needs fs, so separate module. Exports only buildGateState + result type; consumed by EV-65 transport + tests.
- Inputs: buildGateState(card: ParsedCard, repoRoot) with ParsedCard = {id, title, goal, acceptance, touchedFiles: {path, linesChanged}[]} — touched-file manifest is an explicit input, never ambient git diff (purity).
- Fixed section order (JSON): card {id,title,goal,acceptance} cap 4000; touchedFiles sorted lex {path,linesChanged} cap 2000; wiki top-k pages {slug,title,summary,aliases} frontmatter-only cap 4000; rulings {slug,date,title,summary} newest-first cap 8000; tests = names by stem/path affinity cap 1000. Sum 19000 ≤ 32000 so a well-formed pack fits without dropping in the normal case.
- Token measure: ceil(byteLength/3.5), documented as conservative over-count (prose ~4 chars/token, code ~3).
- Matcher: stopwords-extracted lowercase terms from title+goal+acceptance; doc-to-page map derived per-call by scanning each page's frontmatter + body for repo-path tokens → inverted path→slug index; scoring aliases×3 title×2 tags×2 summary×1 paths×2; k=6 named constant, tie-break lex by slug.
- Rulings: pages under vault/wiki/sources/ whose tags contain pi-council/ruling; relevant if shares a non-namespace tag with a selected page or aliases/summary match card terms; filename-date descending.
- Drop rule: fixed order, whole-entry granularity; first section whose addition exceeds remaining budget truncated to largest whole-entry prefix; every later section dropped entirely; drops = [{section, truncated, kept, droppedAfter[]}]; if even one entry can't fit its own cap the section is dropped entirely. Ledger copies drops + stateHash so truncation is journaled (EV-65).
- Policy: add gateStateBudgetTokens (positive int) to GatePolicy + ALLOWED_POLICY_KEYS, fail-loud single-line gateFail; absent key → code constant 32000 (absent-mode→off precedent). R3 untouched.
- Tests: mkdtemp synthetic vault/wiki + card; byte-identity across calls; oversized-rulings tail-drop with earlier sections deep-equal to untruncated pack; content sentinel absent; matcher determinism; policy FAIL cases; budget-ceiling over pathological fixtures; "sum of caps ≤ budget ⇒ no drop" invariant.
- Accepted tradeoffs: ±15% estimator drift (conservative direction); per-call map derivation (wiki small); whole-entry truncation may leave a section under cap (byte-level cuts would make invalid JSON fragments); caps in code not policy (fixed contract like MODE_PANELS).

### Round 1 — principal (job-8.2)

- Cross-seam: gate.ts is pure data surface (first-hit whole-file, fail-loud, ALLOWED_POLICY_KEYS); gate-ledger consumes only stateHash/questionSetVersion/answers/resolvedMode/policyVersion — never state bytes. buildGateState is the missing producer: bytes for transport, hash as the ledger stateHash's single source, drop record the ledger can carry.
- Blind spots named: (1) ambient git diff inside the packer would make state a function of uncommitted ambient state — the card's one real spec gap (manifest source must be decided in the plan, explicit input or injectable derivation); (2) a drop recorded only in the return value is invisible to readGateLedger — the ledger line must carry drops; (3) tests can prove determinism+budget, not relevance — precision rides the model, not the packer.
- Architecture: extensions/gate-state.ts imports types from ./gate.ts only; gate.ts/gate-ledger.ts never import it. Packer, counter, matcher, map derivation in one pure module.
- Policy: add gateStateBudgetTokens; fail-loud; absent → 32000 in code; also ship the field explicitly in packaged policy.json (coefficients-live-in-data convention). Whole-file override semantics untouched.
- Token measure: one pinned pure estimator (e.g. ceil(chars/4)) as named constant, documented as estimate; monotone, stable, pinned in one function; "measured" = this estimator's count.
- Matcher: minimal flat-frontmatter parser (no YAML dep), term-overlap scoring with pinned tie-break (page filename); fill pages in score order until section cap — k emerges from the cap, not a second knob.
- Doc-to-page map: derived per invocation from each page's sources: frontmatter plus body path-like tokens existing in the live tree; never hand-maintained (FLLWUP-59 lesson verbatim); ~80 pages, cheap.
- Section contract: fixed declared order as const tuple; per-section caps as pinned constants in the module.
- Truncation: greedy forward fill in declared order; first section that does not fit dropped together with the entire remaining suffix (contiguous tail, always); drops = ordered [{section, measuredTokens}]; buildGateState writes nothing; EV-65 persists into the ledger line.
- Hash: sha256(state bytes) computed in gate-state.ts and returned, so ledger stateHash and transported state can never diverge.
- Claims C1–C7: budget ceiling always; oversized-rulings prefix byte-identity vs huge-budget pack + drop record in declaration order; policy absent→32000, 0/-1/1.5/"x" → single-line FAIL; fixed-tree byte+hash identity; touched-file canary never in state bytes; budget-only change moves the cut never the prefix; map derivation pure function of the fixture tree.
- R3 note: packing is mode-independent; tests touching non-off policies set mode explicitly.

### Skeptic attack (step 4, job-8.5) — objections and actual results

Probes ran against the real tree (148 wiki pages, 19 ruling-tagged sources pages, real loadGatePolicy, o200k_base reference tokenizer). Main repo + worktree verified clean after.

- **O1 — closed-red.** "bytes/3.5 is a conservative over-count" is false as a uniform claim. Reference-tokenizer ratios: dense code −35.9%, rare CJK −13.3% (龘 → 2 tokens vs 0.86 allotted), emoji −17.2%; over-counts ASCII prose +45.8%, common CJK +10–27%. Bounded (real section shapes measured +28–42%) but the doc must say "estimate, not uniformly conservative." Residual open-untested: the gate model's own tokenizer unprobed; magnitudes are reference ratios.
- **O2 — closed-red on owner's date-descending; closed-green on principal's scorer-then-date.** Real-corpus probe: mean relevance of top-6 — filename-date desc 1.00, updated-field desc 1.33, scorer-then-date 3.17; 15/19 rulings share updated: 2026-09-20 (3 distinct values) so date ordering is tie-dominated; top-5 overlap of the two orderings 0/5; owner's date-desc picks for a gate card are ev12/epic5/epic6/epic8/epic9 rulings. The principal's refinement wins by direct measurement. Correction: epic9 skew is 13/19, not 15/19.
- **O3 — closed-red (quantified).** The agreed matcher on EV-64's own goal+acceptance picks test-suite-budget (47), retired-path-tokens (17), smoke-test (16); gate-parity ranks 17, deterministic-merge-check 15, metered-deliberation-routing 23. Determinism held (byte-identical runs) — acceptance survives — but "selected for the card's patterns" is not met on the design's own motivating card. Record as a known term-overlap limitation, not implied competence.
- **O4 — closed-red.** index.md contamination claim falsified on this tree: index.md has no frontmatter and zero live-tree path tokens in its body → score 0, rank 73/76; its [[links]] are invisible to the agreed field set. Keep the exclusion as cheap insurance, not load-bearing. Adjacent real gap: with sources/ pages in the wiki candidate set they take 2 of the top 6 slots — sources/ must be explicitly excluded (tested rule) or rulings pages double-dip into the wiki section.
- **O5 — closed-red (producerless).** touchedFiles/linesChanged exist only in the deliberation record — no ParsedCard type, no card-template field, nothing in GateCallInput. Explicit-input shape is load-bearing (changed-line counts cannot be derived deterministically without pinning a diff base), but an explicit input with no defined producer is a spec gap; the plan must say who builds the manifest or EV-65 invents one.
- **O6 — closed-red.** Whole-entry-prefix truncation is undefined for single-entry object sections: with "entry = whole section object", an over-cap card section keeps 0 entries → empty state, identical to the drop-whole-tail rule the owner argued against; only "entry = per-field" preserves the owner's degenerate-case defense. "Entry" must be pinned per-section (field-granularity for `card`).
- **O7 — closed-red (structural).** Caps sum to 19,000 < 32,000 default: at the default the budget can never bind, the production drop path is unreachable, and the card's demanded oversized-tail test is constructible only by setting gateStateBudgetTokens below 19,000 in the fixture policy — a coupling the deliberation never tied to the test design. When the budget is lowered and a section exceeds both its cap and remaining budget, the drops record must distinguish cap-trims from budget-drops or one {section, truncated, kept} shape conflates two mechanisms.
- **O8 — closed-green machinery; closed-red analogy.** Real loadGatePolicy probe: fail-loud single-line FAILs confirmed; absent mode → off confirmed. But policyVersion/model/endpoint are required; mode is the only defaulted key and its default is a safe no-op. A budget default is an active parameter (packer still emits up to 32k with the key absent) — the absent-mode→off analogy fails gate.ts's own "a silently defaulted policy is an untested policy" philosophy; also packaged-explicit-32000 and code-fallback-32000 are two independent constants that can drift. Plan must weigh: require the key (compat break for existing repo-local policies), or require when mode ≠ off, or keep the fallback with drift documented.

Skeptic verdict: **blocks step 5 on five falsified deliberation claims** (O1 wording, O2 ordering — settled by measurement in favor of scorer-then-date, O5 producer, O6 entry granularity, O7 cap/budget seam) **plus two unshaped rules** (sources/ exclusion; cap-trim vs budget-drop in drops record). No objection open-untested except the noted tokenizer residual.
