## Intent

State is packed deliberately because the transport's context cap forces it: the
model is calibrated against what it is given, so thin state produces confident
wrong answers rather than visible uncertainty. The declared sections are the
card's goal and acceptance criteria; a touched-file manifest as paths and
changed-line counts, never file contents; the top-k wiki pages selected for the
card's patterns; the recent rulings relevant to those patterns; and the names of
existing tests covering the area. Each section has a token cap, the order is
fixed, and an over-budget state drops from the tail by a documented rule.

One premise needs correcting here. There is no retrieval substrate behind
`/wiki-query` to reuse — that command is prose instructing a model to read the
wiki index and drill in, and no selector function exists in the engine. Page
selection must therefore be a new deterministic matcher over the wiki pages'
own frontmatter (tags, aliases, summary) and the repository's doc-to-page map;
it must not call a model, because a model call inside state assembly would
reintroduce the cost and the nondeterminism the gate exists to remove.

Packing is pure and testable: the same card and repo state must yield the same
state bytes, and the recorded drop must name which section was truncated so a
reader can tell a thin state from a full one.

## Acceptance

The returned state's measured token count never exceeds the configured budget;
with an oversized tail section the earlier sections are byte-identical to the
untruncated pack; the drop is recorded with the section name; wiki page
selection is deterministic for a fixed repo tree and performs no network or
model call; and file contents never appear in the touched-file section.
