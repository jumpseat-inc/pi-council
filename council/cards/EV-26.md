## Intent

The search input in the `/council-models` model selection modal (EV-27)
renders from a filtered row set; this card extracts the filter itself as a
pure unit mirroring EV-22's resolver so the match contract is testable in
isolation. The contract is pinned: match field is `qualifiedId` only (the
field the modal actually renders — display `name` is never rendered, and
matching an invisible field would make rows vanish under a query that
matches nothing on screen); match algorithm is case-insensitive substring
(the intake's word is "filter"); the filter runs on the model cross-product
rows before the `:level` suffix is applied at render time, so a query like
`:off` never matches a suffix; and the surviving rows are returned as the
identical `PickRow` references so `resolveSelection()` keeps emitting
byte-verbatim keys. An empty query returns all rows; a query matching
nothing returns an empty array — the modal owns the no-match copy (EV-27).

Not user-visible — pure function, no rendering.

## Acceptance

- Unit tests drive `filterModelRows` with `rowsForProvider`-shaped
  cross-product rows: case-insensitive substring matches on `qualifiedId`,
  non-matches excluded, empty query returns all rows, no match returns
  empty array.
- A query containing `:` (e.g. `:off`) does not match thinking-level
  suffixes.
- The returned rows are the identical `PickRow` objects (reference
  equality), not copies.
