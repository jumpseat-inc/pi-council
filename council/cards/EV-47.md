## Intent

`/features-deliver` ends at Phase 3, which reports the run — every merge with
its basis, every follow-up filed, every card's usage block — and stops.
Nothing in the command ingests what the run learned; the durable run ledgers
under `vault/raw/` have been written by hand after the fact. The ask is that
the run's own record is ingested when the run closes, in the same autonomous
pass, with the run's learnings filed rather than summarized in chat.

The seam is different from a single card's completion. Phase 3 is the one
place the whole run is assembled in one context: the per-card reports, the
merge bases, the follow-ups, the escalations the orchestrator answered. A
per-card ingest covers each card's own run; this card covers the run-level
record those cards do not — the schedule, the escaped dependencies, the
aggregate. The card states how the two ingests divide the source material so
the same facts do not become two source pages with two summaries, and it
names the artifact that becomes the source: the Phase 3 ledger is what the
run already produces, while the run substrate under `.pi/council/runs/` is
pruned and self-gitignored and cannot be the cited source.

Two boundaries bound the design. `council/procedures/features-deliver.md`
declares its authority map "complete and exhaustive" and forbids inferring
authority beyond it, so a new `vault/`-writing step is an authority-map
change, not an implementation detail. And a contradiction the ingest cannot
resolve is judgment, not retrieval: it reaches the ruling seat the authority
map already names for judgment, and the outcome is recorded in the run's
ledger.

This card is Backlog until the run-ledger ingest capability is settled and
until the single-card ingest's completion semantics are settled, because its
source-division rule depends on both.

Surface: the Phase 3 ledger line a person reads at run close gains the ingest
outcome — pages created, pages updated, contradictions flagged — plus the
durable pointer on the closed epic card and the wiki source page.

## Acceptance

- `council/procedures/features-deliver.md` Phase 3 performs the run-level
  ingest before the run is reported closed, and states how the run-level
  source differs from each card's own run source so no fact becomes two
  source pages.
- The authority map gains the ingest and its escalation as an explicit row,
  or the ingest is re-homed into an existing row that already covers it; no
  authority is inferred from the autonomy mandate.
- The run-level source artifact lives under `vault/raw/` and is durable
  before `.pi/council/runs/` pruning can drop the underlying transcripts.
- The Phase 3 ledger reports the ingest outcome in the wiki schema's own
  vocabulary (pages created, pages updated, contradictions flagged).
- A contradiction the ingest cannot resolve reaches the ruling seat the
  authority map names for judgment, and the outcome is recorded in the run's
  ledger.
- The smoke transcript carries an operation marker naming the ingest (e.g.
  `[run-ledger-ingest]`) asserted by `grep -q` against the runner's session
  JSONL, or a sabotage arm (a runner instructed to skip the ingest reports an
  observable failure on the same assert set).
- `SMOKE_PHASE` isolation today supports only 5 and 6; a multi-card epic smoke
  is an engine extension. The card requires it as a prerequisite; the engine
  work is out of this card's scope.
- Phase 3's ingest outcome reports via the wiki source page (frontmatter
  `provenance: run-ledger` + backlink to the epic card) and a `## Ingested
  into wiki:` row on the closed epic card; the chat-line ledger summary stays.
- The run-level source artifact differs from each card's run source per the
  wiki schema's one-source-per-page convention: the run-level page cites the
  Phase-3 ledger under `vault/raw/`; per-card pages cite each card's run
  ledger.
- A smoke phase carries a multi-card epic to completion with no human step
  and asserts the run-level source page, its `vault/wiki/index.md` entry, and
  its `vault/wiki/log.md` entry.
- The repo's typecheck, the full test suite, `python3 council/validate.py`,
  and the repo's preflight pass.
