## Intent

Cross-model comparison is worthless if runs differ in anything but the
model, so each fixture is a pinned, self-contained task: for a procedure, a
fixed input (e.g. a specific card draft or a specific repo state) whose
success is observable in produced artifacts; for a seat, a fixed turn input
whose success is observable in the seat's output. One fixture per shipped
procedure (board-create-card, council, features-deliver, features-new,
wiki-ingest, wiki-lint, wiki-query) and per packaged seat (consolidator,
council-runner, designer, judge, owner, principal, product-owner, skeptic,
steward). Repo-local `.pi/` overrides shadow packaged fixtures per
convention 5, so a consumer can add fixtures without forking the package.

Not surface-touching (test data; no person-facing surface).

## Acceptance

- The fixtures directory ships one fixture per packaged seat and per shipped
  procedure, each pinning its inputs and any seed or commit it depends on.
- Each fixture is runnable from a fresh checkout with no manual setup or
  network-dependent state, and produces a deterministic starting state.

### Round 1 (step 2) — owner (job-7.1), verbatim

**Approach** — Deliver 16 self-contained fixture dirs (`council/fixtures/<task>/` at `PKG_ROOT`, one per packaged seat + one per shipped procedure) plus `extensions/eval-fixtures.ts` (pure loader, schema validators, and the structured-rulings engine), shadowed repo-side at `<repo>/$CONFIG_DIR_NAME/council/fixtures/<task>/` per convention 5. Every fixture pins its full starting state as a checked-in `seed/` tree with a sha256 digest, its exact inputs, its harness-as-human policy, and its pinned `graderModel`. Seeds are **full-only** (self-contained), never overlays onto the caller's checkout — `proceduresDir`-style `[repoOverride, packaged]` resolution, whole-dir first-hit-wins. The loader stamps `fixtureVersion`/`rubricVersion` into every result it seeds; EV-19/EV-20/EV-21 consume this module's interfaces rather than re-resolving fixtures.

**1. Concrete `fixture.json` schema**

```jsonc
{
  "schemaVersion": 1,               // reject anything else, loudly
  "taskId": "board-create-card",    // must equal the dir name; ^[a-z0-9][a-z0-9-]*$
  "name": "Draft a card from a pinned intent",
  "fixtureVersion": "1.0.0",        // semver, required
  "kind": "procedure" | "seat",     // disjoint target shapes, schema-enforced
  "target": {
    "type": "procedure", "command": "/board-create-card", "arguments": ["Add a --json flag to the links CLI"]
    // XOR: "type": "seat", "seat": "skeptic"   (seat name must resolve via loadSeat)
  },
  "inputFile": "input.md",          // required iff kind=seat: the exact pinned turn input
  "seed": { "dir": "seed", "treeDigest": "sha256:<hex>" },   // see §2
  "env": { "GIT_AUTHOR_NAME": "…", "GIT_AUTHOR_EMAIL": "…", "TZ": "UTC" },  // optional, pinned
  "timeoutMinutes": 240,            // optional ceiling hint for the cell; runner-side default exists
  "policy": { "gates": […] },       // §4; empty gates array when the procedure has no human gate
  "graderModel": "openrouter/<p>/<id>",   // resolved from the fixture file, never .council.json (settled)
  "graderThinking": "medium"        // optional
}
```

`rubricFile` is **not** a field — the §3.4 wiring table already fixes `council/fixtures/<task>/rubric.json`; a second field is drift surface. Procedure inputs are short by nature and pinned inline in `target.arguments`; seat turn inputs are long and pinned as `input.md` (exactly-one rule, validator-enforced). Required keys: `schemaVersion, taskId, name, fixtureVersion, kind, target, seed, policy, graderModel`.

**2. Seed representation**

- **`seed/` is a plain directory subtree inside the fixture dir; `type: "full"` is the only supported kind; `"overlay"` is reserved and the loader rejects it.** Determinism acceptance kills overlay: an overlay onto the caller's HEAD is a different starting state in every consumer repo. The scratch (EV-20) is the fixture's own git repo materialized from `seed/`, the smoke precedent, not a worktree of the caller's tree — A1 is satisfied by construction, and my materialization test (below) proves the fixture half of A1 on this card.
- **`treeDigest` = sha256 over (sorted relpath, bytes) pairs**, recomputed and verified by the loader at every load — a cheap pin that catches accidental seed edits without a version bump and gives EV-20 upstream proof the scratch started from the authored tree. No git-commit pinning: fresh `git init` re-derives SHAs; the digest is the reproducible pin, and the acceptance's "any seed or commit it depends on" is vacuous for self-contained trees. `commitRef` stays reserved for a future card that references external history.
- **Authoring guard, loader-enforced:** a seed containing `.council.json`, `.pi/council/mcp.json`, or `.env` fails load. The cell-invariance contract (§1) makes model pins the one thing seeds must not carry — the smoke fixture gets away with flash overrides because the smoke *is* a fixed model run; eval cells vary the model, so `COUNCIL_EVAL_MODEL` + `graderModel` are the only sanctioned pinning surfaces.
- **Seeds are self-contained, not shared-archetype.** The heavy fixtures (council, features-deliver, owner, council-runner) each carry their own mini project (package.json+bun.lock, tsconfig, small CLI, board, `_template.md`, card-aware `preflight.sh` no-MCP/no-origin like smoke's, validate.py, minimal vault, AGENTS.md). Shared bases would couple 16 digests: any archetype edit invalidates every seed's pin, which is exactly the drift fixtures exist to prevent.

**3. Loader + rulings-engine placement**

One module, **`extensions/eval-fixtures.ts`**:
- `listFixtureTasks(repoRoot)` — unions packaged `PKG_ROOT/council/fixtures` with `<repoRoot>/$CONFIG_DIR_NAME/council/fixtures`, per-task first-hit (mirrors `listSeatNames`); each task validates self-description (taskId == dir).
- `loadFixture(repoRoot, taskId)` → `{ fixture, rubric, seedDir }` — loud failure on: unknown task, missing `rubric.json` (C3, no silent `[]`), schema violation, `schemaVersion ≠ 1`, digest mismatch, forbidden seed files, procedure-kind command not in the 7 shipped procedures, seat-kind seat not resolvable. Repo-side dir present → **the whole task dir resolves from the repo side** (fixture.json + rubric.json + seed/); a repo fixture.json with a missing repo rubric is a loud C3 error, never a silent fallback to the packaged rubric — mixing a repo seed with a packaged rubric would break pinning.
- Rubric + policy schema validators live here with the authored data (one authority); EV-19's `eval-rubric.ts` imports `validateRubric` from here instead of writing a second validator. I flag this as the one interface choice that touches EV-19's plan text.
- `applyRulings(policy, state)` — pure, no I/O (A4); `state` is a normalized view (job manifests by role, board columns, file facts), so the engine is a finite matcher.

**4. Harness-as-human policy block**

The spec settles exactly two gates by name (merge-gate verdict, delivery ruling); the other three procedures with human touchpoints (board-create-card confirm, features-new confirm, wiki-ingest "discuss first") still need mechanical substitutes or their cells hang at a gate. Schema:

```jsonc
"policy": { "gates": [
  { "id": "merge-gate", "humanStep": 11,
    "when": [                                  // ordered, all hold; empty when = standing ruling
      { "kind": "job-state", "role": "owner", "state": "done" },
      { "kind": "job-state", "role": "skeptic", "state": "done" },
      { "kind": "report-contains", "role": "judge", "token": "PASS" },
      { "kind": "board-column", "cardId": "$args[0]", "notIn": ["Needs Human"] },
      { "kind": "file-exists", "path": "docs/superpowers/specs/…-design.md" } ]
    "verdict": "approve" },
  { "id": "ingest-discussion", "humanStep": 1, "verdict": "answer",
    "answerText": "<pinned canned takeaway>" } ] }
```

- Condition kinds (enumerated, finite): `job-state {role,state,negate?}`, `report-contains {role,token,negate?}`, `board-column {cardId,in?|notIn?}`, `file-exists {path,negate?}`, `file-contains {path,token,negate?}`; `$args[N]` expands from `target.arguments` at load. Verdicts: `approve | hold | answer` (`answerText` required iff answer).
- The engine decides **verdicts from cell state**, nothing else; the *mechanical act* (git merge, confirm write, inject text) is EV-20's to perform per gateId. Interactive gates get canned `answer` texts because a pure engine cannot converse — the judge criterion then grades the **artifact** (card written, wiki updated), never conversation quality, which is consistent with the smoke philosophy of never trusting prose.
- features-deliver's delivery ruling encodes the smoke MERGE-CHECK precedent as conditions (local gates-re-run attest + judge PASS per child substitute for the absent GH CI) — the fixtures' rubrics likewise never touch `gh`/network, so the "no network-dependent state" acceptance holds by authoring.

**5. Rubric scope (concrete `rubric.json`)**

```jsonc
{ "schemaVersion": 1, "rubricVersion": "1.0.0",
  "criteria": [
    { "id": "c1", "type": "gate", "description": "…", "check": { "kind": "command",
      "argv": ["python3", "council/validate.py"], "expect": { "exitCode": 0, "stdoutContains": "All council artifacts valid" } } },
    { "id": "c2", "type": "gate", "check": { "kind": "artifact", "path": "council/cards/EV-1.md" } },
    { "id": "c3", "type": "gate", "check": { "kind": "file-content", "path": "council/board.md", "contains": "- EV-1 — …" } },
    { "id": "c4", "type": "judge", "description": "…" } ] }
```

- **Depth rule: 1–5 criteria per rubric; ≥1 required (schema).** Check kinds enumerated (`command` with exitCode/stdoutContains expectations, `artifact`, `file-content`, `board-state`) so EV-19's grading stays a finite pure function. **Gate-dominated for procedures** (re-runnable, stable: validate.py clean, `bun test` green, board state, artifact-probe) with 0–1 judge criterion for open-ended quality; **judge-dominated for seats** (exactly 1 judge criterion — success *is* the seat's output per the card — plus 0–1 non-empty gate). Unweighted fraction over a few meaningful criteria beats many fragile ones at n=3 with triage rendering.

**6. Task inventory (16 = 7 + 9) and naming**

Ids: procedures `board-create-card, council, features-deliver, features-new, wiki-ingest, wiki-lint, wiki-query`; seats `consolidator, council-runner, designer, judge, owner, principal, product-owner, skeptic, steward`. No kind prefix — the spaces are disjoint today and a future collision is a loud load-time error (dir name uniqueness). **7 procedure fixtures** — council (mini-project, one Ready EV card, merge-gate policy); features-deliver (epic + children with recorded standing rulings, delivery-ruling policy, smoke EPIC-1 pattern); features-new and board-create-card (confirm-gate canned policies); wiki-ingest (pinned raw source, "discuss first" canned answer, CLAUDE.md-conformance gates); wiki-lint (wiki **seeded with a known orphan + known stale claim** — deterministic defects the lint must surface); wiki-query (wiki with known facts; 1 judge criterion). **9 seat fixtures** — each a crafted turn input and seed where the outcome is observable: skeptic gets a claim about a **planted bug** (judge criterion + its winning probe re-runnable as a gate); judge gets a goal + evidence where the goal is met/not met (expected verdict is a deterministic fact the grading judge cross-checks); owner/council-runner grade on artifacts + gates; the rest judge on output structure.

**Tradeoffs accepted**

1. **Archetype duplication across ~6 seeds** (each heavy fixture owns its mini project). Worth it: per-fixture pinning is the product; sharing couples digests and lets one edit invalidate all pins.
2. **No scaffold seeding of fixture bodies** (spec §3.1's "seeded by the scaffold" read restrictively — card acceptance is the tiebreaker). Scaffold's non-clobber copy would freeze consumers on stale pins after package upgrades; packaged resolution gives fresh-checkout runnability with zero setup. Consumers add/edit via `.pi/council/fixtures/`.
3. **Full-only seeds** — no reuse of caller-checkout content; every fixture owns its complete starting state. Loses overlay convenience, gains cross-consumer determinism, which the acceptance demands.
4. **Shallow rubrics** — coarse scoring steps at 3–5 criteria. Honest at n=3 where EV-21 renders triage anyway; stable across versions.
5. **Canned harness answers** at interactive gates — the fixture exercises the gate mechanically, never conversationally. Acceptable because scoring is artifact-based, and the alternative (LLM-answered gates) breaks A4 purity.

**Testable claims (test/fixtures.test.ts, plus what I'd hand EV-19/EV-20)**

- **C3** — `loadFixture` on a dir whose `fixture.json` exists without `rubric.json` throws naming the file; never returns `[]`.
- **A4** — `applyRulings` is pure: identical policy + identical state → identical verdict, twice, with no I/O; and an exact-decision-table test pins expected verdicts for a fixed policy/state pair so the engine's semantics are frozen.
- **Inventory** — `listFixtureTasks(PKG_ROOT)` returns exactly the 16 ids (7 procedures + 9 seats); every fixture loads clean (digest self-check, schema, rubric present); every `taskId` == dir name; procedure-kinds reference real shipped commands; seat-kinds resolve via `loadSeat`.
- **Determinism (this card's A1 half)** — materialize each seed to a tempdir → recompute digest → equals the pinned `treeDigest`; the full A1 (caller tree byte-identical) is EV-20's per the plan, but the fixture's half of the contract is proven here.
- **No network-dependent state (card acceptance)** — static scan: no `http(s)://` anywhere in fixture.json/rubric.json; no rubric `command` argv references `gh`/`mcp`/`curl`/`wget`; no seed contains `.council.json`/`.pi/council/mcp.json`/`.env` (the same check, inverted, is the loader's refusal test).
- **Shadowing** — repo `.pi/council/fixtures/<task>/` shadows packaged whole-dir (fixture.json + rubric.json + seed from the repo side); `listFixtureTasks` unions both sides; a repo dir missing its own rubric fails loudly rather than falling back to packaged.

**Not settled here** (left to later cards, interfaces pinned only): cell-driver execution mechanism and scratch construction, grading-time gate execution, verdict/result records, leaderboard version grouping — EV-20/EV-21 read the versions the loader stamps.

### Round 1 (step 2) — principal (job-7.2), verbatim

**Cross-seam reading — the contract as it actually is**

**The settled path is `council/fixtures/<task>/`, not `.pi/…`.** Spec §3.4 (`council-eval <task> <model...>` → `council/fixtures/<task>/` → `rubric.json`) and §3.1 ("repo-root consumer data, seeded by the scaffold") name a path that is *not* the convention-5 override dir. Convention 5 as actually implemented uses `.pi/agents/` (seats) and `.pi/council/procedures/` (procedures) — both override-only, neither scaffold-seeded (`proceduresDir` in `seats.ts` just *prefers* the override if the dir exists; `scaffoldInto` never writes `.pi/council/procedures/`). Fixtures are a third category: **consumer data with a shipped default**, like `board.md`/`vault/` (scaffold-seeded, edited in place), *not* a pure override (like procedures). The card Intent's "`.pi/` overrides" is the pre-spec phrasing; the promotion ruling makes the spec authoritative, and §3.1+§3.4 are unambiguous. Reading "convention 5" and stopping at the literal `.pi/` path is the one trap in this card.

**The graderModel grammar is a live cross-card contract, not free text.** `fixture.json`'s `graderModel` is "resolved from the fixture file, never from `.council.json`" (§9) and is passed by the harness as an explicit `model` param that must *beat* `COUNCIL_EVAL_MODEL` (§6.5). That param flows through `resolveEffectiveModel` → `parseQualifiedModel` (`seats.ts`), which throws on an unqualified id. So EV-18's `graderModel` field must be authored in the `provider/id[:thinking]` grammar *today*, or the grader dispatch's precedence chain breaks in EV-20. This is a seam between EV-17 (owns the grammar) and EV-18 (authors data against it) that neither seat sees from inside its slice.

**The harness-as-human is structured policy, not the smoke fixture's prose.** The smoke precedent (`smoke/driver.sh`) hard-codes the merge gate *in bash* and only *persuades* the LLM via an appended delivery-ruling paragraph. Spec §3.3 explicitly overrides that: standing rulings are "machine-applicable structured policy" evaluated by a pure engine, because eval has no human and a deterministic gate can't consult prose (A4 tests purity). EV-18 must move the decision *from* the driver *into* `fixture.json.harnessAsHuman`. The smoke fixture's `seed` shape (plain tree, `cp -R` + `git init -b main` + one commit, driver.sh phase 0a) is the right *seed* precedent; the smoke driver's *ruling* technique is the wrong one and §3.3 says so.

**The rubric content is EV-18; the rubric executor is EV-19; the vocabulary must freeze across the two cards.** Any gate/`kind` string EV-18 authors today must validate under EV-19's `validateRubric`. The seam is the authoring schema, which has one home.

**Reframe**

The card earns one reframe, on the shadowing clause. Stop asking **"where do overrides live?"** (`.pi/` vs `council/`, which is the two-readings deadlock) and ask **"which layer owns a fixture's lifetime?"** A fixture is *consumer data that ships with a default*, not a pure override: the packaged default lives at `<pkg>/council/fixtures/<task>/`, the consumer's seeded copy lives at `<repo>/council/fixtures/<task>/`, and "shadowing" is simply "the consumer's copy wins because it sits first in the resolution order" — identical to `board.md`/`vault/` (seeded, edited in place), extended to hold shipped defaults. That single phrase dissolves the `.pi/`-vs-`council/` ambiguity without reopening §3.4, and it makes the "no fork to add a fixture" guarantee a consequence (drop a dir in `council/fixtures/`, done) rather than a separate mechanism. On every other axis — schema shape, seed representation, engine placement, naming, rubric depth — the proposed design is sound and I'm settling concrete values below, not reframing.

**Concrete design:**

1. **Schema — `fixture.json`** (*new keys → throw, mirrors `seats.ts` strictness*): `id` (must equal dir basename — validate.py's filename==id discipline, extended), `name`, `version` (semver string → `record.fixtureVersion`, spec §8/§6.3), `kind` (`"procedure"|"seat"`), and exactly one of `command` (slash invocation string, e.g. `/council EV-1`) / `input` (seat turn prompt) per `kind`; `repoState.seed` (default `"seed"`); `harnessAsHuman` (structural `{ decision, when, then }` rules for procedures, `{}` for seats); `graderModel` (validated via the existing `parseQualifiedModel` grammar — reuse, don't fork); `rubric` (relative ref, default `"rubric.json"`, validated to exist → C3). **`rubric.json`**: `version` → `record.rubricVersion`, `criteria` = ordered list of `{ id, name, type: "gate"|"judge" }`; gate carries `{ kind, ... }` from a **closed vocabulary** — `gates` (pinned command exits 0), `settled` (dispatch finished done, not stalled), `artifact-present`, `artifact-contains` (pinned path matches pinned regex — the anti-stub criterion, echoing board-create-card's own "name the concrete evidence" doctrine); judge carries `prompt`. EV-18 authors *content*; EV-19 authors *semantics*; the schema + vocabulary home is EV-18's loader, which EV-19 imports.

2. **Seed representation — `seed/` subdirectory, plain files, no git history.** A complete repo tree (smoke-fixture shape: `council/board.md` + `council/cards/`, `vault/wiki/index.md`, `.pi/council/mcp.json`, `.council.json`, task-specific sources). The runner (EV-20) materializes scratch by `cp -R seed/` + `git init -b main` + single commit — exactly driver.sh phase 0a. Justification: the 7 procedures need only `main` + committed files + clean worktree, and the harness *makes* the merge/commit moves via the rulings engine; history-bearing seed states (a pinned commit graph) are a YAGNI extension point — none of the 7 procedures needs one, so I don't bless a `gitBundle` field now. Each task dir carries its own `seed/` copy — no runtime sharing; shared *content* at authoring time across the 9 seat-seeds is fine, shared *objects* is cross-task coupling and violates the §1 cell-invariance contract.

3. **Placement — loader `extensions/eval-fixtures.ts` (`loadFixture(repoRoot, taskId)`, `listFixtureTasks(repoRoot)`, the fixture/rubric authoring-schema validator); rulings engine `extensions/eval-rulings.ts` (`applyRulings(policyBlock, cellState)`, pure).** Engine code lives in `extensions/` (AGENTS.md layout); the data lives in `council/fixtures/`. `loadFixture` is read-only w.r.t. `repoRoot`; `applyRulings` takes only `(policyBlock, cellState)`, no fs, no repoRoot. The *execution* of `then`-actions (merge, set-Done, move-board, commit) is EV-20's runner. Tests import via PKG_ROOT for packaged fixtures + `fs.mkdtempSync` repoRoot (the seats.test.ts pattern).

4. **Shadowing mechanics — `fixtureDirs(repoRoot) = [<repo>/council/fixtures, <pkg>/council/fixtures]`, first dir containing `<task>/` wins** (whole-task-dir shadow, mirroring `seatDirs`/`proceduresDir` first-hit-wins). **Seeding**: `/council-init` runs `scaffoldInto(repoRoot, path.join(PKG_ROOT, "council", "fixtures"))` — the packaged dir *is* the seed source, one copy in the package, non-clobbering so consumer edits survive re-init. Seeding ships on EV-18 (it's one §3.1 clause; splitting it to EV-20 leaves the loader + fixtures half-seeded for a card).

5. **Inventory + naming — 16 task-ids, flat dirs: `proc-<cmd>` ×7 (`proc-board-create-card`, `proc-council`, `proc-features-deliver`, `proc-features-new`, `proc-wiki-ingest`, `proc-wiki-lint`, `proc-wiki-query`) + `seat-<name>` ×9 (`seat-consolidator`, `seat-council-runner`, `seat-designer`, `seat-judge`, `seat-owner`, `seat-principal`, `seat-product-owner`, `seat-skeptic`, `seat-steward`).** The `proc-`/`seat-` prefix prevents a future seat/procedure stem collision and keeps `council-eval seat-skeptic …` self-documenting; matches spec §8's "16-inventory" cost comment.

6. **Rubric scope at EV-18 vs EV-19** — settled above: EV-18 = full per-task criteria *content* + the closing of the authoring schema/vocabulary; EV-19 = `validateRubric` + gate executors + judge-verdict record/replay. One home for the schema (`eval-fixtures.ts`), imported by EV-19 — no drift window.

**Testable claims (spec §10 A1/A4/C3 govern EV-18)**

- **C3** — `loadFixture(repoRoot, taskId)` on a fixture dir whose `rubric.json` is absent/unnamable throws naming the file; never returns `[]`/partial.
- **A4** — `applyRulings(policyBlock, cellState)` is a pure function of its two arguments: declared/tests assert no fs, no repoRoot; 100 invocations on identical `(policy, state)` yield an identical verdict object (deep-equal).
- **A1-adjacent (loader side; full byte-identity is EV-20's runner, honestly)** — loading every shipped fixture leaves `repoRoot` byte-identical before/after; the shipped `seed/` dirs contain no `.pi/git/`, `.pi/npm/`, `node_modules/`, symlinks, or timestamps (plain deterministic trees). The scaffold-seeding test: `scaffoldInto(repoRoot, PKG_ROOT/council/fixtures)` then re-run → second pass `skipped`-only, no clobber.
- **Shadowing** — temp `repoRoot` with `<repo>/council/fixtures/seat-judge/fixture.json` (marker-edited) → `loadFixture` returns repo-local; `loadFixture(repoRoot, "proc-council")` (not overridden) → packaged; `listFixtureTasks` unions both, repo wins on collision.
- **Inventory + schema** — `listFixtureTasks(PKG_ROOT)` equals exactly the 16 ids; for each: `id === dirname`, `version` present, `graderModel` parses via `parseQualifiedModel` (no throw), procedure fixtures have `command`∧no `input` and non-empty `harnessAsHuman`, seat fixtures have `input`∧no `command`.
