## Intent

This is the mechanism that actually addresses the intake. No retry API exists
for the parent's own provider call, so it is built from the `agent_settled`
event plus a continuation send, and it must hold in both the TUI and the
headless branches.

The intake's terminal word is `Continue`, the only affordance between the error
and the person's next action, so the surface is named by ruling rather than
left to the implementer. This card carries the epic's real risk; the Council
should expect it to be split if the continuation path turns out not to be
reachable from a handler.

## Orchestrator rulings (Phase 1, binding)

Recorded human decisions for this run. Immutable and binding on every seat,
`steward` included; a runner that hits one applies it and cites the ruling
rather than re-asking.

- **R5 (retry surface copy).** During backoff the input bar reads
  `Retrying in 2s (attempt 2 of 3) — Esc to abort`, and `Esc` aborts the
  remaining retries. When the budget is exhausted the session stops with
  `Retries exhausted after 3 attempts. The provider kept failing. Press Enter
  to try again.` The per-branch observable for the goal is the input bar's
  text delta in the TUI and the equivalent stdout line in the headless branch.
