## Intent

This is the mechanism that actually addresses the intake. No retry API exists
for the parent's own provider call, so it is built from the `agent_settled`
event plus a continuation send, and it must hold in both the TUI and the
headless branches.

The intake's terminal word is `Continue`, the only affordance between the error
and the person's next action. The card must name what the input bar shows
during the backoff (`Retrying in 2s (attempt 2 of 3) — Esc to abort`) and the
headless branch's stdout line that announces the wait, plus the exhausted-budget
copy shown in both branches. The goal must name that terminal copy verbatim and
the per-branch observable — the input bar's text delta in the TUI, the stdout
line in headless. This card carries the epic's real risk; the Council should
expect it to be split if the continuation path turns out not to be reachable
from a handler.
