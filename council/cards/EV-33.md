## Intent

The transcript parser is the source of the tool-call rendering defect. Its
block shape carries `kind`, `text`, `detail`, `label`, `bytes`, and `at`,
and it discards the JSONL's `toolCallId` and `isError` fields, so a call and
its result become two unrelated flat blocks and no renderer can show which
result belongs to which call or whether it failed. This card restores that
fidelity in `extensions/transcript.ts`.

It also absorbs the duplicated primary-argument derivation. Today
`firstArgOf` in `navigator.ts` ad-hoc parses `detail`, and `activityCopy`
uses it for the tree's `/ran <tool> <arg>` row copy. The transcript header
needs the same summary string. One accessor is the single source of truth;
two derivations is the failure mode this card closes. The tree row copy must
keep passing its existing assertion.

No user-visible surface is owned here; the surface work is EV-34 onward.

## Acceptance

- A fixture with two same-named tool calls whose results arrive out of
  order is parsed so each result pairs with its own call by identity, and a
  positional call[i]→result[i] implementation fails the assertion.
- A failed tool result is distinguishable from a successful one in the
  parsed blocks.
- The primary-argument summary has exactly one production derivation. The legacy ad-hoc `firstArgOf` definition is removed from `navigator.ts`; the accessor lives in `transcript.ts` and is exported. The tree row copy in `navigator.ts` consumes it (the existing `/ran bash` assertion in `test/ev7-council-tree-widget.test.ts` stays green). Adding the second production consumer — at the transcript header — is EV-34's scope per R-COPY.
- `bun test` and `bunx tsc --noEmit` stay green; no render code changes.
