## Intent

The user-visible surface is the inline progress transcript body beneath pi's
input bar, at width 80, reading the blocks the parser produces. Each tool
call and its own result become one rendered unit: a single composed head
line carrying the tool name, the primary argument, and the failure status,
with the result body indented beneath it when the block is expanded. The
collapsed state shows only the composed head. The failed-result token is
`muted "✗"`; `warning` is already the call's token and cannot carry the
failure without losing the distinction.

The existing head lines this replaces are the `warning` call line and the
`muted` result line in `blockLines`. The empty inline-progress state copy
(`(waiting for output…)` / `(no transcript)`) is part of this body and is
worded `(waiting for output · idle)` so a person can tell a still-running
seat from a broken one.

The full-screen modal transcript is out of scope; it is the legacy path
guarded at navigator.ts:57. Depends on EV-33 for call identity and the error
bit; unpaired or legacy blocks must still render without throwing.

## Acceptance

- At width 80, the call unit's header names the tool and its primary

- The collapsed-first / expand-with-`e` behavior asserted today

- A legacy-blocks fixture with no identity fields renders without throwing.
