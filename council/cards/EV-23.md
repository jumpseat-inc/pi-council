## Intent

User-visible surface: the `/council-models` full-screen modal window. The
component reuses `withModalFrame` (`extensions/navigator.ts:91`) and the
`ctx.ui.custom` overlay options (`extensions/navigator.ts:522-538`), drawing
only through `theme.fg`/`theme.bg`/`theme.bold` per AGENTS.md 9.6.

The interaction is a single cascade — a seat list, Enter opens that seat's
providers, Enter opens a provider's models with supported thinking levels,
Enter quotes the resolved selection back for confirmation before the write,
Esc backs up one level. A header line names the surface and a footer line
lists the active keys for the current cascade level, matching the council
tree's render conventions. Every seat row signals current state — the
effective model and thinking in dim tokens, with a distinct marker when the
seat sits at its frontmatter default rather than a `.council.json` override.

Three empty states are first-class display states with committed copy, not
blank panels — no providers configured, a provider with no models, and a
seat with no override — because the modal opens in fresh clones and headless
environments where the catalogue is plausibly empty.

## Acceptance

- Source-audit tests on the modal source (the `theme-compliance.test.ts`
  pattern) assert no literal hex and no foreign ANSI outside theme tokens.
- Output tests assert every color-bearing ANSI sequence in render output
  matches the theme's own palette — the modal's color is the theme's, not
  zero-ANSI.
- Key-handling tests cover the cascade navigation and the echo-then-run
  confirmation — the pre-confirmation action quotes the selection and does
  not write; the confirmation commits.
- All three empty states render their committed copy.

## Phase 1 rulings (features-deliver, binding for this run)

- **R-1 (header copy)**: the modal's header line, bold, reads
  `council models — pick a model per seat`.
- **R-2 (footer copy)**: the footer lists the keys active at the current
  cascade level — `↑/↓ move · enter open · esc back` at the seat and
  provider levels, `↑/↓ move · enter select · esc back` at the model
  level, `enter confirm · esc back` at the confirm level.
- **R-3 (seat-row markers)**: a seat with an override renders a dim
  suffix `— using <provider>/<id>[:thinking] (override)`; a seat at its
  frontmatter default renders a dim suffix `— frontmatter default`.
- **R-4 (empty states)**: with no providers configured the modal reads
  `No providers configured — authenticate a provider in pi, then reopen
  /council-models.`; a provider with no models reads `No models available
  for <provider>.`; the third recorded state (a seat with no override)
  renders as R-3's frontmatter-default marker, not an empty panel.

These are recorded human decisions — immutable for the run and binding on
every seat, `steward` included. Any change to the ruled wording routes
through the orchestrator as an escalation.
