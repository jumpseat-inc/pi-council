## Intent

User-visible surface: the `/council-models` full-screen modal window. The
component reuses `withModalFrame` (`extensions/navigator.ts:91`) and the
`ctx.ui.custom` overlay options (`extensions/navigator.ts:522-538`), drawing
only through `theme.fg`/`theme.bg`/`theme.bold` per AGENTS.md 9.6.

The interaction is a single cascade — a seat list, Enter opens that seat's
providers, Enter opens a provider's models with supported thinking levels,
Enter quotes the resolved selection back for confirmation before the write,
Esc backs up one level. A header line names the surface and a footer line
lists the active keys for the current cascade level, matching the council
tree's render conventions. Every seat row signals current state — the
effective model and thinking in dim tokens, with a distinct marker when the
seat sits at its frontmatter default rather than a `.council.json` override.

Three empty states are first-class display states with committed copy, not
blank panels — no providers configured, a provider with no models, and a
seat with no override — because the modal opens in fresh clones and headless
environments where the catalogue is plausibly empty.

## Acceptance

- Source-audit tests on the modal source (the `theme-compliance.test.ts`
  pattern) assert no literal hex and no foreign ANSI outside theme tokens.
- Output tests assert every color-bearing ANSI sequence in render output
  matches the theme's own palette — the modal's color is the theme's, not
  zero-ANSI.
- Key-handling tests cover the cascade navigation and the echo-then-run
  confirmation — the pre-confirmation action quotes the selection and does
  not write; the confirmation commits.
- All three empty states render their committed copy.

## Phase 1 rulings (features-deliver, binding for this run)

- **R-1 (header copy)**: the modal's header line, bold, reads
  `council models — pick a model per seat`.
- **R-2 (footer copy)**: the footer lists the keys active at the current
  cascade level — `↑/↓ move · enter open · esc back` at the seat and
  provider levels, `↑/↓ move · enter select · esc back` at the model
  level, `enter confirm · esc back` at the confirm level.
- **R-3 (seat-row markers)**: a seat with an override renders a dim
  suffix `— using <provider>/<id>[:thinking] (override)`; a seat at its
  frontmatter default renders a dim suffix `— frontmatter default`.
- **R-4 (empty states)**: with no providers configured the modal reads
  `No providers configured — authenticate a provider in pi, then reopen
  /council-models.`; a provider with no models reads `No models available
  for <provider>.`; the third recorded state (a seat with no override)
  renders as R-3's frontmatter-default marker, not an empty panel.

These are recorded human decisions — immutable for the run and binding on
every seat, `steward` included. Any change to the ruled wording routes
through the orchestrator as an escalation.

## Engineering position — EV-23 modal picker

### 1. Shape: a pure content `Component` plus a resolution function, zero I/O

New file **`extensions/model-picker.ts`**. It exports:

- `export type ModelSelection = { seat: string; provider: string; id: string; qualifiedId: string; thinking?: string }` — a plain, serializable, frozen object whose fields are exactly `writeSeatOverride`'s args (`seat`, `model` = `qualifiedId`, `thinking`) (`council-config-writer.ts` signature), so EV-25 can mock the picker "at its selection-encoding contract" (`council/cards/EV-25.md` acceptance) without importing the component.
- `class ModelPicker implements Component` with constructor `(catalogue: ResolverResult, theme: NavTheme, onConfirm: (sel: ModelSelection) => void, onClose: () => void, opts?: { maxRows?: number })`. `render(width)`, `handleInput(data)`, `invalidate()` — the same surface `CouncilTree` exposes (`navigator.ts`).
- Pure, unit-test-target helpers: `seatMarker(state: SeatState): string` (R-3), `footerFor(level: Level): string` (R-2), `resolveSelection(): ModelSelection` (single resolution function used by **both** the confirm echo and the commit — this is how echo==write is guaranteed), and `HEADER`/`EMPTY_*`/`FOOTER_*` constants carrying the ruled copy verbatim.

**Zero I/O by construction**: the modal takes no `repoRoot`, touches no fs, and never calls `writeSeatOverride`. "Confirm commits" means `onConfirm(sel)` fires exactly once; EV-25's opener owns the write (per EV-25's wiring). The modal returns **content lines** from `render(width)`; the EV-25 opener applies `withModalFrame(theme, w, termRows, content, { maxPanelHeight: termRows - 2 })` at `Math.min(96, Math.max(1, w-8))` using `ctx.ui.custom` with `overlay: true, overlayOptions: { width: "100%", maxHeight: "100%", margin: 0, anchor: "top-left" }` — byte-for-byte the `openTranscript` pattern (`navigator.ts:88-118`, `navigator.ts:522-538`). This keeps the component framable and unit-testable exactly like `CouncilTree`, while satisfying "reuses `withModalFrame`".

### 2. The cascade: four levels, one cursor rule, branch rows only for multi-level models

Levels `seat → provider → model → confirm`, per the card. Every level clamps its cursor with `Math.max/Math.min` — **no wrap-around**, matching `CouncilTree` (`navigator.ts`). Enter descends, Esc ascends one level; Esc at the seat level closes (`onClose()`, mirroring the tree's Esc). Entering a level resets that level's cursor to 0. After a confirm-Enter the picker sets a `settled` flag and ignores all further input (teardown races can't double-emit).

**Thinking is folded into the model level** — R-2 allots exactly four footers, so thinking selection cannot be a fifth level. The model level is a single linear list computed per focus:

- model with `supportedThinkingLevels.length ≥ 2` → a **branch row** (`▸ <id>`); Enter descends into its level child-rows (the levels in resolver order, no re-sort). Enter on a level row selects `(model, level)` → confirm. Esc at a child row returns to the model rows.
- length `=== 1` → Enter selects with `thinking = levels[0]` — the modal's only supported level *is* its offered thinking; the echo shows the `:level` suffix so it is transparent and cancellable.
- length `=== 0` → `thinking` is `undefined`; the modal passes `thinking: undefined` to the writer call. EV-24's documented merge semantics then apply: an absent `thinking` **preserves** the seat's existing level (`council-config-writer.ts` merge block). The modal's contract is the *writer call*, not the file postcondition, so the echo omitting the suffix is byte-truthful at the call boundary.

That is the entire thinking rule — deterministic, three cases, each falsifiable.

**Confirm screen**: one accent line `Set <seat> to <provider>/<id>[:thinking]` (suffix only when defined) + one dim line `Writes <COUNCIL_CONFIG_FILE> — takes effect at the next dispatch.` — file name via the `COUNCIL_CONFIG_FILE` constant (`seats.ts`), never a literal, per AGENTS.md convention 3. The second line is unruled copy but it is what makes echo-then-run a forcing function (the EV-20 "echo as forcing function" precedent, `vault/raw/2026-09-04-design-ev20*`); it mirrors EV-25's R-3 language pre-write.

### 3. Ruled copy applied exactly

- Header (R-1): `theme.bold("council models — pick a model per seat")` — the tree's bold-header convention.
- Footers (R-2), dim: seat & provider `↑/↓ move · enter open · esc back`; model `↑/↓ move · enter select · esc back`; confirm `enter confirm · esc back`. (The branch-row descend inside the model level keeps the model footer — R-2's four footers stay exhaustive.)
- Seat rows (R-3): selected row prefixed `theme.fg("accent", "> ")` (the `CouncilTree` modal's cursor convention); then the name; then dim suffix `— using ${currentModel}${currentThinking ? ":" + currentThinking : ""} (override)` or `— frontmatter default`. `currentModel` is already the qualified `provider/id` from `resolveCatalogue` — no re-qualification in the modal.
- Empty states (R-4): no-providers → the whole body is the exact sentence, dim; provider-with-no-models → `No models available for <provider>.` (I use `displayName`, the same label the provider list shows — flipped to the raw `provider` id at zero cost, the sentence shape is unchanged); seat-without-override → the R-3 marker, never an empty panel.

### 4. Rendering & compliance mechanics

- Selected rows, dim suffixes, branch rows, empty-state lines, and the confirm echo are the only color-bearing draws: tokens `accent`, `dim`, `bold`, and (chosen deliberately) nothing else. Frame chrome uses `border`/`customMessageBg` inside `withModalFrame` as today.
- **Render cache is a (width, signature) pair** — signature = `level:cursors:top` — invalidated on every mutation, mirroring the `CouncilTree`/widget memoization. Critical corollary: EV-25 must call `invalidate()` on theme change; the council-theme wiki's EV-4 lesson is that memoized output goes stale mid-session on recolor and "a half-painted surface worse than none" (`vault/wiki/council-theme.md`). The modal inherits the `onThemeChange → picker.invalidate()` wiring.
- Windowed scrolling copied from `CouncilTree`: when rows exceed `maxRows`, window around the selection (`start = max(0, min(selected - floor((maxRows-1)/2), len - maxRows))`).
- No sorting anywhere in the modal: J-1 ordering is the resolver's sole property (`catalogue.ts` comparator comments); the modal renders resolver order verbatim.

### Round 1 — principal (verbatim)

## Cross-seam reading

EV-23 sits between two already-shipped modules and one about-to-be-wired command, and all three contracts are now concrete in code:

**What it consumes (EV-22, `extensions/catalogue.ts`).** `resolveCatalogue` returns `{ providers: ProviderGroup[], seats: SeatState[] }`. `ModelEntry.qualifiedId` (`${provider}/${id}`) is documented as "the selection/write key" (`catalogue.ts:20`); `supportedThinkingLevels` is "the sole capability authority, never a hand-rolled level set" (`catalogue.ts:24, 65`); `reasoning` is "passthrough; NOT consumer-contract" (`catalogue.ts:23`). `SeatState` carries `hasOverride`, `currentModel` (always qualified), `currentThinking?` (`catalogue.ts:39-43`). Two structural facts the modal must render against: (a) the resolver **never emits a `ProviderGroup` with `models: []`** — a ghost provider in the display map produces *no group* (`catalogue.ts` test: `byName.has("ghost") === false`), so R-4's second empty state ("a provider with no models") is a **render-contract-only input**, reachable in tests/mocks, never from the real resolver; (b) `seats[i].currentModel`/`currentThinking` are populated for **both** `hasOverride` branches — the frontmatter value is still in `currentModel` when `hasOverride === false`, so R-3's "frontmatter default" marker is a *suppression* decision, not an absence of data.

**What it hands to (EV-24, `extensions/council-config-writer.ts`).** `writeSeatOverride({repoRoot, seat, model, thinking?, catalogue})` validates: `model` must parse as qualified `provider/id` AND be in the catalogue `qualifiedId` set; `thinking` (when present) must be in `THINKING_LEVELS`; and there is **deliberately no per-model capability check** (`council-config-writer.ts:24-35`). Absent `thinking` **preserves** the existing value (field-level merge). So the modal's only obligations to the writer are: emit `model` as the `qualifiedId` verbatim (never a bare id, never re-derived from `provider`+`id` — the writer's `parseQualifiedModel` rejects unqualified values), and emit `thinking` only when the user actually chose a level. The capability bound is the *modal's* job, not the writer's (settled in EV-24's deliberation: "capability YES in picker, NO in writer").

**How EV-25 will invoke it.** `ctx.ui.custom<T>(factory, opts)` is generic and `done(result: T)` carries the object **un-serialized** (`pi dist/core/extensions/types.d.ts`, `custom<T>`: `done: (result: T) => void`, returns `Promise<T>`). The navigator already uses `ctx.ui.custom<string | null>` (`navigator.ts:522`). So the selection-encoding is a **named object type flowing through `done`**, not a JSON string — there is no hidden serialization seam, and EV-25's "mock the modal at its selection-encoding contract" is literally "stub the open-wrapper with a function returning `SeatModelSelection | null`."

## Blind spots

- **The resolver/data vantage (EV-22 owner) cannot see** that its "ghost provider → no group" decision orphans R-4's second empty state — the modal still has to render `No models available for <provider>.` from an input shape the resolver will never hand it, so that state must be a pure function of the input `models: []` array and must *not* trigger a resolver change. Nor can it see that R-3 requires the modal to *hide* `currentModel`/`currentThinking` it computed and shipped, in the `hasOverride === false` branch.
- **The writer vantage (EV-24 owner) cannot see** that its "absent thinking preserves existing" merge composes badly with a model whose `supportedThinkingLevels` is `[]` (all-nulled) or `["off"]`: a user who changes a seat to a `[]` model and picks no level silently preserves a thinking level the new model may not support (pi clamps at spawn). The writer accepts this by contract; the *modal* is the only place that can show it — the confirm echo must quote the **effective post-merge** thinking, not a blank. And it cannot see that its `parseQualifiedModel` rejection is why the modal must pass `qualifiedId` byte-verbatim.
- **The surface/command vantage (EV-23/EV-25 owners) cannot see** two things from inside the render path: (1) the ruled footers admit only `↑/↓/enter/esc` — there is no fifth "thinking level" navigation state, so the thinking affordance must live *inside* the model level without advertising any key the ruled copy doesn't name; (2) the `providers` list is **repo-wide**, not per-seat — the card's "opens that seat's providers" is loose wording, and the modal's state machine must scope only the *seat* (fixed at step 1) while provider/model lists are the shared resolver arrays, never a per-seat catalogue that doesn't exist.

## Reframe

The design is sound in its bones (pure resolver, capability data bounded at selection, writer strict only where dispatch is strict). No deep reframe — four contract pin-downs make it slot cleanly:

1. **Name and export the selection-encoding type, and make it the single `done` payload.** `interface SeatModelSelection { seat: string; model: string /* = ModelEntry.qualifiedId, verbatim */; thinking?: string }`; the modal resolves `ctx.ui.custom<SeatModelSelection | null>` and calls `done(selection)` on confirm, `done(null)` on close. `thinking` is present iff the selected model's `supportedThinkingLevels` is non-empty and the user picked one; it is always a member of that array. This is the exact type EV-25 mocks and the exact tuple EV-24 consumes — no JSON layer, no re-derivation.

2. **The modal is a pure view; the write and the registry read live in EV-25.** The modal holds no `repoRoot`, no `catalogue`, no `writeSeatOverride`, no registry reference — it renders resolver data + `theme` and emits a selection. EV-25 performs the single `writeSeatOverride` using the *same* flat catalogue array it handed to `resolveCatalogue` (extending EV-22's one-snapshot rule: the modal must never trigger a second `getAvailable()`). This is what makes EV-25's mock-at-contract meaningful — if the modal wrote, the mock couldn't separate the view from the write.

3. **The thinking affordance = exactly `supportedThinkingLevels`, in array order, encoded within the model level.** `[]` ⇒ the model renders as selectable with no sub-level, selection omits `thinking`; `["off"]` ⇒ "off" is the single selectable level that writes `thinking:"off"` (uniform rule: the affordance lists the array verbatim; only `[]` omits). `reasoning` and `thinkingLevelMap` are never read. Whatever the owner picks for the key shape (cross-product rows vs. a level cursor), it must be navigable with only the ruled keys and must leave the emitted `thinking` inside the selected model's set — that is the runnable constraint, not the widget choice.

4. **R-3 markers and the echo are functions of `hasOverride` and post-merge effective state, not of value presence.** Seat row: `hasOverride` → `— using <currentModel>[:<currentThinking>] (override)`; else → `— frontmatter default` with the model id suppressed. Confirm echo: seat + `qualifiedId` verbatim (the write key — `displayName`/`name` are decoration only) + effective thinking = picked level, else "preserved `<currentThinking>`", else none. Seat-without-override is the R-3 default marker, never an empty panel.

## Testable claims

1. **Selection round-trip:** for every `(ProviderGroup, ModelEntry, level)` triple the modal can emit, feeding `{seat, model: qualifiedId, thinking: level}` to `writeSeatOverride` (with the resolver's own model array as `catalogue`) returns `{ok:true}`; and the modal's model-level render offers exactly `supportedThinkingLevels` — a deepseek-style holey model offers `["off","minimal","low","medium","high"]` with no `xhigh`/`max`, so no selection path can hand the writer a capability-invalid `thinking`. (Falsifies any affordance that re-derives levels or consults `reasoning`.)
2. **Qualified-id verbatim:** the emitted `model` field is byte-identical to some `ModelEntry.qualifiedId`, never the bare `id`, never `provider + "/" + id` recomposed — assert on a provider whose `id` contains a `/` (`openrouter/deepseek/deepseek-v4-pro-0813`), where bare-`id` would accidentally look qualified but is not in the catalogue set.
3. **Empty-state non-conflation (three distinct assertions):** `providers: []` renders the no-providers copy; a `ProviderGroup{models: []}` renders exactly `No models available for <provider>.`; a `ModelEntry{supportedThinkingLevels: []}` renders a *selectable model row* (never skipped, never folded into the provider-empty copy) whose selection omits `thinking`.
4. **R-3 honesty:** seat with `hasOverride:false` + non-empty `currentModel` renders a row whose text contains `frontmatter default` and does **not** contain that model id; `hasOverride:true` renders `using <model>[:thinking] (override)`. Keyed off `hasOverride`, not off `currentThinking` presence.
5. **Echo-under-merge:** modal opened with a seat whose `currentThinking` is `"high"`; user selects a `[]` model and confirms → the confirm line names the effective thinking (`high`, preserved) or an explicit "no thinking" marker, and the subsequently emitted selection has `thinking` absent so `writeSeatOverride` preserves `high` — the echo text must match the post-write effective value, never a blank.
6. **No-side-effect boundary:** the modal module's source contains no `writeSeatOverride`, no `resolveCatalogue`, no `getAvailable`, no `repoRoot`/`fs` import — its only output is `done(selection|null)`. EV-25's test then stubs the open-wrapper to return a canned `SeatModelSelection` and asserts `writeSeatOverride` is called exactly once with those fields.
7. **Ruled-copy byte-exact + theme-only:** header, the four footers, the R-3 suffix strings, and the three empty-state strings appear byte-identically (including the en-dash in the header and em-dashes in the markers); no footer advertises a key beyond `↑/↓`, `enter`, `esc`; and the render output's color-ANSI set is a subset of the theme's own `fg`/`bg` ANSI (the existing `colorAnsi` harness), with the source carrying no literal hex or `\x1b`.

### Round 1 — designer (verbatim)

## Design position

**The picker is a single-focus token-only modal that teaches via the cascade itself, with the confirm screen being the only place a write is possible.** Navigation follows one direction (↓/↑/Enter/Esc) and one vocabulary that is already in muscle memory from `/council-tree`: U+258C ▌ left-edge marker in `theme.fg("accent", …)` for the active row, ↑/↓ to move, Enter to descend or commit, Esc to ascend one level. The cascade is not three separate screens bolted together; it is one `level: 'seats' | 'providers' | 'models' | 'confirm'` state in the same `ctx.ui.custom` overlay, re-rendered through the same `withModalFrame`. This makes the seat list feel like the start of a conversation, not the front of a wizard — the header (R-1) and the level-specific footer (R-2) re-render every keystroke, so the same screen always tells the person where they are and what their keys do *now*. The confirm step (R-2 footer `enter confirm · esc back`) is the load-bearing piece of teaching: it quotes the resolved `<provider>/<id>[:thinking]` selection as a single bold line and waits for a second Enter before the writer card (EV-25) is called. That is the *forcing function* that closes the Gulf of Execution for a costly, slightly-load-bearing, easily-fat-fingered write — the modal will not write a single byte until the person has seen and acknowledged the exact string the file will gain.

The two rows of affordance that matter most are the seat-list markers (R-3) and the empty states (R-4), because the picker opens most often in *the wrong moment*: the person has just noticed a seat behaving badly or has just installed a provider and wants to verify. The seat row has to answer two questions in one glance — *who is this seat?* and *is it on the default?* — and R-3 already does that with the `— using <provider>/<id>[:thinking] (override)` vs `— frontmatter default` suffixes in `theme.fg("dim", …)`. Crucially, R-4 rules the seat-without-override case as a marker, not a panel — so the seat list always renders N rows for N seats, no exceptions, no surprises about *why a seat is missing*. A first-time visitor lands in a list of nine dim-suffixed `frontmatter default` rows and immediately knows the override surface is alive and inert.

For the catalogue levels, I argue the provider row reads `provider (N models)` in normal fg and the model row reads `<name> · <id>` with the supported thinking levels (`getSupportedThinkingLevels` from EV-22) shown on the *next line* under the cursor in dim. That second line is what closes the Gulf of Evaluation for the most common mistake: assuming a non-reasoning model accepts a `:thinking` suffix. The thinking-level list is rendered from the catalogue's authoritative set (never hand-derived), and a model with no supported levels shows `no thinking levels` so the picker never silently drops a `:thinking` decision the catalogue already knows is invalid.

## (c) Echo-under-merge — adopt principal, refine

The seam bug principal discovered is precise and I can reproduce it from code:

`existingThinking` at `council-config-writer.ts:200-216` reads **either** a string shorthand (`"openrouter/x:low"` → `low` via `lastIndexOf(":")` + `THINKING_LEVELS.has(...)`) **or** an object's `.thinking` key. It never reads a `:suffix` from an *object-form* model's `model` field. So a config of `{"model":"openrouter/x:low"}` — model string contains a `:suffix`, no `thinking` key — loads correctly via `applySeatOverride` (`seats.ts:412-422` does parse the model's suffix), but `existingThinking` returns `undefined`.

If the modal's `currentThinking` (resolved via `applySeatOverride`) is `"low"` for that seat and the user picks a level-less model and confirms, the modal writes `selection.thinking = undefined`, then the writer's merge logic (`council-config-writer.ts:319-323`) calls `existingThinking(parsedDoc, seat)`, gets `undefined`, and emits `{"model":"<new qualified>"}` with **no `thinking` key**. **Post-write the file loses `low`.** pi at spawn falls through to frontmatter. The user has just written an override that *silently changed* their seat's thinking. That is the seam bug — it is real, it is observable, and it routes to EV-24 (the writer owns `existingThinking`).

**EV-23 owns the echo, not the fix.** The modal must not assert a preserved level it cannot compute from current input alone; `currentThinking` is sufficient as a *display* fact (R-3 renders it; that's already settled), but the echo language must not become a claim of post-write state that the writer seam cannot guarantee.

**Between owner's three-case and principal's two-case, principal's wins because owner's "preserved" branch quotes `currentThinking` verbatim — and `currentThinking === post-write thinking` is *false* exactly when the seam bug triggers.** A user who sees `Set <seat> to openrouter/y — keeps thinking low` and then watches their post-write seat row tip back to `frontmatter default` (because the writer's merge silently dropped `low`) will lose trust in the picker's echo for a reason the picker cannot see. The picker cannot fix EV-24's seam; the picker can refuse to assert what EV-24's seam cannot guarantee.

**Owner holds "the writer is replace-preserve / insert-frontmatter / greenfield-frontmatter — currentThinking always equals post-write effective."** That is correct for the *current* writer code on configurations where `existingThinking` *works*. The modal earns this by including `[:level]` *exactly when* the user picked one — same rule as the model-row text (cross-product). Echo = row text by construction; no separate reasoning needed.

### Round 3 — designer (verbatim; final)

# Designer — Round 3 (FINAL)

## Design position

The picker is a single-focus token-only modal: active row prefixed `> ` in `theme.fg("accent", …)` (modal precedent, `navigator.ts:206`); model level is a flat cross-product over `(model, level)` in resolver order so R-2's `enter select` is literally true on every row; confirm echo is a two-case non-assertive form — `Set <seat> to <provider>/<id>:<level>` when a level was picked, `Set <seat> to <provider>/<id> — thinking unchanged` when it wasn't. `SeatModelSelection.thinking` is present iff the cross-product row carries `:level`. R-1..R-4 are binding and untouched.

## Gulf closed

- **Execution — "which `(model, level)` am I picking?"** The cross-product row's *rendered text* is the resolved string; the cursor sits on the decision. No descend, no separate display-only affordance, no fifth key. R-2's four footers stay exhaustive and `enter select` is true by construction.
- **Execution — "what will land on disk?"** Confirm echo is byte-equal to the row text (`Set <seat> to ` prepended); the dim second line names the file constant `COUNCIL_CONFIG_FILE` and the timing ("takes effect at the next dispatch"), making the second Enter the only write trigger.
- **Evaluation — "did the override stick?"** EV-25 (out of scope here) re-renders the seat list post-write; the picker's own surface does not need to refresh.
- **Evaluation — "did I change my seat's thinking without meaning to?"** Echo is non-assertive in the no-level case (`thinking unchanged`), so the picker cannot tell the user a falsehood that the writer's seam cannot guarantee (see seam-bug routing below).

## Principle and evidence

- **Marker glyph — `> ` accent.** The modal precedent is `CouncilTree.render()` at `extensions/navigator.ts:206` — `idx === this.selected ? this.theme.fg("accent", \`> ${row}\`) : \`  ${row}\``. `TREE_ROW_MARKER = "\u258C"` (`extensions/focus-nav.ts:37`) is a tree-focus/inline-widget constant gated on `controller?.surface === "tree"` (`navigator.ts:429-430`), paired with `TREE_MODE_LABEL = "-- TREE --"` and `tab`-driven focus handoff. The modal has none of that grammar — no editor binding, no mode label, no `tab` — so `▌` would import a cross-surface signifier that loses its meaning at the import. Inside `withModalFrame`, only `> ` is precedent. Modal source must not import `focus-nav.ts`.
- **Thinking — cross-product rows in resolver order.** A model with `supportedThinkingLevels.length === 0` produces one row, no `:thinking` suffix; `length === 1` produces one row with `:levels[0]`; `length >= 2` produces `1 + length` rows (one without `:thinking`, one per level in array order). Ordering is `displayName asc, provider id` then `name ?? id asc` (EV-22 settled), and inside a model the levels appear in `supportedThinkingLevels` array order — the catalogue's own authority, never hand-ranked. The modal does not import `THINKING_LEVELS`, `parseQualifiedModel`, or `applySeatOverride`.
- **Echo — two-case, non-assertive.** Picked → `Set <seat> to <provider>/<id>:<level>` (verbatim `qualifiedId`). Omitted → `Set <seat> to <provider>/<id> — thinking unchanged` (em-dash with spaces, R-3 punctuation). The picker asserts only what it did at this screen; whether the writer preserves, drops, or clamps the prior level is the writer's contract.
- **Type contract.** `SeatModelSelection { seat: string; model: string /* = ModelEntry.qualifiedId, verbatim */; thinking?: string }` is the single `done()` payload (`ctx.ui.custom<SeatModelSelection|null>` per `navigator.ts:522`). The modal holds no `repoRoot`, no `writeSeatOverride`, no `fs`. EV-25 mocks the open-wrapper returning a canned `SeatModelSelection` and calls `writeSeatOverride` directly.
- **Forcing function — confirm step.** The modal's only path to a write is `onConfirm(sel)` firing exactly once from the `confirm` level after a second Enter; Esc at confirm returns to `models` and `settled` guarantees no double-fire on a second Enter.
- **Token-only drawing.** Every color-bearing draw uses `theme.fg` / `theme.bg` / `theme.bold`. Source audit (`test/theme-compliance.test.ts` pattern) asserts no `\x1b` and no `#[0-9a-fA-F]{3,8}` outside comments/imports; palette test (`colorAnsi` harness, `test/theme-compliance.test.ts:77-89`) asserts every emitted ANSI is in the materialized dark theme's own `fg`/`bg` sets, and at least one such sequence is emitted.
- **Empty states — first-class copy.** R-4's three sentences render byte-exact in the body; header + footer suppressed only when no rows render. R-4#2 (`No models available for <displayName>.`) is render-contract-only input: `resolveCatalogue` cannot produce a `ProviderGroup` with `models: []` (groups are built only from present models, `extensions/catalogue.ts`), so the sentence is reachable from hand-built fixtures in tests and from a future mock — never from the real resolver.

## Why owner's remaining basis does not stand

- **▌ collapses on the import graph, not on taste.** `TREE_ROW_MARKER` (`focus-nav.ts:37`) is gated on `controller?.surface === "tree"` (`navigator.ts:427-430`), is rendered alongside `TREE_MODE_LABEL` in the editor's last line, and is paired with `tab` switching surfaces. That grammar is the marker's *meaning*. The modal has no editor, no mode label, no `tab`, and no controller — importing the codepoint strips the meaning while leaving the glyph. The modal convention is `navigator.ts:206`'s `> ` accent, used today by `CouncilTree.render()` in the only modal-with-row-selection this codebase ships.
- **Branch-rows collapse on R-2.** R-2 rules the model-level footer as `↑/↓ move · enter select · esc back` — binding and immutable. Enter on a `▸ <id>` branch row *descends*, which makes `enter select` false on those rows; the picker would need a fifth footer to keep its key vocabulary honest. Branch-rows cannot exist inside R-2's key contract.
- **Branch-rows collapse on the selection-mechanism problem they were meant to solve.** Owner's argument is that a display-only peek line cannot close the Gulf of Execution for "which level am I picking." That is right — but the cross-product is the *selection* affordance the peek was missing. The level list is the cursor list; the displayed level list *is* the choice.
- **Three-case echo with `— keeps thinking <currentThinking>` collapses on the writer seam.** `existingThinking` at `council-config-writer.ts:200-216` parses a string-shorthand `:suffix` *or* an object's `.thinking` key — it never reads a `:suffix` from an object-form `model` string. A config of `{"model":"openrouter/x:low"}` loads correctly via `applySeatOverride` (`seats.ts:407-422`) but `existingThinking` returns `undefined` for it. So `currentThinking` does not equal the writer's `existingThinking` value on every reachable file shape. Owner's "preserves thinking <level>" echo would assert `currentThinking` as the post-write effective — a true claim for the common cases the writer handles, a false claim for the object-`:suffix` edge it does not. "thinking unchanged" is the honest middle.

## J-2 — model-level row shape for ≥2-level models

**Ruling:** `N` rows for an `N`-level model (no level-less row). A ≥2-level model produces exactly one row per level, in array order, with `:level` suffix on every row. The `[]` model remains a single level-less row (no `:suffix`, omitted `thinking`). The `["off"]` model remains a single row with `:off`. Echo = row text by construction, with `thinking unchanged` only for the `[]` row.

A level-less row on a multi-level model is the silent-no-thinking decision the forcing function exists to prevent — a user lands on `<provider>/<id>` with no suffix on a model that clearly has levels, presses Enter, and the picker writes a selection with no thinking on a model that has a thinking affordance. The cross-product without the level-less row closes that gap: the cursor row *is* the thinking decision. Every multi-level row carries the level the user picked in the same bytes as the confirm echo; `enter select` is literally true, R-2 holds, and the only place `— thinking unchanged` ever appears is the `[]` case (Skeptic O-2: `reasoning:false` → `["off"]`; `[]` is essentially unreachable from real data; max 5 levels per model, so at most 5 rows — bounded, already windowed). Rejected: `1 + length` rows (the bare row invites the exact silent drop the forcing function exists to prevent; symmetry-with-`[]` is a column-alignment argument, not a forcing-function argument — `[]` and `["off"]` already differ in suffix, so cross-product row-count asymmetry by model capability already exists); branch rows (withdrawn in round 3 on R-2 grounds — the bound footer makes branch-rows a lie on half the model rows). Reversibility: one-line change to the row-building helper with a single cross-product test asserting exact row count and order; re-running the modal test suite flips it back.
