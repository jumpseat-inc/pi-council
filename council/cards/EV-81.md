## Intent

The follow-up decision is not worth shipping without a safe failure. This card
reuses the card gate's pinned model, endpoint, and fail-closed transport, and
pins the failure posture at the module boundary: any refusal, timeout, non-2xx,
unparseable body, or unresolved credential records a `gate call failed:` basis
and falls back to the human confirm gate — never dropping a candidate, never
auto-merging one, never writing before confirmation.

## Acceptance

- The call uses `GATE_PINNED_MODEL` and `GATE_ENDPOINT` (never a
  chat/completions path) — one pin, one endpoint, asserted by a test importing
  the constants rather than re-declaring literals.
- An unreachable-endpoint fixture asserts the posture at the module boundary —
  the recorded `gate call failed: <reason>` basis, exactly zero `Drop`
  dispositions, no automatic `Merge`, and the human-confirm fallback — all
  provable offline today; the end-to-end "reaches step 13" arm belongs to
  EV-84's third arm.
- No pathology of the call produces an automatic `Merge` or any write before
  confirmation.
- Availability/credential resolution reuses the resolver the run-start
  preflight already uses; under `gate.mode` on with no credential the run fails
  loud at run start exactly as the card gate does (the FLLWUP-89–92 class, not
  a fork).
- The repo's typecheck, the full test suite, `python3 council/validate.py`, and
  the repo's preflight pass.

### Round 1 — principal (first pass, job-9.2)

**Contract reading.** `runGate` is a card-domain orchestrator (guards → credential →
wire shaping → one transport call → failRun or light parse → decide() → one
appendGateCall); "reuse the transport" is satisfied by importing the transport seam;
the ORCHESTRATION is what EV-81 mirrors and is not exported as reusable pieces.
`decisionLine` is generic over `{resolvedMode, basis}` → renders `Mode: <disposition> —
<basis>` for EV-82 unchanged. `FollowupState.drops` already pinned assignable to
`GateDropRecord[]`.

**Load-bearing points the card does not spell out:**
1. **The fail-safe target differs from runGate's — failure decision must be a LITERAL
   `{disposition:"File"}`, never routed through decideFollowup, never touching
   MODE_PANELS.** "Zero Drop, no automatic Merge" only holds if the failure constructor
   is File by construction. (Agrees with owner's literal-File pick.)
2. **`failure.kind` must ride the RETURNED result, not only the basis.** EV-82's
   unavailable-state bullet lists `gate call failed: <reason>` AND `credential
   unresolved` as distinct literals; with only a `FollowupDecision` EV-82 would have to
   string-match the basis. Export `FollowupRunResult { status, decision, callId,
   failure?:{kind,reason} }` mirroring `GateRunResult`; EV-83's `ESCALATION` needs the
   same kind+reason.
3. **The ledger line's `policyVersion` semantics are already broken in the shipped card
   gate; EV-81 must not inherit the bug.** `runGate` writes `policyVersion:
   policy.policyVersion` ("gate-policy-1") but `resolveRoute` validates
   `record.policyVersion !== decisionPolicy.version` ("gate-decision-1",
   gate-route.ts:219) — on real data the two never match, so every live card-gate line
   is classified as policy drift and routes full Deliberate; the recorded-decision fast
   path EV-69 exists to provide is dead. Tests miss it because `appendRecorded`
   fabricates lines with `decisionPolicy.version` (test/gate-route.test.ts:142), not
   runGate's actual output. For EV-81 the field must carry the FOLLOWUP DECISION
   policy's version (`followup-decision-1`) and `questionSetVersion` the followup set's.
   The shipped defect is not EV-81's to fix, but it must be named and carded; mirroring
   `policy.policyVersion` would replicate it.
4. **No line domain discriminator exists.** Both domains write kind:"call",
   schemaVersion 2 to the same gate-ledger.jsonl with `resolvedMode` an open string.
   Shipped consumers inert (resolveRoute filters by stateHash first + rejects
   non-GATE_DECISION_MODES; decisionLine generic; gate-render joins by callId). EV-84
   must identify followup lines. Options: (a) vocabulary disjointness pinned by a test
   using the exported constants (principal LEANS (a) — the ledger deliberately keeps
   resolvedMode a string; no shipped consumer needs a tag); (b) additive optional
   `domain` field. Card should decide explicitly.
5. **Off-mode ownership:** `buildFollowupState`'s own comment assigns the off
   short-circuit to "the EV-81/82 call site … before the state build";
   `runFollowupGate` throws loudly on off (mirroring runGate); short-circuit lives in
   the caller BEFORE buildFollowupState (else an off policy with no budget key throws
   from the packer). EV-82's "off leaves the prose review unqualified" depends on this
   ordering.
6. **Module placement: COLOCATE `runFollowupGate` in gate-run.ts** (opposite the
   owner): `transportFailure`/`FailureShape` are private in gate-run.ts; exporting them
   widens the surface EV-82/83's reason grammar depends on; a private duplicate is the
   drift the taxonomy fears. Smallest import delta; type-only import of `FollowupState`
   from followup-state.ts (avoids pulling followup-state→gate-route→runs.ts'
   child_process edge into runtime). If the owner insists on domain separation, export
   the failure taxonomy to one shared home rather than copy it.
7. **Range residual:** agrees — fix the SHARED `sideProbability` choice branch to
   reject [0,1], closing both arms and discharging the PO's re-card trigger; parse-site-
   only leaves the shipped decide() arm accepting out-of-range probabilities = the named
   NEW card at step 13. Cost named: the thrown error is `gate:`-prefixed inside the
   followup domain, weakening EV-79's `followup:`-prefixed grammar for that one arm —
   acceptable (EV-82/83 surface the invalid-response class at the call boundary, not
   the prefix). Owner must record which seam was chosen so the re-card trigger's status

8. **EV-84 wiring (build nothing):** injectable transport; repoRoot+ledgerPath so the
   fixture's line lands in a tmpdir; result carrying status:"failed" + failure.kind +

9. **FLLWUP-96's composition site — mis-assignment risk:** if EV-81 mirrors runGate's
   "loads nothing itself" posture, the site holding BOTH questions and decisionPolicy

   composition entry point that loads+composes both files, or FLLWUP-96's promotion
