## Intent

This is the only surface of the epic: a one-shot info toast at TUI/RPC
start-up, gone within seconds, no persistent row. It fires once per `pi`
process, at `session_start` when `reason === "startup"` and `ctx.hasUI` is true
(true in TUI and RPC; false in `-p`/`--mode json`), and nowhere else. The
identity it shows comes from EV-57's resolver applied to the running package
root (`PKG_ROOT`, `seats.ts:29`) — never the consumer cwd. Plain text only, no
inline ANSI and no theme tokens. The copy is `council: pi-council v<version>
(<sha>)`, with the two named degraded copies `(no git metadata)` and
`(git unavailable)`.

## Acceptance

- For a fixture identity, one `session_start` with `reason: "startup"` and
  `ctx.hasUI: true` emits exactly one notify of kind `info` whose text
  byte-equals `council: pi-council v<version> (<sha>)`.
- In a session where another `council:`-prefixed notification also fires,
  exactly one notification's text starts with `council: pi-council v`.
- For `reason` in {new, resume, reload, fork}: no identity notify.
- For `ctx.hasUI` false (print, json): no identity notify and no console
  output; nothing on fd 1.
- When the resolver returned `no-git-metadata`: text byte-equals
  `council: pi-council v<version> (no git metadata)`.
- When the resolver returned `git-unavailable`: text byte-equals
  `council: pi-council v<version> (git unavailable)`.
- The two degraded strings render distinct from each other and from the normal
  string.
