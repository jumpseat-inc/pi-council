## Intent

changed; the slash command's echo is the copy surface (TUI and headless), and it
must share the loader so the printed value cannot drift from what dispatch
resolves. Operator-facing copy says "gate"; "jev" appears in no operator-facing
string.

### Designer (job-5.4)

Position: three copy surfaces — post-write echo, no-arg status read, unknown-arg failure — are easier to make honest than to make clever; pushing clever into them is the largest standing hazard. Echo after successful write: one line, command-family prefix, names .council.json (so hand-edit and command agree on location — echo lines double as documentation of the write), ends with R5's timing claim: `[council-gate] gate mode is now active in .council.json — applies to dispatches after this echo.` The "in .council.json" clause does real work (operator verifying by editor needs the file name). The trailing timing clause is load-bearing: resolver is lazy-at-call; "dispatches after this echo" is the strongest claim the surface can back; do NOT transplant /council-models' "takes effect at the next dispatch" verbatim — a gate change applies on the next loadGateConfig call, different in kind from a seat-model change.

Redundant-set echo (the harder one): non-assertive echo rule bites — cannot say "wrote" when no write occurred; "when an echo quotes post-merge effective state, it must quote the effective value, never a blank." Literal names the no-op as a no-op, names the mode, stops: `[council-gate] gate mode is already active in .council.json — no change.` Test for copy honesty: glance-diff of change vs no-op echo reveals the difference is precisely "did we write," nothing else. Sister precedent: /council-models' "— thinking unchanged".

No-arg form: a status read, not an assertion. One line: `[council-gate] gate mode is off.` No usage block, no gloss footnote — those belong to EV-77's docs sweep. Same grammatical skeleton as the echoes (three forms, one skeleton) — makes the no-arg form feel like a read, not a write.

Unknown-arg failure: fail loud, single line, name the allowed set, offending arg in quotes: `[council-gate] error: unknown mode "actiev" — expected one of off, advisory, active`. Typing cases: actiev, Active, "off " (trailing ws — trim then reject), --off, 0 — all land on the same error line.

Conceptual-model hazards: (H1) advisory vs active are NOT symmetric (advisory makes a network call and writes a ledger line, never blocks; active may block) — but the explainer belongs to EV-77's docs surface, NOT inline parentheticals on every echo (repeats fifty times a day, smuggles glossary copy past the EV-77 surface). (H2) naming .council.json on every form — right and load-bearing. (H3) the timing claim — any variant claiming "now"/"this session"/"all future commands" is too strong; any variant omitting timing leaves the operator wondering.

Consistency: `[council-gate]` bracket tag for errors (family pattern); success line bare-name `council-gate:` mirroring `council-models: wrote ...` (defensible opposite; defer to owner); headless emit(line) per item, no blocks (single tri-state value; /council-models' block is multi-line because seven seats); require the analogous pure helper so TUI and headless share copy — echo-then-run not enforceable if one surface has bespoke copy.

P3 no-op echo never asserts a write (`not.toMatch(/\bwrote\b/)`; matches already/no change). P4 every other top-level key byte-preserved through one change (theme, retry, council.<seat>, unknown "foo":"bar"). P5 unknown arg: single line, quoted offender, allowed set enumerated. Sharp critique for the skeptic: the post-write echo does two things at once (what changed + when it applies); press whether a fast reader sees the timing clause as the gating constraint or a footnote (predicts trailing is right; leading verb is the operator's primary question).

Ranked preferences: (1) echo names .council.json on every form; (2) success and no-op echoes share a grammatical skeleton differing only on whether a write happened; (3) timing clause trails as "— applies to dispatches after this echo"; (4) `[council-gate]` prefix matches the family; (5) bare-name success line mirroring council-models (defer to owner); (6) advisory/active gloss lives in EV-77, not the echo; (7) no-arg one line, not a block.
